## §2 界面与数据流（**逐字冻结**）

### §2.1 数据流（**一份草稿、两个视图**）

```
                    ┌── 产品视图「产品树」        ← 本批：**器件的编辑面**
草稿（唯一那一份） ──┤
                    └── 板级内存图编辑器（#/memory-map）
                            ├─「外设窗口」表  ← **器件**（与树**同一份草稿**）
                            └─「RAM / ROM 段」表 ← **内存**（同一份草稿）
                                  │
                                  ▼
                    submit-memory-map（**同一个命令** · F-9）
                                  ▼
                    内核造实例 + 绑基址（F-10）→ 逐实例清单多一行（F-11）
                                  ▼
                    产品视图那张「内存映射 (M-14)」卡 ← **显示生效的图**
                              （⚠️ 内核的真相 ⇒ ⇒ 它**要等内核接受**才变
                                ⇒ ⇒ 这正是「待生效」标注的意义）
```

⚠️ **两个「表」不是一回事**（实测踩过）：
- **编辑器**（`#/memory-map`）里那张「外设窗口」表 = **草稿** ⇒ ⇒ 树上改一下**它立刻变**；
- **产品视图**里那张「内存映射 (M-14)」卡 = **当前生效的图**（内核的真相）⇒ ⇒ 改草稿**它不动**，**提交被内核接受后**才动。

⇒ ⇒ 所以「同一个量只显示一处」这条纪律**仍然成立**：草稿只在编辑器里显示，生效的图只在产品视图那张卡显示 ⇒ ⇒ **不重复**。

### §2.2 DOM 契约（**新增钩子**）

| 钩子 | 落点 | 含义 |
| --- | --- | --- |
| `data-board-tree` | 树的根 | **树 = 草稿的派生视图**（F-4 ⇒ 不再读 `state.tree`） |
| `data-device-node="<id>"` | 每个器件节点 | 一个器件实例 |
| `data-device-node-kind="<kind>"` | 同上 | 该实例的类型 |
| `data-device-node-pending="0\|1"` | 同上 | **待生效**（判据来自**内核的**逐实例状态 · F-3 ⇒ 不前端自己算） |

| `data-mm-device-kind` | 类型下拉 | **类型下拉**（选项来自**内核的类型表** · H） |
