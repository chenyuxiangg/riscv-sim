1 功能概述

1.1 模块定位

M-12 事件驱动仿真引擎实现量子化混合调度主循环（4.4.1.1）：以 1µs 时间量子（可配置）为 IRQ 采样节奏，每量子先处理到期事件再让 ISS 执行至多「量子指令配额」条指令；无到期事件且 guest 处于空闲区间时，批量推进虚拟时间到下一事件/检查点（不逐量子空转）。确定性由固定种子 PRNG + 稳定事件排序（虚拟时间, 插入序）保证；控制注入只在安全检查点（事件边界 ∨ 指令计数边界）发生。

指令预算 watchdog 采用「无进展检测」：连续 N 条指令无任何外部可见进展（中断/事件/访存 I/O 完成，仅 MMIO 区域访问计进展）判定 guest 失控，宿主时间仅作辅助预算（默认 200ms，暂停期扣除），触发后同步终止内核并置幂等标志（与 guest trap 严格区分）。承接 FR-06（中断采样节奏）/FR-12（确定性）；M-12 在确定性适用范围（2.4 表6）。

1.3 MVP 范围与预留

MVP 实现范围：主循环 runUntil（量子化混合调度 + 每量子指令配额）、事件队列（min-heap，稳定排序，支持取消/溢出恢复）、虚拟时间推进（批量推进限定空闲区间）、量子边界中断采样（pollIRQ，M-16 交接结构）、安全检查点与控制命令队列（injectCommand）、watchdog 无进展检测（watchdogCheck，幂等）、确定性 PRNG（种子化随机源）、输入事件时间戳化入口（scheduleEvent，唯一输入路径）、状态查询（getEngineState）与探针点（engineHooks）。

预留项（本模块仅保留演进承接说明，不展开实现）：录制/回放事件源接入（FR-17，P1，复用 M-20 录制格式）；跨板事件同步（FR-25，P1，与 M-15 port/link 协作）；多核/SMP 调度（FR-18，P2，随 M-17 扩展）。

2.1.1 复杂结构字段定义

Event 是事件队列条目；EventPayload 为载荷类型体系（值语义，入队拷贝、分发后释放）；EngineState 为主循环整体状态。字段定义如下：

// Event: 事件队列条目（稳定排序键 = time + seq）
struct Event {
  uint64_t      time;      // 虚拟时间（到期时刻；迟到事件归一为当前时间）
  uint64_t      seq;       // 插入序（同时间稳定排序锚点；取消令牌）
  EventKind     kind;      // EV_TIMER / EV_UART_RX / EV_GPIO_IN / EV_WATCHDOG / EV_CHECKPOINT
  EventPayload  payload;   // 载荷（值语义：入队拷贝、分发后释放）
};
// EventPayload: 载荷类型体系（联合，无所有权转移）
union EventPayload {
  TimerEv     { uint32_t id; uint64_t cmpVal; };   // EV_TIMER
  UartRxEv    { uint32_t len; uint8_t  data[8]; }; // EV_UART_RX（≤8 字节）
  GpioEv      { uint32_t pin; uint8_t  level; };   // EV_GPIO_IN
  WatchdogEv  { uint32_t reason; };                // EV_WATCHDOG（仅日志/回放记录）
  CheckpointEv{ uint32_t reason; };                // EV_CHECKPOINT
};
// Command: 控制命令（排队，安全检查点按序执行）
struct Command {
  CommandKind kind;   // CMD_PAUSE / CMD_STEP / CMD_RUN_UNTIL / CMD_SET_BREAKPOINT
  uint64_t    arg;    // 参数（目标时间/断点地址等）
  uint64_t    seq;    // 命令序（先进先出）
};
// EngineState: 仿真引擎整体状态
struct EngineState {
  heap<Event>   eventQueue;      // min-heap：按（time, seq）稳定排序
  uint64_t      virtualTime;     // 虚拟时间（仅由量子推进）
  uint64_t      quantum;         // 时间量子（默认 1µs，可配置）
  uint64_t      quantumInstrQuota; // 每量子指令配额（量子↔指令映射）
  uint64_t      instrCount;      // 指令计数（检查点与无进展检测基准）
  uint64_t      nextSeq;         // 下一插入序（事件/命令共用）
  uint64_t      progressBase;    // 无进展检测基准（上次产生外部进展的指令位置）
  uint64_t      lastCheckHostUs; // 上次宿主时间检查点（暂停期扣除）
  uint64_t      queueCapacity;   // 事件队列容量（溢出暂停告警）
  uint8_t       paused;          // 暂停标志（安全检查点置位）
  uint8_t       watchdogFired;   // watchdog 幂等标志（一次运行仅触发一次）
  uint8_t       hostSlowWin;     // 宿主时间超窗计数（滑动窗口确认）
  RngState      prng;            // 确定性 PRNG（固定种子）
  Queue<Command> cmdQueue;       // 控制命令队列（FIFO）
};

2.2 事件类型

事件类型产生源载荷说明
EV_TIMERM-15 Timer 比较到期 / M-16 mtimecmpTimerEv{id, cmpVal}定时器到期回调（onEvent）
EV_UART_RXM-04 输入注入（UART 写）UartRxEv{len, data[8]}接收就绪，时间戳化入事件流（FR-12）
EV_GPIO_INM-04 输入注入（按键/GPIO）GpioEv{pin, level}引脚电平变化，时间戳化入事件流
EV_WATCHDOGM-12 watchdog 检查WatchdogEv{reason}仅日志/回放记录；处置走同步终止（评审 12-3）
EV_CHECKPOINTM-04/M-12 检查点触发CheckpointEv{reason}每 10s 虚拟时间或关键事件（M-20 联动）

输入事件唯一路径（评审 B12-2）：外部输入（UART 写/按键/GPIO 注入）一律经 M-04 recordInput 写入 M-20 事件流，由 M-12 scheduleEvent 在时间戳化后入队；业务模块不得绕过该路径直接入队。scheduleEvent 同时承接引擎内部事件（如检查点触发）。

迟到事件语义（评审 12-6）：入队时间 time 小于当前 virtualTime 时，归一为「当前虚拟时间 + 0」入队（seq 递增保持稳定排序），并 log 警告；不允许丢弃。

2.3 数据流说明

主循环：事件队列（min-heap）→ 到期分发（外设 onEvent → 中断请求）→ 量子边界采样（M-16 交接 PendingIntr）→ ISS 执行至多量子指令配额（M-13，访存经 M-14、钩子触发）→ 安全检查点（命令队列执行 + watchdog 无进展检测）→ 空闲区间批量推进 → 循环。确定性：固定种子 PRNG + （虚拟时间, 插入序）稳定排序；虚拟时间不依赖宿主时钟（2.4 表6）。

3 实现设计

3.1 主循环 runUntil（量子化混合调度）

「量子↔指令」映射（评审 12-1）：每量子执行至多 quantumInstrQuota（默认 1000 条，估算基线）条指令；指令边界与量子边界统一为安全检查点。批量推进仅限 guest 空闲区间（无到期事件且无待交付中断）；非空闲时逐量子执行。runUntil 伪代码如下：

// runUntil: 连续执行到虚拟时间 t 或暂停条件（主循环入口）
RunReason runUntil(EngineState* s, uint64_t t) {
    while (s->virtualTime < t && !s->paused) {
        if (eventQueue_empty(s) && pending_intr_empty(s)) {
            // guest 空闲区间：批量推进到下一事件/检查点，不空转
            uint64_t next = next_event_time_or_checkpoint(s);
            advanceTime(s, min(next, t));
            continue;
        }
        dispatchDueEvents(s);                 // 分发到期事件（外设 onEvent）
        pollIRQ(s);                           // 量子边界采样（M-16 交接）
        uint64_t done = 0;                    // 本量子已执行指令数
        while (done < s->quantumInstrQuota && !s->paused) {
            RunReason r = iss_step(s);        // M-13：执行一条指令
            done++;
            if (r == BREAKPOINT_HIT) return r;
            if (event_due_now(s)) break;      // 有事件到期：回到分发
            if (done % s->instrCheckpoint == 0)
                watchdogCheck(s);             // 指令计数检查点（每 ≤10⁴ 条）
        }
        injectCommandsAtSafePoint(s);         // 安全检查点：命令队列按序执行
        hook(SEC_QUANTUM_END);                // 探针：量子结束
    }
    return s->paused ? PAUSED : TIME_REACHED;
}

3.2 事件队列与稳定排序

min-heap 按（虚拟时间, 插入序）稳定排序：同一虚拟时间的事件按 seq 严格定序，保证同种子 + 同输入序列 → 结果唯一（2.4 表6）。支持取消（eventCancel，按 seq 标记取消）与溢出恢复（评审 12-8）。

// scheduleEvent: 事件入队（时间戳化输入事件统一入口；唯一输入路径，评审 B12-2）
uint64_t scheduleEvent(EngineState* s, Event ev) {
    if (ev.time < s->virtualTime) {
        log(WARN, "ENGINE", "late event, normalized", "");
        ev.time = s->virtualTime;             // 迟到事件归一（评审 12-6）
    }
    if (queue_depth(s) >= s->queueCapacity) {
        s->paused = 1;                        // 溢出：暂停仿真并告警，不丢事件
        log(ERROR, "ENGINE", "event queue overflow", "");
        return 0;
    }
    ev.seq = s->nextSeq++;
    s->eventQueue.push(ev);
    return ev.seq;                            // 输出：插入序（取消令牌）
}
// eventCancel: 按 seq 标记取消（留在堆中，分发时跳过）
void eventCancel(EngineState* s, uint64_t seq) { s->eventQueue.cancel(seq); }
// 稳定排序键：time 升序，同 time 按 seq 升序（确定性）

3.3 虚拟时间推进与空闲区间

advanceTime 仅推进到下一事件/检查点，且仅在 guest 空闲区间（无到期事件且无待交付中断）调用；虚拟时间仅由推进更新，不依赖宿主时钟（2.4 表6）。

3.4 安全检查点与控制命令队列

控制命令（pause/step/runUntil/setBreakpoint）结构化入队（评审 B12-3）：非安全检查点到达的命令先入 cmdQueue，到安全点（量子边界 ∨ 指令计数边界 ∨ 事件边界）按 FIFO 执行；保证不打断执行中的访存、不产生半指令状态（4.4.1.1）。

// injectCommand: 控制命令注入（结构化命令，排队执行）
uint64_t injectCommand(EngineState* s, Command cmd) {
    cmd.seq = s->nextSeq++;
    s->cmdQueue.push(cmd);
    return cmd.seq;
}
// injectCommandsAtSafePoint: 安全检查点按序执行命令队列
void injectCommandsAtSafePoint(EngineState* s) {
    while (!cmdQueue_empty(s)) {
        Command c = s->cmdQueue.pop();
        switch (c.kind) {
          case CMD_PAUSE:       s->paused = 1; break;
          case CMD_STEP:        s->stepMode = 1; break;  // step：执行 1 条指令后返回
          case CMD_RUN_UNTIL:   s->runUntilT = c.arg; break;
          case CMD_SET_BREAKPOINT: set_breakpoint(c.arg); break;
        }
    }
}

3.5 watchdog 无进展检测

watchdog 采用「无进展检测」（评审 12-2）：记录上次产生外部可见进展（事件分发/中断交付/访存 I/O 完成）的指令位置，连续超过 progressWindow（默认 10⁶ 条，估算基线）条指令无进展 → 判 guest 失控。宿主时间仅作辅助预算（每 ≤10⁴ 条检查、超 hostBudgetUs 计一次超窗），且需连续 3 个检查窗口均无进展才触发（滑动窗口确认，评审 12-9）；宿主时钟采用单调时钟、暂停期扣除（评审 12-4）。触发后同步终止（评审 12-3）：直接调 report(HMS_FATAL)（M-22 报告接口，hms_report 为其内部封装名，文档统一用 report）同步终止内核，EV_WATCHDOG 仅作日志/回放记录，不再入队投递；watchdogFired 幂等标志保证一次运行仅触发一次。progressBase 更新点（评审 R12-2）：三类外部可见进展分别在 ① dispatchDueEvents() 分发任一到期事件后、② pollIRQ() 仲裁命中并交付中断后、③ onProgress() 回调（仅 MMIO 区域访问完成，评审 R12-3；普通 RAM 读写不计进展，避免死循环带访存测不到）处回写。

// watchdogCheck: 指令计数检查点（每 ≤10⁴ 条）；无进展检测 + 宿主时间辅助 + 幂等
// progressBase 更新点（三类外部可见进展各自回写基准，评审 R12-2）：
//   ① 事件分发：dispatchDueEvents() 分发任一到期事件后    → progressBase = instrCount;
//   ② 中断交付：pollIRQ() 仲裁命中并交付中断后            → progressBase = instrCount;
//   ③ 访存 I/O：onProgress() 回调（仅 MMIO 区域访问完成，
//                普通 RAM 读写不计进展，评审 R12-3）      → progressBase = instrCount;
void watchdogCheck(EngineState* s) {
    s->instrCount++;
    if (s->instrCount % 10000 != 0) return;
    if (s->watchdogFired) return;             // 幂等：一次运行仅触发一次
    // 条件1：无进展检测（连续 progressWindow 条无外部事件）
    bool noProgress = (s->instrCount - s->progressBase) >= s->progressWindow;
    // 条件2：宿主时间辅助（单调时钟，暂停期已扣除）
    bool hostSlow = (host_now_us() - s->lastCheckHostUs) > s->hostBudgetUs;
    if (hostSlow) s->hostSlowWin++; else s->hostSlowWin = 0;
    bool hostSlow3 = (s->hostSlowWin >= 3);   // 滑动窗口：连续 3 窗确认
    if (noProgress || hostSlow3) {
        s->watchdogFired = 1;                 // 幂等标志
        log(ERROR, "ENGINE-WD", "guest runaway", "");
        report(HMS_FATAL, "guest runaway");   // M-22 报告接口（hms_report 为其内部封装名）；同步终止（不投递事件）
        // EV_WATCHDOG 仅作日志/回放记录（WatchdogEv{reason}）
    }
    s->lastCheckHostUs = host_now_us();
}

3.6 确定性 PRNG

种子化 PRNG 服务噪声/去抖/ADC 等随机源：同一种子生成同一随机序列，不依赖宿主熵（2.4 表6）；随机源消费顺序由事件排序锁定，保证跨运行一致。

3.7 宿主时间与暂停扣除

宿主墙钟仅用于 watchdog 辅助预算：使用单调时钟（host_now_us，performance.now 语义），回拨差值为负按 0 处理；暂停（paused）与断点期间在 resume 时重置 lastCheckHostUs 为当前宿主时刻，暂停时长不累积（评审 12-4）。

5 处理流程

5.1 主循环流程

主循环闭环如下（对应图 1，源设计 4.4.1.4；时序按评审 12-1 修订）：

（1）取最早到期事件：eventQueue.top（虚拟时间，插入序）；迟到事件归一为当前时间（评审 12-6）。

（2）分发到期事件：外设 onEvent → 中断请求（M-15/M-16）；跳过已取消事件。

（3）量子边界采样 + 执行：pollIRQ → M-16 交接（PendingIntr{line, cause, prio}）；ISS 执行至多每量子指令配额（访存同步分发、钩子触发、trap 记录）。

（4）安全检查点：指令计数边界 ∨ 事件边界；命令队列按序执行 + watchdog 无进展检测（每 ≤10⁴ 条）。

（5）批量推进（仅空闲区间）：无到期事件且无待交付中断 → 推进到下一事件/检查点，不空转；回到循环顶。

（6）观测与记录：probe → M-18 → M-19；log → M-21（调度/watchdog 日志）。

（7）watchdog 确认：连续窗口无进展 → HMS 同步 terminate（幂等，与 guest trap 严格区分）。

6.2 边界与降级

（1）性能边界：每量子固定开销（到期事件检查 + IRQ 采样 + 控制注入检查）预算 ≤10% 单量子执行时间（估算基线，评审 P-11）；批量推进仅限空闲区间、不空转。

（2）确定性边界：虚拟时间不依赖宿主时钟；事件队列按（虚拟时间, 插入序）稳定排序；违反 → 确定性断言失败（2.4 表6、源文档 7.3 表92）。

（3）watchdog 阈值边界：无进展窗口（10⁶ 条）与宿主时间辅助预算（默认 200ms）为估算基线，实现后实测校准；宿主慢速仅作辅助判据，连续 3 窗确认，不误判正常慢速仿真与宿主 GC（评审 12-2/12-9）。

（4）事件队列溢出：暂停仿真并告警，不丢事件；恢复路径 = drain 非关键事件或扩容后继续（评审 12-8）。
