1 功能概述

1.1 模块定位

M-14 维护地址区间树（range→region），实现 RAM/ROM/外设归属与读写 O(log n) 分发，是仿真内核层（④层）的访存通路中枢。M-13 的取指与访存读写均经本模块分发：命中 RAM 直接访问；命中外设转调 M-15 的 Peripheral.read/write；未命中产生可观察的访存异常（E_BUS-01，guest trap 语义）。映射表支持 UI 查看与编辑，编辑校验通过后即时生效（FR-03）。

在平台整体中，M-14 不直接面对前端：映射配置经 M-02 产品视图 / M-05 命令协议进入；访存 trace 事件经 M-18 钩子输出。本模块为 ExecutionBackend（M-17）抽象的自洽实现提供访存基座（L1~L3 共用）。

1.3 MVP 范围与预留

MVP 实现范围：RAM/ROM/PERIPHERAL 三类区间注册与删除（mapRegion/unmap）、地址查表（lookup，O(log n)）、读写分发（read/write，支持 8/16/32 位宽度与小端字节序）、未映射访存异常（E_BUS-01，guest trap 语义）、映射编辑即时生效（FR-03）、访存 trace 钩子（M-18 总线 trace 底）。

预留项（本模块仅保留演进承接说明，不展开实现）：多主/多核总线仲裁（FR-18，P2，经 M-17 扩展预留）；Cache/TLB 与写缓冲建模（随 S/U 特权模式演进）；总线时序握手建模（突发/等待状态，源设计基线不建模）；64 位地址空间（当前按 32 位地址空间设计）。

2.1.1 复杂结构字段定义

Region 是区间树的叶子语义实体，描述一段地址区间归属：

// region: 地址区间实体
struct Region {
  uint32_t base;        // 区间起始地址（左闭）
  uint32_t size;        // 区间长度（字节），[base, base+size) 左闭右开；拒绝 size=0（评审 14-12）
  uint8_t  type;        // 区间类型：RAM / ROM / PERIPHERAL（见 2.2 表）
  Target   target;      // typed handle（评审 14-12）：按 type 解释，不用裸 void*——
                        //   RAM → RamBackend*（3.2 注）；ROM → RomBackend*；PERIPHERAL → Peripheral 实例句柄
  uint8_t  readonly;    // 只读标志（ROM 置 1；RAM/PERIPHERAL 置 0）
  uint32_t attr;        // 预留属性位（多核/优先级等演进预留）
};
// RAM 后端契约（评审 14-5）：region.target 在 type==RAM 时指向 RamBackend
struct RamBackend {
  uint8_t* mem;         // 存储指针（容量 = region.size，越界即总线 bug，mapRegion 校验保证）
  uint32_t capacity;    // 容量（字节，= region.size）
  uint32_t base_addr;   // 绑定基址（= region.base）
};
// 接口：ram_read(backend, off, width) / ram_write(backend, off, width, val)
// 固件加载入口：loadImage(base, data, len) 由 M-06 加载 ELF 后调用（数据进入 RAM 的唯一入口，
//   归属 M-06/M-07 侧调用方；初始化内容默认全 0，loadImage 覆盖写入）。

IntervalNode 为增强型区间树节点，携带 maxEnd 用于查找剪枝（算法见 3.1）：

// intervalNode: 区间树节点（按 base 排序的增强 BST）
struct IntervalNode {
  uint32_t start;       // 区间起点 base
  uint32_t end;         // 区间终点 base+size（左闭右开）
  uint32_t maxEnd;      // 子树最大 end，命中剪枝依据：右子树 maxEnd > addr 才可能命中
  Region*  region;      // 指向区间实体
  IntervalNode* left;   // 左子树（start 更小）
  IntervalNode* right;  // 右子树（start 更大）
  int8_t   balance;     // 平衡因子（AVL 维护，保证查找 O(log n)）
};

busStats 为指标与确定性记录提供数据源；busHook 事件字段与 M-18 总线 trace 契约对齐（每访存记时间戳+地址+方向+宽度）：

struct BusStats {

};

2.2 区间类型与访问语义

源设计 4.4.3.2 定义区间类型 RAM/ROM/外设；下表给出各类区间的读写行为、异常语义与对拍断言（带 ※ 的为本文档补充的设计决策，源基线未明确规定）：

类型读写行为访存异常对拍语义
RAM读直接返回；写直接生效不产生与 Spike golden 内存语义一致（入对拍）
ROM读返回；写忽略并可选上报调试事件（※设计决策）不产生ROM 写忽略为平台自测语义，Spike 无 ROM 概念（内存可写），ROM 写用例不入 Spike 对拍（评审 14-4）
PERIPHERALread 经 target.read(offset,width)；write 经 target.write 即时生效（M-15）外设内错误由外设语义决定；外设抛错转 E_BUS-05 外设错误（※设计决策，评审 14-3）外设行为由 M-15 对拍；总线仅保证分发正确

2.3 数据流说明

访存数据流：M-13 fetch/load/store → read(addr,width)/write(addr,width,val) → lookup(addr) → 命中 RAM 直接读写 / 命中 PERIPHERAL 转调 M-15 / 未命中产生 E_BUS-01 → 数据或异常回 M-13；每次访问触发 on_bus_access（M-18）。

映射配置数据流：UI（M-02 映射视图/外设面板）或命令（M-05）→ mapRegion/unmap → 校验（越界 E_BUS-04、重叠 E_BUS-03）→ 应用并即时生效；失败返回错误码，UI 保留旧配置（4.4.3.5）。

trace 数据流：总线事件流（时间戳+地址+方向+宽度）→ M-18 traceStream → M-11 导出；观测类事件允许节流合并、不要求可靠投递（平台管道设计）。

3 实现设计

3.1 区间树结构与查找算法

源设计 4.4.3.2 点名 interval tree：区间按 base 排序组织，节点携带 maxEnd（子树内最大 end），命中判定可在 O(log n) 完成。MVP 区间数量小（RAM/ROM + 少量外设），实现上可选择增强 BST（查/改均 O(log n)）或有序数组二分（查 O(log n)、编辑 O(n) 重建）；本文以增强 BST（AVL 平衡）为设计基线，与两种简化方案对比如下：

方案查找 lookup插入/删除适用说明
线性扫描O(n)O(1) 追加区间数极少（≤8）时简单直接，不做推荐
有序数组 + 二分O(log n)O(n) 重建编辑不频繁、以查询为主时足够，实现最简单
增强 BST 区间树O(log n)O(log n)源设计基线；映射编辑频繁时性能稳定

lookup 查找算法（区间左闭右开 [start, end)）：

// lookup: 区间树查找（O(log n)）
Region* lookup(uint32_t addr) {
    IntervalNode* node = root;
    while (node != NULL) {
        if (addr < node->start) { node = node->left; continue; }   // 只可能命中左子树
        if (addr < node->end)   return node->region;               // 命中 [start, end)
        if (node->right != NULL && node->right->maxEnd > addr)
            node = node->right;                                    // 右子树仍可能命中
        else
            node = NULL;                                           // 剪枝：右子树最大 end 也 ≤ addr
    }
    return NULL;                                                   // 未映射
}
// maxEnd 维护：插入/删除后自底向上更新
//   maxEnd(node) = max(node->end, maxEnd(node->left), maxEnd(node->right))

正确性要点：区间不允许重叠（mapRegion 保证，见 3.3），因此「addr < node->end 即命中」判定唯一；maxEnd 剪枝是 O(log n) 的关键——右子树所有区间的 end 均 ≤ maxEnd，若 maxEnd ≤ addr 则右子树绝无命中区间，直接跳过。

3.2 读写分发实现

宽度语义：read/write 支持 8/16/32 位宽度，其余宽度返回 E_BUS-02 非法地址宽度；RV32 为小端序，16/32 位值按「低字节在低地址」组装。非对齐访问：单区间内直接允许（与 Spike golden 一致——前提是参考侧 Spike 启用 Zicclsm 扩展，见台账 D-42）；跨区间边界的非对齐访问拆分为字节切片、逐切片落在单一区间内分发（※设计决策，源基线未规定）。

错误传递契约（评审 14-6）：read/write 返回 BusResult{val, err} 结构——err==OK 时 val 有效；err!=OK 时 val 无效（恒 0），调用方（M-13）按 err 转同步陷入；不使用哨兵值（0xFFFFFFFF 可能是合法数据，避免歧义）。

跨区间拆分语义（评审 14-1）：写访问跨区间时改为「两阶段」——先对全部字节片预检可访问性（任一未映射/外设错误 → 整笔失败并返回错误码，不执行任何写），预检通过后再逐片执行写；保证写操作原子性语义（不允许「RAM 已写 + 异常上报」的部分成功状态）。读访问无副作用，可逐片分发拼接。

读写分发伪代码（read 为例；write 同构，两阶段预检）：

// 错误传递契约（评审 14-6）：BusResult 同时表达数据与错误
//   err==OK → val 有效；err!=OK → val 恒 0，调用方转同步陷入
typedef struct { uint32_t val; err_t err; } BusResult;

// bus_read: 读分发（宽度 8/16/32，小端）
BusResult bus_read(uint32_t addr, uint8_t width) {
    if (width != 8 && width != 16 && width != 32) return (BusResult){0, E_BUS-02};
    if (crosses_region(addr, width)) return bus_read_split(addr, width);  // 跨区间逐片读拼接
    on_bus_access(ts, addr, width, DIR_READ);            // trace 钩子（M-18），覆盖全部访存
    Region* r = lookup(addr);
    if (r == NULL) return (BusResult){0, E_BUS-01};      // 未映射 → guest trap（M-13 转 mcause 1/5/7）
    uint32_t off = addr - r->base;
    if (r->type == RAM) return (BusResult){ram_read(r->target, off, width), OK};
    if (r->type == ROM) return (BusResult){rom_read(r->target, off, width), OK};
    return periph_read(r->target, off, width);           // M-15 Peripheral.read（err 非 OK → E_BUS-05，见 6.1）
}

// bus_write: 写分发（两阶段，评审 14-1：不允许部分提交）
err_t bus_write(uint32_t addr, uint8_t width, uint32_t val) {
    if (width != 8 && width != 16 && width != 32) return E_BUS-02;
    if (crosses_region(addr, width)) return bus_write_split(addr, width, val); // 两阶段见下
    on_bus_access(ts, addr, width, DIR_WRITE);
    Region* r = lookup(addr);
    if (r == NULL) return E_BUS-01;
    uint32_t off = addr - r->base;
    if (r->type == RAM) { ram_write(r->target, off, width, val); return OK; }
    if (r->type == ROM) { rom_write_ignore(addr, width, val);  return OK; }  // 写忽略（可选调试事件）
    return periph_write(r->target, off, width, val);       // err 非 OK → E_BUS-05
}

// 跨区间拆分（评审 14-7：crosses_region 判定 = 两端 lookup 比对）
bool crosses_region(uint32_t addr, uint8_t width) {
    if (width == 8) return false;                          // 单字节不跨
    Region* r0 = lookup(addr);                             // 首字节所在区间
    Region* r1 = lookup(addr + (width - 1));               // 末字节所在区间（width≤32 无溢出）
    if (r0 == NULL || r1 == NULL) return true;             // 任一端未映射 → 需拆分（逐片定位错误片）
    return r0 != r1;                                       // 两端区间不同 → 跨区间
}

// 写拆分两阶段（评审 14-1）：预检全部字节片 → 通过后统一执行，保证无部分提交
err_t bus_write_split(uint32_t addr, uint8_t width, uint32_t val) {
    for (int i = 0; i < width/8; i++) {                    // 阶段一：预检
        uint32_t a = addr + i;
        Region* r = lookup(a);
        if (r == NULL) return E_BUS-01;                    // 任一未映射 → 整笔失败，不执行任何写
        if (r->type == PERIPHERAL && periph_precheck(r->target, a - r->base) != OK)
            return E_BUS-05;                               // 外设片不可访问 → 整笔失败
    }
    for (int i = 0; i < width/8; i++) {                    // 阶段二：统一执行
        uint32_t a = addr + i; uint8_t b = (val >> (8*i)) & 0xFF;
        Region* r = lookup(a);
        if (r->type == RAM) ram_write(r->target, a - r->base, 8, b);
        else if (r->type == PERIPHERAL) periph_write(r->target, a - r->base, 8, b);
        /* ROM 片：写忽略 */
    }
    return OK;
}
// 读拆分逐片分发拼接（无副作用，无需预检）：
//   bus_read_split 按字节片分别 lookup + 读，小端拼接返回；片未映射 → 整笔 E_BUS-01。

3.3 映射编辑事务

mapRegion 按「校验 → 构建新树 → 原子替换」三步执行：① 地址越界检查（base+size 溢出 32 位地址空间 → E_BUS-04）；② 重叠检查（与现有任一区间相交 → E_BUS-03）；③ 通过后插入新节点并更新 maxEnd，随后整体替换根指针，即时生效。任一步失败均保留旧配置（源设计 4.4.3.5）。

// mapRegion: 注册/更新映射区间（事务式，失败保留旧配置）
err_t map_region(Region* r) {
    if (r->size == 0)                return E_BUS-06;   // 非法区间：size=0（评审 14-12）
    if (r->base + r->size < r->base) return E_BUS-04;   // 越界：32 位地址空间溢出
    if (overlaps(r))                 return E_BUS-03;   // 冲突：与现有区间重叠
    IntervalNode* new_root = tree_insert(root, r);      // 构建新树（不改旧树，COW 风格）
    root = new_root;                                    // 原子替换 → 即时生效（FR-03）
    rebuild_map_table(root);                            // mapTable = regionTree 派生投影（评审 14-2）
    return OK;
}
// unmap: 删除映射（幂等：不存在视为成功 no-op，※设计决策）
//   输出：确认；失败（越界/冲突类校验）保留旧配置并返回错误码
// 原子性说明：单线程执行模型下 lookup 与 map_region 天然互斥；
// 采用构建-替换保证编辑期间的查找始终看到一致快照（多核预留版本化）。
// mapTable 同步（评审 14-2）：mapTable 不单独维护写路径，rebuild_map_table()
//   在每次原子替换后由 regionTree 中序遍历重建（O(n)，编辑低频可接受）。
// 外设生命周期（评审 14-11）：M-15 attach 返回句柄；外设销毁/注销时经 detach(handle)
//   强制清理对应区间（自动 unmap），杜绝悬垂 target；RAM/ROM 后端随平台生命周期同生共死。

配置通道：UI 编辑（FR-03）经 M-02 映射视图发起，命令通道经 M-05 协议进入；失败时返回完整错误码（E_BUS-03/04），前端保留旧映射视图不刷新。

5.2 映射编辑流程

（1）配置来源：UI（M-02 映射视图/外设面板）或命令（M-05）发起 mapRegion/unmap。

（2）校验：checkRegion 检查越界（E_BUS-04）与重叠（E_BUS-03）。

6.2 边界与降级

（1）非对齐访问：单区间内允许（与 Spike golden 一致——前提是参考侧 Spike 启用 Zicclsm 扩展，见台账 D-42）；跨区间边界按字节切片拆分分发（※设计决策）。

（2）跨区间写拆分：两阶段执行（预检全部字节片 → 统一执行，评审 14-1）；任一片未映射/外设不可访问 → 整笔失败（E_BUS-01/E_BUS-05），不产生「RAM 已写 + 异常上报」的部分提交状态。

（3）ROM 写：忽略并可选上报调试事件（※设计决策），不产生访存异常；该语义为平台自测范围，ROM 写用例不入 Spike 对拍（Spike 无 ROM 概念、内存可写，评审 14-4）。

（4）外设访问异常：Peripheral.read/write 返回非 OK → 总线层转 E_BUS-05 上抛（评审 14-3），与未映射 E_BUS-01 可区分；M-15 错误接口契约（read/write 返回 err_t + 预检 periph_precheck，评审 N1：预检为独立接口，与探针上报 periph_probe 语义分离）由 9.1 定义，本模块不自行假设。

（5）trace 钩子失败：降级为不记录，不影响访存正确性（观测类事件不要求可靠投递，允许节流合并）。

（6）映射编辑与访存并发：单线程执行模型天然一致；构建-替换保证编辑期间 lookup 始终看到一致快照（多核预留版本化）。

（7）对拍边界（评审 14-9）：仅「未映射 → trap」与「区间边界命中」入 Spike 差分对拍；跨区间拆分、ROM 写忽略、映射编辑（重叠/越界/size=0）归平台自测，Spike 无区间/ROM/映射编辑概念。

接口方向契约（输入 → 输出；错误码/约束）
Bus::export_map()提供（driving）输出：段 3 内存映射拓扑（区域表按 base 升序）——段 3 的生产者
Bus::load_map(map)提供（driving）输入：段 3；重建区域（RAM / ROM 的内容不恢复）；重叠 / 越界 → 报错（E_BUS-03/04 一类的既有码）
Bus::export_pages()提供（driving）输出：段 2 内存页（guest 可见的 RAM 内容）——段 2 的生产者
Bus::load_pages(pages)提供（driving）输入：段 2；必须先 load_map——页要写进已存在的区域；未先重建映射 → 报错（不静默）

⚠️ ROM 的内容不在拓扑里——ROM 内容随固件镜像走（固件是会话的输入，不是状态），恢复时由固件重新装载；RAM 内容在段 2。⚠️ 活的外设实例不可序列化——拓扑里只记外设 id，恢复时按 id 重新绑定。⚠️ 恢复顺序（不可换）：① M-14 load_map（映射）→ ② M-14 load_pages（内存页）→ ③ M-15 load_state（外设状态）→ ④ M-16 load_state（IRQ 行）→ ⑤ M-17 restore_full（引擎段）。⚠️ 校验先于应用：载荷必须先整体校验通过，再按上述顺序逐段回灌——半个应用完的快照比被拒绝的快照更糟。
