1 功能概述

1.1 模块定位

M-19 波形管道（4.5.2）：实现「探针 → 边沿编码 → 环形缓冲 → 增量推送 → 前端渲染 / trace 导出」管道（差异化核心，FR-10）。边沿编码只记录 {time, ch, value, edge}（只记变化点）；每通道环形缓冲固定容量（默认 2×10⁵ 事件起步，容量模型 = 边沿速率 × 期望回看窗口，默认窗口 ≥100ms）；批量增量推送（≤20ms 一批、节流、单调序列号，调度者 = M-12 事件循环周期回调，19-5）；溢出默认丢最旧 + 标记（可配置暂停仿真 PAUSE_SIM，MVP 可用，19-9）；内存预算默认 4 通道 × 2×10⁵ × 32B ≈ 25MB 常驻（满容量 = 预算上限，固定容量下无运行时超预算，19-2；P1 长回看转 IndexedDB spool）。推送载荷字节预算（19-1 复核）：峰值 4 通道全速 ≈24.4 MiB/s（2×10⁵ 事件/s/通道 × 32B × 4 通道）；常规观测（边沿变化实际速率）约 0.5 MiB/s，对应 ~4k 事件/s/通道。按 ≤200ms 刷新预算：全速峰值单批 ≈4.9MiB，超单帧承受，推导需二进制载荷（定长头）+ 可选压缩 + 前端降采样；常规场景单批 ≈100KB 可直推（评审 P-09 节流合并）。观测类事件不要求可靠投递、允许节流合并（评审 P-09）。M-18 的 m19Encode 即本模块 encodeEdge 入口（边沿事件源）。波形只读观测，不修改仿真状态（2.2 只读约束；PAUSE_SIM 暂停执行属控制面操作，不修改状态数据，19-9）。

1.3 MVP 范围与预留

MVP 实现范围：encodeEdge(ev)（边沿编码压缩）、pushDelta()（批量节流推送，单调序列号；调度者 = M-12 周期回调，19-5）、setOverflowPolicy(p)（溢出策略配置，含 PAUSE_SIM 暂停仿真，MVP 可用，19-9）、exportCSV()/exportVCD()（分块导出，跨通道归并 + 可续导 + 进度可见，19-4）；4 通道环形缓冲（2×10⁵/通道）；二进制增量推送（定长头）。
预留项（P1 演进承接，不属现实现）：IndexedDB 长回看 spool（P1，M-23，超出 25MB 内存预算时转存）；跨板波形同一时间轴（FR-27，P1，经 M-18/M-19 链路通道）；导出格式压缩扩展（wireFormat COMPRESSED 可选压缩落地）；容量规划运行时保护细化（动态通道数/窗口放大场景，19-2）。
语义边界（19-9）：PAUSE_SIM 暂停的是仿真执行（控制面操作，经 M-12 暂停语义实施），不修改寄存器/内存等状态数据，符合 2.2 只读观测约束。

2.1 核心数据结构（源文档表71）

2.1.1 复杂结构字段定义

ringBuffer 为每通道定长环形缓冲（固定容量 + 覆盖策略，容量 = 边沿速率 × 回看窗口）；deltaQueue 为批量节流推送队列（单调序列号，断线续拉锚点）；overflowPolicy 定义溢出处置（图4）；memBudget 为内存预算基线；wireFormat 定义二进制载荷形态。字段定义如下：

// RingEntry: 波形环条目（边沿编码后，32B/条：t 8B + ch 1B + value 8B + edge 1B + 对齐）
struct RingEntry { uint64_t t; uint8_t ch; uint64_t value; uint8_t edge; };
// ringBuffer: 每通道波形环形缓冲（4.5.2.2 表71；固定容量、覆盖策略）
struct ringBuffer {
  RingEntry buf[RING_CAP];  // 定长环形缓冲（默认 RING_CAP=2×10⁵ 事件/通道，起步基线实测校准）
  uint32_t  head;           // 写游标（溢出丢最旧 + 标记：overflowCount++ 后覆盖）
  uint64_t  overflowCount;  // 溢出丢弃计数（标记，供前端/日志提示）
};
// 容量模型：RING_CAP = 边沿速率 × 期望回看窗口（默认窗口 ≥100ms），实现后实测校准
// deltaQueue: 增量推送队列（≤20ms 一批、节流、单调序列号；断线续拉锚点）
struct deltaQueue {
  WaveformDelta pending;    // 当前批（节流窗口内累积）
  uint64_t seqNo;           // 单调序列号（推送自增；失败批次亦前移，空间连续无空洞，19-3）
  uint32_t batchMs = 20;    // 批窗口（≤20ms，主线程合并刷新预算）
  DropRange droppedRanges[];// 丢弃区间记录（推送失败本批丢弃，前端按 seq 空洞续拉，19-3）
};
// overflowPolicy: 溢出策略（4.5.2.2 表71；图4；PAUSE_SIM 属 MVP 可配，19-9）
enum overflowPolicy { DROP_OLDEST_MARK, PAUSE_SIM }; // 默认 DROP_OLDEST_MARK（可配）
// memBudget: 内存预算（4.5.2.2 表71；容量规划对账基线，19-2）
const uint32_t memBudget = 4 * RING_CAP * 32;        // ≈25MB 常驻（满容量 = 预算上限）
//   固定容量模型下运行时占用恒 ≤ 满容量，无运行时超预算（19-2）；通道数增长 /
//   RING_CAP 放大时按配置期对账（3.5）：超预算 → 拒绝或强制降采样（联动 M-18 setRate）；
//   P1 长回看转 IndexedDB spool（M-23）
// wireFormat: 载荷形态（4.5.2.2 表71；载荷预算推导，评审 P-09）
enum wireFormat { BIN_LE_HEADER, BIN_LE_COMPRESSED }; // 二进制定长头 + 可选压缩（P1）
// WaveformDelta: 增量推送载荷（带序列号；断线续拉/前端合并）
struct WaveformDelta {
  uint64_t seqStart;        // 推送起始序列号
  uint64_t seqEnd;          // 推送结束序列号（单调）
  uint64_t t_virt;          // 虚拟时间戳（M-12 权威源，前端时间轴对齐）
  RingEntry entries[];      // 本批边沿事件（≤20ms 窗口累积）
};

3 实现设计

3.1 encodeEdge(ev) 边沿编码压缩

encodeEdge(ev)：边沿编码压缩——输入 {time, ch, value}（M-18 sample 产出，M-18 的 m19Encode 即本入口），输出 {time, ch, value, edge} 事件写入 per-channel 环形缓冲；只记变化点（M-18 已做边沿判定，本模块仅编码落环）。PAUSE_SIM 溢出策略属 MVP 可配（19-9）；暂停仿真执行不修改状态数据（控制面操作，符合 2.2 只读约束）。伪代码如下：

// encodeEdge: 边沿编码压缩（4.5.2.3 表72；输入：{time,ch,value}；输出：{time,ch,value,edge}）
//   M-18 的 m19Encode(ev) 即本入口（边沿事件源，M-18 v1.1 已对接）
void encodeEdge(EdgeEvent ev) {
  RingEntry r = {t: ev.t, ch: ev.ch, value: ev.value, edge: ev.kind};
  ringBuffer[ev.ch].append(r);                     // 按通道入环（固定容量 + 覆盖策略）
  if (ringBuffer[ev.ch].full()) {                  // 溢出（图4）
    if (overflowPolicy == DROP_OLDEST_MARK) {      // 默认：丢最旧 + 标记
      ringBuffer[ev.ch].overflowCount++;           // 计数标记（不阻塞仿真）
      ringBuffer[ev.ch].head = (head + 1) % RING_CAP;
    } else {                                       // PAUSE_SIM：暂停仿真（可配）
      m12Pause("waveform_overflow", ev.ch);        // 联动 M-12 暂停语义
    }
  }
  deltaQueue.enqueue(r);                           // 同时累积进推送队列（≤20ms 批）
}

3.2 pushDelta() 批量节流推送

pushDelta()：批量增量推送——≤20ms 一批（节流）、单调序列号（seqStart/seqEnd）。调度者（19-5）：挂 M-12 事件循环周期回调（每 batchMs=20ms 触发；首个触发时机 = 首次事件入队后的下一个周期回调），前端按 ≤200ms 刷新预算拉取合并。观测类不要求可靠投递（评审 P-09）；推送失败 → 丢弃本批 + droppedRanges 记录（seq 空洞），前端经续拉通道补齐（对齐 M-07 v1.1 resumeBySeq / E_PROTO-05，19-7 已核对）。伪代码如下：

// pushDelta: 批量增量推送（4.5.2.3 表72；输出：waveformDelta 带序列号）
// 调度者：M-12 事件循环周期回调（每 batchMs=20ms 触发；前端 ≤200ms 预算消费，19-5）
WaveformDelta pushDelta() {
  if (deltaQueue.pending.entries.empty()) return null; // 无新事件不推送（节流）
  uint64_t s = deltaQueue.seqNo;                   // 当前批起点
  WaveformDelta d = {seqStart: s, seqEnd: s + n,
                     t_virt: timeVirt, entries: pending.entries};
  deltaQueue.seqNo = d.seqEnd;                     // 序列号空间单调前移（无空洞，19-3）
  deltaQueue.pending.clear();                      // 本批移交（下批重新累积）
  if (m03Push(d) != OK) {                          // 推送失败（P-09 可丢，19-3）
    droppedRanges.append({seqStart: s, seqEnd: d.seqEnd}); // 记录丢弃区间
    log(WARN, "WAVE", "push", "dropped");          // 前端按 seq 空洞续拉补齐
    return d;                                      // 本批不重推、不阻塞仿真
  }
  return d;                                        // 输出：waveformDelta（带序列号）
}
// 失败语义（19-3）：丢弃本批 + 依赖续拉补齐（推荐，P-09）；seqNo 单调前移、droppedRanges
//   记录丢弃区间；前端检测 seq 空洞即经续拉通道补齐（对齐 M-07 v1.1 resumeBySeq(seq) /
//   E_PROTO-05 缺口对账，19-7 已核对）；观测类不重试、不阻塞仿真

3.3 setOverflowPolicy(p) 溢出策略配置

setOverflowPolicy(p)：溢出策略配置——丢最旧 + 标记（默认）/ 暂停仿真（可配），输出确认；配置即生效（后续溢出按新策略处置）。伪代码如下：

// setOverflowPolicy: 溢出策略配置（4.5.2.3 表72；输出：确认）
uint8_t setOverflowPolicy(overflowPolicy p) {
  overflowPolicy = p;                              // 默认 DROP_OLDEST_MARK；可配 PAUSE_SIM
  log(INFO, "WAVE", "overflow_policy", p);         // 策略变更日志（M-21）
  return OK;                                       // 输出：确认
}

3.4 exportCSV()/exportVCD() 分块导出

exportCSV()/exportVCD()：波形导出（FR-10/14）——数据源为 per-channel 环形缓冲当前窗口；跨通道按 t_virt 归并排序（多通道事件交叉时序单流，19-4）；按 filter（通道子集 + 时间窗 + 格式）分块导出（10⁴ 条目/块），nextOffset 为归并流条目索引（续导锚点），进度回调 onProgress(pct)；大文件不阻塞主线程。伪代码如下：

// exportCSV / exportVCD: 波形导出（4.5.2.3 表72；FR-10/14；契约展开 19-4）
// filter: {channels: 通道子集, tStart/tEnd: t_virt 时间窗}；fmt 由调用入口决定（CSV/VCD）
ExportHandle exportCSV(filter, nextOffset = 0, onProgress = null)
ExportHandle exportVCD(filter, nextOffset = 0, onProgress = null) {
  merged = mergeSortByTvirt(ringBuffer[channels(filter)]); // 跨通道归并（t_virt 单调，19-4）
  chunk  = merged[nextOffset : nextOffset + CHUNK];        // CHUNK = 10⁴ 条目/块
  return {handle, chunk, nextOffset: nextOffset + CHUNK,   // 续导锚点 = 归并流条目索引
          progress: nextOffset / merged.size, done};       // 进度：onProgress(pct) 回调
}
// 数据源：per-channel ringBuffer（当前窗口，含 overflowCount 标记；历史丢失以标记提示）
// 大文件分块落盘/下载，不阻塞主线程（FR-14）

3.5 内存超预算处置（与 M-18 联动）

内存预算对账（19-2）：固定容量模型下运行时占用恒 ≤ 满容量（4×RING_CAP×32 ≈25MB），不存在运行时超预算；对账在容量规划期触发——通道数增长（超出默认 4 通道）或 RING_CAP 放大（回看窗口增大）时，按「通道数 × RING_CAP × 32B」对账 memBudget，超预算 → 拒绝通道创建/窗口放大 + 提示，或强制降采样（联动 M-18 setRate 节流加倍）。P1 演进：动态通道数/窗口放大引入运行时保护，长回看转 IndexedDB spool（M-23，环形窗口滑动保留最近窗口）。伪代码如下：

// 容量规划对账（19-2：固定容量下无运行时超预算；配置期触发）
uint8_t budgetReconcile(uint32_t channelCount, uint32_t ringCap) {
  uint64_t used = channelCount * ringCap * 32;     // 规划占用（通道数 × 容量 × 32B）
  if (used > memBudget) {                          // 超 ≈25MB 预算（图4 分支）
    m18SetRate({throttleN: *2});                   // 强制降采样（联动 M-18，采样减半）
    log(WARN, "WAVE", "budget", "reconcile");      // 提示（拒绝 or 降采样由调用方选择）
    return E_CTX-02;                               // 资源超限（既有码语义，无新增码）
  }
  return OK;
}
// P1：动态通道/窗口放大运行时保护；长回看 → 环形窗口滑动 + IndexedDB spool（M-23 原子写），
//   导出/回看经 spool 续取（wireFormat COMPRESSED 压缩落地）

6 异常处理

6.1 错误码与处置（无新增码）

M-19 为只读观测模块（2.2），观测类事件可丢（评审 P-09），不新增错误码；异常统一按以下处置：

错误码 / 场景触发条件处置
缓冲溢出per-channel 环形缓冲满（边沿速率超容量模型）丢最旧 + 标记（overflowCount++，默认）/ 暂停仿真（PAUSE_SIM，可配，图4）
推送失败waveformDelta 推送失败（断线/通道异常）丢弃本批 + droppedRanges 记录（seq 空洞）+ 前端续拉补齐（对齐 M-07 v1.1 resumeBySeq / E_PROTO-05，19-3/19-7；观测可丢不重试）
容量规划超预算通道数增长/窗口放大超 memBudget（固定容量下无运行时超预算，19-2）配置期拒绝或强制降采样（联动 M-18 setRate）+ 提示；P1 转 IndexedDB spool（M-23）
无效策略setOverflowPolicy 传入未定义策略值拒绝 + 日志（WARN），保持当前策略

6.2 边界与降级

（1）溢出降级：默认丢最旧 + 标记（overflowCount，不阻塞仿真）；可配暂停仿真（PAUSE_SIM，MVP 可配，19-9）；PAUSE_SIM 暂停仿真执行属控制面操作，不修改寄存器/内存等状态数据，符合 2.2 只读约束。
（2）推送失败（P-09）：观测类不要求可靠投递、允许节流合并；推送失败 → 丢弃本批 + droppedRanges 记录（seq 空洞，19-3），前端经续拉通道补齐（对齐 M-07 v1.1 resumeBySeq / E_PROTO-05，19-7），不重试不阻塞。
（3）内存预算：4 通道全速常驻 ≈25MB（满容量 = 预算上限，固定容量下无运行时超预算，19-2）；通道增长/窗口放大按配置期对账，超预算拒绝或强制降采样（联动 M-18 setRate）；P1 长回看转 IndexedDB spool（M-23）。
（4）时间基准：t_virt 取 M-12 虚拟时间（权威源），跨板波形同轴（FR-27，P1）同基准。
（5）导出降级：导出数据源为环形缓冲当前窗口（含 overflowCount 标记）；跨通道导出按 t_virt 归并排序（19-4）；历史丢失部分以标记提示，不伪造数据。

7.2 可维护性手段

（1）通道独立：per-channel ring 独立容量与游标，新增通道不涉核心逻辑。
（2）策略可配：overflowPolicy / batchMs / wireFormat 为结构化配置，调整不涉核心逻辑。
（3）载荷自描述：二进制定长头 + 序列号，前端解码不依赖宿主时序（确定性）。
（4）能力降级：观测类可丢（P-09）+ 续拉补齐，断线/降载不阻塞仿真。
（5）CI 门禁：波形刷新 ≤200ms + 溢出标记 + 序列号单调用例纳入回归基线。
