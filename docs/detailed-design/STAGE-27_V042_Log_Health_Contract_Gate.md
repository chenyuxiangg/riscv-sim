### §0.2 本批**明确不做**的事（**七件**）

1. **不搬任何场景码**（D-132 陷阱①）⇒ ⇒ 搬一次就是一次**跨 crate 的破坏性变更** ⇒ ⇒ 本批**只定口径、只登记**。
2. **不新增 `ErrorFamily`** ⇒ ⇒ `error_families!` **一个字不改** ⇒ ⇒ 「加码不加族」这条守住。
3. **不实现调试触发器**（D-156）⇒ ⇒ 实测证明「能写能读回」会把**空洞的 PASS** 变成**真的 FAIL** ⇒ ⇒ 见 **§1.2 F9**。
4. **不改 `query` 的既有返回形状**（D-134 陷阱③）⇒ ⇒ **新增**一个入口，**不**动旧的。
5. **不把 `time_host_ms` 的「宿主时钟不可用」标注塞进契约层的诊断 DTO** ⇒ ⇒ 那是**跨层**改动 ⇒ ⇒ 本批只做**内核侧的状态显式化**，「诊断包可见」**留到下一批**。
6. **不升级任何版本常量**（`SCHEMA_VERSION` 仍 **7** / `SIM_STATE_SCHEMA_VERSION` 仍 **2** / `PLATFORM_SCHEMA_VERSION` 仍 **1**）。
7. **不动 `rv32mi/breakpoint` 那条语料**（D-156 陷阱①）⇒ ⇒ 两侧都 PASS、但那是**空洞的 PASS** ⇒ ⇒ 塞进去会把覆盖率**高估**。

### §0.3 为什么这六条能**一批**做

⇒ ⇒ 它们**落在同一条链上**：**M-21 日志**（D-128 / D-134）⇒ **M-22 健康**（D-133）⇒ **契约层**（D-127 / D-132）⇒ **宿主时钟**（D-135）⇒ ⇒ 而**契约层那两条**（D-127 / D-132）**不动协议形状** ⇒ ⇒ **零升版** ⇒ ⇒ ⇒ 这就是「**一条约束一个落点**」的又一次同形：**六条约束、六个落点、零个真相源**。

## §2 契约层与工具设计

### §2.1 版本：**三个都不升**（裁决 A）

⇒ ⇒ 本批**零新 DTO / 零新命令 / 零新事件** ⇒ ⇒ `SCHEMA_VERSION` 仍 **7** / `SIM_STATE_SCHEMA_VERSION` 仍 **2** / `PLATFORM_SCHEMA_VERSION` 仍 **1** ⇒ ⇒ 前端镜像**零改动** ⇒ ⇒ **不制造 D-143 那类存量问题**。

### §2.2 D-127：改**那一栏** + 一条单测（裁决 B）

⇒ ⇒ **只改 `crates/contract/src/csr.rs` 那张表的一行** ⇒ ⇒ 把 `irq_clear` 从「internal **line**」栏**移走**，**另起一行**写它是**位掩码** ⇒ ⇒ ⚠️ **另外两栏一个字不动**（**F3** ⇒ ⇒ 那是 **D-84 / D-100** 的不变量）。

⇒ ⇒ **单测**：断言「`irq_clear` 的语义是**位掩码**」—— 即：写 `mask` ⇒ ⇒ 清的是 **mask 里每一个置位的 bit 对应的那条 line** ⇒ ⇒ **不是**「写 `3` 就清 line 3」⇒ ⇒ ⚠️ **判据必须能让两种读法给出不同结果**（**通用判据**）：

| 写法 | 掩码语义 | 行号语义 |
| --- | --- | --- |
| 写 `0b1010` | 清 line **1** 与 line **3** | 清 line **10**（不存在 ⇒ 无效） |
| 写 `0b0010` | 清 line **1** | 清 line **2** |

⇒ ⇒ **选 `0b0010`**：掩码语义清 **line 1**，行号语义清 **line 2** ⇒ ⇒ 两条 line 的状态**必然不同** ⇒ ⇒ 判别力成立。

### §2.3 D-132：定判据 + 归类 + 一条**可执行**的检查（裁决 C / D）

**判据（裁决 C）**：一个场景码住哪 ⇒ ⇒ 看**两件事**是否同时成立：

1. 它**跨模块共享**（**别的 crate** 要引用它），**或**
2. **前端要按码分派**（前端拿到这个码要决定做什么）。

⇒ ⇒ **满足 ⇒ 住契约层**；**不满足 ⇒ 住模块内**（内核 crate 自己定义、自己用）。

⚠️ **判据的边界**（裁决 D）：**不是**「凡是错误码都住契约层」⇒ ⇒ 那会让契约层变成**杂物间** ⇒ ⇒ 违背「契约层只放**跨模块**的东西」这条初衷 ⇒ ⇒ **判据是「或」，不是「且」** ⇒ ⇒ 「前端要按码分派」这一条**单独**就够。

⇒ ⇒ **本批只登记、不搬**（陷阱①）⇒ ⇒ **归类结果写进台账**（哪一族住哪、为什么）⇒ ⇒ **一条可执行的检查**（裁决 D 的后半）：`tools/error_code_check.py` ⇒ ⇒ 列出**每个 `E_XXX_NN` 的定义处 + 全部引用处** ⇒ ⇒ 人工过一遍新增 ⇒ ⇒ ⚠️ **它检查的是「唯一定义」，不是「住哪」**（住哪是**判据 + 人工**）⇒ ⇒ 别把它写成自动分类器。

### §2.4 D-128：只订正 LLD 的**通过准则**（裁决 E）

⇒ ⇒ **零代码改动** ⇒ ⇒ 只改 `docs/detailed-design/M-21_Logging.html` 里那条通过准则 ⇒ ⇒ 把它从「**单次 log() 无分配（槽位预分配）**」改成「**单次 log() 有界长度**（`ctx` ≤ **24** / `err_code` ≤ **12** / `msg` ≤ **128** 字节）⇒ ⇒ **截断必落 UTF-8 字符边界** ⇒ ⇒ **被截过**这件事由条目的 `truncated` 标记**可见**」⇒ ⇒ 并**如实记录**那条**有意偏差**（LLD 原值 **23 / 11 / 127** vs 取值 **24 / 12 / 128** ⇒ ⇒ **差一字节是刻意的**：Rust `String` 不含结尾 NUL ⇒ ⇒ 要存同样多的**有效载荷**就必须多给一个字节的额度）。

⚠️ **HTML 门禁**：`docs/doc_check.py` 查**标签配平** ⇒ ⇒ 改 HTML 时**标签数不变** ⇒ ⇒ 只改**文字**。

### §2.5 D-135：`available` **显式化** ⇒ ⇒ **加函数不改签名**（裁决 F）

⇒ ⇒ `HostInstant` 增一个 `available: bool`（native 恒 `true`；wasm 侧 = `performance` 是否存在）⇒ ⇒ `HostClock` 暴露 `is_available()`。

⇒ ⇒ ⚠️ **不改 `classify_window` 的签名**（它有既有断言）⇒ ⇒ **新增** `classify_window_with_clock(elapsed_ms, stalled, clock_available)` ⇒ ⇒ 旧的 `classify_window(elapsed_ms, stalled)` 保留成**薄封装**（`clock_available = true`）⇒ ⇒ **既有断言一条不红**（与 D-134 陷阱③ **同一条纪律**）。

⇒ ⇒ **新语义**：`clock_available == false` ⇒ ⇒ 「**时间预算**」那一路**恒不触发**（**不是**「按 0 算」）⇒ ⇒ 但「**引擎停滞**」那一路**照常**（`stalled` 仍是或项）⇒ ⇒ ⇒ ⚠️ **这正是台账 D-135 做法 B 要的口径** ⇒ ⇒ 而 **F12** 说明**现状已经是这个行为** ⇒ ⇒ ⇒ **本批做的是把「为什么」钉住**（`available` 显式）⇒ ⇒ **不是**改行为。

### §3.1 Lane A · D-134：`query_recent`

⇒ ⇒ **新增** `LogBuffer::query_recent(&self, filter: &LogQuery, n: usize) -> Vec<LogEntry>` ⇒ ⇒

* **排序键 = `time_virt_ps`**（虚拟时间）⇒ ⇒ **不用**宿主时间 ⇒ ⇒ **确定性可复现**（陷阱①）；
* 排序**必须稳定**且同刻条目有**确定的次序**（陷阱②）⇒ ⇒ 排序键用 **`(time_virt_ps, 带序内序号)`** ⇒ ⇒ **同刻**时按**带序**（trace → debug → info → warn → error）+ **带内写入序** ⇒ ⇒ 两次跑**逐条相同**；
* **既有 `query` 一个字不改**（陷阱③）⇒ ⇒ 它的带状返回**形状**不变 ⇒ ⇒ **既有断言一条不红**；
* `n` 的边界：`0` ⇒ ⇒ 空；`> 总数` ⇒ ⇒ 全部（按序）。

⇒ ⇒ `AdminDiagnosis.log_ref`（在 `m22_hms/mod.rs`）改走 `query_recent` ⇒ ⇒ 「最后 N 条」**名副其实** ⇒ ⇒ ⚠️ **角色不变式不许破**：`Role::Product` 的诊断结果里**仍然搜不到任何日志文本**（D-131 陷阱③）⇒ ⇒ ⇒ **这条不变式必须由用例钉住**（既有不变式，**不许**顺手改）。

### §3.2 Lane A · D-133：HMS 保留带加上界

⇒ ⇒ **保留带**（FATAL / CRITICAL，**永不丢弃**）**加上界** ⇒ ⇒ ⚠️ **不能**用「丢最旧的」来腾地方（那就**违背**了「永不丢弃」）⇒ ⇒ ⇒ **正确形态 = 满了之后**把**整带**转成**一个聚合信号**（保留**首条** + **计数**）⇒ ⇒ ⇒ 事实**不丢**（取证要的是「有过致命信号」这个事实 + 首条原文）⇒ ⇒ **条数**有界 ⇒ ⇒ **内存**有界。

⇒ ⇒ ⚠️ **具体形态由 lane 定**，但**必须**满足：① 上界是**一条常量**（不散落）；② 满了之后**不静默丢**（要么聚合、要么标一个「已折叠」标志）⇒ ⇒ **判别力靠「插满之后仍能查到首条 + 计数正确」**。

### §3.3 Lane B · D-132：判据 + 归类 + 检查脚本

⇒ ⇒ 按 §2.3 的判据，把现有各族**归类** ⇒ ⇒ 结果写进**台账**（不是搬代码）⇒ ⇒ 新增 `tools/error_code_check.py` ⇒ ⇒

* 列出**每个 `E_XXX_NN` 的定义处**与**全部引用处**；
* 断言**唯一定义**（同一码只有一处定义）⇒ ⇒ 这是 **D-120** 那条不变式的**机器化**；
