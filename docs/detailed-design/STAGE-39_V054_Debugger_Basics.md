## §0 本批的边界

**主题**：用户在 v0.53 批交付后的直接反馈 —— 「**断点不支持查找任意地址后增加，当前界面上只能加开头的几条指令**」
与「**内存也不支持任意读取**」⇒ ⇒ 目标是把这两条变成「**想停哪儿就停哪儿、想读哪儿就读哪儿**」。

⚠️ **本批只做前端** ⇒ ⇒ **契约层零升版**（`SCHEMA_VERSION` 仍 **8** /
`SIM_STATE_SCHEMA_VERSION` 仍 **2** / `PLATFORM_SCHEMA_VERSION` 仍 **1** /
`PLATFORM_RULES_VERSION` 仍 **3**）⇒ ⇒ **零**新 DTO / **零**新命令 / **零**新事件
⇒ ⇒ **内核与宿主零改动**。

⚠️ **本批不做「条件断点」** —— 条件断点**必然**要升契约（`Breakpoint` **没有**条件字段）
⇒ ⇒ 它属于**升版批次**（v0.55）⇒ ⇒ 深度（表达式 / 最小面 / 完整触发器机制）
由用户拍板 ⇒ ⇒ **本批不猜**（裁决 H）。

⚠️ **本批不做「整段内存转储」** —— 契约的 `ReadMemory` **一次最多 4 字节**
（`WriteSize` = `Byte` / `Half` / `Word`）⇒ ⇒ 「一次看一段」要么前端循环发很多条
⇒ ⇒ 要么**升契约加 range** ⇒ ⇒ 属于升版批次 ⇒ ⇒ **本批不做**（裁决 H）。

⚠️ **本批不做「按符号名定位」** —— 契约层**没有**「列出符号」的事件
⇒ ⇒ 只能填**数值地址** ⇒ ⇒ 符号查询属于升版批次（裁决 H）。

## §1 为什么要做这一批

### §1.1 用户看到的现象

1. **断点**：调试视图的「断点」列只在**反汇编表的那几行**上 ⇒ ⇒ 要在**别处**下断点，
   唯一的办法是「先反汇编到那个地址、再在那一行点」⇒ ⇒ 但反汇编窗口**从当前 PC 起**
   ⇒ ⇒ 想在一个**离当前 PC 很远**的地址下断点 ⇒ ⇒ **做不到**。
2. **内存**：内存视图的工具栏只有一个按钮「**读内存 @0x100**」⇒ ⇒ 地址**写死**在
   按钮文案与命令参数里 ⇒ ⇒ 想读别的地址 ⇒ ⇒ **没有任何入口**。

### §1.2 实测事实（每条都对着**当前树**量过）

| 编号 | 事实 |
| --- | --- |
| F1 | 契约的 `Breakpoint`（`crates/contract/src/model.rs`）**有** `addr: u32` ⇒ ⇒ **任意地址**在契约层**早就支持** ⇒ ⇒ 本批**不需要**新 DTO |
| F2 | 契约的 `CommandPayload::ReadMemory { addr: u32, size: WriteSize }` **有** `addr` ⇒ ⇒ 同上 |
| F3 | `WriteSize` 只有 `Byte` / `Half` / `Word`（`model.rs`）⇒ ⇒ **一次最多 4 字节** ⇒ ⇒ 「整段转储」需要**升契约** |
| F4 | M-08 的 `hit_check(&self, pc: u32) -> Option<Breakpoint>`（`crates/kernel/src/m08_breakpoint/mod.rs`）**按 pc 精确匹配** ⇒ ⇒ **任意地址**断点**内核侧已支持** |
| F5 | M-08 的 `set()` 的校验只有三条：**2 字节对齐** / **同地址不重复** / **同 id 不换地址** ⇒ ⇒ **不要求**地址已映射 ⇒ ⇒ 「在没跑过的地址下断点」内核**照收** |
| F6 | `front/app.js` 的 `case "set-breakpoint"` **已经**从 `detail.params.addr` 取地址 ⇒ ⇒ **命令路径已参数化** ⇒ ⇒ 缺的**只是 UI 能给出地址** |
| F7 | `front/app.js` 的 `case "read-mem"` 调的是 `registerMemory.readMemory(0x100, "Word")` ⇒ ⇒ **地址与宽度都写死** ⇒ ⇒ 这**就是**「内存不支持任意读取」的根因 |
| F8 | `front/services/m10_registermemory.js` 的 `readMemory(addr, size = WRITE_SIZE.Word)` **两个参数都已参数化** ⇒ ⇒ 服务层**不用改** |
| F9 | 视图层发命令的机制是 `emitCommand(action, viewId, params)`（`front/views/m02_viewcomponents.js`）⇒ ⇒ `params` **在 signal 里** ⇒ ⇒ 视图层**不碰**服务层 |
| F10 | 输入框的**草稿**惯例 = **住视图状态**（terminal 的 `term.draft`）⇒ ⇒ 重渲染**不丢** ⇒ ⇒ **本批沿用同一条路**（不是新发明） |
| F11 | 输入框的**监听器**惯例 = **事件委托**（绑在**容器**上，不绑在输入框上）⇒ ⇒ 输入框元素被重建时监听器**不丢** |
| F12 | 契约层**没有**「列出符号」的事件（`protocol.rs` 里 `Symbol` 零命中）⇒ ⇒ **符号名定位**做不到 ⇒ ⇒ 属升版批次 |
| F13 | M-11 的 `symbols()` 返回 `&SymbolTable` ⇒ ⇒ **内核侧有**符号表 ⇒ ⇒ 只差契约通道 |
| F14 | 契约的 `CommandPayload::Disasm { addr, count }` **起始地址任意** ⇒ ⇒ 「在任意地址反汇编」内核侧已支持 |
| F15 | v0.53 批的「**同内容不重建**」（`applyRenderEvent`）⇒ ⇒ 内容不变时**不重写** `innerHTML` ⇒ ⇒ **输入框不会被重建** ⇒ ⇒ **焦点不丢**（这是 v0.53 批的额外收益） |
| F16 | 内核的断点命中**在取指之前** ⇒ ⇒ 命中时该条指令**尚未执行** ⇒ ⇒ 状态**无副作用** |

### §1.3 根因（**实测出来的**，不是猜的）

- **断点**：**不是**内核不支持、**不是**契约不支持 ⇒ ⇒ 是**界面少了一个「地址输入」入口**
  ⇒ ⇒ **纯前端缺口**。
- **内存**：**不是**内核不支持、**不是**契约不支持 ⇒ ⇒ 是**界面把地址写死了**
  ⇒ ⇒ **纯前端缺口**。
- ⇒ ⇒ ⚠️ **两条的共同点**：**契约与内核早就够用了，界面没把它们露出来**
  ⇒ ⇒ ⇒ **通用判据**：**「用户做不到」不等于「平台做不到」** ⇒ ⇒ 先量「差在哪一层」
  ⇒ ⇒ ⇒ 别一上来就升契约（升版是最贵的一步）。

## §2 裁决

| 编号 | 裁决 |
| --- | --- |
| A | 「任意地址」= **数值地址**（十六进制，可带 `0x`）⇒ ⇒ 前端**不查符号表**（契约层没有那条通道 ⇒ ⇒ 裁决 H） |
| B | 断点地址**由界面给** ⇒ ⇒ 走**既有的** `set-breakpoint` 命令路径 ⇒ ⇒ **内核行为一字不变** ⇒ ⇒ 脚本口与界面**共用一条路** |
| C | 断点 **id 仍 = 地址**（v0.50 批裁决 J）⇒ ⇒ 「一址一断点」这条内核语义**继续成立** ⇒ ⇒ 前端**不需要**第二个计数器状态 |
| D | 读内存**地址 + 宽度**都从界面给 ⇒ ⇒ 宽度用契约已有的 `WriteSize` 三档（`Byte` / `Half` / `Word`）⇒ ⇒ **不新造**宽度枚举 |
| E | **前端不预校验地址合法性**（对齐、是否已映射、是否存在）⇒ ⇒ 那是**内核的判据** ⇒ ⇒ 前端只挡**「压根不是一个数」**（解析不出来）⇒ ⇒ ⇒ **不写第二份校验器** |
| F | 非法输入 ⇒ ⇒ **不发命令** + **就地提示** ⇒ ⇒ 「点了没反应」是最差的 UX ⇒ ⇒ 必须**看得见** |
| G | 输入框的**草稿住视图状态** + **监听器走事件委托** ⇒ ⇒ 沿用 terminal 的既有两条惯例（F10 / F11）⇒ ⇒ **零新机制** |
| H | **条件断点 / 整段转储 / 符号定位**三条**都属升版批次** ⇒ ⇒ 本批**不做** ⇒ ⇒ **不猜** ⇒ ⇒ 深度由用户拍板 |
| I | v0.53 批的「**运行中不许读内存**」**语义一个字不改** ⇒ ⇒ 本批的读内存入口**同样**受那条约束 ⇒ ⇒ ⇒ **回归判据必须有** |
| J | 「**同内容不重建**」⇒ ⇒ 输入框**不被重建** ⇒ ⇒ 焦点**不丢** ⇒ ⇒ ⇒ **白拿的**收益（不额外做什么） |
| K | 两个入口的**位置不动**（断点入口在调试视图、读内存入口在寄存器/内存视图）⇒ ⇒ 用户**本来就在那两屏里** ⇒ ⇒ **不为了「显眼」而搬家** |
| L | 契约层**零升版**、内核与宿主**零改动** ⇒ ⇒ 前端镜像（`front/lib/message.js`）**零改动** ⇒ ⇒ ⇒ **D-143 那一类存量问题不产生** |

## §4 已知边界

⚠️ **本批登记五条**（**不销账、不新登记**）：

1. **「任意地址」是数值地址** ⇒ ⇒ **不能按符号名**（契约层没有「列出符号」的事件 ⇒ ⇒ 属升版批次）；
2. **一次读最多 4 字节**（`WriteSize` 三档）⇒ ⇒ **没有整段转储** ⇒ ⇒ 「一次看一段内存」属升版批次；
3. **断点地址必须 2 字节对齐**（M-08 的规则）⇒ ⇒ 前端**不预校验** ⇒ ⇒ 奇数地址**由内核拒**（前端**照发**）；
4. **界面回显的断点列表不是内核断点集的镜像**（内核**没有**「列出断点」的事件）⇒ ⇒ 脚本口设的断点在界面上**看不到**（**v0.50 批就登记过**，本批**原样保留**）；
5. **写内存仍只有脚本口**（契约有 `WriteMemory`，界面**没有**入口）⇒ ⇒ 用户本批**没提** ⇒ ⇒ **不做**。

## §5 接口契约

### §5.1 前端的两个新输入（视图层）

| 落点 | 选择器 | 说明 |
| --- | --- | --- |
| 调试视图 · 断点卡 | `data-bp-addr-input` | 断点地址输入框（文本） |
| 调试视图 · 断点卡 | `data-bp-addr-error` | 解析失败时的**就地提示** |
| 寄存器/内存视图 · 工具栏 | `data-mem-addr-input` | 读内存的地址输入框（文本） |
| 寄存器/内存视图 · 工具栏 | `data-mem-size` | 宽度选择（`Byte` / `Half` / `Word`） |
| 寄存器/内存视图 · 工具栏 | `data-mem-addr-error` | 解析失败时的**就地提示** |

### §5.2 两条命令的 `params`（**沿用既有机制**，零新命令）

| 命令 | `params` | 消费点 |
| --- | --- | --- |
| `set-breakpoint` | `{ addr: number }` | `front/app.js` 的 `case "set-breakpoint"`（**已存在**，只多一个来源） |
| `read-mem` | `{ addr: number, size: "Byte" \| "Half" \| "Word" }` | `front/app.js` 的 `case "read-mem"`（**已存在**，参数从写死改成读 `params`） |

⚠️ **命令的名字与形状一个字都不改** ⇒ ⇒ **契约层零变更** ⇒ ⇒ **前端镜像零变更**（裁决 L）。

### §5.3 地址解析的**唯一落点**

⚠️ **一条约束一个落点** ⇒ ⇒ 「把用户输入的文本解析成一个地址」这件事
**只允许有一处实现** ⇒ ⇒ 视图层两处入口（断点 / 读内存）**共用它** ⇒ ⇒
⇒ ⇒ 前端**不写第二份校验器**（裁决 E）⇒ ⇒ A-15 盯住这一点。

### §5.4 四个版本号（**唯一权威处**）

⚠️ **本批契约层零升版** ⇒ ⇒ **四个全不动** ⇒ ⇒ **前端镜像也零改动**（裁决 L）。

| `SIM_STATE_SCHEMA_VERSION` | **2** |
| `PLATFORM_SCHEMA_VERSION` | **1** |

### 订正 3 · 裁决 J 的「焦点不丢」**只是有条件的**

**实测**

**同内容不重建**只保证「**渲染结果逐字相同**时」不重建 ⇒ ⇒ 而**草稿一改**

⇒ ⇒ 焦点**丢**。

**已改成**

**不会被重建** ⇒ ⇒ 焦点与光标位置**保住**。⇒ ⇒ 规格正文的裁决 J **不动**（它是冻结的），

### 订正 9 · 宽度选择用 `<select>` ⇒ ⇒ `dom-stub` **不反射**选中项

### 订正 10 · A-8 的字面量判据必须按「**完整的那个数**」匹配

### 订正 11 · B-52 的**等待余量**只有 200 ms ⇒ ⇒ 负载下会**假红**

**已改成**
