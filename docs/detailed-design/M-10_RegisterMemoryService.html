1 功能概述

1.1 模块定位

M-10 寄存器/内存服务（4.3.3）：提供通用寄存器 + CSR + PC 的读写与内存读写（暂停态，FR-09）；维护 SimState 缓存并按量子边界采样、节流 ≤200ms 推送 simStateDelta（4.3.3.1）。读写全部经 ExecutionBackend 抽象（M-17 readReg/writeReg/readMem/writeMem），M-10 不感知内核实现（2.1 表5：调试服务 → M-17）。

暂停态冻结保证视图一致（4.3.3.4）：命令 → ExecutionBackend 读写 → 更新缓存 → 增量入队 → 节流推送；非暂停态读写一律 E_CTX-02 拒绝。内存读写的未映射地址按宿主侧访存失败事件上报（等价 GDB 读失败语义，非平台故障、非 guest trap，4.3.3.5）；非幂等写带版本校验防冲突（writeMem 带版本/确认）。simStateDelta 供 M-03 View Store 消费渲染（寄存器/内存/波形刷新 ≤200ms 估算基线，表93 性能行）。

MVP 实现范围：readReg(name) / writeReg(name, value)（含 CSR/PC）、readMem(addr, width) / writeMem(addr, width, value)（非幂等 + 版本校验）、getStateDelta()（deltaQueue 节流 ≤200ms 合并推送）、simCache（暂停冻结）、未映射 → 宿主侧访存失败事件、非暂停态 E_CTX-02 拒绝。

2.1.1 复杂结构字段定义

simCache 缓存暂停态冻结的寄存器/PC/内存视图；deltaQueue 按节流窗口合并待推送增量；deltaVersion 记录每次写操作版本（非幂等写防冲突）。字段定义如下：

// SimCache: 寄存器/PC/内存页缓存（4.3.3.2 表44；暂停冻结）
struct SimCache {
  uint32_t regs[32];      // 通用寄存器 x0~x31（x0 恒 0，写忽略）
  uint64_t pc;            // PC 快照
  csr_t    csrs[CSR_N];   // CSR 快照（mstatus/mepc/mtvec/mie/mip 等，读写经 M-17 readReg/writeReg）
  memPage  pages[MEM_N];  // 内存页缓存（LRU；命中直返，未命中拉取回填，10-8）
  uint8_t  frozen;        // 暂停冻结标记（1=暂停态冻结，视图一致；运行时量子边界采样刷新）
};
// DeltaEntry: 增量条目（待推送增量，节流合并）
struct DeltaEntry {
  uint32_t  kind;         // 增量类型：REG=0 / CSR=1 / PC=2 / MEM=3
  uint32_t  name;         // 寄存器/CSR 名或内存地址（kind 区分；MEM=addr，10-4）
  uint64_t  value;        // 新值（MEM：按地址粒度，value=写入值；10-4）
  uint64_t  seq;          // 单调序列号（M-05 事件分发去重/前端 reconcile 对账）
  uint64_t  time_virt;    // 虚拟时间（M-12 权威时钟）
};
// deltaQueue: 待推送增量队列（节流 ≤200ms 估算基线，表93 性能行）
struct deltaQueue {
  DeltaEntry buf[Q_CAP];  // 窗口累积缓冲（enqueue 顺序追加；写路径状态变化入队）
  uint32_t   wpos;        // 写入游标（追加位置；flush 后复位为 0）
  uint32_t   count;       // 当前窗口条目数（getStateDelta 到期快照 + flush 清空）
  uint32_t   dropped;     // 超窗口丢弃计数（只计数不告警风暴）
};
// WriteVersion: 写版本号（非幂等写防冲突，4.3.3.5）
struct WriteVersion {
  uint64_t lastWrite;     // 最近一次写版本（写前必须匹配调用方携带版本）
  uint64_t monotonic;     // 单调递增（每次写 +1）
};

2.3 数据流说明

命令流：前端（M-01~M-03）→ M-05 会话 → M-10 readReg/writeReg/readMem/writeMem → 暂停态校验（否则 E_CTX-02）→ M-17 读写抽象（不感知内核实现）→ 结果回写 simCache → 增量入 deltaQueue。

推送流：getStateDelta() 按节流窗口（≤200ms）合并 deltaQueue → 单调序列号 + 虚拟时间戳 → 经 M-05 事件分发 publish(simStateDelta) → M-03 View Store 消费 → 寄存器/内存/波形视图局部刷新（≤200ms 估算基线，表93）。

异常流：未映射地址 → M-17 返回 E_BUS-01 → M-10 包装为宿主侧访存失败事件上报（等价 GDB 读失败，非平台故障、非 guest trap）；非幂等写版本冲突 → 拒绝 + 提示重取（4.3.3.5）。

3 实现设计

3.1 readReg / writeReg 寄存器读写

readReg(name)：暂停态校验 → 经 M-17 readReg 读取（通用寄存器 x0~x31、pc、CSR 名）→ 回写 simCache。writeReg(name, value)：暂停态校验 → M-17 writeReg 写入 → 更新缓存 + 增量入队；x0 写忽略、CSR 只读位拒绝（M-13 CSR 语义）。读路径仅更新缓存、不产生 delta，写路径产生状态变化增量（10-2）。伪代码如下：

// readReg: 读寄存器（含 CSR/PC；4.3.3.3 表45）
uint64_t readReg(const char* name, err_t* err) {
    if (!isPaused()) { *err = E_CTX-02; return 0; }       // 非暂停态调用拒绝
    uint64_t v = m17_readReg(name, err);                  // M-17 抽象读取（不感知内核）
    if (*err == E_OK) { simCacheUpdate(name, v); }  // 读路径仅更新缓存，不产生 delta（10-2）
    return v;                                             // 输出：值
}
// writeReg: 写寄存器（含 CSR/PC；4.3.3.3 表45）
void writeReg(const char* name, uint64_t value, err_t* err) {
    if (!isPaused()) { *err = E_CTX-02; return; }         // 非暂停态调用拒绝
    if (strcmp(name, "x0") == 0) { *err = E_OK; return; } // x0 恒 0，写忽略（10-7）
    m17_writeReg(name, value, err);                       // M-17 抽象写入
    if (*err == E_OK) { simCacheUpdate(name, value); enqueueDelta(REG, name, value); }
}                                                        // 输出：确认（err）

契约 v2 的线格式（ReadRegisters / WriteRegister / Registers 事件）：契约层 v2 新增了一等公民的寄存器通道——此前契约根本没有寄存器载体，前端只能从波形边沿里刨寄存器，把「信号历史」和「寄存器快照」混为一谈。宿主发 ReadRegisters{index, count}（读一段通用寄存器）或 WriteRegister{index, value}（写一个通用寄存器），本模块回 Registers{index, values} 事件——读命令与写命令共用这一条回复（写命令的 values.len() == 1）。

⚠️ 「读是钳位、写是拒绝」不是笔误，是两条不同的语义：

  • 读 → 钳位：index / count 钳到 [0, 32)，回复里的 index 是实际起点、values.len() 是实际条数；count = 0 则回复空区间（values: []，index 是钳位后的实际起点）。理由：读越界没有副作用，钳到合法区间即可；⚠️ 「不回复」是错的——M-05 按 reqId 配对请求与回复，「没有回复」与「消息丢失」在协议上不可区分，会变成 500 ms 假超时（E_CTX-06），用户看到的是「内核没应答」而不是「读到了空区间」。契约的回复模型只有两种：一条配对的回复，或一条 Error——「不回复」不在模型里，它等价于传输故障（冻结规格 §5）
  • 写 → 拒绝：index > 31 → 拒绝（E_DBG-01），不钳位。理由：写若也钳位，会静默写到别的寄存器——那正是不可接受的副作用。
  • 写 x0 → 丢弃：index == 0 的写入被丢弃（x0 恒为 0，台账 D-04 的硬连线在 M-13 侧），但仍要回复（values 里是 0）。理由：丢弃是语义（写 x0 无效），不是错误——回一个「已丢弃」的确认比回错误更贴合调用方的预期（它要的只是「写完了没有」）。
// 契约 v2：ReadRegisters / WriteRegister → Registers 事件（3.1；冻结规格 §4.1 / §5）
Registers readRegisters(uint32_t index, uint32_t count) {
    index = min(index, 31);                       // 读：钳位（无副作用）
    count = min(count, 32 - index);               // 读：钳位到寄存器文件末尾
    if (count == 0) return Registers{index, []};  // count=0 → 回复空区间（不是「不回复」：不回复 ≡ 消息丢失）
    uint32_t values[32];
    for (uint32_t i = 0; i < count; i++)
        values[i] = m17_readReg(index + i);       // 经 M-17 取值（x0 恒 0）
    return Registers{index, values[0..count]};    // index = 实际起点
}
Registers writeRegister(uint32_t index, uint32_t value) {
    if (index > 31) return ERR(E_DBG-01);       // 写：拒绝（不钳位——钳位会写错寄存器）
    if (index == 0) return Registers{0, {0}};     // 写 x0：丢弃（D-04）但仍回复（值恒为 0）
    m17_writeReg(index, value);                   // 经 M-17 写入
    simCacheUpdate(index, value); enqueueDelta(REG, index, value);
    return Registers{index, {value}};             // values.len() == 1
}

3.2 readMem / writeMem 内存读写

readMem(addr, width)：暂停态校验 → 经 M-17 readMem 读取；未映射地址返回宿主侧访存失败事件（等价 GDB 读失败，非平台故障、非 guest trap）。writeMem(addr, width, value)：非幂等写带版本校验（deltaVersion 匹配）防冲突；成功则更新内存页缓存 + 增量入队。伪代码如下：

// readMem: 读内存（4.3.3.3 表45；缓存命中直返；未映射 → 宿主侧访存失败事件）
uint64_t readMem(uint32_t addr, uint8_t width, err_t* err) {
    if (!isPaused()) { *err = E_CTX-02; return 0; }
    uint64_t hit; if (memPageHit(addr, width, &hit)) return hit; // 缓存命中直返并刷新 LRU（10-8）
    uint64_t v = m17_readMem(addr, width, err);
    if (*err == E_BUS-01) { publish("dbg_mem_fail", &(MemFail){addr, width}); return 0; }
    // ↑ 宿主侧访存失败事件（等价 GDB 读失败，非平台故障、非 guest trap，4.3.3.5；事件名 10-11）
    if (*err == E_OK) { memPageFill(addr, width, v); }  // 未命中拉取回填缓存（10-8）；读不产生 delta（10-2）
    return v;                                             // 输出：值
}
// writeMem: 写内存（非幂等，带版本/确认，4.3.3.3/4.3.3.5）
void writeMem(uint32_t addr, uint8_t width, uint64_t value,
              uint64_t version, uint64_t* outVersion, err_t* err) {
    if (!isPaused()) { *err = E_CTX-02; return; }
    if (version != deltaVersion.lastWrite) { *err = E_CTX-04; return; }
    // ↑ 版本校验防冲突：调用方需基于最新读取版本写（version 不匹配拒绝并提示重取）
    m17_writeMem(addr, width, value, err);
    if (*err == E_OK) {
        deltaVersion.lastWrite = ++deltaVersion.monotonic;
        *outVersion = deltaVersion.lastWrite;             // 新版本经 out 参数返回（10-3/10-10）
        memPageUpdate(addr, width, value); enqueueDelta(MEM, addr, value); // 写路径状态变化，按地址粒度（10-4）
    }
}                                                        // 输出：确认（err + 新版本）
// getWriteVersion: 读取当前写版本（10-3 版本获取通道，乐观锁前置）
uint64_t getWriteVersion() { return deltaVersion.lastWrite; }

3.3 getStateDelta / 节流推送

getStateDelta()：按节流窗口（≤200ms 估算基线）快照 deltaQueue 当前窗口，附单调序列号 + 虚拟时间戳，一次 publish(simStateDelta) 推送并 flush 清空；节流未到期返回 NULL 且不丢增量（10-1/10-9）。伪代码如下：

// getStateDelta: 生成增量推送（4.3.3.3 表45；节流合并）
SimStateDelta* getStateDelta() {
    if (deltaQueue.count == 0) return NULL;               // 窗口无增量 → 不推送
    // 节流 ≤200ms（估算基线，表93 性能行）：窗口到期或强制刷新才合并推送
    if (now() - lastPushTime < 200ms) return NULL;        // 节流窗口未到期
    SimStateDelta* d = snapshotQueue();                   // 快照拷贝当前窗口（副本；flush 前可重复生成）
    d->seq = ++deltaSeq; d->time_virt = m12_virtTime();   // 单调序列号 + 虚拟时间戳
    publish("simStateDelta", d);                          // M-05 事件分发 → M-03 View Store
    clearQueue(); lastPushTime = now();                   // flush：count=0、wpos 复位（丢弃仅计数 dropped）
    return d;                                             // 输出：simStateDelta（节流合并）
}

6 异常处理

6.1 错误码与处置

本模块错误码归属 E_CTX 族（3.4 表16，一场景一码）；未映射访存按宿主侧失败语义经事件通道上报（非平台故障、非 guest trap）：

错误码 / 事件场景处置
E_CTX-02非暂停态读写（运行态/复位态执行 readReg/writeReg/readMem/writeMem）拒绝执行并返回错误码；提示先暂停（4.3.3.5）；log(WARN, "DBG-RM", …, "E_CTX-02")
E_CTX-04写版本冲突（writeMem 携带 version 与 deltaVersion.lastWrite 不匹配）拒绝并提示基于最新读取版本重取（4.3.3.5 非幂等写防冲突）
E_BUS-01 → 宿主侧访存失败事件未映射地址读/写内存publish(dbg_mem_fail, MemFail{addr,width})；非平台故障、非 guest trap；不触发 HMS（4.3.3.5，10-11）
E_DBG-01契约 v2 WriteRegister 的 index > 31（写越界）拒绝，不钳位——钳位会静默写到别的寄存器（3.1）；与读的钳位语义相反，两者的差别就在「有没有副作用」
透传 M-17 返回码CSR 只读位/非法写（x0 写忽略除外）码值/语义由 M-13 CSR 契约裁决，本模块不自行定义（10-11）；写入失败不产生半指令状态

6.2 边界与降级

（1）非暂停态调用：运行/复位/故障态下读写命令一律 E_CTX-02 拒绝，不排队不缓存（确定性语义，2.4 表6）。

（2）未映射地址：返回宿主侧访存失败事件（等价 GDB 读失败，非平台故障、非 guest trap）——不触发 HMS、不中断会话（10-5）。

（3）非幂等写：writeMem 带版本校验（deltaVersion），版本不匹配拒绝并提示重取；避免覆盖用户尚未看到的并发修改。

（4）QEMU 后端（L1 子集）：读写经 RSP g/m 命令；未映射语义与快照能力按 M-17 能力位协商降级（4.7 表86 能力降级）。

（5）x0 写忽略、CSR 只读位拒绝（透传 M-17/M-13 CSR 语义），写失败不产生半指令状态。

（5b）契约 v2 的 WriteRegister：写 x0 丢弃（D-04 硬连线）但仍回复（值恒为 0）——丢弃是语义、不是错误；写越界（index > 31）拒绝（E_DBG-01）而不是钳位。对照：ReadRegisters 的越界是钳位——读没有副作用（3.1）。

（6）内存页缓存 LRU（10-8）：readMem 命中直返并刷新 LRU；未命中经 M-17 readMem 拉取回填；MEM_N 满淘汰最久未用页（纯视图加速层，不改变读语义）。

（7）deltaQueue 超窗口丢弃：只计数（dropped）不告警风暴（对齐 M-21 溢出计数限频语义）。

（8）单写者声明（10-6）：暂停态会话命令串行执行（同一调试会话单写者），writeReg 直接写无需乐观锁；writeMem 版本校验用于「前端编辑内存」与「平台异步刷新」之间的防覆盖——两者不对称是设计选择，9.1.1 契约注明。

7.2 可维护性手段

（1）读写经 M-17 抽象（readReg/writeReg/readMem/writeMem），M-10 无内核感知，双内核替换不影响本模块。

（2）缓存与推送解耦：simCache（视图层）与 deltaQueue（推送层）独立，可分别单测（缓存一致性/节流合并）。

（3）窗口快照 + flush：getStateDelta 到期快照拷贝当前窗口、flush 清空复位（单消费者 flush 模型，10-1）；未到期返回 NULL 不丢增量。

（4）异常语义隔离：宿主侧访存失败走 dbg_mem_fail 事件通道，平台故障走 HMS；guest trap 仅 ISS 执行期产生（改 mstatus/mepc/mtval）——三类通道分离不混淆（10-5/10-11）。

（5）CI 门禁：核心模块单测覆盖率 ≥70%（估算基线，源文档 7.3 表92）；读写用例纳入确定性夹具。

（6）契约层可替换性（源 2.5 对齐）：本模块对外的 driving 端口收敛到 9.1.1 端口契约表，替代实现遵守同端口契约并通过契约测试即可接入。
