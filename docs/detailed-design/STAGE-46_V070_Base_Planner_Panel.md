## §2 界面与数据流（**逐字冻结**）

### §2.1 数据流

```
   草稿（memory-map 视图状态里那一份 · 唯一落点）
     │
     ├─▶ 占用区间（每段一条）
     │      RAM/ROM  ⇒ [base, base+size)
     │      外设     ⇒ [base, base+window_bytes)   ← **window_bytes 取自内核类型表**
     │
     ├─▶ 规划范围（面板顶部两个输入框 · 用户可改）
     │
     └─▶ **空隙** = 规划范围 − 占用区间**并集**
            │
            ▼
      基址规划面板（列出前 N 条空隙 · 起止地址 + 大小）
            │  用户挑一条 ⇒ ⇒ 填进「目标行」
            ▼
      草稿那一行的 base  ⇒ ⇒ 仍是**描述里的 base**（真相不变）
            │
            ▼
      提交 ⇒ ⇒ **内核判重叠**（E_PLT_06 · 原文显示）⇒ ⇒ 前端**不**写第二份校验器
```

⚠️ **用户始终自己决定落在哪** ⇒ ⇒ 面板只提供**信息（哪里空着）+ 入口（挑一个）** ⇒ ⇒ **不替用户决定**。

### §2.2 DOM 契约（**新增钩子**）

| 钩子 | 落点 | 含义 |
| --- | --- | --- |
| `data-mmap-plan` | 基址规划面板的根 | 面板**在** |
| `data-mmap-plan-range-from` / `-to` | 面板顶部 | **规划范围**（起 / 止） |
| `data-mmap-plan-target` | 面板顶部 | **目标行**（填给哪一行） |
| `data-mmap-plan-gap` | 每条空隙 | 一条**可用区间** |
| `data-mmap-plan-gap-from` / `-to` / `-size` | 每条空隙 | 该区间的起 / 止 / 大小 |
| `data-mmap-plan-use` | 每条空隙 | **「用这个」**按钮 |
| `data-mmap-plan-note` | 面板里 | **如实标注**（窗口大小未知 / 空隙条数被截断 / 范围里没有空隙） |
| `data-mmap-plan-window-unknown` | 面板里 | **外设窗口大小未知**（内核类型表还没到 ⇒ ⇒ 折算用的是占位值 ⇒ ⇒ **不假装**） |

| # | 事实 | 症状 | 真因 |
| --- | --- | --- | --- |
| 1 | **替身的 `<select>` 不保真** | 面板那个「目标行」下拉，替身里 `select.value` **永远是空串** ⇒ ⇒ 读它的代码恒拿到「0」⇒ ⇒ 「换一行填给那一行」那条判据**根本测不到** ⇒ ⇒ **零判别力** | `front/tests/dom-stub.mjs` 的 `value` **property** 照 `<input>` 那样读 `value` **属性** ⇒ ⇒ 而真实的 `<select>` **没有** `value` 属性 ⇒ ⇒ 它的 `value` 是**当前选中那个 `<option>` 的值** ⇒ ⇒ **修法**：按**真实语义**实现它（`selected` 优先、否则第一个 `<option>`）⇒ ⇒ **通用判据：替身也得保真** ⇒ ⇒ 一个「替身读法」与真浏览器不同的字段 ⇒ ⇒ 会让**一整类**判据**恒真或恒假** ⇒ ⇒ 比「断言写错」更隐蔽 |
| 2 | **时序陷阱：刚敲完字就点按钮 ⇒ ⇒ 点击**根本到不了** | 用户在「规划范围」框里改了数 ⇒ ⇒ 直接点「用这个」⇒ ⇒ **点了没反应** | ⛔ **顺序**：`blur`（→ `change` → **重渲染**）**先于** `click` ⇒ ⇒ 重渲染把那个按钮**换掉**了 ⇒ ⇒ `click` 的目标**已脱离 DOM** ⇒ ⇒ 事件**不再冒泡**到面板 ⇒ ⇒ 处理器**收不到** ⇒ ⇒ **修法**：在 **`pointerdown`** 阶段就把动作做完（**在 blur 之前**）⇒ ⇒ 随后的 `change` 重渲染**带着已更新的草稿**⇒ ⇒ 状态一致 ⇒ ⇒ **通用判据：同一个面板里既有输入框又有按钮 ⇒ ⇒ 那个按钮的动作必须在 `blur` 之前被接住** |
| 3 | **测试之间**串了状态** | N-6 报「面板一条空隙都没列」⇒ ⇒ 看着像面板没渲染 | ⛔ **视图状态是模块级单例** ⇒ ⇒ N-9 留下的 `plan`（规划范围）**漏进**了 N-6 ⇒ ⇒ **修法**：`setDraft` **连 `plan` 一起重置** ⇒ ⇒ **通用判据：测试之间共享单例状态 ⇒ ⇒ 每条用例必须显式写下它要的那份状态** ⇒ ⇒ 否则「测的是上一条留下的现场」 |
| 4 | ⚠️ **红集重叠是结构性的**（**不是**「没设计好」） | T-1 与 T-2 都让 **N-7 / N-9** 红 ⇒ ⇒ T-3 也让 **N-4** 红 | ⚠️ **连带红**的成因：那些判据**共享同一个前提**（例如 N-7 先要「面板里有空隙」才能点那个按钮 ⇒ ⇒ 面板整个没了 ⇒ ⇒ 它的**前置断言**先失败 ⇒ ⇒ 它也红）⇒ ⇒ ⇒ **通用判据：「红集互不重叠」这条纪律只在「判据各自独立」时成立** ⇒ ⇒ 真正的纪律是「**每条判据都要有一条「专打它」的变异**」⇒ ⇒ **专属**判据**只有**它能打红 ⇒ ⇒ **连带红不算重叠**（详见 §7.2 那张表的第二列） |
