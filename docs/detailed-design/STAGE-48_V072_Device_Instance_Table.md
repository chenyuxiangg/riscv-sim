## §2 判定口径（**逐字冻结**）

### §2.1 「宿主抬得了这根线」= **五条判据**（**分开算** · 稳定词表）

| 判据 | 含义 | 理由词 |
| --- | --- | --- |
| **源器件在实例表里吗** | 否 ⇒ 抬不了 | `source-unknown` |
| **源器件是 UART 吗** | 不是 ⇒ 抬不了（宿主只从 UART 抬 `rx_ready`） | `source-type` |
| **目标器件在实例表里吗** | 否 ⇒ 抬不了 | `target-unknown` |
| **目标器件是 PLIC 吗** | 不是 ⇒ 抬不了（宿主只往 PLIC 递源） | `target-type` |
| **源号在这个 PLIC 的源数范围内吗** | 否 ⇒ 抬不了 | `source-out-of-range` |

⚠️ **五条必须分开算** ⇒ ⇒ 界面要能说清「**为什么**抬不了」⇒ ⇒ 「不知道抬不了」与「抬不了」是**两件事** ⇒ ⇒ 只给一个布尔 = 用户**没法修**。

⚠️ **理由词表是稳定枚举（6 个值）**，**不是**场景码 ⇒ ⇒ 描述**被接受了**（没有失败）⇒ ⇒ **不进 `error.rs`** ⇒ ⇒ `error_code_check.py` **零改动**。

⚠️ ⚠️ **但其中只有两条在「合法描述」上可达**（**施工期撞见** ⇒ ⇒ 详见 §7.1 订正 6）：
**契约层的描述校验器（`PLATFORM_RULES_VERSION` = 3 的 V-18 / V-19）已经拒掉了**
「端点不存在」/「目标不是 PLIC」/「源号越界」三类描述 ⇒ ⇒ 那**三条理由**
（`source-unknown` / `target-unknown` / `target-type` / `source-out-of-range`）
⇒ ⇒ 在**经校验**的描述上**不可达** ⇒ ⇒ 它们是**兜底**（宿主**不盲目信任**
描述 ⇒ ⇒ `compile_bridge` 是 `pub` ⇒ ⇒ 可能被喂进一份**没过校验**的描述）。

⇒ ⇒ **合法描述上真正可达的两条**：`source-type`（源器件**存在**但**不是 UART**
—— V-18 **不管**源的**类型** ⇒ ⇒ 这是真的能发生）与 `overridden`
（同键的后一条把前一条顶掉 —— 契约层**不管**这件事）。

### §2.2 连线报告的三个字段 + **一条恒等式**

```
BridgeReport {
    declared: u32,          // 描述里 `bridge` 段的条数（「你写了 N 根线」）
    live:     u32,          // 其中**当前真的在连线表里**的条数
    dropped:  Vec<DroppedWire>,  // 其余的，逐条带理由
}
DroppedWire { from_device, event, to_device, source, reason }
```

⇒ ⇒ **恒等式**：`declared == live + dropped.len()` ⇒ ⇒ **一个判据管三件事**（§4 的 A-3 钉它）。

⚠️ **`declared` 只数「描述里用户写的线」** ⇒ ⇒ **默认连线不计入** ⇒ ⇒ 否则一块没写任何线、但 PLIC 源数不够的板会报「你写了 1 根线、抬不了 1 根」⇒ ⇒ 那是**宿主的默认策略**，不是用户写的 ⇒ ⇒ 口径要分清。

### §2.3 角色怎么办（**三个角色** · **角色 = id，句柄 = 查出来的**）

| 角色 | 今天的口径 | 本批 |
| --- | --- | --- |
| **console UART**（宿主写进 / 取走的字节） | 第一个 UART | **不变**（由实例表按 base 序给出「第一个」）|
| **时间 CLINT**（`time` / `mtimecmp`） | 第一个 CLINT | **不变** |
| **主 PLIC**（抬 M-16 外部线的那一个） | 第一个 PLIC | ⚠️ **升级为「所有被线用到的 PLIC」**（裁决 F）|

⚠️ **角色 ≠ 句柄**：角色只决定「**哪个 id** 扮演这个角色」⇒ ⇒ 句柄**一律从实例表按 id 查** ⇒ ⇒ **只有一个真相源**（表）⇒ ⇒ 「塌缩成固定角色」这件事**在数据层**被消掉了。

## §3 裁决 A~N

| # | 裁决 | 理由 |
| --- | --- | --- |
| **A** | `MappedDevices` 从「三个固定角色句柄」改成「**按 id 索引的实例表**」（表里带**句柄**）⇒ ⇒ `uart0` / `clint` / `plic` 三个字段**删掉** | F-1 + F-2 ⇒ ⇒ `MappedDevices` 只在 `platform.rs` 内部用 ⇒ ⇒ **不是公开 API 变更** ⇒ ⇒ 「塌缩」在数据层消失 |
| **B** | **角色 = id，句柄 = 从表里查出来的** ⇒ ⇒ 宿主**不再持有**「角色句柄」⇒ ⇒ 表是**唯一真相源** | ⇒ ⇒ 少一个状态就少一处可能不同步的地方 |
| **C** | `compile_bridge` 末尾那个 `retain` **换成**「**查得到就留、查不到就记一笔**」⇒ ⇒ 丢线**不再静默** | F-3 ⇒ ⇒ 这就是 D-177 的**正题** |
| **D** | ⚠️ **默认连线逐字不变**（「第一个 UART → 第一个 PLIC · 源 10」）⇒ ⇒ 「第一个」由**实例表**按 base 序给出 | F-4 ⇒ ⇒ 与今天的 `first_uart_id` / `first_plic` **同序** ⇒ ⇒ **存量行为一字不变** |
| **E** | `sync_interrupts` 第 2 步**遍历所有线**、每根线**各自查表**（源查 UART、目标查 PLIC）⇒ ⇒ **第二个 UART 的线也真的通电** | F-5 ⇒ ⇒ ⚠️ **只修 `retain` 不够**（线的两端从来没被分别查过）⇒ ⇒ 这才是里程碑 |
| **F** | `sync_interrupts` 第 3 步**遍历所有 PLIC** ⇒ ⇒ 任一 PLIC 有可交付源就抬 M-16 外部线，否则撤线 ⇒ ⇒ **单 PLIC 时与今天逐字相同** | F-6 ⇒ ⇒ 「UART1 的线通了但中断抬不到架构层」= **通了一半** ⇒ ⇒ 不算通电 |
| **G** | **丢线报告过 wire**：`EventPayload::MemoryMap` 增字段 `bridge_report` ⇒ ⇒ ⚠️ **契约升版**（10 → 11） | F-7 + F-11 ⇒ ⇒ 「内核接受描述时明说」⇒ ⇒ 报告必须在**接受的那一刻**到 ⇒ ⇒ `memory.map` 事件是那一刻的载体 |
| **H** | **理由词表**是**稳定枚举**（6 个值）⇒ ⇒ **不是**场景码 ⇒ ⇒ `error.rs` **零改动** | ⇒ ⇒ 描述**被接受了** ⇒ ⇒ 没有失败 ⇒ ⇒ 「一场景一码」不适用 |
| **I** | **恒等式** `declared == live + dropped.len()` | §2.2 ⇒ ⇒ 一个判据管三件事 |
| **J** | **默认连线不计入** `declared` | §2.2 ⇒ ⇒ 「你写了 N 根线」= **用户写的**线 |
| **K** | **被同键后一条顶掉的线**（`overridden`）**也算丢线**并**如实报出来** | ⇒ ⇒ 否则「你写了 2 根、只有 1 根生效」这件事**仍然静默** ⇒ ⇒ 「一个键一根线」是**构造保证**，但**顶掉了哪根**必须**看得见** |
| **L** | 前端**只显示内核给的**（一行 + 逐条原因）⇒ ⇒ 前端**不自己判** | ⇒ ⇒ 与仓内既有纪律一致（错误**按位显示**内核原文） |
| **M** | 本批**不做**：D-177 **C**（描述里显式声明角色）· D-177 **D**（连线编辑面）· **通用连接路由**（第 58 批）· 引脚层 · MCU 概念 · 描述格式升版 | ⇒ ⇒ 那些是第 57 ~ 59 批的活 |
| **N** | ⚠️ **契约升版的唯一形状改动** = `MemoryMap` 事件**多一个字段** ⇒ ⇒ **命令侧零改动** ⇒ ⇒ 前端镜像 `SCHEMA_VERSION` 同步到 **11** ⇒ ⇒ 跨层夹具（X 组）跟着动 | F-12 ⇒ ⇒ 「一个约束一个落点」⇒ ⇒ 升版**只**因为这一处形状变化 |

### §4.2 内核（K 组）

| 编号 | 判据 |
| --- | --- |
| **K-1** | **第二个 UART 的线真的通电**：板上有 UART0 + UART1 + 一个 PLIC，描述里写 `UART1.rx_ready → PLIC.source 11` ⇒ ⇒ guest 侧把 UART1 的 IER bit0 打开、宿主往 **UART1** 的 RX FIFO 塞一个字节 ⇒ ⇒ **PLIC 的源 11 真的挂起** ⇒ ⇒ **guest 真的 claim 得到源 11** |
| **K-2** | ⚠️ **必要对照**：**把 UART1 换成 GPIO1** ⇒ ⇒ 那根线**抬不了** ⇒ ⇒ 源 11 **不**挂起 ⇒ ⇒ claim **不是** 11 ⇒ ⇒ **证明 K-1 不是「本来就通」** |
| **K-3** | **存量逐字不变**：默认连线仍是「第一个 UART → 第一个 PLIC · 源 10」⇒ ⇒ guest 仍 claim 得到源 10（承 v0.34 批 `s19_b2`）⇒ ⇒ **加了第二个 UART 也不改变**它 |
| **K-4** | **描述里的线覆盖默认线**（同键）⇒ ⇒ 仍然只有一根线 ⇒ ⇒ **不追加**（承 v0.34 批 `s19_b5`） |
| **K-5** | ⚠️ **端点不存在 ⇒ 描述被拒**（`E_PLT-16`，契约层 V-18）⇒ ⇒ **那种线根本到不了宿主** ⇒ ⇒ 报告里**不会**出现 `source-unknown` ⇒ ⇒ **这条是边界登记**（不是「报告里有它」） |
| **K-6** | **合法描述上可达的两条理由**分别可达：`source-type`（源是 GPIO）与 `overridden`（同键两根）⇒ ⇒ **各归各的词** ⇒ ⇒ 混用必红 |
| **K-7** | **被顶掉的那根**（同键两根）⇒ ⇒ 报告里**有**它 ⇒ ⇒ 理由 == `overridden` ⇒ ⇒ 且 `live` 只算**一根** |
| **K-8** | **默认连线不计入 `declared`** ⇒ ⇒ 一块没写线的板 ⇒ ⇒ `declared == 0` ⇒ ⇒ `live == 0` ⇒ ⇒ `dropped` 为空 |
| **K-9** | **报告跟着图走**：改板（`SetMemoryMap`）⇒ ⇒ 报告**重算** ⇒ ⇒ 不留上一份的残留 |
| **K-10** | **零板时**：没有 PLIC / 没有 UART 的板 ⇒ ⇒ **不 panic** ⇒ ⇒ 报告**如实**（`declared` 按描述算，`dropped` 按五条判据算） |
| **K-11** | ⚠️ **四条兜底理由**（`source-unknown` / `target-unknown` / `target-type` / `source-out-of-range`）在**绕过描述校验**时**仍能判出来**（直接调 `compile_bridge` 喂一份**没过校验**的描述）⇒ ⇒ 它们**不是死词** ⇒ ⇒ 判别力**有** |
| **K-12** | **恒等式**：**真报告**（五种板各一份）都必须满足 `declared == live + dropped.len()` |

### §7.3 **本批撞到的四个「测量 / 夹具自身出错」**（**如实登记**）

1. ⚠️ ⚠️ **变异脚本的红集解析一度是错的** ⇒ ⇒ **T-1 ~ T-5 明明红了 5 条却被报成「零红」** ⇒ ⇒ **假红**（**第五种形态**：不是判据空转，而是**判据根本没被读出来**）。
   - **根因**：Rust 的默认 test harness **不是**逐行打 `test … FAILED` ⇒ ⇒ 失败用例在 **`failures:` 那个块里** ⇒ ⇒ 只扫「`test ` 开头且以 `FAILED` 结尾」的行 ⇒ ⇒ 一条都扫不到。
   - **修法**：解析 `failures:` 块 **＋** 额外加一条「**编译就挂了 ⇒ ⇒ 那不是「零红」，是「落点写错了」**」的检查 ⇒ ⇒ 「编译错」**不再**会被当成「零判别力」。
   - ⚠️ **通用判据**：读变异脚本的输出时 ⇒ ⇒ **先看红集是不是真的为空** ⇒ ⇒ 再看**基线**是不是绿的 ⇒ ⇒ 两样都对 ⇒ ⇒ 才认这个红集。
2. ⚠️ ⚠️ **`debug_assert_eq!` 让红集**归因失真** ⇒ ⇒ T-4 的红集里 **10 条全是它先炸** ⇒ ⇒ 「哪条判据抓到了错」**看不出来**。
   - **根因**：恒等式（`declared == live + dropped.len()`）在**两处**都写着（实现里的 `debug_assert` **＋** 用例 **K-12**）⇒ ⇒ **一个约束两个落点** ⇒ ⇒ 而且那个 `debug_assert`（**release 里被编掉**⇒ ⇒ 生产上**根本不守**）⇒ ⇒ 它**只**在测试里生效 ⇒ ⇒ 却在**掩盖**别的判据。
   - **修法**：**删掉**那个 `debug_assert_eq!` ⇒ ⇒ 恒等式的落点**只剩 K-12 一处** ⇒ ⇒ 红集**立刻可归因**（T-4 从 10 条变成 7 条 ⇒ ⇒ 那 7 条**每一条都真的在看那个数**）。
   - ⚠️ **通用判据**：一条变异打出一大片红 ⇒ ⇒ **先问「是不是某个 assert 先炸了」** ⇒ ⇒ 否则「红集很大」会被当成「判别力很强」⇒ ⇒ 其实那是**一条 assert 掩盖了其余所有判据**。
3. ⚠️ ⚠️ **真机夹具的板「预算不够」⇒ ⇒ 内核拒了它 ⇒ ⇒ 报告**根本没更新** ⇒ ⇒ 四条判据全红且 `declared=0`** ⇒ ⇒ **看起来像「报告没实现」**。
   - **根因**：PLIC 的窗口（`0x200000 + 0x1000×contexts`）**约 2 MB** ⇒ ⇒ 夹具板给的 1 MB 预算**装不下** ⇒ ⇒ 内核报 `E_PLT-07` ⇒ ⇒ 板**被拒** ⇒ ⇒ 生效图**没变** ⇒ ⇒ 报告还是**旧板**的。
   - **修法**：夹具板预算给 **128 MB**（与内置 `qemu-virt` 同档）。
   - ⚠️ **通用判据**：真机判据**全红**且「读到的数是**零**」⇒ ⇒ **先问「板被内核收下了吗」** ⇒ ⇒ 再问「报告实现了吗」⇒ ⇒ ⇒ **顺序反了会白查半小时**。
4. ⚠️ ⚠️ **真机段污染了后面的段** ⇒ ⇒ ⇒ **两段假红**（基址规划那条 + 板档案那条）⇒ ⇒ 而**根因在自家这一段**。
   - **根因**：本段**卸载了工程**（为了「改板立即生效」）**＋**换了板 ⇒ ⇒ 后面那段要「**待生效**横幅」（⇒ ⇒ **已装载**时才有）⇒ ⇒ 而工程被卸了 ⇒ ⇒ 横幅**不出现** ⇒ ⇒ 那段**假红**。
   - **修法**：本段**收尾时把两样都复原** —— ① 板（配回能装下 demo 的那张）② **装载状态**（**重新装 demo 固件**）⇒ ⇒ 后面那些段拿到的还是「**已装载**的正常现场」。
