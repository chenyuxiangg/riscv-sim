1 功能概述

1.1 模块定位

M-01 工作台装配与多视图路由（4.1.1）：前端交互层入口，按会话携带的 role 装配三类工作台（产品工作台 / 嵌入式工作台 / 系统管理员工作台 P1）——工作台 = 视图组合 × 能力面 × 观测通道可见性，三者由 role 统一驱动（评审 L1：MVP 只装配「嵌入式工作台 + 产品工作台基础面」）；实现多视图 hash 路由（FR-23，M-01/M-03），视图切换后经 View Store 保持仿真与调试状态（V-11），route 阶段按 role × 能力位复校验目标视图（01-1，防 hash 直改绕过）。可用性约束零安装、同源 HTTP 部署直接可开、移动端 375px 可读（NFR-05）。

1.3 MVP 范围与预留

MVP 实现范围：assembleWorkspace(role)（按 role 装配视图组合 × 能力位 × 通道可见性）、route(hash)（hash 路由 + 未注册/无能力兜底，01-1）、switchView(target)（切换 + View Store 状态保持 + hash 同步，01-4）；MVP 装配 = 嵌入式工作台 + 产品工作台基础面（评审 L1）；hash 路由零依赖可用（NFR-05）。装配规则表（MVP 两 role 全量）见 3.5（01-5）。
预留项（P1 演进承接，不属现实现）：系统管理员工作台（P1）；诊断详情/系统日志观测面（随角色边界扩展）；工作台主题/布局自定义与多标签页；与 M-07 断线重连联动的装配态恢复（会话重建后按 role 重装配）；视图多能力位 AND/OR 组合（01-5）。

2.1.1 复杂结构字段定义

role 为会话角色枚举（product/embedded/admin，admin 属 P1 预留）；viewRegistry 为 hash → 视图组件注册信息的路由表（产品/调试/波形/串口终端）；workspaceState 为当前装配的工作台状态（激活视图、可见通道集合）；capBits 为会话能力位集合（M-05 negotiate 协商结果，01-6 实测）；RenderEvent 为切换渲染事件载荷（01-8）。字段定义如下：

// role: 会话携带的角色（4.1.1.2 表17；决定工作台装配与能力位过滤）
enum Role { product, embedded, admin /* admin 属 P1 预留（评审 L1） */ };
// capBits: 会话能力位集合（01-6 实测：来源 = M-05 v1.1 negotiate 返回的 capBits，
//   含 ExecutionBackend L1/L2/L3 分级协商；无 capabilityWhitelist 接口，装配/路由统一按 capBits 校验）
Set<Capability> capBits;
// viewRegistry: 路由表（FR-23）：hash → 视图组件注册信息
struct View {
  string hash;            // 路由 hash（如 "#debug"）
  Component component;    // 视图组件（M-02 视图组件库提供，待文档落地双侧核对，01-6）
  string name;            // 视图名称（产品/调试/波形/串口终端）
  Capability capability;  // 所需能力位（MVP 单能力；多能力 AND/OR 组合 P1 预留，01-5）
};
Map<hash, View> viewRegistry;
// workspaceState: 当前装配的工作台状态
struct WorkspaceState {
  Role role;                      // 装配角色
  View activeView;                // 激活视图
  Set<channel> visibleChannels;   // 可见通道集合（S1/W1/T1/E1 按 role 过滤，§3.4）
};
// RenderEvent: 切换渲染事件（01-8 展开；驱动 M-02 渲染）
struct RenderEvent {
  string viewId;                  // 目标视图 id
  ViewState state;                // 视图状态（首进入为视图默认 state，01-2）
  RenderType type;                // mount（首进入）/ update（切换回）/ unmount（切出）
};

3 实现设计

3.1 assembleWorkspace(role) 工作台装配

assembleWorkspace(role)：按 role 装配工作台——视图组合 × 能力位 × 通道可见性；未知 role 回退嵌入式工作台默认装配（4.1.1.5）；能力位读取会话 capBits（M-05 negotiate 协商结果，01-6 实测，拉取失败降级 role 默认能力位）；装配失败不阻塞已有视图（调用方捕获，保留当前 workspaceState）。伪代码如下：

// assembleWorkspace: 按 role 装配工作台（4.1.1.3 表18；输入：role；输出：装配后的视图集合）
WorkspaceState assembleWorkspace(Role role) {
  if (!isValidRole(role))
    return fallbackEmbedded();                            // 未知 role → 回退嵌入式默认装配（4.1.1.5）
  capBits = sessionCapBits(role);                         // 会话能力位（M-05 negotiate 协商结果，01-6 实测）
  if (capBits == null)
    capBits = defaultCapBits(role);                       // 拉取失败 → role 默认能力位降级（6.2）
  viewSet = filterByCapability(roleViewSet(role), capBits); // 视图组合 × 能力位过滤（规则表见 3.5，01-5）
  ws = {role, activeView: viewSet.primary, visibleChannels: channelFilter(role)};
  m21Log(INFO, "WS", "assemble", role);                   // 装配日志（M-21）
  return ws;                                              // 输出：装配后的视图集合
}
// 装配失败不阻塞已有视图：assembleWorkspace 抛错由调用方捕获，保留当前 workspaceState（4.1.1.5）
// 通道可见性：产品/嵌入式工作台不接触系统日志与诊断详情（§3.4 角色边界，HMS 提示脱敏）

3.2 route(hash) hash 路由

route(hash)：解析 location.hash 并在 viewRegistry 匹配；未注册路由显示兜底页并记日志（E_CTX-05）；已注册路由按 role × capBits 复校验目标视图能力位（01-1，防 hash 直改绕过），不满足同样走兜底页；兜底页为浮层覆盖（01-3）。伪代码如下：

// route: 解析 hash 并切换到对应视图（4.1.1.3 表18；输入：location.hash；输出：目标视图）
View route(String hash) {
  viewId = parseHash(hash);                               // "#debug" → "debug"（FR-23）
  target = viewRegistry.get(viewId);                      // 路由表匹配
  if (target == null) {                                   // 未注册路由 → 兜底页（4.1.1.5）
    m21Log(WARN, "WS", "route", "E_CTX-05", hash);        // 兜底页日志（E_CTX-05，表16 既有）
    return FALLBACK_VIEW;                                 // 兜底页视图（浮层覆盖，不卸载原视图，01-3）
  }
  if (!capBits.allows(target.capability)) {               // 路由复校验：role × 能力位（01-1）
    m21Log(WARN, "WS", "route", "E_CTX-05", hash);        // 无能力视图（hash 直改绕过）→ 兜底页 + 日志
    return FALLBACK_VIEW;
  }
  return switchView(target);                              // 切换并保持状态（V-11）
}

3.3 switchView(target) 视图切换与状态保持

switchView(target)：视图切换，切换后状态保持——同视图判重直接返回（01-2）；保存当前视图状态（M-03 setState），恢复目标视图状态（M-03 getState，空 → 视图默认 state 非兜底，01-2）；同步写回 location.hash（replace，不污染历史栈，01-4）；输出渲染事件（RenderEvent，01-8）驱动 M-02 渲染。伪代码如下：

// switchView: 视图切换，切换后状态保持（4.1.1.3 表18；调用 M-03 getState/setState；输出：渲染事件）
RenderEvent switchView(View target) {
  if (target.id == workspaceState.activeView.id)
    return;                                               // 同视图判重：直接返回（01-2）
  prev = workspaceState.activeView;
  m03SetState(prev.id, snapshot(prev));                   // 保存当前视图状态（M-03 setState）
  state = m03GetState(target.id) ?? defaultState(target); // 恢复目标视图状态；空 → 视图默认 state（01-2，
  //                                                       //   首进入初始化，非兜底）
  workspaceState.activeView = target;
  location.replace("#" + target.hash);                    // 同步写回 hash（replace：不污染历史栈，01-4）
  type = (firstEnter(target)) ? MOUNT : UPDATE;           // 渲染事件类型（01-8）
  return publishRender(target, state, type);              // 输出：渲染事件（驱动 M-02 渲染）
}
// 说明：hash 切换后状态保持 = 每视图独立 state 存于 View Store（M-03），切换不丢失（V-11）；
//   刷新页面按当前 hash 恢复目标视图（01-4）

M-03（View Store）getState/setState 保存与恢复各视图状态（V-11；getState 空 → 视图默认 state，01-2，签名待 M-03 文档落地双侧核对，01-6）switchView 切换时
M-05（命令路由/能力面）会话能力位 capBits（negotiate 协商结果，01-6 实测：M-05 v1.1 9.1.1 无 capabilityWhitelist 接口）；装配/route 按 capBits 过滤与复校验assembleWorkspace/route 时
M-21（日志）装配/路由日志（含 E_CTX-05 兜底日志）装配/路由节点
M-22（异常提示通道）HMS 脱敏提示（装配失败/兜底页面向用户的可读提示，签名待 M-22 文档落地双侧核对，01-6）异常节点

6 异常处理

6.1 错误码与处置（源表16 既有码，无新增）

M-01 为装配/路由层，异常统一兜底不崩溃；错误码全部取自源表16（E_CTX-05 既有），无新增码。处置如下：

错误码 / 场景触发条件处置
E_CTX-05（未注册/无能力路由）location.hash 在 viewRegistry 无匹配；或目标视图能力位不满足 capBits（hash 直改绕过，01-1）兜底页浮层覆盖 + 记日志（4.1.1.5）；原视图保持挂载与状态（不卸载，01-3）
未知 role（降级）会话携带 role 非 product/embedded/admin回退嵌入式工作台默认装配（L1）
装配失败（降级）assembleWorkspace 内部异常不阻塞已有视图：保留当前 workspaceState + WARN 日志 + HMS 脱敏提示
能力位拉取失败（降级）M-05 negotiate 能力位（capBits）不可得role 默认能力位降级装配（6.2）
状态恢复（首进入/异常）M-03 getState 返回空 → 首进入视图；getState 异常 → 状态不可得getState 空 → 视图默认 state 初始化（非兜底，01-2）；getState 异常 → 空状态渲染兜底 + 日志，不影响其他视图

6.2 边界与降级

（1）未知 role：一律回退嵌入式工作台默认装配（4.1.1.5），装配不中断。
（2）未注册路由/无能力视图：兜底页浮层覆盖并记日志（E_CTX-05），原视图保持挂载与状态（不卸载，01-3），已激活视图不受影响。
（3）装配失败：不阻塞已有视图——调用方捕获异常，保留当前 workspaceState，HMS 脱敏提示。
（4）能力位拉取失败：降级 role 默认能力位完成装配，WARN 日志标注降级。
（5）通道可见性过滤：产品/嵌入式工作台不接触系统日志与诊断详情（§3.4 角色边界）；HMS 提示脱敏，原始诊断仅管理员通道可见。
（6）移动端：375px 可读（NFR-05），导航折叠、视图单列布局；hash 路由零依赖可用（同源 HTTP 部署直接打开）。
（7）视图注册缺失：viewRegistry 未注册的目标视图按未注册路由处理（兜底页），不产生空白视图。
（8）hash 直改绕过防护（01-1）：产品 role 直改 #admin/未授权 hash → route 复校验能力位不满足 → 兜底页 + E_CTX-05，不进入目标视图。
（9）首视图语义（01-2）：首次进入视图 getState 空 → 渲染视图默认初始化 state（非兜底）；同视图重复切换直接返回（判重）。
（10）hash 同步（01-4）：switchView 以 replace 写回 location.hash（不污染历史栈），刷新页面按当前 hash 恢复目标视图。

7.2 可维护性手段

（1）视图注册表驱动：viewRegistry 集中注册，新增视图不改路由/装配逻辑（注册即接入）。
（2）装配规则表化：role → 视图组合/能力位/可见通道为声明式规则（roleViewSet/capabilityFilter/channelFilter，规则表见 3.5，01-5），调整装配不涉流程代码。
（3）错误码收敛：未注册/无能力路由统一 E_CTX-05（源表16 既有），提示语义一致。
（4）装配/路由与渲染解耦：M-01 只产出装配结果与渲染事件（RenderEvent，01-8），渲染落 M-02（M-01 逻辑纯函数可单测）。
（5）CI 门禁：三 role 装配 + V-11 状态保持 + 未注册/无能力路由兜底用例纳入回归基线（表92）。

9.2 日志对接（M-21）

装配成功 -> log(INFO, "WS", "assemble", role)（含视图数/可见通道数）；未知 role 回退 -> log(WARN, "WS", "assemble", "fallback_embedded", role)；未注册/无能力路由 -> log(WARN, "WS", "route", "E_CTX-05", hash)（01-1 复校验拦截同样记录）；装配失败 -> log(WARN, "WS", "assemble", "err", detail)；能力位降级 -> log(WARN, "WS", "assemble", "capbits_fallback", role)。会话关联字段（sessionId）随 M-21 双时间戳统一记录；产品/嵌入式工作台不可见系统日志与诊断详情（角色边界 §3.4），仅管理员通道可查。
