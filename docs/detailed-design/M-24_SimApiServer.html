1 功能概述

1.1 模块定位

M-24 是 riscv_sim 的进程级对外操作入口：把内核已有的能力（装载 / 运行 / 步进 / 断点 / 寄存器 / 内存 / 反汇编 / console 字节流）以稳定的 HTTP + WebSocket 形态暴露，使 Agent / CI 不必 import front/assets/pkg/riscv_sim_kernel.js，也不必知道 front/ 的目录结构。

它不是第 24 个内核模块：M-13 仍然解释指令，M-12 仍然持有虚拟时钟，M-14 仍然管理映射，M-08 仍然持有断点表。M-24 只做四件事 —— 传输（HTTP/WS）、会话（表 + 生命周期 + 隔离）、缓冲（console 的绝对 offset）、映射（内核码 ↔ HTTP 状态）。浏览器形态里住在 M-04/M-05/M-07 的三块职责，在服务端形态里由 M-24 承担；内核与契约层不动。

三条设计红线（与需求的「非目标」逐条对齐）：

  • 不替代浏览器工作台：前端仍是主交互面，M-24 是第二个入口，两者共用同一份内核与契约。
  • 不在 API 层改内核语义：无板不装载、镜像落在板外即拒、ISA 门禁不过即拒 —— 一律原样透出，不做「贴心兜底」。
  • 不给同一个故障造第二个码：错误码只在契约层拥有，M-24 只补 HTTP 状态与 detail。

2.2 会话状态机

状态只由会话线程写（HTTP 层读），因此「谁改状态」只有一个落点。非法迁移一律在动手之前拒绝，机器状态不动 —— 与内核既有的次序纪律同款。

表 4 · 状态迁移与拒绝码

NewPUT boardBoarded模板存在 ⇒ 200；未知模板 ⇒ 404 + E_PLT-22
BoardedPOST imageLoaded镜像合法且不越板 ⇒ 200；越板 ⇒ 422 + E_PLT-17
NewPOST image—无板 ⇒ 409 + E_PLT-22，detail 保留「先从模板导入 default / minimal / qemu-virt」
LoadedPUT boardLoaded允许换板，但不自动重载；返回 pending:true，需再发一次 image 才生效
Loaded / Idlerun / stepRunning占用命令面；同一时刻只允许一个推进者

2.3 数据流与缓冲

一条命令的完整路径：HTTP handler 组 Message → mpsc 投递给会话线程 → KernelHost::handle_message 执行 → 事件分批返回 → 先把 Console 字节 append 进 ring、再按停因组响应。「先日记账、后作结论」是 R-06 与 R-05 一致性的关键：响应里说的字节数必须此刻已经可读。

3.4 错误体与状态映射

统一错误体 {code, detail, status, request_id}；status 同时出现在 HTTP 状态行与体内，便于只看体的客户端判错。码一律使用契约层既有的族：新增场景码只有两处 —— SESS 族进契约层（见 §3.5），E_STORE-07 住本 crate。

3.5 契约增量（只增不改）

全量核对过契约 v18：装载 / 运行 / 步进 / 断点 / 观察点 / 寄存器 / 内存转储 / 符号 / 反汇编 / 快照 / trace / 模板 / 板图 —— 本需求需要的命令一条不缺。因此契约层只加一个错误族，消息形状一个字段不动。

5 处理流程

5.1 会话建立与配板

建会话是一个串行化的装配：配额 → 线程 → 板 → 注册。任一步失败都要把已经拿到的资源还回去（线程 join + 配额归还），否则「建会话失败」会漏出孤儿线程。

  • 配额检查通过才起线程；线程启动后立刻进入等待态（队列空），不会有「半初始化会话」被别的请求看见。
  • --board 的默认板在建会话时执行一次 PutBoard，并在会话元数据记 board_source="startup-default"；客户端自己配的记 "client"。
  • 模板来源走 GetPlatformTemplate 取整份描述再 SetMemoryMap —— 与前端同一条路径，不另抄模板数据。
  • 装配失败一律不注册；POST /api/sessions 返回错误体，客户端拿到的是 404/409，而不是一个「建好了但没板」的会话。

5.2 运行：分段推进与停因

「跑到什么时候停」由服务端判定，客户端不再切 StepN。一个窗口 = 一次 Continue（量子 10 000 条）；每个窗口结束做四件事：取 console、记账、判停因、查 deadline。

// run_window 的核心循环（伪码，逐字对应表 13 的判定次序）
fn run_window(host, spec, deadline, ctrl) -> StopReport {
    let before = host.total_executed();
    let mut windows = 0u64;
    loop {
        // ① 内核先跑一个量子窗口（不在服务端切更小的片）
        let ev = host.handle_message(&Message::command(seq, Continue));
        let halted = ev.iter().find_map(|e| as_halted(e));       // HaltReason

        // ② 先记账：console 进 ring，事件进 fanout（响应之前必须可读）
        ring.append(&host.drain_console());   // 取走本窗口产生的字节
        windows += 1;

        // ③ 再判停因（纯函数，固定次序）
        let obs = Obs { halted, ctrl, deadline, ring, spec,
                        executed: host.total_executed() };
        if let Some(reason) = judge_stop(&obs) {
            return StopReport::new(reason, host.total_executed() - before,
                                   host.pc(), host.now_ps(), ring);
        }
        if let Err(err) = first_kernel_error(&ev) { return StopReport::failed(err); }
    }
}

两个入口、一份判定：停止条件（预算 / 前缀 / 墙钟 / 停因次序）只实现一次 —— 就是住内核的 run_window。osz-boot 保留为离线入口（不起 daemon、不占端口、不需要 token），服务端 run 与 /api/boot 走同一函数，差别只在传输形态。判据是 T-14：同 ELF、同参数，两侧 stop_reason 与 console 字节必须一致；次序表被改歪时，表 19 的 judge_stop 先红。

5.3 console 的一致性

console 是字节不是字符串：ANSI 序列、\r、半截 UTF-8 一律不加工。ring 用绝对 offset，只追加、不改写；裁剪只从尾部发生，并在丢弃表里留证据。

// append：只追加，裁剪时记账（不静默丢）
fn append(&mut self, bytes: &[u8]) -> Range<u64> {
    let from = self.total;
    self.buf.extend_from_slice(bytes);
    self.total += bytes.len() as u64;
    while self.buf.len() > self.max {
        let cut = self.buf.len() - self.max;
        self.buf.drain(..cut);              // 只从头部裁
        let dropped_from = self.base;
        self.base += cut as u64;
        self.dropped.push((dropped_from, self.base));
    }
    from..self.total
}

// read：三种结果必须可区分，不许都变成「空」
fn read(&self, off: u64, limit: usize) -> ReadResult {
    if off < self.base {
        return ReadResult::Lost { base: self.base, dropped: self.dropped.clone() };
    }
    if off > self.total { return ReadResult::Future { total: self.total }; }
    let start = (off - self.base) as usize;
    let end = (start + limit).min(self.buf.len());
    ReadResult::Bytes { bytes: self.buf[start..end].to_vec(), total: self.total }
}

5.4 超时、熔断与回收

超时只做一件事：让推进中的 run 停在窗口边界并返回 504。它不改内核时钟、不改寄存器、不重置会话 —— 所以「超时后同会话还能继续用」是结构保证，不是靠重试凑出来的。

5.5 并发、隔离与复位

为什么是「一会话一线程」而不是共享内核：KernelHost 内部是 Rc/RefCell（wasm 侧还有 thread_local 单会话约束），不是 Send。用 tokio::Mutex 持锁跨 await 编译不过；用 spawn_blocking 又会让状态留在池线程里、下次请求换个线程就找不到。专属线程是唯一既通用又不需要改内核的形态。

6.2 边界与降级

  • 装载失败不改变机器状态：与内核次序纪律一致 —— 解析、门禁、建图都在写入之前完成，失败时寄存器与内存一个字节不动。
  • 配板 pending 不自动重载：换了板但没重装镜像时，返回 pending:true；不替客户端做「顺手重装载」，否则故障现场被抹掉。
  • 超时后再 run：允许；reset 也只是重发一次 LoadProject，语义与前端「复位」同口径。
  • WS 断流：连接断即退订；不保留「断线期间的事件」缓冲（P1 只保证 console 可从 REST 补齐）。
  • 请求体过大：413 + E_PROTO-08（tower_http::limit，默认 32 MiB）+ E_PROTO-08；不给解析器制造 OOM 的机会。
  • token 缺失（远程模式）：401 + E_SESS-07，detail 只说「需要 X-Auth-Token」，不回显期望值。

可维护性:三件事坚持住。① 量子常量只有一个来源（DEFAULT_INSTRUCTION_BUDGET），M-24 不抄第二份数；② 错误映射是表，不是 if-else 链；③ 停因判定只有一个落点：run_window 住内核，服务端与离线 runner 都调它 —— 两条入口各有自己的传输形态，但不各写一套停因次序。

附录 A 最小可脚本化序列

# 1) 版本协商（打印实际绑定地址与 schema）
curl -s http://127.0.0.1:9876/api/version

# 2) 建会话 + 配板 + 装镜像（任一步失败都带 code / detail / status）
SID=$(curl -s -X POST http://127.0.0.1:9876/api/sessions | jq -r .session_id)
curl -s -X PUT  "http://127.0.0.1:9876/api/sessions/$SID/board" -d '{"template":"qemu-virt"}'
curl -s -X POST "http://127.0.0.1:9876/api/sessions/$SID/image" \
     -H 'Content-Type: application/octet-stream' --data-binary @output/image/osz.elf

# 3) 跑到 shell，拿停因
curl -s -X POST "http://127.0.0.1:9876/api/sessions/$SID/run" \
     -d '{"prefix":"OSZ$ ","timeout_ms":30000}'
# → {"stop_reason":"prefix","executed":1500000,"pc":2147506812,
#    "console":{"from":0,"to":31,"total":31},
#    "meta":{"quantum":10000,"windows":150,"overshoot_max":10000}}

# 4) 取 console 原始字节（直接与 spike stdout 做 cmp）
curl -s "http://127.0.0.1:9876/api/sessions/$SID/console?offset=0" > platform.bin
cmp platform.bin spike.bin && echo MATCH

# 5) 一把梭（唯一判定口径）
curl -s -X POST http://127.0.0.1:9876/api/boot \
     -d '{"path":"output/image/osz.elf","prefix":"OSZ$ ","timeout_ms":30000}' \
     -o console.bin -D meta.txt   # meta 全部在 X-Sim-Meta / X-Stop-Reason 头里
