# STAGE-9 · v0.24 批 —— 把 v0.23 的遗留一次做掉

> **状态**：冻结（v0.24.0）
> **基线**：`0d1b282`（v0.23 批合 main）
> **前序规格**：`docs/detailed-design/STAGE-8_OSZ_Runtime.md`（v0.23 · osz 落地）
> **台账**：`docs/reviews/REVIEWS.md`

---

## §0 背景与范围

v0.23 批让真实 M 模式 RTOS（osz）在本平台上**跑起来**，三档验收全部达成
（CLI 闭环 / 浏览器可视化 / 与 Spike 逐字节对拍）。但那条链路的**交互侧**是空的，
而且批次本身留了 8 条账。

**本批的目标只有一句话**：**让 osz 的 shell 真的能用**，并把 v0.23 的遗留清账。

具体三件事：

1. **能打字**（E-8 / D-119）—— osz 的 `OSZ$ ` 提示符已经出现了，但**打不了字**：
   平台的 UART 只有 TX 方向（guest 写 ⇒ 宿主取），**反向**通路不存在
   ⇒ 契约层没有「往 UART 写」的命令、前端没有输入框、宿主没有喂 RX 的入口。
2. **能看到源码行**（E-6 / D-121 / D-102 收尾）—— osz 带 `-ggdb`（DWARF v5 行表），
   平台的 `resolve_line` **已经有真值**，但**反汇编面板**拿不到：
   `DisasmEntryDto` 的 `file` / `line` 契约形状在 v0.23 定了，**内核侧一律填 `None`**。
3. **能在调度器上下断点**（E-7）—— 平台的断点机制是通的（demo 固件的断点命中 PC 停在对齐地址），
   但**没有在真实 RTOS 上验证过**。

顺带清四条账：**D-117**（CLINT / PLIC 进不了会话快照）· **D-118**
（`UartStateDto` 缺 ns16550 的七个寄存器）· **D-120**（M-12 自写一份 `E_ENG_*` 字面量）
· **D-121**（反汇编的行号内核侧不填）。

⚠️ **本批不做**：S 扩展 / PMP / 计数器（**D-94**）· 取指侧 `cause 1`（**D-103**）·
**D-13** · **M-21 / M-22 / M-23** 三个 stub 模块。那是**下一批**的题目。

## §1 冻结决策（裁决 A ~ I）

### 裁决 A · 「往 UART 写」走**新命令**，不复用 `WriteMemory`

**决策**：契约层新增一条命令 `WriteConsole { bytes: Vec<u8> }`。
**理由**：`WriteMemory` 的语义是「写**内存**」—— 往 `0x1000_0000` 写一个字节在
技术上就是「写内存」，但**它绕过了平台对外设的语义层**（不会走 UART 的接收 FIFO、
不会置 `LSR` 的 RX_VALID、不会抬中断线）⇒ guest 读 `RHR` 会拿到**旧值**，
而 `LSR` 说「没有数据」⇒ **自相矛盾**。

⇒ 「往 UART 写」必须走**外设的语义入口**，不能走内存入口。

⚠️ **一条命令只做一件事**：`WriteConsole` 往**当前会话唯一的 UART0** 写。
本批**不做**「往哪个 UART 写」的选择（平台只有 UART0）。

### 裁决 B · 宿主收到 `WriteConsole` 后的三步

**决策**：宿主按顺序做三件事，**每一步都要可观察**：

1. 把字节塞进 UART 的 **RX FIFO**（`Uart16550::receive`）；
2. UART 的 `LSR` 的 **RX_VALID(bit0)** 随之置位（这是 UART 自己的事，模型已经做了）；
3. 若 `IER` 的 **RX 中断使能位(bit0)** 是开的 ⇒ 宿主抬 **PLIC 源 10** ⇒ PLIC 交付
   ⇒ M-16 的外部中断线 ⇒ guest 收到 `mcause = 0x8000_000B`（架构码 11）。

⚠️ **第 3 步是「平台代 guest 做」还是「等 PLIC 自己发现」**：本批沿用 v0.23 的
`sync_interrupts()` —— 宿主在**跑之前与跑之后各同步一次**，同步时若 UART 的
RX 就绪且 IER 允许 ⇒ `plic.request(10)` ⇒ PLIC 交付 ⇒ 抬 M-16 的外部线。
⇒ **`WriteConsole` 本身不抬线**（抬线是同步器的活）⇒ **一条命令不产生两个真相**。

### 裁决 C · 反汇编的行号由 **M-11 填**，宿主不猜

**决策**：`DisasmEntryDto` 的 `file` / `line` 由 **M-11 的反汇编器**填
（它手上有 `SymbolService::resolve_line`），**宿主不猜**。

⚠️ **两态不得混**（STAGE-7 裁决 J 的老规矩）：「查过行表、没命中」= `Missed`；
「没查」= `NoDwarf` ⇒ **绝不**产出猜出来的行号 ⇒ 字段填 `None` 是**合法且诚实**的。

⚠️ **性能**：反汇编是**按地址缓存**的 ⇒ 每条指令查一次行表**只发生一次**
⇒ 缓存命中时不重复查 ⇒ 不引入 N 次 DWARF 解析。

### 裁决 D · 前端终端视图加**输入框**，输入即发 `WriteConsole`

**决策**：终端视图（`terminalView`）加一个输入框 + 发送按钮；输入的字节
（**按 UTF-8 编码**）发 `WriteConsole` 命令；发送后**清空输入框**。

⚠️ **回显不是平台做的**：guest（osz 的 shell）自己回显 ⇒ 终端上看到的回显
**来自 guest** ⇒ 这是**端到端**的证据（平台写进去 ⇒ guest 读出来 ⇒ guest 写回来）。

⚠️ **不模拟终端的 Ctrl-C / 退格等控制序列**：本批只送**原始字节**。

### 裁决 E · 源码树的来源：**前端自己的入口**，不进内核

**决策**：源码树（路径 → 内容）**只进 M-03 的视图状态**、**不进内核**、
**不进契约**（这是 v0.22 定的老规矩，STAGE-7 裁决 A）。
本批给前端补一个**明确的可编程入口**（供真机段用），
但**内核侧一个字都不改**。

⚠️ **为什么不能让内核去读源码**：内核**不联网、不碰文件系统**（契约的
`ImageSource::Url` 会报 `E_LDR-01`，就是这个道理）⇒ 源码只能由前端拿到。

### 裁决 F · 会话快照补全：CLINT / PLIC 变体 + UART 的七个寄存器

**决策**：契约层加 `PeripheralSessionState::Clint(ClintStateDto)` 与
`::Plic(PlicStateDto)` 两个变体；`UartStateDto` 加 **LCR / IER / FCR / MCR /
SCR / DLL / DLM** 七个字段。

⚠️ **这是破坏性变更** ⇒ `SESSION_SNAPSHOT_SCHEMA_VERSION` **1 → 2**。
⚠️ **契约层再升一次版**（`SCHEMA_VERSION` **4 → 5**）—— v0.23 刚升过，
本批**是本批唯一一次**，且**只升这一次**。

⚠️ **M-15 侧的 DTO 形状由 M-15 定，契约层只承载**：具体字段由实现 lane 拍板，
但**必须**满足「往返一次快照后不变」这条判别力。

### 裁决 G · `E_ENG_*` 的字面量收拢到契约层

**决策**：M-12 里自写的 `E_ENG_01/02/03` 字面量改成**引用契约层的具名常量**
（D-120）⇒ 「一个约束一个落点」。

⚠️ **M-12 在内核 crate 里、契约层在内核 crate 的依赖里** ⇒ 引用方向是对的
（内核依赖契约），**不构成循环依赖**。

### 裁决 H · 真机验收的三条判别式

**决策**：三条都要**断言具体值**，不许断言「非空」：

| 判别式 | 断言 |
| --- | --- |
| **E-6** | 反汇编面板里出现 osz 的**真** `file` 与 `line`（不是 `None`、不是 0） |
| **E-7** | 在 osz 的调度器符号上下断点 ⇒ 命中时 **PC 落在那个符号的地址** |
| **E-8** | 往终端输入框送一个字节 ⇒ guest 的 **UART RX 就绪**（`LSR` bit0 置位）**且**（若 osz 回显）console 上出现该字节 |

⚠️ **E-7 的符号从哪来**：osz 带 `-ggdb` ⇒ `.symtab` 在 ⇒ 平台的 M-11 符号表
能查到调度器符号 ⇒ 真机段**用符号名**取地址，**不写死地址**（写死就成恒绿）。

⚠️ **E-6 的行号从哪来**：同一份 ELF 的 `.debug_line`（v5）⇒ 平台的
`resolve_line` 能给出真 `file` + `line`。

### 裁决 I · 外部产物一律不进仓库

**决策**：osz 的源码 / ELF / Spike 输出 / 调度器符号表**都在仓外**
（`$OSZ_ELF`、`$OSZ_SRC`）⇒ 真机段**没有这些文件就跳过**（退出码仍是 0），
**有**却跑不出 ⇒ **判负**。

⚠️ 这与 v0.23 的 `tools/boot-osz.sh` 同一条纪律。

## §2 验收清单

### 2.1 Lane H · 契约层 v5

- [ ] **H-1** `SCHEMA_VERSION` = **5**，`front/lib/message.js` 同步，**两侧逐字对照表**扩到含新命令与新变体
- [ ] **H-2** 新命令 `WriteConsole { bytes: Vec<u8] }` 进契约层与 JS 镜像（**形状逐字一致**）
- [ ] **H-3** `UartStateDto` 加 **7 个** ns16550 寄存器字段
- [ ] **H-4** `PeripheralSessionState` 加 **Clint / Plic** 两个变体与对应 DTO
- [ ] **H-5** `SESSION_SNAPSHOT_SCHEMA_VERSION` **1 → 2**（破坏性变更要**显式**）
- [ ] **H-6** `E_ENG_*` 三个场景码在契约层有**具名常量**（M-12 引用它们，不复制字面量）

### 2.2 Lane I · M-15 / M-12 生产侧

- [ ] **I-1** UART 的会话状态**带**七个寄存器（`LCR` 的 `DLAB` 位在快照往返后**仍然**是原值）
- [ ] **I-2** CLINT 的会话状态带 `mtimecmp`（**往返一次后不变**）
- [ ] **I-3** PLIC 的会话状态带优先级 / 使能 / 门限（**往返一次后不变**）
- [ ] **I-4** 两个新器件的 `validate_session_state()` **不是**默认放行（**畸形状态被拒**）
- [ ] **I-5** M-12 **不再**自写 `E_ENG_*` 字面量（**全仓只有一个来源**）

### 2.3 Lane J · 宿主 + M-11

- [ ] **J-1** `WriteConsole` 命令被宿主接住 ⇒ 字节进 **UART 的 RX FIFO**
- [ ] **J-2** 写进去之后 UART 的 **`LSR` RX_VALID(bit0)** 置位（guest 读 `RHR` 能读到）
- [ ] **J-3** `IER` 的 RX 中断使能位开着 ⇒ 同步后 **M-16 的外部中断线**被拉起（`mcause = 0x8000_000B`）
- [ ] **J-4** 反汇编的 `DisasmEntryDto` **填上真 `file` + `line`**（DWARF 行表命中时）
- [ ] **J-5** 行表**没命中**时填 `None`（**不猜**）——「查过没命中」与「没查」**不得混**

### 2.4 Lane K · 前端 + 真机

- [ ] **K-1** 终端视图有**输入框**，输入的字节发 `WriteConsole`
- [ ] **K-2** 前端有**可编程的源码树入口**（供真机段用）
- [ ] **K-3** 反汇编面板**逐条**显示 `file` / `line`（**没有行号的条目如实显示「无行号」**）
- [ ] **K-4** **E-6 真机**：反汇编面板里出现 osz 的**真** `file` 与 `line`
- [ ] **K-5** **E-7 真机**：在 osz 的调度器符号上下断点 ⇒ 命中时 **PC 落在那个符号的地址**
- [ ] **K-6** **E-8 真机**：往终端送一个字节 ⇒ guest 的 UART RX 就绪（**断言具体位**）

## §3 边界：明确**不做**的事

1. **不做** S 扩展 / PMP / 计数器（**D-94**）。
2. **不做** 取指侧未映射访问的 `cause 1`（**D-103**）。
3. **不做** **M-21 / M-22 / M-23** 三个 stub 模块。
4. **不做**「往哪个 UART 写」的选择（平台只有 UART0）。
5. **不做**终端控制序列（Ctrl-C / 退格 / 历史）的模拟。
6. **不做**内核侧读源码（裁决 E）。
7. **不做**`WFI` 的真等待（仍是忙等，D-94 同批遗留）。
8. **不做**软件中断源（架构 cause 码 3 仍无生产者）。
9. **不做**把 osz 的源码 / ELF / 符号表提交进仓库（裁决 I）。
