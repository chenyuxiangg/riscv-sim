1 功能概述

1.1 模块定位

M-22 健康管理 HMS（4.6.3）：健康管理横切模块（NFR-08）——采集健康信号（引擎心跳、会话状态机、错误码、命令超时、崩溃信号、传输连接、guest 失控 watchdog）→ 异常分级（致命/严重/警告，阈值可配置）→ 分角色分发（产品/嵌入式 = 脱敏可读提示；系统管理员 = 诊断详情 + 日志关联）→ 降级动作（自动快照 + 恢复/暂停/断开外设/关闭 trace 降载/terminate 失控内核）。故障三分类：① guest trap = 模型内 guest 异常（正常调试语义）；② 平台崩溃 = 平台故障；③ guest 失控 = watchdog 超时（terminate 内核并告警）。MVP 基线 = 崩溃自动快照 + 恢复（评审 L1）。指标通道（承接 FR-20，评审 P-18）；提供「导出脱敏诊断包」（评审 P-23）。与日志系统职责分离（M-21 只记录，HMS 只监控分发，图6）。

2.1.1 复杂结构字段定义

健康信号为结构化条目（信号源 + 错误码 + 上下文）；分级映射表阈值可配置；降级动作策略可重试；指标条目写入环形指标带（FR-20/P-18）；诊断包仅含取证要素、不含原始日志（角色边界，P-23）。字段定义如下：

// HealthSignal: 健康信号条目（healthSignals 流元素，report 输入）
struct HealthSignal {
  uint8_t  src;                 // 信号源：M-04 会话 / M-05 命令 / M-07 传输 / M-12 引擎 / M-17 后端（映射表见下）
  uint32_t errCode;             // 错误码（E_CTX/E_PROTO 体系，源表16）
  uint64_t tVirt;               // 虚拟时间（M-20 事件流虚拟时钟，双时间戳定位）
  uint64_t tHost;               // 宿主时间（M-21 TimeSource）
  uint32_t ctx;                 // 上下文标识（会话/队列/连接 id）
  uint8_t  kind;                // HEARTBEAT / STATE / ERROR / TIMEOUT / CRASH / CONN / WATCHDOG / TRAP（22-9 补 TRAP）
};
// src -> 上报模块映射（22-9）：M-04 会话（STATE/ERROR/CRASH）、M-05 命令（TIMEOUT/CONN/ERROR）、
//   M-07 传输（CONN）、M-12 引擎（HEARTBEAT/WATCHDOG）、M-17 后端（CRASH）；TRAP 由 M-13/M-14 模型内上报
// 故障三分类（4.6.3.1）：guest trap = 模型内 guest 异常（正常调试语义）；平台崩溃 = 平台故障；
//   guest 失控 = watchdog 超时（terminate 内核并告警）
// Severity: 异常分级（classify 输出，阈值可配置）
enum Severity { FATAL, CRITICAL, WARNING, INFO_NO_DEGRADE };   // 22-3：扩枚举（guest trap 仅提示/未命中默认）
// 分发载荷（22-10）：脱敏提示 vs 管理员诊断详情两类结构
struct NoticeMsg {            // 脱敏提示（产品/嵌入式，不含原始日志）
  uint8_t  sev;               // 级别（脱敏后展示）
  uint32_t errCode;           // 错误码（可展示部分）
  uint32_t ctx;               // 上下文标识（脱敏）
};
struct AdminDiagnosis {       // 诊断详情（系统管理员）
  uint8_t  sev;               // 级别
  uint32_t errCode;           // 完整错误码
  uint32_t ctx;               // 会话/队列/连接 id
  uint64_t tVirt; uint64_t tHost;   // 双时间戳
  LogRef   logRef;            // M-21 日志关联（根因查询引用）
};
// DiagnosticKit: 脱敏诊断包（评审 P-23；不含原始日志，角色边界 §3.4）
struct DiagnosticKit {
  uint32_t errCode;             // 错误码
  Snapshot  snap;               // 快照（M-20）
  InputSeq  inputs;             // 稀疏输入序列（M-20）
};

2.3 数据流说明

处理流程（4.6.3.4）：信号采集 → 分级 → 分角色分发 → 降级动作 → 恢复（检查点 + 输入重放）；指标采集 → 环形指标带（面板 P2）；崩溃/上报 → 现场包或脱敏诊断包导出；与日志系统职责分离（M-21 只记录，HMS 只监控分发，图6）。

3 实现设计

3.1 report(signal) 健康信号上报

report(signal)：接收各业务模块健康信号（信号源 + 错误码），统一时间戳化（tVirt 取 M-20 事件流虚拟时钟、tHost 取 M-21 TimeSource）后**先分级再入流**（classify 定级后写入 healthSignals，分级保留策略据此判定）；分级结果进入分角色分发与降级决策（degradePolicy 查表 → 统一转调 degrade，22-4）。信号流环形带分级保留（致命/严重不丢）与崩溃冻结（取证前因，22-12）。伪代码如下：

// report: 健康信号上报（表81；输入：信号源 + 错误码；输出：分级结果）
Severity report(HealthSignal s) {
  s.tVirt = m20CurTimeVirt();                      // 双时间戳（M-20 虚拟时钟 + M-21 TimeSource）
  s.tHost = m21TimeSource().nowHostMs();
  sev = classify(s);                               // 先分级（定级后再入流，供 22-12 保留策略判定）
  healthSignals.append(s);                         // 健康信号流（环形 + 分级保留，见下）
  if (healthSignals.size > SIG_CAP && sev != FATAL && sev != CRITICAL) {
    healthSignals.shift();                         // 22-12：致命/严重相关信号不丢（独立保留带）
  }
  dispatch(sev, { src: s.src, errCode: s.errCode, ctx: s.ctx });   // 分角色分发
  act = degradePolicy[sev];                        // 22-4：查策略表 → 统一转调公开 degrade(action)
  if (act != NONE && (sev == FATAL || sev == CRITICAL)) {
    degrade(act);                                  // 致命/严重 → 自动降级处置（L1）
  }
  return sev;
}
// 22-12：崩溃/失控时冻结信号流（不再 shift），保证诊断包取证含失控前因（watchdog 时序证据）

3.2 classify(signal) 异常分级

classify(signal)：按 severityTable 分级映射判定致命/严重/警告（阈值可配置）；guest trap 归正常调试语义（仅提示不降级，22-3）；watchdog 超时 → guest 失控（致命）；severityTable 未命中 → 仅记录/提示（NO_DEGRADE，不触发降级动作，22-5）。伪代码如下：

// classify: 异常分级（表81；输出：致命/严重/警告/NO_DEGRADE）
Severity classify(HealthSignal s) {
  if (s.kind == WATCHDOG && s.ctx == GUEST_RUN) {   // guest 失控（watchdog 超时，4.6.3.1）
    return FATAL;                                  // terminate 内核并告警
  }
  if (s.kind == TRAP) {                            // guest trap = 模型内异常（正常调试语义）
    return INFO_NO_DEGRADE;                        // 仅提示不降级（4.6.3.1；22-3 枚举成员）
  }
  return severityTable[s.src][s.errCode] != null
       ? severityTable[s.src][s.errCode]           // 分级映射（阈值可配置，表80）
       : INFO_NO_DEGRADE;                          // 22-5：未命中仅记录/提示，不触发降级动作
}
// severityTable 可配置（Map<signal, level>，表80）：会话异常/命令超时/断连/后端崩溃分级由 M-04/M-05/M-07/M-12 上报
// 22-5：降载类动作（关 trace 等）仅对明确匹配的降载信号触发，未知错误码默认不处置

3.3 dispatch(severity, info) 分角色分发

dispatch(severity, info)：按角色分发——产品/嵌入式 = 脱敏可读提示（不含原始日志）；系统管理员 = 诊断详情 + M-21 日志关联（根因查询）。伪代码如下：

// dispatch: 分角色分发（表81；产品/嵌入式：可读提示（脱敏）；管理员：诊断详情（关联 M-21））
void dispatch(Severity sev, Info info) {
  if (role == ADMIN) {
    details = m21RootCause(info.ctx);              // M-21 根因查询（日志关联；接口名/入参双侧同步锚点，22-8）
    adminChannel.send(AdminDiagnosis{              // 22-10：诊断详情载荷（2.1.1 结构定义）
      sev: sev, errCode: info.errCode, ctx: info.ctx,
      tVirt: info.tVirt, tHost: info.tHost, logRef: details
    });                                            // 管理员：诊断详情（§3.4）
  } else {
    m01Notify(NoticeMsg{ sev, errCode: info.errCode, ctx: info.ctx });  // 22-10：脱敏提示载荷（不含原始日志）
    // M-01 异常提示通道（表82 使用方）
  }
}
// 角色边界（§3.4）：产品/嵌入式工作台不接触系统日志与诊断详情；提示脱敏（4.6.3.5）

3.4 degrade(action) 降级动作

degrade(action)：执行降级动作（自动快照 + 恢复/暂停/断开外设/关闭 trace 降载/terminate 失控内核）；处置动作可重试（重试上界 ≤3 次 + 终态上报，22-11）；恢复失败回退更早检查点（4.6.3.5）。时序语义（22-2）：崩溃恢复回退**崩溃前最近检查点** + 输入重放，「自动快照」仅作现场保护导出、非恢复源；降载通道经 M-12 暂停 trace 事件（22-7，M-19 降采样契约双侧核对锚点）。伪代码如下：

// degrade: 执行降级动作（表81；自动快照+恢复/暂停/断开外设/关trace/terminate；输出：处置结果）
DegradeResult degrade(Action action) {
  for (try = 0; try < RETRY_MAX; try++) {          // 22-11：重试上界（≤3 次）
    r = tryDegrade(action);                        // 执行一次动作
    if (r.ok) return { ok: true, action, try };
  }
  m22Report(DEGRADE_FAILED, action);               // 22-11 终态：上报 + 停止会话/人工介入
  return { ok: false, action };
}
DegradeResult tryDegrade(Action action) {
  switch (action) {
    case SNAPSHOT_RESTORE:
      protectScene();                              // 22-2：自动快照=保护现场（导出，非恢复源）
      r = m20Restore();                            // 22-2：回退崩溃前最近检查点 + 输入重放（M-20）
      if (!r.ok) { return r; }                     // 恢复失败 → 下次重试回退更早检查点（4.6.3.5）
      break;
    case PAUSE:        m04PauseSession(); break;   // 暂停（M-04 会话处置）
    case DISCONNECT:   m07Disconnect();   break;   // 断开外设（M-07 传输）
    case TRACE_DOWN:   m12PauseTraceEvents(); break; // 22-7：经 M-12 暂停 trace 事件（降载通道）
    case TERMINATE:    m04Terminate();    break;   // terminate 失控内核（guest 失控）
  }
  return { ok: true, action };
}
// 处置动作可重试（4.6.3.5）；guest 失控 terminate 后重新加载固件或从最近检查点恢复（4.6.3.5）
// 动作触发链：report → classify → degradePolicy[sev] → degrade（4.6.3.4；22-4 统一转调）
// 22-2：恢复源 = 崩溃前最近检查点 + 输入重放；崩溃时刻状态不新打检查点（现场保护导出仅取证）
// 22-7：降载经 M-12 暂停 trace 事件；M-19 侧降采样契约（预算口径）作为 P1 双侧核对锚点

3.5 collectMetric(name, value) + exportDiagnosticKit()

collectMetric：指标采集（FR-20）写入 metrics 环形指标带（MIPS、命令响应 P50/P99、推送周期、队列水位、溢出次数、会话内存、异常率，P-18）；指标面板 P2 展示（MVP 只做采集与现场包）。exportDiagnosticKit：导出脱敏诊断包（错误码 + 快照 + 稀疏输入序列，不含原始日志，P-23）。伪代码如下：

// collectMetric: 指标采集（表81；FR-20；写入 metrics 环形指标带；指标面板 P2 展示，评审 P-18）
void collectMetric(string name, double value) {
  metrics.append({ tVirt: m20CurTimeVirt(), name, value });
  if (metrics.size > METRIC_CAP) { metrics.shift(); }   // 环形（估算基线 4096 条）
}
// 指标项：MIPS、命令响应 P50/P99、推送周期、队列水位、溢出次数、会话内存、异常率（表80，P-18）
// 22-6 同源口径：队列水位/溢出次数/异常率由 report 信号派生（M-05/M-12 上报即写指标，不双写）；
//   MIPS/命令响应 P50/P99 由 M-05/M-12 周期采集经 collectMetric 写入（单一数据源）
// exportDiagnosticKit: 导出脱敏诊断包（表81；错误码 + 快照 + 输入序列，不含原始日志；评审 P-23）
DiagnosticKit exportDiagnosticKit(uint32_t errCode) {
  kit = {
    errCode: errCode,
    snap:   m20LatestSnapshot(),                  // 快照（M-20）
    inputs: m20InputSeqTail(1024) };              // 稀疏输入序列（M-20，不含日志）
  m23Archive(kit);                                // M-23 归档（供用户上报后管理员链路取证）
  return kit;
}
// 角色边界（P-23/§3.4）：诊断包不含原始日志——用户上报链路只含取证要素，日志关联仅管理员可见

6.2 边界与降级

（1）处置动作可重试，重试上界 ≤3 次 + 终态（上报 DEGRADE_FAILED → 停止会话/人工介入，22-11）；恢复失败回退更早检查点（4.6.3.5）。
（2）提示脱敏不含原始日志；产品/嵌入式工作台不接触系统日志与诊断详情（§3.4 角色边界）。
（3）guest 失控 terminate 后重新加载固件或从最近检查点恢复（4.6.3.5）。
（4）guest trap = 模型内异常（正常调试语义），仅提示不降级（4.6.3.1；22-3 枚举 INFO_NO_DEGRADE 承载）。
（5）恢复时序（22-2）：恢复源 = 崩溃前最近检查点 + 输入重放；崩溃时刻不新打检查点（自动快照=现场保护导出，非恢复源）。
（6）severityTable 未命中默认（22-5）：仅记录/提示（NO_DEGRADE），不触发降级动作；降载类动作仅对明确匹配的降载信号。
（7）错误码一场景一码（22-1）：watchdog 失控用 E_CTX-12，与 M-04 E_CTX-11=会话不存在 不冲突。
（8）诊断包导出不含原始日志（角色边界，评审 P-23）；日志关联仅管理员可见。
（9）与日志系统职责分离：M-21 只记录，HMS 只监控分发（图6）。
（10）指标采集 MVP 只做现场包（P-19）与健康信号；指标面板 P2 展示（P-18）；与 healthSignals 同源派生不双写（22-6）。
（11）健康信号流环形 ≤10⁴ 条（分级保留：致命/严重不丢，22-12；崩溃时冻结信号流）、指标环形 ≤4096 条（估算基线），溢出丢最旧 + warn。
（12）移动端：375px 可读（NFR-05），面板单列 + 横向滚动；file:// 直接可开。
