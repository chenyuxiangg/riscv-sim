# STAGE-41 · v0.56 · 终端屏幕仿真批（串口回显重画堆成多行）

> **状态**：规格**冻结**（实现与判据照此施工）。
> **版本**：v0.56 · 契约层**零升版**（`SCHEMA_VERSION` 仍 **8** · `SIM_STATE_SCHEMA_VERSION` 仍 **2** · `PLATFORM_SCHEMA_VERSION` 仍 **1** · `PLATFORM_RULES_VERSION` 仍 **3**）⇒ ⇒ **零新 DTO / 零新命令 / 零新事件**。
> **主题**：串口终端**按终端语义显示** —— guest 的 shell 每敲一个键就**重画整行**（`ESC[2K` + `CR` + 提示符 + 缓冲区）⇒ ⇒ **真实终端**显示成**一行** ⇒ ⇒ 平台此前把字节流**原样**当文本显示 ⇒ ⇒ `\r` 被渲染成换行 ⇒ ⇒ 用户看到的是「提示符 + 半截命令」**堆成好几行**的乱码。
> **台账**：销账 **D-161**（本批新登记即闭环）；**零新登记**。
> **规格号**：**STAGE-41** ⇒ ⇒ I2C 那批顺延为 **STAGE-42**（见裁决 J）。

---

## §0 本批的边界

| 维度 | 本批 | 理由 |
| --- | --- | --- |
| 契约层 | **零变更** | 改的是**前端怎么把字节流画成屏幕**⇒ 不需要新的 DTO / 命令 / 事件 |
| 内核 / M-15（UART） | **零改动** | 字节流是**对的**（与 Spike 逐字节对拍通过 ⇒ 事实 F8）⇒ ⇒ **改字节流才是错的** |
| 前端 | **一个新模块 + 一处接线 + 一个开关** | 新模块 = 屏幕仿真（`front/views/components/terminal-screen.js`）· 接线 = 终端视图的显示口径 · 开关 = 「原始字节」档 |

⛔ **本批不做**：多行终端输入、终端的字号/配色（SGR）、回滚缓冲（scrollback）、把终端搬进 Web Worker、契约升版。

## §1 为什么要做这一批

### §1.1 用户看到的现象

用户在串口界面输入 `cyx`，**理论上**屏幕上应该只有**一行** `OSZ$ cyx`；**实际上**看到的是：

```
[2K
OSZ$ [2K
OSZ$ c[2K
OSZ$ cy[2K
OSZ$ cyx
```

⇒ ⇒ **四次重画**堆成**四行**（外加每行末尾的 `[2K` 字面量）。

### §1.2 实测事实（每条都对着**当前树**或**上游源码**量过）

| 编号 | 事实 | 怎么量的 |
| --- | --- | --- |
| F1 | osz 的 `kernel/shell/src/shell.c`：`#define SHELL_CLEAN_LINE "\033[2K\r"` · `#define SHELL_NAME "OSZ$ "` · `inner_shell_reset_line()` = 打 `SHELL_CLEAN_LINE` + 打 `SHELL_NAME` | 读上游源码 |
| F2 | osz 的 shell 在**每敲一个键**之后都走 `inner_shell_reset_line()` + 重打缓冲区 ⇒ ⇒ **敲 N 个键 = N 次整行重画** | 读上游源码（`inner_shell_reset_line` 的调用点） |
| F3 | osz 的 shell 还用 `SHELL_MV_CURSOR_LEFT` = `"\033[1D"` · `SHELL_MV_CURSOR_RIGHT` = `"\033[1C"` 与 `"\b"` ⇒ ⇒ **光标移动类序列**是真实存在的 | 读上游源码 |
| F4 | 平台**不做本地回显**：终端视图的字节**全部**来自内核的 `Console` 事件（`front/app.js` 的 `wireConsole`）⇒ ⇒ 屏幕上的每一个字都是 guest 吐的 | 读当前树 |
| F5 | 终端视图此前把字节流**原样**渲染：`escapeHtml(buf)` ⇒ `<pre class="terminal-out" data-terminal-out>`（`front/views/m02_viewcomponents.js`） | 读当前树 |
| F6 | `.terminal-out` 的 CSS 是 `white-space: pre-wrap` ⇒ ⇒ **CR 是「段分隔符」**⇒ ⇒ 渲染成**强制换行**（CSS Text 3）⇒ ⇒ `\r` 变成一行 | 读 `front/style.css` |
| F7 | 走 `innerHTML` 那条路（重渲染）时，**HTML 解析器把 CR 规范化成 LF** ⇒ ⇒ 两条路（快路径 `textContent` / 重渲染 `innerHTML`）**看起来一样**⇒ ⇒ 用户看到的就是一串换行 | 读 HTML 规范 + 两条渲染路径 |
| F8 | 字节流本身**是对的**：osz 两侧 console **31 字节逐字相同**（`tools/boot-osz.sh` ⇒ `VERDICT MATCH`）⇒ ⇒ **字节流不是缺陷** | 跑 `tools/boot-osz.sh` |
| F9 | ESC（`0x1B`）**不是可见字面量** ⇒ ⇒ 用户看到的 `[2K` 是序列里**剩下**的那几个字符 ⇒ ⇒ 「去掉 ESC」与「解释整个序列」两件事必须**一起**做，否则会剩下 `[2K` | 实测现象 + CSS/渲染口径 |
| F10 | **真实串口终端**把 `ESC[2K` 解释成「擦掉整行」、把 `CR` 解释成「回到列首」⇒ ⇒ **后一次重画覆盖前一次** ⇒ ⇒ 屏幕上就是**一行** `OSZ$ cyx` | 终端语义（ECMA-48）+ 现象反推 |
| F11 | guest 吐的是**光秃秃的 `\n`**（如 `"OSZ$ Q\nQ: No such command.\n"`）⇒ ⇒ 真实串口上 host 端 tty 的 **ONLCR** 会把它变成 **CR+LF** ⇒ ⇒ 下一行**顶格** | 读 v0.55 批实测字节串 + host tty 默认输出处理 |

### §1.3 根因（**一处前端缺陷**，不是内核缺陷）

**根因**：终端视图把 guest 的字节流**当作文本**显示，**不解释**终端语义。

⇒ ⇒ 于是 guest 的**行重画协议**（`ESC[2K` + `CR` + 提示符 + 缓冲区）被摊平成四段普通文本 ⇒ ⇒ 用户看到四行。

⚠️ **三条不是根因的**（都实测过）：

1. **不是**「平台做了本地回显」⇒ ⇒ 平台一个字都没本地回显（事实 F4）；
2. **不是**「guest 的 shell 画错了」⇒ ⇒ 它画的就是**终端协议**（事实 F1 ~ F3），真实终端上就是一行（事实 F10）；
3. **不是**「字节流不对」⇒ ⇒ 与 Spike 逐字节相同（事实 F8）。

⇒ ⇒ **要改的是「怎么把字节流画成屏幕」** —— 这是一处**纯前端**的显示缺陷。

## §2 裁决

| 编号 | 裁决 | 理由 |
| --- | --- | --- |
| **A** | **改显示层，不改字节流**：新增屏幕仿真模块（`front/views/components/terminal-screen.js`），终端视图默认显示**仿真后的屏幕**；store 里的 `term.bytes` **一字不动** | 字节流是真相（事实 F8）⇒ ⇒ 改它会破掉与 Spike 的逐字节对拍 |
| **B** | **LF 顺带 CR**（ONLCR 建模）：guest 的 `\n` 落成「回列首 + 换行」 | 真实串口上 host 端 tty 默认 ONLCR（事实 F11）⇒ ⇒ 否则 guest 打印的下一行会**缩进上一行的长度** ⇒ ⇒ 没有任何真实终端是那个样子；且**保持**了本平台此前「LF 顶格」的样子 |
| **C** | **渲染时去掉行尾空格** | 屏幕上的空格格是**空白**⇒ ⇒ 留着它只会让「这行到底有没有东西」看不清 |
| **D** | **真相是 store 的字节流**；屏幕只是**渲染** ⇒ ⇒ 允许维护一份**增量**的屏幕实例（长会话里不 O(n²)）⇒ ⇒ 但**必须**与「从零重建」给出同一个答案 | 一条约束一个落点 ⇒ ⇒ 增量只是**手段**，不是第二个真相源 |
| **E** | 增量实例**必须核对「确实是追加」**⇒ ⇒ 不是追加就**从零重建**⇒ ⇒ 缓存与真相**不会**悄悄分叉 | 没有这一步，缓存就是第二个真相源 ⇒ ⇒ 迟早显示错 |
| **F** | **保留「原始字节」档**：界面上一个按钮切「终端屏幕 / 原始字节」⇒ ⇒ **不发**契约命令（与板档案那套按钮同一条口径） | 「字节流才是真相」这条**不能丢**⇒ ⇒ 字节级排查仍然需要看原文 |
| **G** | **契约层零升版** | 改的是显示口径 ⇒ ⇒ 没有新的线上形状 |
| **H** | 真机门禁新增 **`terminalScreen`** 段 ⇒ ⇒ 且**必须排在 `osz` 之后、`uartEcho` 之前** | ① 要真 osz（仓外 ELF）② `uartEcho` 用「不加」档留了一个 `E` 在 guest 的**行缓冲**里 ⇒ ⇒ 排在它后面 ⇒ ⇒ 本段敲的 `cyx` 会变成 `Ecyx` ⇒ ⇒ **假红** |
| **I** | 旧的那条断言（「ANSI 转义**原样**显示」）**改写**成两条（屏幕上**不许**出现字面量 + 字节流**一个字都没丢**）⇒ ⇒ **不是**把判据删掉 | 那条断言**编码的正是这个缺陷**⇒ ⇒ 但它背后的**意图**（「不许过滤字节」）必须**保留**⇒ ⇒ 拆成「显示侧」与「字节流侧」两条 |
| **J** | 规格号 = **STAGE-41** ⇒ ⇒ I2C 那批顺延为 **STAGE-42** | 规格号**按创建顺序**⇒ ⇒ 不留空洞 |

## §4 已知边界

1. **屏幕没有回滚缓冲** ⇒ ⇒ 屏幕是一条**线性缓冲**⇒ ⇒ guest 一次吐很多行时，行数会一直涨（与本平台此前的行为一致 ⇒ ⇒ **不是**新引入的退化）；
2. **不实现 SGR（颜色/属性）** ⇒ ⇒ `\x1b[31m` 这类序列被**吞掉**⇒ ⇒ 屏幕上是**单色**（与本平台此前的行为一致 ⇒ ⇒ 此前是显示成字面量，现在是显示成无 ⇒ ⇒ **更好**，但**不是**真终端）；
3. **LF 按 ONLCR 处理** ⇒ ⇒ 与「严格 LF（只下移、不回列首）」的终端**不一样**⇒ ⇒ 选 ONLCR 是因为真实串口链路（事实 F11）如此；
4. **光标不画** ⇒ ⇒ 屏幕上没有闪烁的光标块；
5. **「原始字节」档下用户会看到 `[2K` 这类字面量** ⇒ ⇒ 那是**故意**的（那一档就是看原文）⇒ ⇒ 默认档不是它；
6. **屏幕仿真是前端侧的**⇒ ⇒ 与内核、与 Spike 的对拍**无关**（对拍比的是字节流 ⇒ ⇒ 字节流没动 ⇒ ⇒ 对拍结论不变）。

## §8 施工期订正

### 订正 1 · 「LF 顶格」这条是**裁决**不是**事实**

初稿把「LF 顺带 CR」写成「事实」⇒ ⇒ **不成立**：严格意义上的终端里 LF 只下移、不回列首（是否回列首取决于 **LNM** 与 host 端 tty 的 **ONLCR**）⇒ ⇒ 本批把它降级成**裁决 B**（建模选择）⇒ ⇒ 并把它的**理由**落到「真实串口链路上 host 端 tty 默认 ONLCR」这一条上（事实 F11）。

### 订正 2 · EL 1 是**含光标格**的

初稿的判据把 `ESC[1K` 写成「擦到光标**之前**」⇒ ⇒ **错**：规范口径是**含光标格**⇒ ⇒ 判据 N-4 的期望值订正成 `"    ef"`（四格空白 + `ef`）。

### 订正 3 · CSI C 是**移动光标**不是**插入字符**

初稿以为「光标右移一格再写」会得到 `"abcX"`⇒ ⇒ **错**：光标跨过的那一格**仍是空白**⇒ ⇒ 得到 `"abc X"`⇒ ⇒ 判据 N-5 的期望值订正（真实终端也是这个样子）。

### 订正 4 · DCS / SOS / PM / APC 是**带载荷**的序列

初稿只处理了 `ESC P`（DCS）的**引导字节**⇒ ⇒ **载荷漏到了屏幕上**（实测：`"\x1bP junk \x1b\\ok"` 渲染成 `" junk ok"`）⇒ ⇒ 补上「吞到 ST（`ESC \`）或 BEL」⇒ ⇒ 判据 N-6 的期望值订正成 `"ok"`。

### 订正 5 · 末尾那个 `\n` 是**光标已经换行**了

判据 N-13 的期望值原写成 `"second program"`⇒ ⇒ 实际是 `"second program\n"`（guest 打了 `\n` ⇒ ⇒ 光标到了下一行 ⇒ ⇒ 屏幕是两行、第二行是空的）⇒ ⇒ 期望值订正。

### 订正 6 · 真机判据 B-69 原写成「命令结果出现」⇒ ⇒ **假红**

初稿的 B-69 写的是「console 里出现命令结果（`cyx: No such command.`）」⇒ ⇒ **真机实测红** ⇒ ⇒ 根因不是平台：**用户那份 osz 固件自己注册了一个叫 `cyx` 的命令**（`targets/qemu_virt/src/main.c` 的 `.cmd_name = "cyx"` ⇒ ⇒ 它**不是**「查无此命令」）⇒ ⇒ 而且那个命令的 `argc = 0` ⇒ ⇒ **它一个字都不打**⇒ ⇒ 「命令结果」这条判据**永远不成立**。

⇒ ⇒ 改成真正可观察的那件事：**执行完 ⇒ ⇒ 行缓冲被清空 ⇒ ⇒ 屏幕上回显行的下一行是一个空的新提示符**（`OSZ$`）⇒ ⇒ 这条既不依赖命令名、也不依赖命令的输出。

⇒ ⇒ **通用判据**：**断言「命令的结果」之前，先问「这条命令真的会产生结果吗」** ⇒ ⇒ guest 的命令表**不在平台这边**⇒ ⇒ 平台侧的判据**只能盯可观察的状态变化**（提示符回来了、缓冲空了）⇒ ⇒ 盯「输出长什么样」= 把固件的细节焊进门禁。

### 订正 7 · 「换工程时不重置屏幕」那条变异是**空变**

初稿的 T7 是「把 `app.js` 里那句 `resetTerminalScreen()` 删掉」⇒ ⇒ 实测**红 0 条**⇒ ⇒ 根因：那条护栏**被另一条更前面的护栏掩蔽**了 —— 增量那条路每次都核对「store 里的字节流确实是**追加**的」⇒ ⇒ 换工程后字节流被清空 ⇒ ⇒ 前缀对不上 ⇒ ⇒ **自动从零重建**⇒ ⇒ 屏幕本来就是对的。

⇒ ⇒ **空变 = 验不到任何东西**（打不出红 ⇒ ⇒ 那条变异白写）⇒ ⇒ T7 改成「**重渲染那条路**显示原始字节」（真能打红：任何一次重渲染都会让终端又变回乱码）⇒ ⇒ 而「换工程时不重置屏幕」这条**仍然有护栏**（裁决 D / E）⇒ ⇒ 只是它**不再是一条变异**。

### 订正 8 · 增量那条路需要**一条专属判据**

初稿以为 N-12（增量 vs 从零重建一致）能覆盖「增量路不核对追加」⇒ ⇒ **不能**：那条护栏只在「store 的字节流被**替换**」时才起作用⇒ ⇒ 补 **N-15**（替换 ⇒ ⇒ 屏幕跟着真相走）⇒ ⇒ 这是「**判据存在 ≠ 判据有人管**」的又一个样本。
