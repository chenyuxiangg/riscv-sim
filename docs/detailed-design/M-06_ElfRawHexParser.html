1 功能概述

1.1 模块定位

M-06 ELF/Raw/HEX 解析器（4.1.4）：前端交互层，在浏览器内解析 ELF 段（text/data/bss）与 Raw/HEX 镜像，构建符号表与「地址→源码行」映射（DWARF 行表），供反汇编·源码联动使用（FR-05）；解析结果经命令协议 loadELF 下发内核（M-05 dispatchCommand），写 RAM 由内核侧执行（loadELF 命令处理器内调 M-14 loadImage，06-1 单一写入路径，前端不直调 M-14）。输入设具体上限防畸形输入 OOM（评审 L3/P-12）：ELF 文件 ≤16 MiB、段数 ≤64、符号表 ≤10⁵ 条、DWARF 行表条目 ≤2×10⁵、DWARF 通用递归解析深度 ≤64（行表线性推进不适用，06-3）——均为估算基线，超限明确拒绝并提示，不进入内核。

1.3 MVP 范围与预留

MVP 实现范围：parseELF(binary)（ELF 段 + 符号表 + DWARF 行表解析，输入上限前置校验）、parseRaw(binary, base)（Raw 镜像基址加载）、parseHEX(text)（Intel HEX 解析，含 0x02/0x04 扩展地址记录）、loadToKernel()（经 M-05 loadELF 下发，内核侧写 RAM，输出加载摘要）；64KB ELF ≤3s 性能基线（解析全流程，06-8）。
预留项（P1 演进承接，不属现实现）：DWARF 高级特性扩展（.debug_info DIE 树/表达式求值/变量定位，递归深度防护随其落地启用，06-3）；更多镜像格式（Motorola S-Record 等）；符号/行表增量更新（热更新，配合 M-08/M-09 断点联动）；解析子组件独立打包（WASM 分块加载，配合零安装形态 NFR-05）。

2.1.1 复杂结构字段定义

segmentTable 为 ELF 段解析结果（text/data/bss，含基址/大小/数据）；symbolTable 为符号表（地址→符号名，FR-05）；lineMap 为 DWARF 行表（地址→{源文件, 行号}，FR-05）；parseLimit 定义输入上限（估算基线，评审 L3/P-12），解析前置校验、超限拒绝（E_PROTO-04）。字段定义如下：

// segmentTable: ELF 段解析结果（4.1.4.2 表26；text/data/bss）
struct Segment { uint32_t addr; uint32_t size; byte[] data; };
Map<name, Segment> segmentTable;
// symbolTable: 符号表（FR-05）：Map<addr, name>
// lineMap: DWARF 行表（FR-05）：Map<addr, {file, line}>
struct LineInfo { string file; uint32_t line; };
Map<uint32_t, LineInfo> lineMap;
// parseLimit: 输入上限（估算基线，评审 L3/P-12；超限 → E_PROTO-04 拒绝）
const parseLimit = {
  elfSize:          16 MiB,   // ELF 文件 ≤16 MiB
  segmentCount:     64,       // 段数 ≤64
  symbolCount:      1e5,      // 符号表 ≤10⁵ 条
  lineEntryCount:   2e5,      // DWARF 行表 ≤2×10⁵ 条
  dwarfDepth:       64        // DWARF 通用递归解析深度（.debug_info DIE 树落地时启用；
                              //   行表线性推进非递归，不适用本限制，06-3）
};

3 实现设计

3.1 parseELF(binary) ELF 解析

parseELF(binary)：解析 ELF——段、符号表、DWARF；输入上限前置校验（parseLimit，超限 E_PROTO-04）；畸形输入拒绝（E_PROTO-03）；无 DWARF 降级（lineMap 空，R7）。伪代码如下：

// parseELF: 解析 ELF（4.1.4.3 表27；输入：ELF 二进制；输出：segmentTable/symbolTable/lineMap）
ParseResult parseELF(byte[] binary) {
  if (binary.size > parseLimit.elfSize) return E_PROTO-04;   // 超限拒绝（P-12/L3）
  if (elfMagic(binary) != 0x7F454C46 || !elfHeaderOk(binary))
    return E_PROTO-03;                                       // 畸形 ELF（L3，不进入内核）
  for (seg in elfSections(binary)) {
    if (segmentTable.size >= parseLimit.segmentCount)
      return E_PROTO-04;                                     // 段数超限
    segmentTable[seg.name] = {addr: seg.addr, size: seg.size, data: seg.data};
  }
  symbolTable = buildSymbols(elfSymtab(binary), parseLimit.symbolCount); // FR-05
  if (hasDwarf(binary)) {                                    // DWARF 行表（FR-05）
    lineMap = parseDwarfLineTable(debugLine(binary));        // 行表线性推进，无深度限制（06-3）
    if (lineMap.size > parseLimit.lineEntryCount) return E_PROTO-04; // 行表超限
  } else {
    lineMap = {};                                            // 无 DWARF 降级（R7）
  }
  return {segmentTable, symbolTable, lineMap};               // 输出：三表（加载摘要依据）
}
// 06-3：行表为线性推进（非递归），无深度限制；dwarfDepth 仅适用于 DWARF 通用递归解析
//   （.debug_info DIE 树，P1 预留随其落地启用）

3.2 parseRaw(binary, base) Raw 镜像加载

parseRaw(binary, base)：Raw 镜像按起始地址加载——输出加载段；超限（地址/大小越界）拒绝（E_PROTO-04 语义，输入超限族）。伪代码如下：

// parseRaw: Raw 镜像加载（4.1.4.3 表27；输入：裸二进制 + 基址；输出：加载段）
Segment parseRaw(byte[] binary, uint32_t base) {
  if (binary.size > parseLimit.elfSize) return E_PROTO-04;   // 输入超限（P-12）
  if ((uint64)base + binary.size > 4 GiB) return E_PROTO-04; // 地址越界（超限语义）
  return {name: "raw", addr: base, size: binary.size, data: binary}; // 输出：加载段
}

3.3 parseHEX(text) Intel HEX 解析

parseHEX(text)：Intel HEX 解析——行前缀/长度/校验和校验；记录类型 0x00 数据 / 0x01 EOF / 0x02 扩展段地址（ESA）/ 0x04 扩展线性地址（ELA，06-2）/ 0x03/0x05 起始地址；扩展地址状态机更新高位，参与后续数据行地址计算；段归并策略 = 连续地址合并、重叠以后行覆盖（06-4）；畸形行拒绝（E_PROTO-03）；段数超限拒绝（E_PROTO-04）。伪代码如下：

// parseHEX: Intel HEX 解析（4.1.4.3 表27；输入：HEX 文本；输出：段表）
// 状态机（06-2/06-4）：extHigh 保存扩展地址高位（0x02: seg<<4 / 0x04: lin<<16）
Map<name, Segment> parseHEX(String text) {
  segs = {}; lineNo = 0; extHigh = 0;
  for (line in text.lines()) {
    lineNo++;
    if (!line.startsWith(':')) return E_PROTO-03;      // 畸形行（L3）
    count = byte(line[1..2]);                            // 数据字节数
    if (line.len != 11 + count * 2) return E_PROTO-03;   // 行内长度与 count 一致（06-4）
    if (count > 255)               return E_PROTO-04;    // 行数据超上限（P-12）
    if (hexChecksum(line) != 0)    return E_PROTO-03;    // 校验和错（L3）
    switch (recordType(line)) {
      case 0x00:                                         // 数据记录（06-4 归并）
        addr = extHigh + addrField(line);                // 扩展高位 + 行内地址
        mergeData(segs, addr, data(line),               // 归并策略：连续地址合并成段、
                  rule: OVERLAP_LAST_WINS);              //   重叠以后行覆盖（06-4）
        break;
      case 0x02: extHigh = segAddrField(line) << 4;  break; // 扩展段地址（06-2）
      case 0x04: extHigh = linAddrField(line) << 16; break; // 扩展线性地址（06-2）
      case 0x01: return segs;                           // EOF 记录 → 输出段表
      case 0x03: case 0x05: break;                      // 起始地址记录：合法，不参与段数据
      default:   return E_PROTO-03;                     // 未知记录类型（L3）
    }
    if (segments(segs).size >= parseLimit.segmentCount)
      return E_PROTO-04;                                // 段数超限（P-12）
  }
  return E_PROTO-03;                                    // 无 EOF 截断（畸形）
}

3.4 loadToKernel() 下发内核

loadToKernel()：经命令协议下发镜像与元数据——调用 M-05 dispatchCommand(loadELF)（载荷 = binary/sections/symbols/lines，行171）；写 RAM 由内核侧执行（loadELF 命令处理器内调 M-14 loadImage，06-1 单一写入路径，前端不直调 M-14）；失败透传 M-05 实际错误码（仅超时 E_CTX-06，06-6）；bss 段仅登记不携带 data，内核侧按 size 清零（06-5）；输出加载摘要。伪代码如下：

// loadToKernel: 下发内核（4.1.4.3 表27；调用 M-05 dispatchCommand(loadELF)；输出：加载摘要）
// 单一写入路径（06-1）：载荷经 loadELF 命令下发，内核侧（M-05 → M-14 loadImage）执行写 RAM；
//   前端不直调 M-14（跨层消除、载荷与写路径不重复）
LoadSummary loadToKernel() {
  payload = {binary: segmentTable.data, sections: segmentTable,   // 含 bss 段登记（data 空，06-5）
             symbols: symbolTable, lines: lineMap};               // loadELF 载荷（FR-05）
  result = m05Dispatch("loadELF", payload);                      // M-05 命令协议（下发内核）
  if (result != OK) return result;                               // 透传 M-05 实际错误码（06-6）
  // 写 RAM 由内核侧执行：loadELF 处理器内 m14LoadImage(seg.addr, seg.data, seg.size)；
  //   bss 段（data 空）按 seg.size 清零（对齐 M-14 全 0 初始化语义，06-5）
  return {segments: segmentTable.size, bss: bssSegments.size,    // 摘要分段计数（06-5）
          symbols: symbolTable.size, lines: lineMap.size, result};
}
// 载荷映射：loadELF = binary/sections/dwarf → 加载结果 + 映射摘要（4.1.1 表8，FR-05）
// 错误码（06-6）：非超时失败透传 M-05 实际码；仅超时路径映射 E_CTX-06（幂等可重试语义）

3.6 parseDwarfLineTable DWARF 行表状态机（06-7 展开，FR-05 核心）

parseDwarfLineTable：解析 .debug_line 行号程序——header 解析（unit_length/version/header_length/min_inst_length/max_ops_per_inst/default_is_stmt/line_base/line_range/opcode_base/standard_opcode_lengths）→ 标准/扩展 opcode 分派 → 行/列寄存器推进 → 地址增量 → 构建 address→line 映射。行表为线性推进（非递归），不受 dwarfDepth 限制（06-3）。伪代码如下：

// parseDwarfLineTable: DWARF 行表状态机（4.1.4.2 表26；FR-05；06-7 展开）
// 行号程序线性推进（非递归，06-3 无深度限制）；受行表条目上限约束（≤2×10⁵，P-12）
Map<uint32_t, LineInfo> parseDwarfLineTable(byte[] debugLine) {
  h = parseHeader(debugLine);                // unit_length/version/header_length/
  //  min_inst_length/max_ops_per_inst/default_is_stmt/line_base/line_range/
  //  opcode_base/standard_opcode_lengths
  reg = {addr: 0, op_index: 0, file: 1, line: 1, col: 0, is_stmt: h.default_is_stmt};
  lineMap = {}; rowSeq = 0;
  while (!h.end) {
    op = nextOpcode(h);                       // 取 1 字节 opcode
    if (op >= h.opcode_base) {                // 特殊 opcode（地址/行增量查表）
      adv = (op - h.opcode_base) / h.line_range;
      reg.addr += adv * h.min_inst_length;    // 地址增量推进
      reg.line += h.line_base + (op - h.opcode_base) % h.line_range;
      emitRow(lineMap, reg, rowSeq++);        // 行寄存器推进 + 记录
    } else if (op == 0) {                     // 扩展 opcode
      len = uleb(); sub = uleb();
      switch (sub) {
        case DW_LNE_end_sequence:  reg = {reset}; break;
        case DW_LNE_set_address:   reg.addr = addr64(); break;
        case DW_LNE_define_file:   files.add(fileEntry()); break; // 源文件登记
        default: skip(len);                   // 未知扩展：跳过
      }
    } else {                                  // 标准 opcode（行列/地址增量分派）
      switch (op) {
        case DW_LNS_copy:       emitRow(lineMap, reg, rowSeq++); break;
        case DW_LNS_advance_pc: reg.addr += uleb() * h.min_inst_length; break;
        case DW_LNS_advance_line: reg.line += sleb(); break;
        case DW_LNS_set_file:   reg.file = uleb(); break;
        case DW_LNS_set_column: reg.col = uleb(); break;
        case DW_LNS_negate_stmt: reg.is_stmt = !reg.is_stmt; break;
        case DW_LNS_set_prologue_end: case DW_LNS_set_epilogue_begin: break;
        case DW_LNS_advance_line_by:  break;
        default: skipOperands(op);            // 未知标准 opcode：按长度表跳过
      }
    }
    if (lineMap.size > parseLimit.lineEntryCount) return E_PROTO-04; // 行表超限
  }
  return lineMap;                             // 输出：address → {file, line}（FR-05）
}
// 说明：rowSeq 单调推进；地址重复时后行覆盖（同地址多行取最后记录）；文件经
//   DW_LNE_define_file / header file_names 登记，LineInfo.file 为归一化路径

4 关键函数（源文档表27）

5 处理流程

5.1 镜像加载流程（源 4.1.4.4 对齐）

文件选择 → 大小校验 → 解析段 → 构建符号/行映射 → 下发内核 → 反馈加载摘要；64KB ELF ≤3s（估算基线）。流程图如下：

分支：畸形输入 → E_PROTO-03 拒绝并提示（L3，不进入内核）；超限 → E_PROTO-04 拒绝并提示（P-12）；无 DWARF → lineMap 空、降级仅反汇编 + 符号表（R7，不阻塞 MVP 主线）；下发失败 → 透传 M-05 实际错误码（仅超时 E_CTX-06，06-6），镜像不进入内核。64KB ELF ≤3s 计时口径 = 解析全流程（文件选择后至解析完成），不含 loadToKernel 命令下发往返（06-8）。

5.2 与相邻模块的协作说明

协作模块协作内容触发时机
M-05（命令路由）dispatchCommand(loadELF) 下发镜像与元数据（载荷 = binary/sections/dwarf）loadToKernel 调用时

6 异常处理

6.1 错误码与处置（源表16 既有码，无新增）

M-06 为前端解析模块，畸形/超限输入统一拒绝并提示、不进入内核；错误码全部取自源表16（E_PROTO-03/04 既有），无新增码。处置如下：

错误码 / 场景触发条件处置
E_PROTO-03（畸形输入）畸形 ELF/HEX/DWARF 输入（魔数错/校验和错/记录类型未知/无 EOF）拒绝并提示，不进入内核（L3）
E_PROTO-04（输入超限）超过 parseLimit：>16 MiB / 段数 >64 / 符号 >10⁵ / 行表 >2×10⁵ / 递归深度 >64拒绝并提示，不进入内核（P-12）
无 DWARF 降级（R7）ELF 无 .debug_line 段lineMap 空，降级仅反汇编 + 符号表（不阻塞 MVP 主线）
下发失败（M-05）dispatchCommand(loadELF) 失败/超时透传 M-05 实际错误码；仅超时路径映射 E_CTX-06（06-6）；镜像不进入内核 + 提示
Raw 基址未映射（06-8）parseRaw 基址超出 M-14 已映射区间内核侧 loadImage 校验失败 → 命令失败并提示（前端不预判映射）

6.2 边界与降级

（1）畸形防护（L3）：ELF 魔数/头校验、HEX 行前缀/长度/校验和/记录类型校验（含 0x02/0x04 扩展地址，06-2/06-4）；畸形一律 E_PROTO-03 拒绝。
（2）超限防护（P-12）：大小/段数/符号/行表/通用递归深度五类上限前置校验，超限 E_PROTO-04 拒绝，不进入内核（防 OOM）；HEX 行数据 count ≤255（06-4）。
（3）无 DWARF 降级（R7）：lineMap 为空，仅反汇编 + 符号表可用（PC 高亮 V-12），不阻塞 MVP 主线。
（4）下发失败（06-6）：loadToKernel 透传 M-05 实际错误码（非超时失败保留拒绝码），仅超时路径 E_CTX-06；镜像不进入内核，前端提示重试。
（5）bss 段（06-5）：仅登记不携带 data；内核侧按 size 清零（对齐 M-14 全 0 初始化）；摘要分段计数（text/data/bss 分别列）。
（6）Raw 基址衔接（06-8）：前端不预判映射，经载荷下发由内核侧 M-14 校验，未映射区间 → 命令失败并提示。
（7）性能降级（06-8）：64KB ELF ≤3s（计时 = 解析全流程，不含命令下发往返）；超时提示解析仍在进行/建议压缩镜像，不静默丢弃。

7.2 可维护性手段

（1）解析子组件独立：ELF 段解析 / DWARF 行表解析 / HEX 解析独立实现，单测互不干扰（对齐 WBS 子组件拆分）。
（2）上限集中配置：parseLimit 为结构化常量，调整上限不涉解析逻辑。
（3）错误码收敛：畸形/超限统一 E_PROTO-03/04（源表16 既有），前端提示语义一致。
（4）载荷自描述：loadELF 载荷结构固定（binary/sections/dwarf），替代实现可接入（契约测试）。
（5）CI 门禁：64KB ELF ≤3s + E_PROTO-03/04 正确 + 无 DWARF 降级用例纳入回归基线（表92）。
