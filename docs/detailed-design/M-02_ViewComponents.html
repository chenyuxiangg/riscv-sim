1 功能概述

1.1 模块定位

M-02 视图组件库（4.1.2）：前端交互层视图渲染层，提供产品视图（2D 产品树/原理图）、调试视图（反汇编/断点/寄存器/内存/源码联动）、波形视图（独立路由）、串口终端、外设面板与时钟树视图（FR-07）等视图组件；所有视图为命令驱动重渲染：不直接触碰仿真状态，只经协议客户端与事件流更新（M-03 状态 → 组件渲染）。可用性约束零安装、file:// 直接可开、移动端 375px 可读（NFR-05，M-01/M-02/M-07/M-13）。

1.3 MVP 范围与预留

MVP 实现范围：productTreeView（产品树/原理图 + 映射表 UI 编辑）、debugView（反汇编区、寄存器/内存面板、断点列表、源码联动）、waveformView（缩放/平移、通道选择、CSV/VCD 导出）、terminalView（串口回显，统一转义）四视图组件；render(storeState)/onCommand(ev)/onDelta(delta) 三函数闭环（命令驱动 + 事件驱动双通道，≤200ms 节流）。
预留项（P1 演进承接，不属现实现）：外设面板与时钟树视图（FR-07 全量）；视图自定义布局/多面板拖拽；波形更多导出格式（VCD 已含）；源码联动增量定位（配合 M-11 行表热更新）。

2.1.1 复杂结构字段定义

四视图组件均以 ViewComponent 结构注册进 M-01 viewRegistry（hash → View.component，M-01 01-6 锚点落地）；render 输入 storeState（S1/W1/T1/E1 合并结果）；onDelta 输入 simStateDelta/waveformDelta 增量。字段定义如下：

// ViewComponent: 视图组件注册结构（注册进 M-01 viewRegistry；M-01 01-6/01-8 双侧核对闭合）
struct ViewComponent {
  string viewId;            // 视图 id（product/debug/waveform/terminal）
  Set<Channel> channels;    // 所需通道子集（S1/W1/T1/E1；M-03 按子集过滤后传 storeState，02-5）
  RenderFn render;          // render(storeState) → DOM 更新（表21）
  CommandFn onCommand;      // 用户操作 → M-05 dispatchCommand → 请求 id（表21）
  DeltaFn onDelta;          // simDelta/waveDelta/termDelta → 局部刷新 ≤200ms（表21）
};
// storeState: View Store 合并结果（M-03 S1/W1/T1/E1 订阅合并，按 ViewComponent.channels 子集过滤后传入，02-5；
//   结构双侧对齐 M-03 v1.1 输出契约，03-9：含 timeVirt/version 顶层字段）
struct StoreState {
  uint64_t timeVirt;            // 虚拟时间（M-03 输出契约 03-9；M-12 权威源）
  uint32_t version;             // 状态版本（M-03 输出契约 03-9；虚拟时间戳单调）
  SimState sim;             // S1 仿真状态（寄存器/内存/PC/断点）
  WaveformState wave;       // W1 波形数据（通道/时间轴）
  TerminalState term;       // T1 串口回显缓冲
  EventState events;        // E1 事件（breakpointHit/trap/paused）
};
// Delta: 增量载荷（onDelta 输入；M-03 v1.1 变更通知 NotifiedDelta{viewIds,delta,flushSeqNo} 中 delta 透传，03-10）
struct Delta {
  SimStateDelta simDelta;   // 仿真状态增量（M-03/M-10）
  WaveformDelta waveDelta;  // 波形增量（M-19）
  TermDelta termDelta;      // 串口增量：追加字节 + 游标（02-8，T1 专用追加通道，不触发全量 render）
};

2.3 数据流说明

事件驱动流：订阅事件流（M-03，S1/W1/T1/E1）→ 状态合并（storeState）→ 局部重渲染（render，≤200ms 节流）；命令驱动流：用户操作 → onCommand → M-05 dispatchCommand → Resp 回写状态 → 待 M-03 同步后重渲染。

3 实现设计

3.1 render(storeState) 按 View Store 状态渲染

render(storeState)：按 M-03 合并快照渲染本组件（纯函数：同 storeState → 同 DOM）；渲染异常视图级隔离（viewError + M-21 日志，4.1.2.5）；M-01 RenderEvent{viewId,state,type} 驱动（mount/update 调 render，unmount 卸载，M-01 01-8）。伪代码如下：

// render: 按 View Store 状态渲染本组件（4.1.2.3 表21；输入：storeState（S1/W1/T1/E1 合并结果）；输出：DOM 更新）
void render(StoreState storeState) {
  try {
    discardPendingDelta();                        // 丢弃 onDelta 未 flush 的合并缓冲（storeState 快照为权威，02-1）
    viewModel = buildViewModel(storeState);      // 纯函数：storeState → 视图模型（确定性）
    viewport.replaceChildren(renderDom(viewModel)); // DOM 更新（全量重建；UI 交互态本地保留，02-1）
  } catch (e) {
    viewError(e);                                // 渲染异常 → 视图级错误提示（4.1.2.5，不中断其他视图/仿真）
    m21Log(WARN, "VIEW", viewId, "render_err", e);
  }
}
// 渲染事件（M-01 01-8）：RenderEvent{viewId, state, type} → type=mount/update 调 render(state)，
//   type=unmount 卸载组件并释放订阅（M-03 退订）
// UI 交互态（波形缩放/终端滚动/面板折叠）为组件本地态，全量重建时保留（02-1，不随 storeState 重建丢失）

3.2 onCommand(ev) 命令下发

onCommand(ev)：用户操作转为命令下发（单步/读写寄存器/内存/断点/导出等）；调用 M-05 dispatchCommand，输出请求 id 待响应；Resp 到达回写本地乐观状态，待 M-03 状态同步后重渲染（命令驱动闭环）。伪代码如下：

// onCommand: 用户操作转为命令下发（4.1.2.3 表21；调用 M-05 dispatchCommand；输出：请求 id 待响应）
RequestId onCommand(UserEvent ev) {
  cmd = mapCommand(ev);                          // 用户操作 → 命令（单步/读写寄存器/读写内存/设断点/导出等）
  reqId = m05DispatchCommand(cmd);               // M-05 dispatchCommand（≤500ms；读类/幂等可重试，E_CTX-06）
  pending[reqId] = {viewId, at: now, optimistic: isReadOnly(cmd)}; // 待响应配对（仅读类乐观回写，02-2）
  if (pending.size > PENDING_CAP) {              // 待响应表上限（02-4）
    dropOldestPending();                         // 丢最旧待重试条目 + WARN 日志（02-4）
  }
  return reqId;                                  // 输出：请求 id
}
// 命令驱动闭环（02-2）：Resp 到达 → 读类应用乐观状态（写类不乐观回写）→ 待 M-03 状态同步后 render（4.1.2.4）
// 失败回滚：Resp 错误 / pending 超时 → rollbackOptimistic(reqId) 回滚乐观状态 + 视图级提示（E_CTX-06）
// pending 清理（02-4）：Resp 到达 delete(pending[reqId])；超时处置后 delete；PENDING_CAP=64

3.3 onDelta(delta) 增量局部刷新

onDelta(delta)：增量状态应用到视图——simStateDelta 更新寄存器/内存/断点面板、waveformDelta 更新波形；节流合并 ≤200ms 一次局部刷新（估算基线，波形与寄存器/内存刷新均适用，4.1.2.4）。伪代码如下：

// onDelta: 增量状态应用到视图（4.1.2.3 表21；输入：simStateDelta/waveformDelta/termDelta；输出：局部刷新 ≤200ms）
void onDelta(Delta delta) {
  if (delta.termDelta != null) {                 // T1 串口增量走专用追加通道（02-8）
    appendTerm(delta.termDelta);                 // 追加字节 + 游标，不触发全量 render（滚动跟随）
    return;
  }
  applyLocal(delta);                             // 增量应用到本地状态（不触碰仿真状态）
  scheduleRefresh(200ms);                        // 节流合并（4.1.2.4）
}
// 节流策略（02-3）：leading-edge 首增量立即刷 + 窗口内增量合并 + trailing-edge 窗口末补刷（≤200ms 基线）；
//   过期判定 = 增量时间戳早于最近一次 flush → 丢弃（对应 6.1 "增量合并溢出"）

分支：命令超时/Resp 错误（≤500ms）→ 视图级提示 + 乐观状态回滚（02-2），读类/幂等可重试（E_CTX-06）；pending 超上限（64）→ 丢最旧待重试 + WARN（02-4）；渲染异常 → 单视图隔离 + M-21 日志（4.1.2.5）；断线重连 → M-03 reconcile 后全量重渲染；高频事件 → ≤200ms 节流合并局部刷新（02-3）。

6 异常处理

6.1 错误码与处置（源表16 既有码，无新增）

M-02 为渲染层，异常统一视图级隔离不冒泡；错误码全部取自源表16（E_CTX-06 既有），无新增码。处置如下：

错误码 / 场景触发条件处置
渲染异常（隔离）render 内部异常（数据畸形/组件缺陷）视图级错误提示 + M-21 日志；不中断其他视图与仿真（4.1.2.5）
命令超时（E_CTX-06）onCommand 后 pending 超时（>500ms）视图级提示；读类/幂等命令可重试（E_CTX-06 语义）
乐观回滚（02-2）Resp 错误 / pending 超时且已应用乐观状态回滚乐观状态 + 视图级提示；写类命令不乐观回写
pending 溢出（02-4）待响应表超上限（PENDING_CAP=64）丢最旧待重试条目 + WARN 日志；拒绝新命令
串口畸形字节T1 流含畸形/非法字节统一转义 + 替换符 U+FFFD 处理（XSS 防护，4.1.2.5）
事件流断连M-03 订阅中断/缺口断线重连 reconcile（M-07 续拉对账）后全量重渲染
增量合并溢出高频 onDelta 合并窗口内超阈值丢弃过期增量、按最新快照渲染（≤200ms 节流语义）

6.2 边界与降级

（1）渲染异常隔离：只影响单视图（视图级错误提示），不中断其他视图与仿真（4.1.2.5）。
（2）串口 XSS 防护：输出统一转义后进 DOM；畸形字节按替换符 U+FFFD 处理（4.1.2.5）；T1 增量走 termDelta 专用追加通道（02-8）。
（3）命令超时：≤500ms 视图级提示；读类/幂等命令可重试（E_CTX-06），写类不自动重试。
（4）事件流节流：波形/寄存器/内存刷新均 ≤200ms 合并（估算基线，4.1.2.4）；节流策略 leading-edge 立即刷 + 窗口内合并 + trailing-edge 补刷（02-3）；过期增量丢弃（判定=时间戳早于最近 flush）。
（5）断线重连：M-03 reconcile（M-07 续拉对账）后全量重渲染，视图状态经 View Store 恢复（V-11）。
（6）移动端：375px 可读（NFR-05），视图单列、表格横向滚动、导出入口折叠；file:// 直接可开。
（7）无数据降级：storeState 对应子集为空（如未加载镜像时反汇编区）→ 视图显示占位态，不报错。
（8）状态权威（02-1）：storeState 快照为权威，onDelta 仅高频中间层；render 全量重建前清空合并缓冲（discardPendingDelta）；波形缩放/终端滚动等 UI 交互态属组件本地态，重建保留。
（9）乐观回滚（02-2）：读类命令 Resp 错误/超时 → rollbackOptimistic 回滚乐观状态 + 视图级提示；写类命令不乐观回写（以 M-03 权威状态为准）。
（10）pending 生命周期（02-4）：Resp 到达 delete；超时处置后 delete；PENDING_CAP=64，溢出丢最旧待重试 + WARN 日志。
（11）通道子集过滤（02-5）：ViewComponent.channels 声明所需通道子集，M-03 按子集过滤后传 storeState（terminalView 不接收 sim 状态）。
（12）导出衔接（02-7）：波形 CSV/VCD 导出经 M-05 命令 → M-19 exportCSV/exportVCD → ExportHandle{handle,chunk,nextOffset,progress} 分块续拉 + 进度展示；导出失败 → 视图级提示 + M-21 日志。

7.2 可维护性手段

（1）视图组件独立注册：四视图以 ViewComponent 注册进 viewRegistry（M-01），新增视图不改渲染框架。
（2）命令/渲染解耦：onCommand 只发命令不直触状态；状态一律经 M-03 storeState 回流（命令驱动闭环）。
（3）渲染纯函数：render(buildViewModel(storeState)) 确定性（同 storeState → 同 DOM），可快照单测。
（4）转义统一入口：escapeHtml + sanitizeBytes 集中实现，串口/用户文本一律走统一入口。
（5）CI 门禁：契约测试 + 节流合并 + XSS 转义 + 渲染隔离用例纳入回归基线（表92）。
