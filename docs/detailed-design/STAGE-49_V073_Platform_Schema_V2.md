## §2 口径（**逐字冻结**）

### §2.1 四项各自的形状

| 项 | 形状 | 破坏性 |
| --- | --- | --- |
| **B2** | `base` 由 `u32` 改成 **`Option<u32>`** ⇒ ⇒ **缺省 = 由内核在装配期分配** ⇒ ⇒ 老描述**带** base ⇒ ⇒ **仍按老办法** ⇒ ⇒ **缺省优先** | ⚠️ **是**（描述格式变了 ⇒ ⇒ `PLATFORM_SCHEMA_VERSION` 1 → 2） |
| **G** | `DeviceSpec` 加 `TimerRiscv { id, irq_line }` ⇒ ⇒ **纯加法** ⇒ ⇒ 老描述**不受影响** | 否 |
| **D1** | 描述加**可选**的 `pins` 段（**加法** ⇒ ⇒ 缺省 = 无引脚 ⇒ ⇒ 老描述**不受影响**） | 否（但它**改**描述格式 ⇒ ⇒ 计入那**一次**升版） |
| **D-177 C** | 描述加**可选**的 `roles` 段（`console` / `time_source` / `main_plic` 三个**器件 id**）⇒ ⇒ **加法** ⇒ ⇒ **缺省 = 今天的「第一个 X」** ⇒ ⇒ **缺省行为逐字不变** | 否（同上） |

⇒ ⇒ **一次升版封顶三件破坏性改动**那条纪律仍然成立 ⇒ ⇒ 真正**改形状**的只有 **B2**（`base` 可缺省）⇒ ⇒ 另外三件都是**加法** ⇒ ⇒ ⇒ **一次迁移**（板档案的 `rules_version` 3 → 4）。

### §2.2 缺省优先（**迁移规则**）

| 情形 | 结果 |
| --- | --- |
| 老描述**带** `base` | ⇒ ⇒ **逐字按老办法**装（**一个字节都不变**）⇒ ⇒ **老板仍能装** |
| 老描述**不带** `base`（新格式） | ⇒ ⇒ 内核在**装配期**分配 ⇒ ⇒ 分配结果**确定**（按**声明顺序**）⇒ ⇒ 同一份描述**两次装**得到**同一个图** |
| 板档案的 `rules_version` = **3**（老） | ⇒ ⇒ **仍能装**（缺省优先）⇒ ⇒ 前端**如实提示**「这块板是按旧规则存的」⇒ ⇒ 用户可以**手动**升级（升级 = 去掉 `base` 让内核分配）⇒ ⇒ **不是**自动迁 |

⇒ ⇒ ⚠️ **不许**「自动把老板迁成新格式」⇒ ⇒ 理由：自动迁会**改掉**用户**明确写过**的基址 ⇒ ⇒ ⇒ 「用户自己决定落在哪」（B1 定案）**被推翻** ⇒ ⇒ ⇒ ⇒ **迁移必须由用户触发**（同 STAGE-16 / v0.33 的先例：「显式提示 → 内核裁决 → 再升级」）。

### §2.3 装配期分配（**内核那一侧**的规则）

- 分配顺序 = **描述里的声明顺序**（不是 base 升序 ⇒ ⇒ 因为还没有 base）；
- 每段按**声明顺序**从当前游标往上找**第一个装得下的**空隙 ⇒ ⇒ 跳过被别的段占掉的区间；
- 分配结果**确定**（同样输入 ⇒ ⇒ 同样输出）⇒ ⇒ ⇒ **可复算**；
- ⚠️ **一条都分配不下 ⇒ ⇒ 报既有码**（`E_PLT-07` 超预算 / `E_PLT-06` 重叠）⇒ ⇒ **不新增场景码**。
