# STAGE-40 · v0.55 · 串口 RX 中断堵死修复批（D-158）

> **状态**：规格**冻结**（实现与判据照此施工）。
> **版本**：v0.55 · 契约层**零升版**（`SCHEMA_VERSION` 仍 **8** · `SIM_STATE_SCHEMA_VERSION` 仍 **2** · `PLATFORM_SCHEMA_VERSION` 仍 **1** · `PLATFORM_RULES_VERSION` 仍 **3**）⇒ ⇒ **零新 DTO / 零新命令 / 零新事件**。
> **主题**：让平台的**中断挂起**回到**电平语义** —— 源的状态消失了，平台就撤线 ⇒ ⇒ **标准固件（不认识平台私有 CSR）也能解开中断** ⇒ ⇒ 平台内部那把「**正在服务**」的锁在 `mret` 时释放 ⇒ ⇒ **标准固件能连着收下一整行**。
> **台账**：销账 **D-158**；新登记 **D-160**（只登记、不修，见 §4 已知边界 7）。

---

## §0 本批的边界

| 维度 | 本批 | 理由 |
| --- | --- | --- |
| 契约层 | **零变更** | 修的是**平台内部**的中断语义 ⇒ 不需要新的 DTO / 命令 / 事件 |
| M-13（ISS） | **一处出参**（`returned_from_trap`） | M-13 **不知道** M-16 的存在 ⇒ ⇒ 「服务结束了」这件事只能由 M-13 报出来（见裁决 B4） |
| M-15（外设） | **零改动** | Spike 源码坐实：**平台的 PLIC 寄存器布局就是标准布局**（事实 F2）⇒ 不需要改寄存器图（语义上的两处分歧只登记，见 §4 已知边界 7） |
| M-16（中断控制器） | **两处语义 + 一个新方法** | 定时器条件由真变假 ⇒ 撤线（裁决 B1）；「服务中」标记在 `mret` 时释放（裁决 B4） |
| 内核宿主 | **一处接线**（`sync_interrupts`） | 第 ② 步跟**设备电平**、第 ③ 步跟**有无源**（裁决 B2 / B3） |
| 前端 | **一处行为**（终端行结束符） | osz 这类固件的 shell **只认 CR** ⇒ 不补行结束符 ⇒ 命令永远不执行 |

⛔ **本批不做**：嵌套中断（A′）、PLIC 寄存器布局改造、契约升版、**替 guest 清架构挂起位**（裁决 C）、多行终端输入。

## §1 为什么要做这一批

### §1.1 用户看到的现象

用户往串口 RX 输入字符后，**guest 没有反应**：命令不回显、命令不执行、`help` 跑了 1100 万+ 条指令零输出。

### §1.2 实测事实（每条都对着**当前树**或**上游源码**量过）

> ⚠️ 事实 F1 ~ F11 是**反汇编 / 上游源码**级别的证据；事实 F12 ~ F18 是**当前树**的代码坐标；事实 F19 ~ F20 是**端到端实测**。
> ⚠️ **反汇编工具是仓外的一次性脚本**（不进仓）⇒ ⇒ 本批**不**把「反汇编器」当成产品能力；它的作用是**一次性坐实事实**。

| 编号 | 事实 |
| --- | --- |
| F1 | osz 的 `interrupt_handler`（`0x8000754e`）反汇编：读 Claim 的地址是 `0x0C20_0004` ⇒ ⇒ **Claim 在 `+4`** ⇒ ⇒ 平台的 Claim 偏移**就是标准偏移** |
| F2 | Spike 上游 `riscv/plic.cc` 的常量：`CONTEXT_BASE 0x200000` · `CONTEXT_PER_HART 0x1000` · `CONTEXT_THRESHOLD 0` · `CONTEXT_CLAIM 4` ⇒ ⇒ **与平台的布局逐字一致** |
| F3 | Spike 的 `context_claim`（**读** Claim）**置 `claimed` 位**、**不清 `pending`**；`context_write`（**写** Claim）**清 `claimed` 位**、**同样不清 `pending`** ⇒ ⇒ 「写 Claim = complete」在参考侧**不是**「清挂起位」 |
| F4 | Spike 的 `set_interrupt_level(id, 0)`（设备把中断线**放下来**）⇒ ⇒ **同时清 `pending` 与 `claimed`** ⇒ ⇒ **源的挂起位跟设备中断线的电平走**（注释原文：「PLIC interrupts are level-triggered」） |
| F5 | Spike 的 `context_best_pending` **跳过 `claimed` 的源** ⇒ ⇒ `claimed` 位 = 「**这个源正在被服务**」的记忆 ⇒ ⇒ 参考侧**也有**一把「正在服务」的锁，只是它是**按源**的 |
| F6 | Spike 的 `context_update` 把 `mip.MEIP` 写成「**有没有可交付的源**」⇒ ⇒ 参考侧的 `mip` 是「**可交付性**」的投影，而平台的是「**挂起线**」的投影 ⇒ ⇒ **口径不同**（见裁决 U） |
| F7 | osz 用到的 CSR 里**没有** `0x7C0` ⇒ ⇒ 平台那个**私有 CSR** 标准固件**永远走不到** ⇒ ⇒ 它不能是唯一的解除路径 |
| F8 | osz 确实重编程了定时器（写 CLINT 的 `mtimecmp`）⇒ ⇒ guest 的「解除」动作是**标准动作** |
| F9 | osz 的 `inner_shell_char_is_special`（`0x800036fa`）逐条比对 `127 / 9 / 13 / 27 / 91` ⇒ ⇒ **只认 CR（13）判行结束** |
| F10 | osz 的 `drv_uart_int_default_handle` 反汇编：**每次中断只读一个字节**（读 LSR `0x10000005` → 判 bit0 → 读 RHR `0x10000000`）⇒ ⇒ **一行 N 个字节需要 N 次交付** |
| F11 | osz 读 Claim 之后**写回 `claim − 16`**（legacy PLIC 约定），而它索引 `g_int_infos` 用 `claim + 16` ⇒ ⇒ **那个写值不是合法的源号** ⇒ ⇒ 参考侧与平台**都忽略它** ⇒ ⇒ **guest 的 complete 写不生效** |
| F12 | `M-16::set_timer_compare` 原来**只写 `mtimecmp_ps`** ⇒ ⇒ **不清挂起项、不撤线** |
| F13 | `M-16::clear` 是 `active_irq` 的**唯一**复位入口 ⇒ ⇒ 挂起项只能靠 `clear` 移除 |
| F14 | `M-16::poll` 的单级护栏：`active_irq != NO_ACTIVE_IRQ ⇒ return Ok(None)` ⇒ ⇒ **一次没释放 ⇒ ⇒ 之后所有中断都交付不了** |
| F15 | 宿主 `sync_interrupts()` 的第 ③ 步**只有 `Some` 才 `request`** ⇒ ⇒ **`None` 分支空着** ⇒ ⇒ **外部线没有回撤路径** |
| F16 | 宿主 `sync_interrupts()` 的第 ② 步**只 `request` 从不撤销** ⇒ ⇒ PLIC 的源挂起位被**锁存** ⇒ ⇒ **与事实 F4 分歧**（参考侧是**电平**） |
| F17 | 时间口径（`crates/kernel/src/m12_engine/mod.rs`）：`TIME_QUANTUM_PS = 1_000_000`（1 µs）· `QUANTUM_INSTR_QUOTA = 1_000` · `INSTRUCTION_COST_PS = 1_000`（1 ns/条）· `DEFAULT_INSTRUCTION_BUDGET = 10_000` ⇒ ⇒ **一个批次 = 10 000 条 = 10 个量子** |
| F18 | `sync_interrupts()` 的调用点是**每一批的头尾** ⇒ ⇒ **同步粒度 = 一个指令预算窗口** |
| F19 | **端到端实测**（真 osz ELF，`/tmp/osz-artifacts/osz.elf`）：**修前**送 `"Q\r"` ⇒ console **零新增字节**、`LSR` 恒 `0x63`（RX_VALID 一直置位 ⇒ guest **一次也没读过**）、`mcause` 停在 `0x80000007`；**修后**送 `"Q\r"` ⇒ console 拿到 `"\x1b[2K\rOSZ$ Q\nQ: No such command.\n\x1b[2K\rOSZ$ "` ⇒ ⇒ **回显 + 执行整行 + 打印结果 + 再出提示符** |
| F20 | 前端的「原文 + 行结束符」是**一次**把整行（含 CR）送进去 ⇒ ⇒ 两个字节**同时**在 FIFO 里 ⇒ ⇒ **平台必须能连着交付两次**（事实 F10 ⇒ ⇒ guest 一次只读一个字节） |

### §1.3 根因（**四处平台缺陷**，实测出来的，不是猜的）

⚠️ **台账 D-158 的原文只指出了其中一处**（M-16 的挂起队列只加不减 ⇒ ⇒ 解除压给了 guest 写私有 CSR `0x7C0`）⇒ ⇒ 那个方向**正确但不完整** ⇒ ⇒ 施工期的真机实测把另外**三处**也坐实了 ⇒ ⇒ **本批的修法是四处，不是一处**（见 §8 订正 1）。

| 编号 | 缺陷 | 后果 |
| --- | --- | --- |
| **①** | M-16 的定时器线**只加不减**（事实 F12 / F13） | guest 用**标准手法**写 `mtimecmp`（事实 F8）⇒ ⇒ 平台**不撤线** ⇒ ⇒ `active_irq` 永不复位 |
| **②** | 宿主第 ③ 步的 `None` 分支**空着**（事实 F15） | PLIC 侧没有可交付的源了 ⇒ ⇒ 外部线**仍然**挂着 ⇒ ⇒ 外部线**永远**撤不掉 |
| **③** | 宿主第 ② 步**只 `request` 从不撤销**（事实 F16） | PLIC 的源挂起位被**锁存** ⇒ ⇒ 与参考侧的电平语义**分歧**（事实 F4）⇒ ⇒ 同一个源**再也**不被当成「已经说完了」 |
| **④** | 平台**没有** Spike 的 `claimed` 位（事实 F5） | guest 认领之后，平台**分不清**「正在服务」与「还有话说」⇒ ⇒ 那把「正在服务」的锁（`active_irq`）**永不释放** ⇒ ⇒ 单级护栏（事实 F14）把之后所有中断**永久**堵死 |

⇒ ⇒ 完整因果链（真机口径，事实 F19）：

1. UART 字节进 FIFO ⇒ ⇒ 宿主第 ② 步 `request(源 10)` ⇒ ⇒ 第 ③ 步 `claim()` 返回 `Some` ⇒ ⇒ 外部线被抬起。
2. 交付 ⇒ ⇒ **`active_irq = 1`** ⇒ ⇒ guest 陷入（`mcause = 0x8000_000B`）。
3. guest 的 ISR 读 RHR ⇒ ⇒ FIFO 排空 ⇒ ⇒ **设备线落下** ⇒ ⇒ 但第 ② 步**从不撤销**（缺陷 ③）⇒ ⇒ 源**永久**挂起 ⇒ ⇒ `claim()` **永远**返回 `Some` ⇒ ⇒ 第 ③ 步的 `None` 分支**永远走不到**（缺陷 ②）。
4. guest 的 `mret` ⇒ ⇒ 但平台**没有** `claimed` 位 ⇒ ⇒ `active_irq` **不复位**（缺陷 ④）⇒ ⇒ 单级护栏（事实 F14）⇒ ⇒ **之后所有中断都交付不了**。
5. ⇒ ⇒ 第二个字节进 FIFO ⇒ ⇒ 外部线的请求被**同线去重**折叠掉 ⇒ ⇒ guest **永远收不到第二个字节** ⇒ ⇒ **用户看到的「没反应」**。

⚠️ **影响面比「串口」大**：卡住的是**平台内部那把锁** ⇒ ⇒ 平台上任何需要**第二次**中断的 guest 都会**永久**失去响应。

## §2 裁决

| 编号 | 裁决 |
| --- | --- |
| A | **根因 = 四处平台缺陷**（§1.3）⇒ ⇒ 修法也必须是四处 ⇒ ⇒ **只修一处**等于把「堵死」从「永久」变成「下一次」 |
| B | **修法落点 = 四处，契约层零变更、M-15 零改动**：**B1** M-16 `set_timer_compare` 在「条件由真变假」时内部 `clear(IRQ_TIMER_COMPARE)`；**B2** 宿主第 ③ 步的 `None` 分支 ⇒ `clear(IRQ_UART_RX_READY)`；**B3** 宿主第 ② 步 ⇒ `rx_ready` 为假时 `p.set_pending(源, false)`；**B4** `mret` / `sret` ⇒ 释放 M-16 的「**服务中**」标记 `active_irq` |
| C | **`mret` 不清 `mip` 的挂起位**（用户明确纠正）：trap 返回**只做**三件事 —— 恢复 PC、恢复特权模式、恢复中断使能 ⇒ ⇒ **架构挂起位的清除是软件在 ISR 里写外设 / PLIC / CLINT 的动作** ⇒ ⇒ 本批**不做**任何「替 guest 清架构挂起位」的事 ⇒ ⇒ 「按标准来」= **平台的内部挂起必须跟着源的状态走** |
| D | 私有 CSR `0x7C0` 降级为「**可选的加速路径**」：它**仍然有效**（guest 写它 ⇒ 立刻清线），但**不再是唯一路径** ⇒ ⇒ M-16 LLD §3.5 的差异表里那句「标准固件不能依赖它」从**缺陷**改写成**可选** ⇒ ⇒ **LLD 必须同步改** |
| E | **标准行为被如实复现，不替 guest 掩盖**：guest 不解除源 ⇒ 平台继续请求 ⇒ guest 立刻再次陷入 ⇒ ⇒ 那是 **guest 的 bug**，平台**不掩盖** ⇒ ⇒ 与台账 D-82 已记的「定时器反复陷入是平台的正常行为」一致 |
| F | M-15 PLIC **寄存器布局**零改动（事实 F1 / F2）⇒ ⇒ **不引入破坏性变更**（`kernel_host/tests_wiring_v034.rs` 等既有测试**一个字都不用改**）⇒ ⇒ **语义**上的两处分歧**只登记、不修**（§4 已知边界 7 ⇒ ⇒ 台账 **D-160**） |
| G | 前端行结束符 = **用户可选，默认 CR（0x0D）**：真实串口终端按回车发的是 **CR**；osz 这类固件的 shell **只认 CR**（事实 F9）⇒ ⇒ 默认 **CR** ⇒ ⇒ 同时提供 **LF / CRLF / 不追加** 三档 ⇒ ⇒ **「不追加」保留 v0.5x 批之前的行为** |
| H | 行结束符的实现用**按钮组**，不用 `<select>`：⚠️ `front/tests/dom-stub.mjs` 的 `<select>.value` 读的是**元素自己的 `value` 属性**（不是选中项）⇒ ⇒ `<select>` 的「非默认项」在 Node 门禁里**测不到** ⇒ ⇒ 按钮组（`data-eol` 取 `cr` / `lf` / `crlf` / `none`）在两层都可测 |
| I | 行结束符的选择住在**视图状态**（`term.eol`）：与草稿同处 ⇒ ⇒ 重渲染不丢 ⇒ ⇒ **一个真相**（不在 DOM 里另存一份） |
| J | **RX 计数**含**追加的行结束符**：RX 的口径是「**前端发出**的字节数」⇒ ⇒ 追加的 CR **确实发出去了** ⇒ ⇒ 计入 |
| K | **释放发生在宿主同步点**，不是「立刻」：事实 F17 / F18 ⇒ ⇒ **一个指令预算窗口（10 µs 虚拟时间）**内释放 ⇒ ⇒ 登记为已知边界 |
| L | **单级嵌套语义不动**：LLD 明写「嵌套中断 P1；MVP 单级」⇒ ⇒ 不做 A′（允许嵌套）⇒ ⇒ **超出 MVP 取舍** |
| M | **契约层零升版**：四个版本常量全不动 ⇒ ⇒ **不制造 D-143 的存量问题** ⇒ ⇒ 前端镜像**不用改版本号** |
| N | `set_timer_compare` 的撤线判据 = 「**条件由真变假**」：旧值成立（`旧值 != 0 ∧ mtime_ps >= 旧值`）**且**新值不成立（`新值 == 0 ∨ mtime_ps < 新值`）⇒ ⇒ 才撤线 ⇒ ⇒ 「guest 重编程但还没到期」与「guest 根本没武装过」都**不**误撤 |
| O | 「**服务中**」标记的**释放点 = `mret` / `sret`**：它是「服务结束」的**准确**时刻（架构规范：`mret` = trap 返回）⇒ ⇒ 不会提前释放 ⇒ ⇒ 嵌套仍被架构的 `mstatus.MIE`（陷阱入口清零）挡住 ⇒ ⇒ **不**做 A′ |
| P | 「**服务中**」标记**只**复位 `active_irq`：**不碰**挂起队列、**不碰**线电平、**不碰**架构 `mip` ⇒ ⇒ 「释放 ≠ 清 pending」⇒ ⇒ 这是与裁决 C **配套**的那半 |
| Q | 判据的固件必须**覆盖三类 guest 行为**：**解除源**（读 Claim + 写 complete + 排空 FIFO）· **不解除源**（只数 + `mret`）· **只排空不 complete**（读 RHR 但不碰 Claim）⇒ ⇒ 自写固件**太礼貌**（会写 complete）⇒ ⇒ **掩盖**「平台没有 `claimed` 位」这件事 ⇒ ⇒ 测不到真缺陷 |
| R | **真机层不可省**：自写固件测不到「**真固件的 complete 写值是非法源号**」（事实 F11）⇒ ⇒ 那一支**只**真机能暴露 ⇒ ⇒ 真机层用**真 osz ELF** |
| S | **验收编号空间**：**A** = Rust 门禁（**每批范围**）· **N** = 前端 Node 门禁（**每批范围**）· **B** = 真机门禁（**跨批次唯一** ⇒ ⇒ 本批接 STAGE-39 的 B-60 ⇒ ⇒ **B-61 ~ B-66**）· **X** = 交叉 ⇒ ⇒ ⚠️ **前端那一组用 `N` 而不是 `B`** —— 因为 `B` 是**真机输出**的编号空间（同一个输出里 ID 必须全局唯一）⇒ ⇒ 复用 `B-1 ~ B-8` 会与 STAGE-32 的 `B-1 ~ B-5` **撞名** |
| T | 平台**没有** Spike 的 `claimed` 位（事实 F5）⇒ ⇒ 「服务中」只能在**平台级**记**一个** ⇒ ⇒ 这就是单级语义 ⇒ ⇒ 也是裁决 O 的成因 |
| U | 平台 `mip` 的投影口径（**挂起线**）与参考侧（**有可交付源**，事实 F6）**不同** ⇒ ⇒ 这是**明示取舍**（跟随用户纠正的那条架构语义）⇒ ⇒ 本批**不**改投影口径 |
| V | 本批**零新场景码 / 零新 DTO / 零新命令 / 零新事件** ⇒ ⇒ 契约层四个版本号全不动 ⇒ ⇒ **不制造 D-143 的存量问题** |

⇒ ⇒ ⚠️ **B2 的判据就是 PLIC 自己的「当前应该交付哪个源」**（`Plic::best_source`：已挂起 ∧ 已使能 ∧ 优先级严格大于门限）⇒ ⇒ **源被 guest 解除 / 被门限挡住 / 被禁用** 三种情况都会让 `claim()` 返回 `None` ⇒ ⇒ **撤线是对的** ⇒ ⇒ **一条判据管三件事**。

⇒ ⇒ ⚠️ **B3 的依据是事实 F4** —— 参考侧 `set_interrupt_level(id, 0)` **同时清 `pending` 与 `claimed`** ⇒ ⇒ **源挂起位必须跟设备电平走** ⇒ ⇒ 这**不是**「平台自己发明的一套语义」⇒ ⇒ 而是把平台**对齐**参考侧。

⇒ ⇒ ⚠️ **B4 为什么必须存在** —— 事实 F11：真固件的 complete 写值**是非法源号** ⇒ ⇒ 参考侧与平台**都忽略**它 ⇒ ⇒ 参考侧靠**设备线落下**清 `claimed`（事实 F4）⇒ ⇒ 而平台那把锁是**平台级**的（裁决 T）⇒ ⇒ **设备线落下时平台的 `active_irq` 不会被清**（它只被 `clear(line)` 清，而那一支在缺陷 ② 修好之前根本走不到）⇒ ⇒ ⇒ **只能在「服务结束」这个准确时刻释放**（裁决 O）。

## §3 验收

### §3.1 A 组 · Rust 门禁（内核 + 宿主）

| 编号 | 判据 |
| --- | --- |
| A-1 | M-16 单测：`set_timer_compare` 在**条件由真变假**时撤掉定时器线（`raised` 里没有线 3、`pending` 里没有线 3、`active_irq == NO_ACTIVE_IRQ`） |

## §4 已知边界

1. **释放不是「立刻」** —— 发生在**宿主同步点**（一个指令预算窗口 = 10 µs 虚拟时间，事实 F17 / F18）⇒ ⇒ ISR 执行期间外部中断仍被单级护栏挡住（LLD 明写 MVP 单级）。
2. **guest 不解除源 ⇒ 会被反复交付**（裁决 E）—— 那是 guest 的 bug，平台不掩盖。
3. **单级嵌套**（LLD 明写 P1）⇒ ⇒ ISR 里来的第二条中断**不**抢占。
4. **前端行结束符是「一行」的约定** —— 输入框是**单行**的 ⇒ ⇒ 多行输入（粘贴脚本）需要用户自己换行。
5. **osz 的 shell 只认 CR** —— 选 LF 时 osz **不会**执行命令（回显仍在）⇒ ⇒ 这是固件的属性，平台不猜。
6. **「服务中」的标记是平台级的一个**（裁决 T）⇒ ⇒ 平台**没有** Spike 那种**按源**的 `claimed` 位 ⇒ ⇒ 「同一个源被认领后、同一时刻」不能像参考侧那样逐源区分。
7. ⚠️ **本批撞见但不在范围内的两处分歧（只登记、不修 ⇒ ⇒ 台账 D-160）**：**①** 平台的 `Plic::complete()`（写 Claim）**清 `pending`**，而 Spike 的写 Claim **只清 `claimed`、不清 `pending`**（事实 F3）⇒ ⇒ **口径相反**；**②** 平台的 `mip` 是「**挂起线**」的投影，而 Spike 的是「**有可交付源**」的投影（事实 F6）⇒ ⇒ **口径不同**（裁决 U 已把它记为明示取舍）。⇒ ⇒ 本批**不受影响**（真固件的 complete 写值非法 ⇒ ⇒ 那一支根本没生效，事实 F11）。

## §5 接口契约

### §5.1 契约层

| 常量 | 值 |
| --- | --- |
| `SCHEMA_VERSION` | **8** |
| `SIM_STATE_SCHEMA_VERSION` | **2** |

**零变更** —— 四个常量**一个字都不动**（裁决 M / V）。

### §5.2 M-16 的语义变更

```rust
// ① set_timer_compare：条件由真变假 ⇒ 撤线（裁决 B1 / N）
pub fn set_timer_compare(&mut self, mtimecmp_ps: u64) {
    let was_armed = self.mtimecmp_ps != 0 && self.mtime_ps >= self.mtimecmp_ps;
    self.mtimecmp_ps = mtimecmp_ps;
    let now_false = mtimecmp_ps == 0 || self.mtime_ps < mtimecmp_ps;
    if was_armed && now_false {
        self.clear(IRQ_TIMER_COMPARE);
    }
}

// ② release_active_line：只复位「服务中」标记（裁决 B4 / O / P）
pub fn release_active_line(&mut self) {
    self.active_irq = NO_ACTIVE_IRQ;
}
```

⇒ ⇒ `InterruptPort` trait **新增一个默认空实现**的方法 `release_active_line` ⇒ ⇒ 其它实现者**不用改** ⇒ ⇒ **不是破坏性变更**。

### §5.3 宿主的接线变更

```rust
// sync_interrupts() 的第 ② 步：源挂起位跟设备电平（裁决 B3）
if rx_ready {
    p.request(wire.source);
} else {
    p.set_pending(wire.source, false);   // ← 新增
}

// sync_interrupts() 的第 ③ 步：与 Some 分支完全对称（裁决 B2）
match claimed {
    Some(_source) => { /* 原样：request(IRQ_UART_RX_READY, …) */ }
    None => {
        self.intc.controller.borrow_mut().clear(IRQ_UART_RX_READY);   // ← 新增
    }
}
```

### §5.4 M-13 / M-17 的接线变更

- M-13：`execute_one` / `execute_with_report` **新增一个出参** `returned_from_trap: &mut bool`；`Op::Mret` / `Op::Sret` 分支把它置真 ⇒ ⇒ `Iss` 里存一个 `last_trap_return` 标志（`take_last_trap_return()` 取走）。
- M-17：每条指令之后 ⇒ ⇒ **若** `take_last_trap_return()` ⇒ ⇒ `self.intc.release_active_line()`。

⚠️ **为什么接线点在 M-17 而不是 M-13**：M-13 **不知道** M-16 的存在（契约层的接线在 M-16 / M-17 之间）⇒ ⇒ M-17 才是那个接缝。

### §5.5 前端的新增（视图层）

- 视图状态：`term.eol`（取值 `cr` / `lf` / `crlf` / `none`，**默认 `cr`**）。
- DOM：终端输入行加一组按钮 `[data-eol]`，当前选中项带 `data-eol-selected`。
- 追加的字节：**CR = `[13]` · LF = `[10]` · CRLF = `[13, 10]` · 不追加 = `[]`**。

## §8 施工期订正

> ⚠️ 规格冻结后**每改一字**都要在这里记一条。格式：`### 订正 N · 标题`，每段含「规格原文 / 实测 / 已改成」。

### 订正 1 · 根因从「**两处**」改成「**四处**」

**规格原文**：§0 与裁决 B 写「修法落点 = **两处**」（`set_timer_compare` 的撤线 + 宿主 `None` 分支）。

**实测**：用**真 osz ELF** 在 `KernelHost` 上做端到端探针（事实 F19）⇒ ⇒ 修完那两处之后，**第二个字节仍然收不到** ⇒ ⇒ 逐处回退才发现另外两处：宿主第 ② 步**从不撤销**源挂起位（事实 F16，与参考侧的电平语义分歧，事实 F4）⇒ ⇒ 平台**没有**参考侧的 `claimed` 位（事实 F5）⇒ ⇒ 「服务中」那把锁**永不释放**（事实 F14）⇒ ⇒ 单级护栏把第二次交付**永久**挡住。

**已改成**：§1.3 改成**四处缺陷**的表 ⇒ ⇒ 裁决 B 改成 B1 ~ B4 ⇒ ⇒ §0 的边界表补 M-13 那一行 ⇒ ⇒ §3 补 A-11 ~ A-15 ⇒ ⇒ §6 的判别力清单补三行 ⇒ ⇒ §9 的变异表补 T5 ~ T8。

### 订正 2 · 事实 F3「写 Claim = complete 与 Spike **一致**」**是错的**

**规格原文**：原 F3 写「平台的『读不清 pending / 写 = complete』与 Spike 一致」。

**实测**：重新取上游 `riscv/plic.cc` 原文 ⇒ ⇒ `context_write` 的 `CONTEXT_CLAIM` 分支只做 `c->claimed[id_word] &= ~id_mask` ⇒ ⇒ **清 `claimed`、不清 `pending`** ⇒ ⇒ 而平台的 `Plic::complete()` **清 `pending`** ⇒ ⇒ **口径相反**。

**已改成**：事实 F3 改成 Spike 的**逐字**语义 ⇒ ⇒ 事实 F4 / F5 补上（`set_interrupt_level` 与 `claimed` 位）⇒ ⇒ 裁决 F 拆成「**布局**零改动」+「**语义**两处分歧只登记」⇒ ⇒ §4 已知边界补第 7 条 ⇒ ⇒ **台账新登记 D-160**（只登记、不修）。

### 订正 3 · 判据的固件从「**两段**」扩到「**四段**」

**规格原文**：§3.1 的 A 组只有一段 UART 固件（会读 Claim、写 complete、排空 FIFO）。

**实测**：那段固件**太礼貌** ⇒ ⇒ 它**掩盖**了「平台没有 `claimed` 位」⇒ ⇒ 只用它做判据 ⇒ ⇒ 缺陷 ③ / ④ 变红时**可能**抓不到 ⇒ ⇒ 而三段固件各测一件事（裁决 Q）⇒ ⇒ 真 osz 那一支（complete 写值非法）**自写固件测不到**（事实 F11）⇒ ⇒ **真机层不可省**（裁决 R）。

**已改成**：§3.1 补 A-11 ~ A-15 ⇒ ⇒ 固件从两段扩到**四段**（第三段「只数 + `mret`」、第四段「读 RHR + 数 + `mret`」）⇒ ⇒ 夹具防漂移用例从 3 条扩到 **5** 条 ⇒ ⇒ §6 补「**太礼貌的固件**自查」那段。

### 订正 4 · 验收编号空间改了（`A` / `N` / `B` / `X`）

**规格原文**：原 §3 用 `A` = Rust · `B` = 前端 Node · `C` = 真机（`C-1 ~ C-3`）。

**实测**：`B` 是**真机输出**的编号空间（同一个 `browser-verify.mjs` 输出里 ID 必须**全局唯一**）⇒ ⇒ STAGE-32 ~ STAGE-39 已经用到 `B-6 ~ B-60` ⇒ ⇒ 前端那一组再叫 `B-1 ~ B-8` 会与 STAGE-32 的 `B-1 ~ B-5` **撞名** ⇒ ⇒ 而真机那一组再叫 `C-1 ~ C-3` 会与 STAGE-32 ~ STAGE-39 的 `C-1 ~ C-3` **在同一个输出里重名** ⇒ ⇒ 前端那一组改用**新字母 `N`**（Node）⇒ ⇒ 真机那一组**接着全局序列** ⇒ ⇒ `B-61 ~ B-66`。

**已改成**：§3 改成 §3.1（A 组 · Rust · A-1 ~ A-15）· §3.2（N 组 · Node · N-1 ~ N-8）· §3.3（B 组 · 真机 · B-61 ~ B-66）· §3.4（X 组 · 交叉）⇒ ⇒ 裁决 S 记录这条口径 ⇒ ⇒ 前端测试文件里的八条编号同步改名 ⇒ ⇒ `tools/stage40_check.py` 的编号空间同步。

### 订正 5 · 真机判据从「**回显**」升级成「**执行了整行**」

**规格原文**：原 C 组写「C-1 guest 的 console 里出现**回显** ⇒ ⇒ UART RX 中断真的被交付了」。

**实测**：**回显**不足以证明「命令被执行了」⇒ ⇒ UART 的回环（或者 guest 自己把字符打回去）也能满足「出现回显」⇒ ⇒ 而且 osz **只认 CR** ⇒ ⇒ 只送原文时**回显仍在、命令不执行** ⇒ ⇒ 「有回显」与「命令执行了」是**两个**命题。

**已改成**：B 组补成六条 ⇒ ⇒ **B-64** 单独盯「guest **执行了整行**」（console 里出现命令结果）⇒ ⇒ **B-66** 用「不加行结束符 ⇒ 只有回显、没有结果」做**反向对照** ⇒ ⇒ 「有回显」不再被当成「命令执行了」。

### 订正 6 · 「释放 ≠ 清 pending」这条护栏要**两条**判据

**规格原文**：原规格只说「释放的是服务中标记」，但没给它**判据**。

**实测**：「释放」这个动作很容易被写成 `clear(line)`（那样连挂起项一起清了）⇒ ⇒ 那样的话「挂起项还在」这件事**没人管** ⇒ ⇒ 而那正是裁决 P 的内容 ⇒ ⇒ 平台与参考侧在这一点上的差别**只有靠这条护栏**才看得见。

**已改成**：A-12 同时钉**两件事**（判别式：计数器能涨到 2；护栏：挂起项还在）⇒ ⇒ A-13 钉架构 `mip` 的 MEIP 位**仍然置上** ⇒ ⇒ §6 的判别力清单补「`release_active_line` 改成『连挂起项一起清』⇒ ⇒ 红 A-12 · A-13」与「trap 返回时误清架构 `mip` ⇒ ⇒ 红 A-13」两行。

### 订正 7 · 「trap 返回时误清架构 `mip`」**不可实现为独立变异** ⇒ ⇒ T8 改写 + 补 T9

**规格原文**：§6 与 §9 都把「trap 返回时误清架构 `mip`」当成一条**独立**的变异（原 T8），并写「必须红 A-13」。

**实测**：架构 `mip` 在平台上**不是**一份独立存储 ⇒ ⇒ 它是**挂起队列的投影**（`m17_backend` 的 `project_mip` ⇒ `pending_lines_to_mip_mask(pending_lines)`）⇒ ⇒ 要让「trap 返回时误清架构 `mip`」成为一条**可施加**的变异 ⇒ ⇒ 必须**先**让 trap 返回去**清挂起项** ⇒ ⇒ 而那正是 T6（`release_active_line` 连挂起项一起清）⇒ ⇒ **T6 实测把 A-13 打成红** ⇒ ⇒ 「误清 `mip`」这条判别力**由 T6 承担** ⇒ ⇒ 它**不能**再单独列成一条变异（否则 §9 会有一行**永远打不出红**的变异 ⇒ ⇒ 那是「规格引用了一条不存在的判据」那一族 ⇒ ⇒ 比没有判据更坏）。

**另外**：实测发现 **A-4 在原变异表里没有任何一条变异能让它变红**（原 §6 写「撤线判据写成『无条件撤』⇒ ⇒ A-4」⇒ ⇒ 实测 T2 的红集是 `A-2` + `export_and_load_round_trip_restores_the_whole_controller_state`，**A-4 不红**）⇒ ⇒ A-4 的判别力是**空的** ⇒ ⇒ 「A-4 没人管」这件事**只有跑一遍变异表才发现得了**。

**已改成**：§9.1 的 T8 改成「宿主第 ② 步的 `if rx_ready` 与 `else` 写反」（**可施加**、**实测红 11 条」）⇒ ⇒ A-13 的判别力记在 T6 那行 ⇒ ⇒ **补 T9**（撤线时把**别的线**也一起撤）⇒ ⇒ 专门给 A-4 补判别力 ⇒ ⇒ 变异编号按**分层连号**重排（Rust 层 T1 ~ T9 · 前端层 T10 ~ T12）⇒ ⇒ §6 的判别力清单同步。

### 订正 8 · §6 / §9 的红集改成**实测值**（含两条新增变异与真机层）

**规格原文**：§6 与 §9 的红集列写的是**期望值**（照着判别式清单推出来的）。

**实测**：跑完整变异自检（Rust 层 T1 ~ T9 · 前端层 T10 ~ T12 · 对照 T-C1 / T-C2 · 真机层 BV-M1 / BV-C1）⇒ ⇒ 三条期望**与实测不符**：① §6 写「撤线判据写成『无条件撤』⇒ ⇒ A-4」⇒ ⇒ 实测 T2 **不红 A-4**（它红的是 `A-2` 与 `export_and_load_round_trip_restores_the_whole_controller_state`）⇒ ⇒ **A-4 在原变异表里没有任何一条变异能让它变红** ⇒ ⇒ **判据存在 ≠ 判据有人管** ⇒ ⇒ 补 **T9** 专门给它判别力（实测：T9 **只**红 A-4 ⇒ ⇒ 一一对应）② §6 写「宿主第 ③ 步撤错线 ⇒ ⇒ A-5 · A-6 · A-11」⇒ ⇒ 实测是 **A-5 · A-11 · A-15**（A-6 不红、A-15 红）③ §9 的 T8 原写「trap 返回时误清架构 `mip`」⇒ ⇒ **不可实现为独立变异**（见订正 7）。

**另外**：叠加检验里 **T3 + T6** 的实测红集是并集的**真子集**（A-15 被 T6 掩蔽）⇒ ⇒ 「红集 == 并集」这条判据**把「掩蔽」与「偷偷依赖」混成了一类** ⇒ ⇒ 前者是**可解释的**（T6 清了挂起项 ⇒ ⇒ A-15「计数器停住」自然成立）⇒ ⇒ 后者**才是失败**。

**已改成**：§6 与 §9 的红集列全部改成**实测值** ⇒ ⇒ §9.1 / §9.2 / §9.3 按**分层连号**重排（Rust T1 ~ T9 · 前端 T10 ~ T12 · 真机 BV-M1 / BV-C1）⇒ ⇒ §9.4 补**叠加检验**表 ⇒ ⇒ 判据改成「**不许多出来**」＋「**每条变异在叠加后仍至少一条红**」（**掩蔽**报出来但**不判失败**）⇒ ⇒ `tools/stage40_check.py` 的 7j 改成**校验编号齐全 ＋ 每条都有非空的实测红集**（⛔ 不许占位 ⇒ ⇒ 「规格引用了一条不存在的判据」比没有判据更坏）。

### §9.4 叠加检验（两条真变异**不还原**地叠加）
