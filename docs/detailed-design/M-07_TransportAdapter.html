1 功能概述

1.1 模块定位

M-07 传输适配器（4.2.3）：双传输适配——WASM 内嵌（Worker + postMessage 承载协议消息）与 WebSocket 远程（服务端形态 P1），协议语义两形态一致。数据面传输语义明确为「每批不可变分块 transfer + 内核重建新块（移动语义）」（生产-消费模型：Worker 写缓冲 → transfer 移交 → 主线程读 → Worker 重建新块继续写入，不做原地共享；零拷贝仅限一次性大块如快照整块 transfer，file:// 下无 COOP/COEP 时不依赖 SharedArrayBuffer，评审 P-08）。控制面分层（07-2）：M-07 为传输帧（TransportFrame 包裹 sessionId/role/crc/seq），M-05 为协议层（ProtocolMessage 解析 msgType/reqId/version/payload），一律走协议封装（评审 R4）。背压治理与 M-05 对齐（07-1）：命令/观测双队列分离——命令不丢（超水位拒绝新命令 E_PROTO-04），仅观测类（波形/状态增量）降采样/丢最旧（评审 P-10）。断线重连按序列号续拉补齐。

1.3 MVP 范围与预留

MVP 实现范围：send(msg)（控制面协议封装，输出序列号）、transferBlock(block)（数据面不可变分块移动语义移交）、recv(cb)（消息接收回调 → M-05 路由）、resumeBySeq(seq)（断线按序列号续拉补齐）、backpressure(kind)（发送队列水位处置：降采样/丢最旧）；WASM 内嵌形态（Worker postMessage）+ 断线序列号锚点。
预留项（P1 演进承接，不属现实现）：WebSocket 远程形态 + 重连鉴权（NFR-04）；REST/CLI 网关接入（headless 命令面，未启用返回 E_CTX-09）；CRC 校验（E_PROTO-06，P1）；SharedArrayBuffer 共享内存路径（COOP/COEP 就绪后，P-08 演进）。

2 数据描述

2.1 核心数据结构（源文档表35）

数据结构类型定义与用途
transportTypeenum传输形态：wasm 内嵌 / ws 远程（协议语义两形态一致）
connStateenum连接状态：connecting / ready / closed / reconnecting
seqNouint64发送序列号（单调递增，断线续拉锚点；缺口 → E_PROTO-05）
pendingQueuequeue待确认命令队列（超时管理 E_CTX-06 ≤500ms，幂等可重试）
txWatermarkfloat发送队列水位阈值（默认 0.8），超限降采样/丢最旧（评审 P-10）

2.1.1 复杂结构字段定义

transportType 决定传输通道实现（postMessage / WebSocket），协议消息结构两形态共用；seqNo 单调递增作为续拉锚点（断线后按序补齐，E_PROTO-05）；pendingQueue 维护待确认命令（超时 E_CTX-06）；txWatermark 触发背压（超限降采样/丢最旧，P-10）。字段定义如下：

// transportType: 传输形态（协议语义两形态一致，4.2.3.1）
enum transportType { wasm, ws };
// connState: 连接状态机（断线 → reconnecting → ready；closed 为终态）
enum connState { connecting, ready, closed, reconnecting };
// seqNo: 发送序列号（单调递增，续拉锚点；缺口 → E_PROTO-05）
struct seqNo {
  uint64_t last;     // 已发送序列号（单调递增）
  uint64_t acked;    // 已确认序列号（07-8：按序推进 TCP 式；乱序 ack 缓存待前序补齐）
};
// 分层模型（07-2）：M-07 传输帧包裹 → M-05 协议层解析 payload
// TransportFrame: 传输帧（M-07 定义：sessionId/role/crc/seq 包裹层）
struct TransportFrame {
  uint8_t  type;        // 0=命令 / 1=事件 / 2=ack / 3=续拉请求
  uint64_t seq;         // 发送序列号（ack/续拉锚点）
  uint64_t sessionId;   // 会话归属（与 M-04 会话关联）
  uint8_t  role;        // 角色（WS 形态鉴权/能力面，NFR-04）
  uint32_t crc;         // CRC 校验（P1，E_PROTO-06）
  ProtocolMessage payload; // 协议层载荷（M-05 解析，见下）
};
// ProtocolMessage: 协议层消息（M-05 定义与解析：msgType/reqId/version/payload）
//   与 M-05 2.1.1 同源：{msgType, reqId, seq, version, payload}；M-07 不做协议层字段校验
// ack 分工（07-3）：命令 ack → M-07 pendingQueue 出队推进；事件 ack → M-05 可靠通道
//   （deliverReliable 重试 ≤3）；M-07 仅做传输层 ack 透传，不承担事件 ack 重试
// PendingEntry: 待确认命令队列条目（超时管理，E_CTX-06）
struct PendingEntry {
  uint64_t seq;         // 命令序列号
  uint64_t deadline;    // 超时截止（≤500ms，读类/幂等可重试）
  uint8_t  retries;     // 已重试次数（≤3，与 M-05 对齐）
};
// TxQueue: 发送队列（07-1：命令/观测双队列分离，水位背压，评审 P-10）
struct TxQueue {
  ring<PendingEntry> cmdQueue;  // 命令队列：不丢（超水位拒绝新命令 E_PROTO-04）
  ring<PendingEntry> obsQueue;  // 观测队列：可丢（降采样/丢最旧，丢弃=本地未发送）
  float watermark = 0.8;        // 水位阈值（默认 0.8，作用于 obsQueue）
  uint32_t cap;                 // 队列容量（超限触发处置）
  uint8_t  kind;                // 处置类别（07-5）：THROTTLE 降采样 / DROP_OLDEST 丢最旧
};
// Delta: resumeBySeq 输出（07-5 展开：补齐的增量，前端对账用，M-03）
struct Delta {
  uint64_t seqStart;            // 续拉起点序列号（断线前已 ack）
  uint64_t seqEnd;              // 续拉终点序列号（当前 last）
  Entry    entries[];           // 补齐增量条目（按 seq 升序，前端对账 M-03 reconcile）
};
// 历史窗口（07-4）：主线程/传输适配器侧持有（Worker 重建不影响 histContains）；
//   WASM 断线重建后仍按序续拉，仅窗口外缺口才全量对账
// Block: 数据面不可变分块（移动语义，评审 P-08）
struct Block {
  ArrayBuffer buf;      // 不可变分块（transferable，移交后原侧不再读写）
  uint64_t   batchNo;   // 批次号（数据面批次锚点）
  bool       immutable; // 不可变标记（重建新块后旧块只读）
};

2.2 缓存与增量语义

机制语义实现通道备注
发送队列命令/观测双队列（07-1）：cmdQueue 不丢（超水位拒绝 E_PROTO-04）；obsQueue 降采样/丢最旧（丢弃=本地未发送）TxQueue.cmdQueue/obsQueue + watermark(0.8)与 M-05/M-19 背压策略一致（P-10）
续拉锚点seqNo 单调递增；断线后 resumeBySeq(seq) 按缺口补齐；历史窗口主线程/适配器侧持有（07-4）seqNo.last/acked + histWindow缺口 → E_PROTO-05；窗口外 → 全量对账
超时管理cmdQueue 条目 deadline ≤500ms，超时 E_CTX-06PendingEntry.deadline读类/幂等命令可重试（与 M-05 对齐）
ack 推进acked 按序推进（TCP 式，07-8）；乱序 ack 缓存待前序补齐seqNo.acked + ackReorderBuf命令 ack → M-07 出队；事件 ack → M-05 可靠通道（07-3）

2.3 数据流说明

建立连接 → 握手（协议版本 + 能力位，E_PROTO-01 拒绝不兼容）→ 收发（数据面不可变分块 transfer，控制面协议封装）→ 断线检测 → 重连 → 按序列号续拉 → 对账完成恢复；发送队列超水位 → 背压处置（降采样/丢最旧，P-10）。

3 实现设计

3.1 send(msg) 协议消息发送

send(msg)：控制面统一封装（评审 R4）——分配单调序列号、按类别入命令/观测队列（07-1）、发送传输帧；命令队列超水位 → 拒绝新命令 E_PROTO-04（命令不丢）；观测队列超水位 → backpressure 降采样/丢最旧（丢弃=本地未发送）。ack 分工（07-3）：命令 ack → 本模块 pendingQueue 出队；事件 ack → M-05 可靠通道重试，本模块仅透传。伪代码如下：

// send: 协议消息发送（控制面统一封装，评审 R4；4.2.3.3 表36）
uint64_t send(ProtocolMessage msg) {
  TransportFrame f = wrap(msg);                    // 07-2：传输帧包裹（sessionId/role/crc/seq）
  f.seq = seqNo.last++;                            // 分配单调序列号（续拉锚点）
  if (isCommand(f)) {                              // 命令：cmdQueue（不丢）
    if (cmdQueueFull()) return E_PROTO-04;         // 07-1：命令队列满 → 拒绝新命令（不丢旧）
    cmdQueue.push({seq: f.seq, deadline: now()+500ms, retries: 0}); // 入待确认（≤500ms）
  } else {                                         // 观测：obsQueue（可丢）
    if (obsQueueOverWatermark()) backpressure(THROTTLE); // 07-1：仅观测降采样/丢最旧
    if (obsQueueFull()) { dropOldest(); return f.seq; }  // 丢弃=本地未发送（前端对账可补）
    obsQueue.push({seq: f.seq});                   // 入观测队列
  }
  transport_send(f);                               // 形态发送：postMessage / WebSocket
  return f.seq;                                    // 输出：序列号
}
// ack 分工（07-3）：命令 ack → cmdQueue 出队推进；事件 ack → M-05 可靠通道（deliverReliable
//   重试 ≤3）；M-07 仅做传输层 ack 透传，不承担事件 ack 重试（E_PROTO-07 仅传输层超时记录）

3.2 transferBlock(block) 不可变分块移交

transferBlock(block)：数据面移动语义（评审 P-08，生产-消费模型 07-9）——Worker 写缓冲 → transfer 移交 → 主线程读 → Worker 重建新块继续写入，不做原地共享；零拷贝仅限一次性大块（如快照整块 transfer）；file:// 无 COOP/COEP 时降级为 postMessage 拷贝语义（不依赖 SharedArrayBuffer）。伪代码如下：

// transferBlock: 不可变分块移交（移动语义，评审 P-08；4.2.3.3 表36）
// 生产-消费模型（07-9）：Worker 侧生产（写环形缓冲）→ transferBlock 移交 →
//   主线程消费（读块，不可变）→ workerRebuildBlock 重建新块供 Worker 继续写
void transferBlock(Block block) {
  assert(block.immutable);                          // 不可变分块（移交后原侧不再读写）
  if (transferableAvailable(block.buf))            // transferable 路径（COOP/COEP 或 Worker 内）
    postMessage(block, [block.buf]);               // 移交所有权（零拷贝；仅一次性大块如快照）
  else
    postMessage(block);                            // file:// 降级：拷贝语义（无 SAB，P-08）
  workerRebuildBlock(block.batchNo);               // Worker 侧重建新块继续写入（环形缓冲场景）
}
// 分块大小/批次频率：按数据面批次（如波形采样批）切分，主线程消费后回写 release 批次号

3.3 recv(cb) 消息接收回调

recv(cb)：消息接收回调分发——解析传输帧（格式错误 → E_PROTO-08；未知字段 → E_PROTO-02 仅日志忽略）、按类型路由（命令/事件/ack/续拉）；ack 分工（07-3）：命令 ack 出队推进、事件 ack 透传 M-05 → 调用 M-05 路由分发。伪代码如下：

// recv: 消息接收回调分发（4.2.3.3 表36；调用 M-05 路由）
void recv(cb) {
  transport_onMessage((msg) => {
    TransportFrame f = parseFrame(msg);            // 传输帧解析（格式错误 → E_PROTO-08 拒绝）
    f.seq == unknownField ? log(E_PROTO-02) : void;// 未知字段仅日志，向后兼容忽略
    if (f.type == ACK) {                           // ack 分工（07-3）
      if (f.payload.msgType == CMD)                // 命令 ack → cmdQueue 出队（按序推进，07-8）
        cmdQueue.ackInOrder(f.seq);                // 乱序 ack 缓存待前序补齐（ackReorderBuf）
      else                                         // 事件 ack → M-05 可靠通道（透传不重试）
        m05RelayEventAck(f.seq);
      return;
    }
    m05Route(f.payload);                           // 07-2：协议层载荷交 M-05 路由
    cb(f);                                         // 回调输出解析后的消息
  });
}

3.4 reconnect() 断线重连

reconnect()：断线重连——WS 形态：重连 + 鉴权（NFR-04）+ 按序列号续拉（resumeBySeq）；WASM 内嵌形态：Worker 重建（postMessage 通道恢复）+ 续拉。重连续拉无法补齐 → 前端主动拉取全量状态对账。伪代码如下：

// reconnect: 断线重连（4.2.3.3 表36；输出：连接状态）
connState reconnect() {
  connState = reconnecting;                        // 进入重连态
  if (transportType == ws) {
    if (!wsAuth()) return closed;                  // WS：重连 + 鉴权（NFR-04，失败 → closed）
    connState = ready;
  } else {
    rebuildWorker();                               // WASM 内嵌：Worker 重建（postMessage 恢复）
    connState = ready;
  }
  resumeBySeq(seqNo.acked);                        // 按序列号续拉补齐（缺口 → E_PROTO-05）
  return connState;                                // 输出：连接状态
}
// 续拉缺口无法补齐 → 前端主动拉取全量状态对账（4.2.3.5）

3.5 resumeBySeq(seq) 按序列号续拉补齐

resumeBySeq(seq)：按断线前序列号续拉补齐（前端对账用，M-03 reconcile 调用）——对端按 seq 返回缺失增量；缺口无法补齐 → E_PROTO-05 + 前端全量对账。伪代码如下：

// resumeBySeq: 按序列号续拉补齐（4.2.3.3 表36；输入：断线前序列号）
Delta resumeBySeq(uint64_t seq) {
  if (seq > seqNo.last || !histContains(seq))      // 缺口（断线期间丢失的消息）
    return E_PROTO-05;                             // 序列号缺口 → 前端全量对账（4.2.3.5）
  Delta d = histFetch(seq, seqNo.last);            // 按序补齐缺失增量
  return d;                                        // 输出：补齐的增量（前端对账用，M-03）
}
// 历史窗口：最近 N 条按 seq 索引，主线程/适配器侧持有（07-4：Worker 重建不影响续拉；
//   对齐 M-05 evHistory 续拉数据源语义）

3.6 backpressure(kind) 背压处置

backpressure(kind)：观测队列水位处置（07-1：命令不丢，仅观测可丢）——kind 枚举（07-5）：THROTTLE 降采样 / DROP_OLDEST 丢最旧，映射观测类数据；队列持续超水位 → 暂停非关键数据流并告警。伪代码如下：

// backpressure: 观测队列水位处置（4.2.3.3 表36；与 M-19 对齐，P-10）
// kind 枚举（07-5）：THROTTLE 降采样（观测高频数据抽稀）/ DROP_OLDEST 丢最旧
//   （按 seq 丢最早未发送条目）；仅作用于 obsQueue，cmdQueue 命令不丢（07-1）
void backpressure(uint8_t kind) {
  if (obsQueue.used() / obsQueue.cap > watermark) { // 观测队列水位超限
    if (kind == THROTTLE) downSample();            // 降采样（观测类数据）
    else if (kind == DROP_OLDEST) dropOldest();    // 丢最旧（按 seq 丢最早未发送条目）
  }
  if (persistentOverflow()) {                      // 观测队列持续超水位（降载仍堆积）
    pauseNonCritical();                            // 暂停非关键数据流（波形/观测订阅）
    m22Report(WARN, "obs_overflow", watermark);    // 告警（评审 P-10）
  }
}
// 命令队列满 → send 返回 E_PROTO-04 拒绝新命令（不丢已发送命令，07-1/07-6）

6 异常处理

6.1 错误码与处置（E_PROTO 族主属方）

M-07 为 E_PROTO 错误码族主属方之一（源文档 3.4 表16），传输路径错误码统一收于此（一场景一码，均为表16 既有码，无新增）：

E_PROTO-02 未知字段协议消息含未知字段仅日志记录，向后兼容忽略

6.2 边界与降级

（1）WS 断连 → 上报 HMS（严重级）+ 重连续拉（reconnect + resumeBySeq）；WS 鉴权失败 → closed（重试 ≤3 → 上报）。
（2）WASM 内嵌传输异常 → 视为引擎故障上报（Worker 重建 + 续拉；历史窗口主线程/适配器侧持有，重建不影响续拉，07-4）。
（3）续拉缺口无法补齐 → 前端主动拉取全量状态对账（E_PROTO-05）。
（4）观测队列持续超水位 → 暂停非关键数据流并告警（评审 P-10）；命令队列满 → 拒绝新命令 E_PROTO-04（命令不丢，07-1）。
（5）file:// 无 COOP/COEP → 不依赖 SharedArrayBuffer，transferable 降级为 postMessage 拷贝语义（评审 P-08）。
（6）CRC 校验失败 → E_PROTO-06（P1 形态启用，MVP 仅记录；E_PROTO-04/06 均已在源表16 核对存在，无新增码）。
（7）acked 推进（07-8）：按序推进（TCP 式），乱序 ack 缓存待前序补齐。

7.2 可维护性手段

（1）协议层可替换：协议消息结构（DTO）语言无关 JSON Schema/IDL 定义，传输形态（transportType）只换通道不换语义。
（2）序列号锚点：seqNo 单调递增 + acked 推进，续拉/对账不依赖宿主时序（确定性约束表6）。
（3）背压可配：txWatermark 水位与处置模式（降采样/丢最旧）为结构化配置，调整不涉核心逻辑。
（4）双形态共享：WASM/WS 共用同一协议解析与路由代码路径，形态差异收敛到 transport_* 适配层。
（5）CI 门禁：双传输语义一致用例纳入契约测试；断线续拉无缺口纳入回归基线。
