1 功能概述

1.1 模块定位

M-08 断点管理器（4.3.1）：管理 PC 断点与条件断点（FR-08）——注册/删除/使能、命中检测与回调暂停。断点列表随 DebugMeta 持久化（会话级调试元数据，经 M-04 会话统一管理）。命中后触发状态快照检查点（关键事件，RPO ≤2s 宿主时间口径）。变量监视（FR-11，watch）语义明确：MVP = 地址/寄存器表达式（解析并轮询求值）；符号名监视列入 P1（依赖 DWARF .debug_info 变量表与栈帧回溯，MVP 仅行表级，评审 P-05）。

调试服务只面对 ExecutionBackend 抽象（3.2.4 表13）：断点注册/命中检测/寄存器内存求值全部经 M-17 抽象代理（自研 ISS L3 / QEMU L1 子集），M-08 不感知具体内核实现。断点命中属于 E1 关键控制事件（5.2 图3），可靠投递（ack/重试），前端在事件缺口或命令超时后主动拉取状态对账（reconcile）。

1.3 MVP 范围与预留

MVP 实现范围：PC 断点与条件断点（setBreakpoint/remove/enable/disable）、命中检测（hitCheck，优先于全量回调）、命中回调（onHit：M-09 暂停 + M-05 publish(breakpointHit) + M-04 checkpoint）、watch 地址/寄存器表达式（addWatch/removeWatch + 轮询求值）、断点表随 DebugMeta 持久化（会话重建恢复）、注册/命中日志（M-21）。

预留项（P1/P2 演进承接，不展开实现）：符号名监视（P1，E_CTX-08，依赖 DWARF .debug_info 变量表与栈帧回溯）；源码级行断点（P1，依赖 M-11 行表映射）；watch 表达式引擎深化（算术/解引用 P1）；硬件断点数量模型（随 QEMU 后端适配，P1）。

2.1 核心数据结构

2.1.1 复杂结构字段定义

Breakpoint 是断点表条目；WatchItem 是监视项；DebugMeta 携带断点持久化数据。字段定义如下：

// Breakpoint: 断点条目（breakpointTable 元素）
struct Breakpoint {
  uint32_t id;          // 断点 id（M-17 hook 注册返回值，会话内唯一）
  uint32_t addr;        // 断点地址（指令边界 PC，需与指令对齐）
  char     cond[64];    // 条件表达式（空串 = 无条件 PC 断点；地址/寄存器表达式，评审 P-05）
  uint8_t  enabled;     // 使能位：0=禁用（保留在表，不命中）/ 1=启用
  uint8_t  sourceType;  // 来源：0=用户 / 1=临时（M-09 stepOver 注入，自动移除）
  uint32_t hitCount;    // 命中次数（诊断，供前端展示）
};
// WatchItem: 变量监视项（watchList 元素，FR-11）
struct WatchItem {
  char     expr[64];    // 监视表达式：MVP = 地址（0x80000010）或寄存器（x1/sp/mepc）表达式
  uint8_t  kind;        // 0=地址 / 1=寄存器（求值通道 = M-17 readMem / readReg 抽象）
  uint32_t lastValue;   // 上次求值结果（暂停态即时求值 + 运行态量子边界轮询刷新）
  uint8_t  evalErr;     // 上次求值错误标记（0=正常；1=表达式非法/符号名 P1 → E_CTX-08）
};
// DebugMeta: 会话调试元数据（断点持久化载体；由 M-04 会话统一序列化到 M-23）
struct DebugMeta {
  uint32_t    bpCount;        // 断点条目数（恢复时按序重建 breakpointTable）
  Breakpoint  bps[64];        // 断点表快照（随会话持久化，会话重建时恢复）
  uint32_t    watchCount;     // 监视项数
  WatchItem   watches[32];    // 监视表快照（随会话持久化）
};
// 注：DebugMeta 的持久化通道 = M-04 会话状态管理（→ M-23 数据存储），
//     M-08 只维护运行态 breakpointTable/watchList，会话重建时从 DebugMeta 恢复。

2.2 断点类型与 watch 语义

断点 / 监视类型语义求值 / 命中通道备注
PC 断点无条件：指令边界 PC 命中即暂停M-17 断点表（self_iss：hook 表；QEMU：RSP Z0）hitCheck(pc) 优先于全量指令回调（表93）
条件断点PC 命中 + cond 表达式求值为真才暂停M-17 地址快判 + M-08 hitCheck 内 condEval 统一求值（唯一链路，评审 08-1）求值异常 → 按未命中处理并记日志（限频，评审 08-7）
临时断点M-09 stepOver 注入，命中一次自动移除（评审 08-3）同 PC 断点；sourceType=1，hitCheck 命中即 remove_bpMVP 支持（M-09 协作）
watch 地址表达式监视指定内存地址（0x80000010）M-17 readMem 轮询求值FR-11；暂停态即时 + 运行态量子边界轮询
watch 寄存器表达式监视寄存器（x1/sp/mepc 等）M-17 readReg 轮询求值FR-11；符号名表达式 → E_CTX-08（P1）

2.3 数据流说明

注册流：setBreakpoint(addr, cond) → 地址校验（E_CTX-07 拒绝无效/重复）→ M-17 注册地址断点（m17_bp，id 由 M-17 唯一产生）→ breakpointTable 登记 + idIndex 反查索引 → DebugMeta 更新（随会话持久化）。

命中流（5.2 图3）：M-17 在指令边界 pre=1 阶段地址快判 → M-08 hitCheck(pc) 统一确认（含 cond 求值）→ 命中 → onHit(bp)：临时断点自动移除（评审 08-3）→ M-09 暂停冻结（SimState 对齐量子边界）→ M-05 publish(breakpointHit)（E1 可靠投递，ack/重试）→ M-04 checkpoint（关键事件，RPO ≤2s）→ M-21 日志。

恢复流（评审 08-6）：会话重建 → M-04 从 DebugMeta 载入断点表 → restoreFromMeta 按 addr 重新注册（新 id 重映射，丢弃旧 id）→ 重建 idIndex。

watch 流：addWatch(expr) → 表达式分类（地址/寄存器）→ watchList 登记 → 求值（暂停态即时 + 运行态量子边界轮询，节流）→ 值变化或 evalErr 切换经 M-05 publish(watchUpdate) 推送前端（刷新 ≤200ms 估算基线，评审 08-9）。

3 实现设计

3.1 断点注册与管理

注册入口 setBreakpoint(addr, cond)：地址校验（指令边界对齐、重复注册）→ 统一经 M-17 注册无条件地址断点（m17_bp，仅地址快判；条件求值统一在 M-08 hitCheck 内，M-17 不再回调求值——唯一命中链路，评审 08-1）→ breakpointTable 登记 + idIndex 反查索引 → DebugMeta 更新。断点 id 唯一来源 = M-17 hook 注册返回值（评审 08-4）。remove/enable/disable 只改表状态与 M-17 钩子启用位，命中检测即时生效。伪代码如下：

// setBreakpoint: 注册断点（PC / 条件；统一 m17_bp 地址快判注册，评审 08-1/08-4）
BpId setBreakpoint(uint32_t addr, const char* cond) {
    if (!aligned(addr) || breakpointTable.has(addr)) return E_CTX-07; // 无效地址/重复注册拒绝
    BpId id = m17_bp(addr);                        // M-17 注册地址断点；id 唯一来源 = M-17 返回值
    Breakpoint bp = { id, addr, cond ? cond : "", 1, 0, 0 };
    breakpointTable[addr] = bp;                    // 表登记（按 addr 索引，命中检测 O(1) 查表）
    idIndex[id] = addr;                            // id→addr 反查索引（onHit/remove 用）
    debugMeta_sync();                              // 断点表随 DebugMeta 持久化（M-04 会话）
    log(INFO, "DBG-BP", "breakpoint set", "E_OK");
    return id;
}
// remove / enable / disable: 断点管理（按 id 反查 addr 后操作；评审 08-4）
// 无效 id 幂等（评审 09-6 联动 / 落实 N8）：id 不存在则直接返回，不产生 UB（remove 兜底清理可安全调用）
void remove_bp(BpId id)     { if (idIndex.count(id) == 0) return; uint32_t a = idIndex[id]; M17_bpControl(id, REMOVE); breakpointTable.erase(a); idIndex.erase(id); debugMeta_sync(); }
void enable_bp(BpId id)     { if (idIndex.count(id) == 0) return; M17_bpControl(id, ENABLE); breakpointTable[idIndex[id]].enabled = 1; }
void disable_bp(BpId id)    { if (idIndex.count(id) == 0) return; M17_bpControl(id, DISABLE); breakpointTable[idIndex[id]].enabled = 0; }
// restoreFromMeta: 会话恢复（DebugMeta → 断点表，id 重映射，评审 08-6）
void restoreFromMeta(DebugMeta* meta) {
    for (i = 0; i < meta->bpCount; i++) {          // 按 addr 重建 + 重新注册，丢弃旧 id
        BpId id = m17_bp(meta->bps[i].addr);
        Breakpoint bp = { id, meta->bps[i].addr, meta->bps[i].cond,
                          meta->bps[i].enabled, meta->bps[i].sourceType, 0 };
        breakpointTable[bp.addr] = bp; idIndex[id] = bp.addr;
    }
}
// 注：M-17 bp 生命周期经 bpControl 接口（M-17 v1.2 已落地，08-2 联动）：
//     op=REMOVE/ENABLE/DISABLE；self_iss 移除/启停 hookTable，qemu 映射 RSP z0/Z0。

3.2 命中检测与条件求值

命中检测（hitCheck(pc)）为唯一命中入口（评审 08-1）：挂载于 M-17 hook pre=1 阶段（指令执行前拦截，与 M-17 17-6 pre 钩子一致；评审 08-5），冻结点 = 指令执行前的 SimState。O(1) 查表命中优先于全量指令回调（表93 性能行）——即断点走专用快速路径（PC 比对），不触发 onInstruction 全量钩子。条件断点命中 PC 后由 condEval 求值：地址/寄存器表达式经 M-17 readMem/readReg 抽象读取（不感知内核实现），求值异常按未命中处理并记日志（限频，评审 08-7）。命中确认后调用 onHit(bp)；临时断点（sourceType=1）命中即自动移除（评审 08-3）。伪代码如下：

// hitCheck: 唯一命中入口（M-17 hook pre=1 阶段调用；地址快判 + cond 统一求值，评审 08-1/08-5）
BpId hitCheck(uint32_t pc) {
    if (!breakpointTable.has(pc)) return NO_HIT;   // O(1) 查表，未命中直接返回
    Breakpoint* bp = &breakpointTable[pc];
    if (!bp->enabled) return NO_HIT;               // 禁用断点不命中
    if (bp->cond[0] != '\0' && !condEval(bp))     // 条件断点：求值失败按未命中（限频记日志）
        return NO_HIT;
    if (bp->sourceType == TEMP) remove_bp(bp->id); // 临时断点命中即自动移除（评审 08-3）
    return bp->id;                                 // 命中 → onHit（经 idIndex 反查）
}
// condEval: 条件表达式求值（地址/寄存器表达式，经 M-17 抽象；评审 P-05）
int condEval(Breakpoint* bp) {
    ExprResult r = exprEngine_eval(bp->cond);      // 解析并求值（地址/寄存器）
    if (r.err) {                                   // 求值失败按未命中；日志限频 ≥1s（评审 08-7）
        if (now - lastCondErrLog >= 1s) { log(WARN, "DBG-BP", "cond eval fail", "E_CTX-08"); lastCondErrLog = now; }
        return 0;
    }
    return r.value != 0;
}
// onHit: 命中回调（源 4.3.1.3；E1 关键控制事件，5.2 图3）
void onHit(BpId id) {
    freezeState();                                 // M-09 暂停冻结（SimState 对齐量子边界，冻结点=指令执行前）
    publish("breakpointHit", id);                  // M-05 E1 可靠投递（ack/重试）
    checkpoint("breakpoint_hit");                  // M-04 检查点（关键事件，RPO ≤2s）
    log(INFO, "DBG-BP", "breakpoint hit", "E_OK");
}

3.3 watch 变量监视（FR-11）

addWatch(expr)：表达式分类（地址/寄存器）后登记 watchList；符号名表达式返回 E_CTX-08（P1 能力，评审 P-05）。求值节奏 = 暂停态即时求值 + 运行态量子边界轮询（节流 ≤200ms 刷新预算）；值变化经 M-05 publish(watchUpdate) 推送前端。伪代码如下：

// addWatch: 注册变量监视（MVP = 地址/寄存器表达式；符号名 → E_CTX-08）
void addWatch(const char* expr) {
    uint8_t kind = classifyExpr(expr);             // 0=地址 / 1=寄存器 / 2=符号名
    if (kind == SYMBOL) return E_CTX-08;           // 符号名监视 P1（依赖 DWARF/栈帧，评审 P-05）
    WatchItem w = { strncpy(w.expr, expr, 63), kind, 0, 0 };
    watchList.insert(w); debugMeta_sync();         // 随 DebugMeta 持久化
}
// watchPoll: 量子边界轮询求值（M-12 节奏驱动；节流 ≤200ms 刷新预算）
void watchPoll(uint64_t now) {
    for (w : watchList) {
        uint32_t v; err_t e = (w.kind == REG)
            ? m17_readReg(w.expr, &v)              // 寄存器（M-17 抽象）
            : m17_readMem(parseAddr(w.expr), 4, &v); // 地址（M-17 抽象）
        uint8_t newErr = (e != OK) ? 1 : 0;        // 本次求值错误标记
        if (newErr == w.evalErr && v == w.lastValue) continue; // 值/错误态均未变，不推
        w.evalErr = newErr;
        if (newErr == 0) w.lastValue = v;          // 仅成功时刷新值
        publish("watchUpdate", w);                 // 值变化 或 evalErr 切换才推（评审 08-9）
    }
}
// removeWatch: 移除监视
void removeWatch(const char* expr) { watchList.erase(expr); debugMeta_sync(); }

3.4 与真实调试器的差异对照表

维度真实硬件调试器（JTAG/GDB）本平台建模（hook 表）差异影响

6.2 边界与降级

（1）QEMU 后端（L1 子集）：RSP Z0 不支持条件断点 cond → 条件断点降级为无条件断点并向前端提示（M-17 17-9）；QEMU 无 hook，命中检测走 M-17 RSP 语义（断点命中经 T05 停止回复交付）——hitCheck/condEval 在 QEMU 下不参与，hitCount 仅本地累计（评审 08-8）。

（2）L1 无 L2 hook：全量指令回调不可用 → 命中检测仍可用（断点为 L1 基础能力）；watch 轮询求值经 RSP 寄存器/内存读命令（qXfer/m），节奏受 RSP 往返限制（尽力而为）。

（3）断点持久化不可用：DebugMeta 写入失败 → 运行态断点表保持可用，告警提示「断点不随会话恢复」；不阻断调试。

（4）前端缺口对账：breakpointHit 事件缺口或命令超时 → 前端主动 reconcile 拉取断点表/暂停状态（5.2 图3）。

（5）命中风暴：断点命中暂停后不自动继续；用户显式 resume 后才再次执行，无自激路径。

7.2 可维护性手段

（1）表驱动断点管理：breakpointTable 单一数据源，命中检测 O(1) 查表，注册/删除/使能只改表与钩子启用位，无隐式状态。

（2）命中检测与回调解耦：hitCheck 只判命中，onHit 只做副作用动作（暂停/上报/检查点），可独立单测。

（3）表达式引擎统一（评审 P-05）：cond 条件与 watch 共用 exprEngine（地址/寄存器表达式），一处解析一处求值，符号名扩展点预留（P1）。

（4）抽象隔离：一切读写经 M-17 抽象（readReg/readMem/bp 注册/bpControl 生命周期，评审 08-2），M-08 无内核感知，双内核替换不影响本模块。

（5）CI 门禁：核心模块单测覆盖率 ≥70%（估算基线，源文档 7.3 表92）；断点用例纳入确定性夹具（同种子同输入序列断言命中行为一致）。

（6）契约层可替换性（源 2.5 对齐）：本模块对外的 driving 端口收敛到 9.1.1 端口契约表，替代实现（替代断点管理器）遵守同端口契约并通过契约测试即可接入。
