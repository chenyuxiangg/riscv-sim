1 功能概述

1.1 模块定位

M-23 数据存储与持久化 DataStore（4.6.4）：公共基础设施——快照、项目、配置、日志归档统一存取；存储适配 IndexedDB（MVP）→ 服务端（P1）；写入原子（临时 + 替换）+ schemaVersion 迁移链；写失败保留内存态 + 提示重试不丢会话；分享用 hash 编码只读链接（含版本标识）；数据以 Project + SimState + DebugMeta 序列化结构为基准。承接 FR-13（项目持久化 / 分享只读链接）、FR-19（反向调试 / 快照存储）；为 M-20 检查点落盘（原子写 + schemaVersion 迁移，RPO ≤2s / 保留 ≥5 由 M-20 触发侧保障）、M-21 日志归档分块导出、M-22 诊断包归档（归档区独立于检查点保留区，20-8）提供统一存储。P1 演进：服务端存储适配、M-19 长回看 spool、FR-24 Topology 持久化（多 Board 实例 / 拓扑配置）。

2 数据描述

2.1 核心数据结构（源文档表83）

数据结构/数据项类型定义与用途

2.1.1 复杂结构字段定义

持久化数据以 Project + SimState + DebugMeta 序列化结构为基准（4.6.4.1）；快照载荷与 M-20 Snapshot{cpMeta, m13State, m14Map, m15Periph} 对齐；原子写对象携带临时态标记；hash 只读链接含版本标识（分享只读，不含可写凭据）。字段定义如下：

// Project: 项目持久化结构（FR-13；saveProject/loadProject 载荷）
struct Project {
  string  projectId;            // 项目 id
  string  name;                 // 项目名
  uint32  version;              // schemaVersion（对齐迁移链）
  Topology topology;            // 拓扑/Board 配置（FR-24，P1 持久化；MVP 空）
  Snapshot snap;                // 最近快照引用（运行状态，对齐 M-20 Snapshot）
  DebugMeta debug;              // 调试元数据（项目级独立持久化，见下）
};
// Snapshot: 快照载荷（23-1 双侧对齐：与 M-20 v1.1 Snapshot 结构完全一致，含 cpMeta.id/version）
//   入参形态 = M-20 完整 Snapshot 单对象（m23SaveSnapshot(snap)/m23LoadSnapshot(cp) 同契约）
struct Snapshot {
  Checkpoint cpMeta;            // 检查点元数据（id/tVirt/tHost/baseSeq/version，M-20 定义）
  M13State  m13State;           // M-13 寄存器/内存序列化
  M14Map    m14Map;             // M-14 总线/内存映射表
  M15Periph m15Periph;          // M-15 外设状态
};
// DebugMeta: 调试元数据（断点/符号/源码映射）——项目级独立持久化（23-8）
//   归属声明：不随快照回滚；快照恢复只回灌运行状态（M-13/14/15）；
//   断点表与 M-08↔M-04 锚点对齐（会话重建按 addr 重注册 + id 重映射）
struct DebugMeta {
  Breakpoints bps;              // 断点集（地址/条件）
  SymbolTable syms;             // 符号表
  LineMap    lines;             // 源码行映射（DWARF）
};
// StoreAdapter: 存储适配（IndexedDB MVP / 服务端 P1，接口不变）
interface StoreAdapter {
  open(name) -> Handle;         // 打开存储库（失败可降级，见 3.6）
  get(key)  -> Value?;          // 读对象（含 schemaVersion 检查）
  set(key, obj);                // 写对象（走 atomicWrite 原子语义）
  del(key); clear(scope);       // 删除/清理
  tx(keys)  -> Tx;              // 事务原语（del+put 同事务提交，23-2 replace 实现基础）
};
// AtomicWrite: 原子写对象（临时写 → 摘要校验 → 替换）
struct AtomicWrite {
  string  tempKey;              // 临时对象键（写失败残留可清理，不污染正式键）
  string  finalKey;             // 正式对象键（校验通过后替换）
  bytes   digest;               // 内容摘要（写入时计算，读回比对，23-3 免全量读回）
  uint32  schemaVersion;        // 本次写入版本（触发迁移链）
};
// HashLink: hash 编码只读分享链接（含版本标识，分享只读不写）
struct HashLink {
  string  token;                // hash 令牌（只读，不含可写凭据）
  uint32  version;              // 版本标识（旧版本链接打开时校验提示）
  string  scope;                // 范围标识（project / snapshot / archive）
};
// ExportFilter: 日志/数据分块导出过滤器（23-7；M-21 归档对接参数）
struct ExportFilter {
  Range   timeRange;            // 时间范围 {tStart, tEnd}（宿主时间）
  Level[] levels;               // 级别过滤（INFO/WARN/ERROR…，空=全部）
  string[] channels;            // 通道过滤（日志类别/数据通道，空=全部）
  uint32  chunkSize;            // 分块大小（估算基线 64 KiB/块）
};
// ArchiveKit: 归档区条目（m23Archive；归档区独立于检查点保留区，20-8）
struct ArchiveKit {
  uint32_t errCode;             // 错误码（诊断包取证要素，M-22）
  Snapshot  snap;               // 快照（M-20）
  InputSeq  inputs;             // 稀疏输入序列（M-20）
  uint64_t  tHost;              // 归档宿主时间（归档不可被回退覆盖）
};
// 归档区 MVP 清理策略（23-9）：保留最近 32 条（环形丢最旧 + WARN），配额治理 P1 扩展

2.3 数据流说明

处理流程（4.6.4.4）：写 = 序列化 → 临时写 → 校验 → 替换 → 确认（失败保留内存态 + 重试）；读 = 读对象 → 版本检查 → 迁移 → 反序列化；分享 = hash 只读链接（含版本标识）。调用方按表86 唯一入口接入（M-04/M-20/M-21/M-22 经 save/load/export/m23Archive 能力接口），禁止绕过 DataStore 自行持久化。

3 实现设计

3.1 saveProject()/loadProject() 项目保存/恢复

saveProject/loadProject（FR-13）：项目 + 配置统一序列化（Project 结构），经 atomicWrite 原子落盘；保存成功返回 hash 只读链接（含版本标识，分享只读不写）；读取时先版本检查，命中旧版本走 migrate 迁移链。M-04 为调用方（项目保存/恢复）。伪代码如下：

// saveProject: 项目保存（表84；FR-13；输入：Project；输出：确认 + hash 只读链接）
HashLink saveProject(Project p) {
  p.version = schemaVersion;                    // 写前锁定当前 schema 版本
  ok = atomicWrite("project:" + p.projectId, p);// 原子写（临时 + 替换）
  if (!ok) return null;                         // 失败保留内存态 + 提示重试（3.3/6.1）
  return hashLink(p.projectId, schemaVersion);  // hash 只读链接（含版本标识，4.6.4.1）
}
// loadProject: 项目恢复（表84；读对象 → 版本检查 → 迁移 → 写回 → 反序列化）
Project? loadProject(string projectId) {
  raw = store.get("project:" + projectId);      // 读对象（StoreAdapter）
  if (raw == null) return null;
  if (raw.version < schemaVersion) {            // 版本检查：旧版本走迁移链
    raw = migrate(raw.version);                 // 逐版本升级（3.4），不静默错读
    atomicWrite("project:" + projectId, raw);   // 23-6：迁移成功后原子写回（迁移即升级持久化）
  }
  return deserialize(raw);                      // 反序列化（校验失败 → 明确拒绝 + 提示）
}
// 分享语义：hash 链接只读（token 不含可写凭据），打开旧版本链接 → 版本校验提示升级

3.2 saveSnapshot()/loadSnapshot() 快照原子写/读取

saveSnapshot/loadSnapshot（FR-19）：入参为 **M-20 Snapshot 完整对象**（含 cpMeta{id,tVirt,tHost,baseSeq,version}，23-1 双侧对齐，单对象形态）；键 = "snap:" + cpMeta.id（23-5）；DebugMeta **不并入快照载荷**——项目级独立存储（23-8）；快照保留 ≥5 裁剪归 M-20 触发侧，M-23 仅按显式删除指令清理（23-4）。伪代码如下：

// saveSnapshot: 快照原子写（表84；FR-19；输入：M-20 Snapshot 完整对象；输出：确认 + cpId）
Result saveSnapshot(Snapshot snap) {
  ok = atomicWrite("snap:" + snap.cpMeta.id, snap);  // 键 = cpMeta.id（23-5）；原子写（临时+替换）
  if (!ok) {                                    // 写失败 → 保留内存态 + 重试 ≤3 + 提示（6.1）
    return { ok:false, code:"WRITE_RETRY", cpId: snap.cpMeta.id };
  }
  return { ok:true, cpId: snap.cpMeta.id };     // M-20 restore 按 cpId 恢复（含 cp.id，23-1）
}
// loadSnapshot: 快照读取（表84；M-20 恢复读取；输入：cpId；输出：Snapshot 状态体）
Snapshot? loadSnapshot(string cpId) {
  raw = store.get("snap:" + cpId);              // 键 = cpMeta.id（23-5 键映射约定）
  if (raw.cpMeta.version < schemaVersion) {     // 版本检查 → 迁移 → 写回（23-6）
    raw = migrate(raw.cpMeta.version);
    atomicWrite("snap:" + cpId, raw);
  }
  return deserialize(raw);                      // 反序列化 → M-20 回灌 M-13/14/15
}
// 双侧对齐锚点（23-1）：M-20 m23SaveSnapshot(snap)/m23LoadSnapshot(cp) = 本契约（单对象形态、
//   载荷 = Snapshot{cpMeta,m13State,m14Map,m15Periph}，两侧结构完全一致）
// DebugMeta 独立存储（23-8）：键 "pdebug:" + projectId（项目级，不随快照回滚）；
//   快照恢复只回灌运行状态，断点表对齐 M-08↔M-04 会话重建锚点
// 保留裁剪单一权威（23-4）：M-20 checkpointList 维护保留 ≥5 并按需显式删除
//   （m23DeleteSnapshot(cpId)）；saveSnapshot 内不做 trim（双归属消除）
// 快照类存储不随 IndexedDB 降级（localStorage 仅存轻量状态，见 3.6/6.2）

3.3 atomicWrite(obj) 原子写实现

atomicWrite（表83/84）：临时写 → **摘要校验** → 替换；失败保留内存态 + 重试（≤3 次）+ 提示，不丢会话（4.6.4.5）；replace 底层为 IndexedDB **单事务 del+put 同事务提交**（23-2）；校验用内容摘要（hash）比对、免全量读回（23-3）。伪代码如下：

// atomicWrite: 原子写实现（表83；临时写 → 摘要校验 → 替换；失败保留内存态 + 重试 ≤3 + 提示）
bool atomicWrite(string finalKey, Object obj) {
  tempKey = finalKey + ".tmp";                  // 临时对象键（写失败残留可清理）
  digest = hash(obj);                           // 23-3：写入时计算内容摘要（免全量读回）
  for (try = 0; try < 3; try++) {
    if (!store.set(tempKey, {obj, digest})) {   // ① 临时写（事务失败 → 保留内存态 + 重试）
      continue;                                 // 内存态由调用方保留（不丢会话，4.6.4.5）
    }
    if (!validate(store.get(tempKey), digest)) { // ② 摘要校验（读回比对 hash，非全量比对）
      store.del(tempKey); continue;             // 校验失败清理临时键，重试
    }
    store.tx([finalKey, tempKey])               // ③ 替换 = 单事务 del(finalKey)+put(tempKey 内容)
      .del(finalKey).put(finalKey, read(tempKey))
      .commit();                                // 23-2：IndexedDB 无"替换"原语，del+put 同事务提交
    store.del(tempKey);
    return true;
  }
  return false;                                 // 终态：提示重试 + 内存态保留（6.1）
}
// 临时键语义：任何失败步骤后正式键不受污染；残留 .tmp 由下次 gcTempKeys() 清理
// 23-3 开销口径：摘要校验 = 1 次写 + 1 次小读（hash 比对），大对象（快照/内存序列化）无全量读回

3.4 migrate(fromVer) schema 迁移链

migrate（表84）：schemaVersion 迁移链，逐版本升级；版本跳跃按链式逐步迁移；目标版本不兼容（缺迁移路径）→ 明确拒绝 + 升级路径提示，不静默错读（4.6.4.5）；**迁移成功后由调用方原子写回持久化**（23-6，迁移即升级，避免重复迁移与旧数据残留）。伪代码如下：

// migrate: schema 迁移链（表84；输入：旧版本；输出：迁移后的数据）
Object migrate(uint32 fromVer) {
  cur = readRaw(fromVer);                       // 读旧版本原始对象
  for (v = fromVer; v < schemaVersion; v++) {
    fn = MIGRATIONS[v];                         // 迁移注册表（v → v+1 变换函数）
    if (fn == null) {                           // 缺迁移路径 → 不兼容
      return { err:"MIGRATE_INCOMPATIBLE", from:fromVer, to:schemaVersion };  // 明确拒绝 + 升级路径
    }
    cur = fn(cur);                              // 逐版本升级（字段增删/语义变换）
  }
  cur.version = schemaVersion;
  return cur;
}
// 不静默错读：缺迁移路径 / 反序列化失败 → 明确拒绝 + 提示升级（4.6.4.5）
// 迁移注册表 MIGRATIONS[v]：每版本一函数（MVP v1 → v2 起步，后续版本只增不删）

3.5 export() 与归档（m23Archive）

export（表86）：M-21 日志导出/归档分块导出（ExportFilter 过滤 + 分块大小 + 进度回调 + 续导锚点，23-7）；M-19 P1 长回看 spool 复用同一存储适配（分块读写）；m23Archive：诊断包/现场包归档区独立于检查点保留区（20-8：归档不被后续回退覆盖，M-20/M-22 引用）；归档区 MVP 保留最近 32 条（环形丢最旧 + WARN，23-9）。伪代码如下：

// export: 日志分块导出/归档（表86；M-21 调用；ExportFilter 过滤 + 分块 + 进度 + 续导锚点）
ExportHandle export(ExportFilter filter) {

             .withChunkSize(filter.chunkSize);    // 23-7：分块大小（估算基线 64 KiB/块）

    checkVersion(block);                          // 扫描对象逐件版本检查 → 迁移 → 写回（23-6 语义）

  }
  return { handle, nextOffset, progress };
}
// M-19 P1 长回看 spool：复用同一存储适配（分块写/读，同 schemaVersion 迁移链）
// m23Archive: 诊断包/现场包归档（20-8；归档区独立于检查点保留区）
Result m23Archive(ArchiveKit kit) {

}

// 23-9 口径：归档区 MVP = 保留最近 32 条 + 容量告警；配额治理 P1 扩展

atomicWrite(obj)提供（driving）临时写 → 摘要校验 → 替换（单事务 del+put 提交，23-2/23-3）；失败保留内存态 + 重试 ≤3 + 提示（不丢会话）
migrate(fromVer)提供（driving）输入：旧版本；输出：迁移后的数据；成功后原子写回（23-6）；缺路径 → E_PROTO-01 明确拒绝 + 升级路径
export()提供（driving）ExportFilter{timeRange,levels,channels,chunkSize} 过滤 + 分块（64 KiB/块）+ 进度 + 续导锚点（23-7；M-21 日志归档；M-19 P1 spool 复用）
m23Archive(kit)提供（driving）归档区独立于检查点保留区（20-8，M-20/M-22 引用）；MVP 保留最近 32 条 + WARN（23-9）
m23DeleteSnapshot(cpId)提供（driving）快照显式删除（23-4：保留裁剪单一权威归 M-20 触发侧，M-23 仅按显式指令清理）
M-04依赖（driven）触发：检查点触发与恢复读取、项目保存/恢复（FR-13）
M-20依赖（driven）快照内容：SimState 载荷（Snapshot{cpMeta,m13State,m14Map,m15Periph}）
M-21依赖（driven）日志归档：export 分块导出契约
M-04被依赖（使用方）项目/配置持久化（saveProject/loadProject，FR-13）
M-20被依赖（使用方）快照存取（saveSnapshot/loadSnapshot 原子写 + 迁移）
M-21被依赖（使用方）日志归档（export）
M-19被依赖（使用方）P1 长回看 spool（复用同一存储适配）

9.2 日志对接（M-21）

项目保存 → log(INFO, "M23", "project_save", projectId/version)；项目恢复 → log(INFO, "M23", "project_load", projectId/version)；快照落盘 → log(INFO, "M23", "snap_save", cpId/tHost)；快照读取 → log(INFO, "M23", "snap_load", cpId/version)；快照删除 → log(INFO, "M23", "snap_del", cpId)；迁移 → log(INFO, "M23", "migrate", fromVer/toVer)；写失败 → log(WARN, "M23", "write_retry", key/try)；降级 → log(WARN, "M23", "storage_degrade", "localStorage")；归档 → log(DEBUG, "M23", "archive", tHost)；归档清理 → log(WARN, "M23", "archive_trim", count)。日志条目含虚拟+宿主双时间戳与会话关联（P-22）；产品/嵌入式工作台不可见（角色边界，§3.4）。
