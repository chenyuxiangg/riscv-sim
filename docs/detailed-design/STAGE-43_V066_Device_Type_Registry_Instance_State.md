## §1 为什么要做这一批

### §1.1 用户拍板的四点架构（**原文**）

| # | 点 | 落点 |
| --- | --- | --- |
| 1 | 每个版本系统支持的**器件类型为固定的** | 内核侧**器件类型注册表**（类型 = 功能逻辑 + 内存布局 + 参数合法域） |
| 2 | 用户**只能根据系统支持的器件类型实例化器件** | 前端的器件类型清单**必须**来自内核（不许自己抄一份） |
| 3 | 器件实例化之后，**前端和内核需要通过一个中间层桥接两者，完成状态关联** | 中间层 = **内核侧**的装配层（用户拍板） |
| 4 | 前端定义开发板**包括哪些器件实例**；内核实现器件类型的**功能逻辑**（Rust）与**内存布局**（**只定义偏移**，集成时绑定到任意基址）；**中间层**负责把实例绑到具体基址 + 按前端定义的 **pin 连接**路由器件间通信 | 内核侧装配层 |

### §1.2 定案事实（**逐条读源码**，不是推断）

| # | 事实 | 出处 |
| --- | --- | --- |
| F-1 | 契约层 `DeviceSpec` 是**封闭枚举 4 变体**（`gpio` / `uart16550` / `clint` / `plic`）⇒ ⇒ 「类型集合固定」**已成立** | `crates/contract/src/platform.rs:376` |
| F-2 | 内核 m15 实现的是 **5 种**（多一个 `timer_riscv`）⇒ ⇒ **两侧集合不对齐**：`build_device` 没有 timer 分支 ⇒ ⇒ **定时器无法被用户实例化** | `crates/kernel/src/m15_peripheral/mod.rs:41-45`、`crates/kernel/src/kernel_host/platform.rs:287` |
| F-3 | 前端 `DEVICE_KINDS` 是**前端自己抄的 4 个字面量** ⇒ ⇒ 契约层加变体前端**不会**自动跟上 ⇒ ⇒ **第二个真相源** | `front/views/components/memory-map.js:132` |
| F-4 | `PeripheralRegistry`（按 id 索引实例、向总线与引擎发**同一个** `SharedPeripheral` 句柄）**已存在但全仓零引用** ⇒ ⇒ 中间层的现成落点是**闲置的** | `crates/kernel/src/m15_peripheral/mod.rs:136` |
| F-5 | `Peripheral` trait 的寄存器访问**本来就是偏移相对**的（`read(offset, size)` / `write(offset, …)`）⇒ ⇒ 「布局只定义偏移」**内核这半边已经成立** | `crates/contract/src/port.rs:185` |
| F-6 | 总线分派时算 `addr - region.base` ⇒ ⇒ 偏移语义在**总线层**闭合 | `crates/kernel/src/m14_bus/mod.rs:2146` |
| F-7 | 各器件模型的寄存器偏移**已是类型级常量**（`Uart16550::THR = 0x0` … `SCR = 0x7`、`UART_WINDOW = 0x8`；`GPIO_WINDOW = 0x10`；`CLINT_WINDOW = 0x1_0000`；`PLIC_WINDOW = 0x21_0000`；`TIMER_WINDOW = 0x10`）⇒ ⇒ 「偏移只写一处」的原料**已在** | `crates/kernel/src/m15_peripheral/{uart,gpio,clint,plic,timer}.rs` |
| F-8 | 契约层 `wiring` 是**器件事件级**（`from.device` + `from.event`，词表**只有** `rx_ready`）且**目标端只允许 PLIC**（V-19）⇒ ⇒ **不是 pin 级** | `crates/contract/src/platform.rs:270-330` |
| F-9 | 内核路由是宿主**硬编码窄口**：`compile_wiring` 最后 `table.retain(...)` **只保留 UART→PLIC 一条** | `crates/kernel/src/kernel_host/platform.rs:562-568` |
| F-10 | 前端**不暴露** `wiring` 编辑 UI ⇒ ⇒ 「从界面提交的板永远没有 `wiring`」是**已知边界** | `front/views/components/memory-map.js:60` |
| F-11 | 器件参数的**合法上下界**已在契约层（`MAX_PLIC_SOURCES = 1024` / `MAX_PLIC_CONTEXTS = 16` / `MAX_CLINT_HARTS = 4096` / `MAX_CLINT_FREQ_HZ = 1 THz`）⇒ ⇒ 注册表**引用**那一份，**不写第二份** | `crates/contract/src/platform.rs:125-151` |
| F-12 | 内核建图前先 `description.validate()` ⇒ ⇒ **描述不合规 ⇒ 一个区域都不留**（原子）⇒ ⇒ 「某个实例建不起来」**今天没有可达路径** | `crates/kernel/src/kernel_host/platform.rs:343` |
| F-13 | `memory.map` 事件在**每次建图后**推送 ⇒ ⇒ 「随建图变化的状态」的推送时机**已有先例** | `crates/kernel/src/kernel_host/mod.rs:2802` |

### §1.3 本批的**唯一目标**

> **把「内核支持哪些器件类型」与「每个器件实例绑到了哪个基址」这两件事，从「散在前端与描述里的手抄」变成「内核侧注册表 + 逐实例状态」这一份真相，并让前端看得见。**

⇒ ⇒ 本批**不**动「基址由中间层分配」（那是描述格式变更 ⇒ 破坏性 ⇒ 顺延），**不**做 pin 路由，**不**做 MCU。

## §2 契约层新增面（**逐字冻结**）

### §2.1 新增 DTO：**四个**（住 `crates/contract/src/model.rs`）

```rust
/// 一个器件类型的描述（**内核侧权威**）。
pub struct DeviceTypeInfo {
    /// 器件类型名（`DeviceSpec` 的标签名，如 `"uart16550"`）。
    pub kind: String,
    /// 寄存器窗口大小（字节）—— **由类型自报**（裁决 C）。
    pub window_bytes: u32,
    /// 该类型的**寄存器偏移表**（**只定义偏移**，不含基址 —— 裁决 D）。
    pub registers: Vec<DeviceRegisterInfo>,
    /// 该类型的**实例参数**及其合法取值域（裁决 E）。
    pub params: Vec<DeviceParamInfo>,
}

/// 一个寄存器（**偏移**，不是地址）。
pub struct DeviceRegisterInfo {
    pub name: String,
    pub offset: u32,
    pub width_bits: u32,
}

/// 一个实例参数 + 它的合法取值域（**区间引用契约层那一份**，裁决 E）。
pub struct DeviceParamInfo {
    pub name: String,
    pub min: Option<u64>,
    pub max: Option<u64>,
}

/// 一个器件实例的**状态关联**（逐实例 —— 裁决 B）。
pub struct DeviceInstanceInfo {
    /// 实例 id（描述里的器件 `id`）。
    pub id: String,
    /// 器件类型。
    pub kind: String,
    /// **绑定的绝对基址** —— `None` ⇒ 该实例在**用户的板**里但**尚未生效**（裁决 F）。
    pub base: Option<u32>,
    /// 寄存器窗口大小（字节）。
    pub window_bytes: u32,
}
```

⚠️ **状态只有两种，且由 `base` 的有无唯一决定** ⇒ ⇒ **不另设状态字段** ⇒ ⇒ 不是第二个真相（裁决 F）。

### §2.2 新增命令：**两条**

```rust
// crates/contract/src/protocol.rs · CommandPayload
/// 列出**内核支持的器件类型**（类型注册表）。
///
/// ⚠️ 回复是 [`EventPayload::DeviceTypes`]。
ListDeviceTypes,

/// 列出**逐实例状态**（每个实例绑到了哪个基址 / 是否已生效）。
///
/// ⚠️ 回复是 [`EventPayload::DeviceInstances`]。
ListDeviceInstances,
```

### §2.3 新增事件：**两条**

```rust
// crates/contract/src/protocol.rs · EventPayload
/// 器件类型注册表（**内核支持什么**）。
DeviceTypes {
    types: Vec<crate::model::DeviceTypeInfo>,
},

/// 逐实例状态（**每个实例绑到哪儿了**）。
DeviceInstances {
    instances: Vec<crate::model::DeviceInstanceInfo>,
},
```

### §2.4 topic：**两个**

| 事件 | topic | 说明 |
| --- | --- | --- |
| `DeviceTypes` | `device.types` | **静态**（由内核代码决定）⇒ ⇒ 只在**订阅后**推一次 |
| `DeviceInstances` | `device.instances` | **动态**（随建图变化）⇒ ⇒ **每次建图后**推（与 `memory.map` 同一时机，裁决 G） |

⚠️ 两个字面量必须与前端 `front/lib/message.js` 的 `EVENT_TOPIC` **逐字一致**。

### §2.5 版本号

| 版本号 | 本批 | 为什么 |
| --- | --- | --- |
| `SCHEMA_VERSION` | **9 → 10** | 两条新命令 + 两条新事件 ⇒ ⇒ **信封形状变了** |
| `SIM_STATE_SCHEMA_VERSION` | 仍 **2** | 快照载荷**没变** |
| `PLATFORM_SCHEMA_VERSION` | 仍 **1** | **描述格式一个字段都没改** ⇒ ⇒ **存量板档案不受影响** |
| `PLATFORM_RULES_VERSION` | 仍 **3** | **合法性规则一条都没收紧**（本批零新判据 ⇒ 零新场景码） |

## §3 裁决 A~N

| # | 裁决 | 理由 |
| --- | --- | --- |
| **A** | **中间层放在内核侧**（Rust）—— 落点是 M-15（类型注册表）+ 宿主（装配与逐实例状态） | **用户拍板**；且内核侧已有闲置的 `PeripheralRegistry`（F-4）⇒ ⇒ 不用另起进程/服务 |
| **B** | **状态关联逐实例**（不是板级） | **用户拍板**；板级已有 `memory.map` 事件 ⇒ ⇒ 逐实例是**新增的那一份** |
| **C** | 窗口大小**由类型自报**（注册表抄**器件模型那一份常量**，不新造） | 「一约束一落点」⇒ ⇒ 偏移/窗口**只写一处** |
| **D** | 寄存器表**只含偏移**，**不含基址** | 点 4 明写「只定义偏移，需要支持在集成时绑定到任意基地址」⇒ ⇒ 基址是**装配期**的事，不是**类型**的事 |
| **E** | 参数合法域**引用契约层那四个常量**（`MAX_PLIC_*` / `MAX_CLINT_*`）⇒ ⇒ 前端**不写第二份区间表** | 与 v0.30 批「区间值只在内核的消息里给出」同一条规矩 |
| **F** | 实例状态**只有两种**，由 `base: Option<u32>` 唯一决定 ⇒ ⇒ **不另设状态字段** | F-12：今天「某个实例建不起来」**没有可达路径**⇒ ⇒ 加一个 `Failed` 变体就是**死代码**⇒ ⇒ 本批只报**可达**的事实 |
| **G** | `DeviceInstances` 在**每次建图后**推（与 `memory.map` **同一时机**、**同一个落点函数**） | F-13 先例 ⇒ ⇒ 前端**不轮询** |
| **H** | 类型集合的**权威在内核**；契约层的 `DeviceSpec` 变体集合是**「描述能写什么」**的清单 ⇒ ⇒ 两者**必须一致** ⇒ ⇒ 加一条**跨层自检**（可实例化的类型 ⊆ 注册表里的类型） | F-1 / F-2 / F-3 ⇒ ⇒ 「可实例化 ⊆ 已实现」是**安全方向**的硬约束 |
| **I** | 前端 `DEVICE_KINDS` **保留**（它是「描述能写什么」的前端副本 + 参数默认值）⇒ ⇒ 但**加一条跨层门禁**断言它 == 契约层的变体集合 ⇒ ⇒ 漂移**变红** | 本批**不**把前端改成「查内核」（编辑器要的是**可实例化**的那 4 种，不是内核实现的 5 种）⇒ ⇒ 见裁决 H 的分工 |
| **J** | `timer_riscv` **照实注册**（内核实现了它）⇒ ⇒ 但**它不在 `DeviceSpec` 里** ⇒ ⇒ 前端能看见「内核有定时器，描述格式还写不出来」⇒ ⇒ 登记为 **D-175 的子项** | F-2 ⇒ ⇒ **不假装**内核没有定时器；⛔ 本批**不**扩 `DeviceSpec`（那是描述格式变更 ⇒ 破坏性 ⇒ 顺延） |
| **K** | 实例清单的**范围** = **用户的板**（`user_board`）**优先**，没有用户板时 = **当前生效的图** | 点 3 说的是「前端定义的器件实例」⇒ ⇒ 前端定义的那份才是主角；⚠️ 用户的板**跨 `LoadProject` 保持** ⇒ ⇒ 改板后能看见「哪些实例还没生效」 |
| **L** | 逐实例的 `base`：**在生效图里且基址相同** ⇒ `Some(base)`；**否则** ⇒ `None`（待生效） | 单一判据 ⇒ ⇒ 「已绑定 / 待生效」由**一个字段**表达 ⇒ ⇒ 不用两个字段互相推导 |
| **M** | 本批**零新场景码** | 只读查询 ⇒ ⇒ 不判错 ⇒ ⇒ 零新码 ⇒ ⇒ `PLATFORM_RULES_VERSION` 不动 |
| **N** | 本批**不改** `RegionSpec::Peripheral.base` ⇒ ⇒ **前端仍然手填基址** | 「基址由中间层分配」要动描述格式 ⇒ ⇒ 破坏性 ⇒ ⇒ 顺延到下一批；⚠️ 但**本批把「偏移」这件事在内核侧立住**（注册表列出偏移）⇒ ⇒ 下一批拆 `base` 时**有据可依** |

## §4 内核侧新增面

### §4.1 M-15：器件类型注册表（**新文件** `types.rs`）

```rust
/// 器件类型注册表 —— **内核支持什么**的那一份真相。
pub struct DeviceTypeRegistry { entries: Vec<DeviceTypeEntry> }
```

⇒ ⇒ 每种类型注册：`kind` · `window_bytes`（抄器件模型的常量）· `registers`（**偏移 + 名字**）· `params`（**引用契约层常量**）。
⇒ ⇒ **零新状态**：注册表是**静态**的 ⇒ ⇒ 每次查询现算 ⇒ ⇒ 不是第二份存储。

### §4.2 宿主：逐实例状态

- 宿主新增字段 `device_instances: Vec<model::DeviceInstanceInfo>`；
- `map_platform` 建图时**顺带**产出实例清单（**谁、什么类型、哪个基址、多大窗口**）⇒ ⇒ 与**建图结果同源** ⇒ ⇒ 不另算一遍；
- 建图后（**同一时机**）推 `DeviceInstances` 事件。

### §4.3 宿主：两条命令

- `ListDeviceTypes` ⇒ 回 `EventPayload::DeviceTypes { types }`（**注册表现算**）；
- `ListDeviceInstances` ⇒ 回 `EventPayload::DeviceInstances { instances }`。

## §5 界面落点（**产品视图** · M-02）

产品视图新增**两张卡**（与既有的「产品树」「内存映射 (M-14)」并列）：

| 卡 | 内容 | 数据源 |
| --- | --- | --- |

⚠️ **前端不判参数合法性** ⇒ 只**显示**内核给的区间。
