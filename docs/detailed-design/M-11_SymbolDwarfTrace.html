1 功能概述

1.1 模块定位

M-11 符号表/DWARF、反汇编·源码联动与 trace 记录/导出（4.3.4）：消费 M-06 的符号表与行映射，将 text 段反汇编为（地址, 机器码, 助记符）序列；无 DWARF 时反汇编区独立可用（PC 高亮，V-12），含 DWARF 时单步联动源码高亮。指令/访存 trace 记录（可整体关闭的性能开关）与 CSV/VCD/JSON 导出（FR-10/14）。内部拆分为两个子组件控制复杂度（对齐架构 WBS：DWARF 解析为 10 人日最大风险项，评审 P-07）：① DWARF 解析子组件（行表解析、地址→行查询、源码路径归一）；② 反汇编渲染子组件（助记符渲染、PC 高亮、源码联动 UI）。

2.1.1 复杂结构字段定义

disasmCache 按地址索引反汇编条目（对齐 M-13 13-6：写内存失效对应 pc，自修改代码不命中陈旧解码）；traceBuffer 为环形缓冲（对齐 M-21 溢出丢最旧语义）；exportFormat 为导出格式枚举。字段定义如下：

// disasmEntry: 反汇编缓存条目（表47；缓存失效键 = 指令地址）
struct disasmEntry {
  uint32_t addr;          // 指令地址
  uint32_t code;          // 机器码（16/32 位原码，压缩指令保留原码，对齐 M-13 13-1）
  char     mnemonic[32];  // 助记符（内置 RV32IMC opcode→助记符映射表渲染）
  uint8_t  width;         // 指令宽度：2（压缩）/ 4（标准）
};
// traceBuffer: 指令/访存 trace 环形缓冲（表47；可整体关闭性能开关）
struct traceBuffer {
  TraceEntry buf[T_CAP];  // 定长环形缓冲（默认 T_CAP=10⁵ 条目，估算基线实现后实测校准）
  uint32_t   head;        // 写游标（满时新条目写旧 head 位置后再前移，11-2：每次仅丢一条最旧）
  uint32_t   count;       // 当前条目数
  uint32_t   dropped;     // 溢出丢弃计数（只计数不告警风暴）
  uint8_t    enabled;     // 性能开关：0=整体关闭（零开销），1=开启（R9 降速提示）
};
// TraceEntry: trace 条目（指令/访存，FR-14）
struct TraceEntry {
  uint64_t time_virt;     // 虚拟时间（M-12 权威时钟，确定性可重放）
  uint32_t addr;          // 指令地址或访存地址
  uint8_t  kind;          // 0=指令执行 / 1=访存读 / 2=访存写
  uint32_t data;          // 指令机器码或访存值
  uint8_t  width;         // 访存宽度（指令条目=0）
};
// TraceEvent: trace 输入事件（11-6：kind 来源与映射规则）
//   kind=0 指令执行：来自 M-17 onInstruction 钩子（data=指令机器码，width=0）
//   kind=1 访存读 / kind=2 访存写：来自 M-18 访存事件流 attachTrace 上报 {t, addr, dir, width}
//   dir=0 映射 kind=1（读）、dir=1 映射 kind=2（写）
struct TraceEvent {
  uint64_t time_virt;     // 虚拟时间（M-12 权威时钟，确定性可重放）
  uint32_t addr;          // 指令地址或访存地址
  uint8_t  kind;          // 0=指令 / 1=访存读 / 2=访存写（映射规则见上）
  uint32_t data;          // 指令机器码或访存值
  uint8_t  width;         // 访存宽度（指令条目=0）
};
// LineRef: 地址→行查询结果（表48；区分降级与未命中，11-4）
//   无 DWARF（降级）→ {file:NULL, line:0}
//   行表查询未命中       → {file:NULL, line:0xFFFFFFFF}
struct LineRef { char* file; uint32_t line; };
// ExportHandle: 分块导出句柄（11-7 续导协议；offset 单位=条目数）
struct ExportHandle {
  uint64_t offset;        // 本块起点（条目偏移）
  uint64_t nextOffset;    // 下一块起点（调用方下次续传的 offset 参数）
  uint64_t total;         // 筛选命中总条目数
  uint64_t bytes;         // 本块序列化字节数
};
// exportFormat: enum { CSV=0, VCD=1, JSON=2 }

2.3 数据流说明

联动流：M-06 loadELF → 符号/行映射构建 → disasmCache 填充（经 M-17 readMem 取指 + 内置解码表）→ 前端反汇编渲染（PC 高亮，V-12）→ 单步联动 resolveLine 源码高亮。
trace 流：M-17 onInstruction 钩子（kind=0）/ M-18 访存事件流（attachTrace 上报 {t, addr, dir, width} → dir 映射 kind=1 读 / kind=2 写，11-6）→ recordTrace 统一写入 traceBuffer（性能开关）→ exportTrace 筛选 → CSV/VCD/JSON 分块导出（FR-14）。

3 实现设计

3.1 disasm(addr, count) 反汇编序列生成

disasm(addr, count)：disasmCache 命中直返；未命中经 M-17 readMem 取指 → 内置 RV32IMC 解码映射表生成助记符 → 写入缓存后继续。未映射地址返回宿主侧失败事件（对齐 M-10 10-5），提前结束序列（非错误）。伪代码如下：

// disasm: 反汇编序列生成（4.3.4.3 表48；缓存优先；宽度判定 11-1）
list<disasmEntry> disasm(uint32_t addr, uint32_t count, err_t* err) {
  list<disasmEntry> out;
  if (count > MAX_DISASM_COUNT) return E_CTX-03;     // count 上限防御（11-10）
  for (i = 0; i < count; i++) {
    if (disasmCache contains addr) {                 // 命中直返（对齐 M-13 13-6 失效语义）
      out.add(disasmCache[addr]); addr += disasmCache[addr].width; continue;
    }
    uint16_t low = m17_readMem(addr, 2, err);        // 先读 2 字节判宽度（text 段 2 字节对齐下不跨界）
    if (*err == E_BUS-01) break;                     // 未映射 → 宿主侧失败，提前结束（10-5 语义）
    uint8_t width = ((low & 0b11) != 0b11) ? 2 : 4;  // 低 2 位 ≠0b11 → 压缩（2 字节），否则 4 字节
    uint32_t code = low;                             // 压缩指令：code 取 16 位原码（对齐 M-13 13-1）
    if (width == 4) code = m17_readMem(addr, 4, err); // 4 字节指令补读完整
    disasmEntry e = decode_mnemonic(code, width);    // 内置 RV32IMC opcode→助记符映射表
    e.addr = addr; e.code = code;
    disasmCache[addr] = e; out.add(e);
    addr += width;                                   // 2（压缩）/ 4（标准）
  }
  return out;                                        // 输出：指令行序列（长度<count 即截断，11-3）
}

3.2 resolveLine(addr) 地址→源码行解析

resolveLine(addr)：经 DWARF 解析子组件行表查询（地址→行，行表 ≤2×10⁵ 条，L3/P-12 二分查找）；无 DWARF 返回空（降级仅反汇编 + 符号表，4.3.4.5）。伪代码如下：

// resolveLine: 地址→源码行解析（4.3.4.3 表48；区分降级与未命中，11-4）
LineRef resolveLine(uint32_t addr) {
  if (!dwarfSub.ready) return {file: NULL, line: 0};         // 无 DWARF → 降级（4.3.4.5）
  return dwarfSub.queryLine(addr) or {file: NULL, line: 0xFFFFFFFF}; // 未命中（行表查询失败）
}

3.3 recordTrace(ev) / exportTrace(fmt, filter) trace 记录与导出

recordTrace(ev)：指令/访存钩子事件写入 traceBuffer（性能开关 enabled=0 零开销直接返回；溢出丢最旧 + 计数，对齐 M-21）。exportTrace(fmt, filter)：时间/地址筛选 → CSV/VCD/JSON 序列化 → 分块下载（大文件可续导，nextOffset 续传）。伪代码如下：

// recordTrace: trace 记录（指令/访存，4.3.4.3 表48；可整体关闭性能开关；11-2）
void recordTrace(TraceEvent ev) {
  if (!traceBuffer.enabled) return;                  // 性能开关整体关闭（零开销）
  if (traceBuffer.count == T_CAP) {                  // 满：写旧 head 位置再前移（每次仅丢一条最旧）
    traceBuffer.buf[head] = ev;
    head = (head + 1) % T_CAP; traceBuffer.dropped++;
  } else {
    traceBuffer.buf[(head + count) % T_CAP] = ev; count++;
  }
}
// exportTrace: trace 导出（4.3.4.3 表48；CSV/VCD/JSON 分块，大文件可续导；11-7）
ExportHandle exportTrace(exportFormat fmt, TraceFilter filter, uint64_t offset) {
  if (fmt != CSV && fmt != VCD && fmt != JSON) return E_INVALID_FORMAT; // 枚举校验
  rows = applyFilter(traceBuffer window, filter);    // 时间/地址筛选（offset=条目偏移起点）
  chunk = serialize(fmt, rows, offset);              // 分块序列化（定长头 + 数据块）
  return {offset, nextOffset, total, bytes};         // 续导协议：前端下次传 offset=nextOffset（经 M-05 命令通道）
}

5 处理流程

5.1 反汇编联动与 trace 导出流程（源 4.3.4.4 对齐）

双链路：联动流 = 加载 → 符号/行映射构建 → 反汇编渲染 → 单步联动高亮；trace 流 = 钩子/访存事件 → 记录 → 筛选 → 分块导出。

分支：无 DWARF → 降级仅反汇编 + 符号表（resolveLine 返回空，4.3.4.5）；trace 开启 → 明确降速提示（评审 R9），退出调试态可关闭恢复全速。

6 异常处理

6.1 错误码与处置

本模块以降级语义为主（无 DWARF/trace 关闭/写失败丢弃均为正常降级路径，不新增 E_CTX 码，一场景一码）；反汇编读未映射按宿主侧失败语义经事件通道处理（对齐 M-10 10-5）：

错误码 / 场景触发条件处置
无 DWARF（降级）行表未构建 / ELF 无 DWARF 段resolveLine 返回空；降级仅反汇编 + 符号表（4.3.4.5）
trace 写失败（T1）traceBuffer 写入失败（容量/异常）降级丢弃 + warn 日志（T1 失败语义）
trace 开启（R9）性能开关 enabled=1 且仿真运行中明确降速提示；退出调试态可关闭恢复全速（4.3.4.5）
导出格式非法exportTrace(fmt) fmt ∉ {CSV, VCD, JSON}拒绝并返回 E_INVALID_FORMAT（枚举校验）
输入超限（L3/P-12）行表 >2×10⁵ / 符号表 >10⁵ / 递归深度 >64M-06 前置校验为主；M-11 侧防御二次校验（disasm count 上限 MAX_DISASM_COUNT，行表超限拒绝，11-10）
访存失败（截断，非错误）disasm 读未映射地址宿主侧失败（dbg_mem_fail 语义，非平台故障、非 guest trap）；返回部分序列，调用方以长度<count 判定截断（11-3）

6.2 边界与降级

（1）无 DWARF：降级仅反汇编 + 符号表（resolveLine 返回空，独立可用，4.3.4.5）。

（2）性能开关：traceBuffer.enabled=0 整体关闭（零开销），退出调试态可关闭恢复全速（评审 R9）。

（3）trace 开启：明确降速提示（命令通道回显，4.3.4.5）。

（4）写失败：降级丢弃 + warn（T1 失败语义，不阻塞主流程）。

（5）大文件导出：分块下载（ExportHandle.offset 单位=条目数；nextOffset 续传，前端下次传 offset=nextOffset，经 M-05 命令通道），中途失败可续传不重导（11-7）。

（6）自修改代码：写内存钩子失效 disasmCache 对应地址，不命中陈旧解码（对齐 M-13 13-6）。

（7）导出格式：枚举校验，非法值拒绝；CSV/VCD/JSON 序列化器独立可增删。

（8）防御校验（11-10）：disasm(addr, count) 的 count 上限 MAX_DISASM_COUNT（10⁵ 条/次，估算基线）；行表/符号表超限在 M-06 前置校验后 M-11 仍二次校验并拒绝。

7.2 可维护性手段

（1）双子组件拆分（评审 P-07）：DWARF 解析（行表解析/地址查询/路径归一）与反汇编渲染（助记符/PC 高亮/联动 UI）独立单测，DWARF 为最大风险项（10 人日 WBS）。

（2）解码表驱动：RV32IMC opcode→助记符映射表独立维护，新增指令只动映射表；独立表与 M-13 指令集存在两套解码语义漂移风险 → 设一致性测试门禁（同代码样本对照 M-13 解码结果，11-5），防漂移。

（3）缓存与 trace 解耦：disasmCache（联动视图）与 traceBuffer（记录导出）独立，可分别单测（缓存失效/溢出语义）。

（4）序列化器独立：CSV/VCD/JSON 各为独立序列化器，格式可增删不影响核心链路。

（5）CI 门禁：核心模块单测覆盖率 ≥70%（估算基线，源文档 7.3 表92）；反汇编/联动用例纳入确定性夹具。

（6）契约层可替换性（源 2.5 对齐）：本模块对外 driving 端口收敛到 9.1.1 端口契约，替代实现遵守同端口契约并通过契约测试即可接入。

9.1.1 端口契约（driving/driven，源文档表49 对齐）

按源文档 2.5 平台共享契约层，本模块对外交互收敛为语言无关的端口契约（驱动端口 = 本模块提供的服务，被驱动端口 = 本模块依赖的服务）；任何替代实现（替代联动/trace 服务）遵守同端口契约并通过契约测试（7.1）即可接入：

端口 / 服务方向契约（输入 → 输出；错误码/约束）
disasm(addr, count)提供（driving）输入：起始地址/条数（count ≤ MAX_DISASM_COUNT）；输出：指令行序列（缓存命中直返；未映射提前结束，长度<count 即截断，11-3）

9.2 日志对接（M-21）

联动成功 → log(INFO, "DBG-DS", "disasm/resolve", "E_OK")；无 DWARF 降级 → log(INFO, "DBG-DS", "no DWARF degrade", "E_OK")；trace 写失败 → log(WARN, "DBG-DS", "trace drop", "T1")；导出格式非法 → log(WARN, "DBG-DS", "invalid export format", "E_INVALID_FORMAT")。产品/嵌入式工作台不可见（角色边界，§3.4），仅管理员通道可查。
