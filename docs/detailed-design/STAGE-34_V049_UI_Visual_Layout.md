## §1 目标与边界

### §1.1 本批要达成的

1. **导航形态**：顶部标签页 ⇒ ⇒ **左侧分组侧边栏**（「运行与调试」5 项 / 「平台」3 项）。
2. **设计语言**：换成原型的深色卡片式（青色主色 / 等宽数值 / 圆角卡片 / 提示条 / 空态）。
3. **顶栏全局运行条**：品牌 + 连接状态胶囊 + **PC / 虚拟时间 / 运行 / 单步 / 复位 / 加载固件**。

### §1.2 事实表（实测 · F1~F12）

| 号 | 事实 |
| --- | --- |
| F1 | 当前顶栏是 `<header class="topbar">`：brand + `data-image-load-slot` + `<nav id="workbench-tabs">`（**7 个** `<a class="tab">`）+ `seed-demo` 按钮 + `#status` 文本（`front/index.html`） |
| F2 | 导航项的**稳定标识**是 `data-view-tab` 属性，**当前项**由 `aria-current="page"` 标记（`front/views/m01_workbench.js` 的 `syncTabState`） |
| F3 | 路由是 **hash 路由**：`location.hash` ⇒ `route()` ⇒ `VIEW_REGISTRY` ⇒ `switchView()` ⇒ `mountPanels()` / `showPanel()`（M-01 §3.2） |
| F4 | 视图面板由 `createPanel()` **动态创建**：`<section data-view-panel="...">` + `<h2>`（用 `v.name`）+ `div.view-body` |
| F5 | **真机门禁 92 条断言没有一条用 tab 选择器** ⇒ ⇒ 它们走 `location.hash` 与 `[data-view-panel]` ⇒ ⇒ **改导航形态不会让判据口径悄悄变**（这正是 STAGE-33 踩过的坑） |
| F6 | 前端**用例**有 **3 处**用 `[data-view-tab]`（`front/tests/frontend.test.mjs` 2 处 + `front/tests/source-view.test.mjs` 1 处）⇒ ⇒ **侧边栏项保留 `data-view-tab` 属性名** ⇒ ⇒ **零用例改动** |

| F8 | app 层**已有** `step` / `step10` / `continue` / `pause` / `reset` 命令（`front/app.js` 的 `case`）⇒ ⇒ 顶栏运行条**不必新增契约命令** |

| F11 | 原型的波形用 `https://fastly.jsdelivr.net/npm/echarts@5.5.0/dist/echarts.min.js` ⇒ ⇒ **外部 CDN 依赖** ⇒ ⇒ 破 ADR-6「零依赖」⇒ ⇒ 用户已拍板引入 ⇒ ⇒ 落在 v0.51 批 |
| F12 | 原型的导航分组是「**运行与调试**」（工作台概览 / 调试器 / 寄存器·内存 / 波形 / 串口终端 = 5）与「**平台**」（产品树 / 板级内存图 / 源码 = 3）⇒ ⇒ 与现有 8 个视图**一一对应** ⇒ ⇒ **不增视图、不删视图** |

### §1.3 本批**不做**

- ⛔ 视图**内部**内容形态（器件 chip / 内存比例条 / 寄存器 ABI 名与变化高亮 / 终端 TX·RX / 产品树可折叠 / 源码文件列表 / 内存 hex 查看器）⇒ ⇒ **v0.50 批**。
- ⛔ **波形图**（echarts / Canvas）⇒ ⇒ **v0.51 批**。
- ⛔ **断点 UI** ⇒ ⇒ **v0.50 批**。
- ⛔ 改**路由契约**（仍是 hash 路由、仍是 8 个视图、仍不增删命令）⇒ ⇒ **面板标题文字也不动**（`v.name` 保持原样 ⇒ ⇒ 前端门禁对页脚文案的断言零改动）。

## §2 裁决

| 号 | 裁决 |
| --- | --- |
| A | **保留 hash 路由，只换呈现** ⇒ ⇒ 侧边栏项是 `<a href="#/...">` ⇒ ⇒ 点它就是改 `location.hash` ⇒ ⇒ `route()` / `switchView()` / `mountPanels()` **一个字不改** ⇒ ⇒ **路由契约零变更** |
| B | 侧边栏项**保留 `data-view-tab` 属性** ⇒ ⇒ `syncTabState()` **零改动** ⇒ ⇒ 前端用例**零改动** ⇒ ⇒ 导航项同时带 `aria-current="page"` 语义 |
| C | 视图的**分组**是 `VIEW_REGISTRY` 的一项元数据（`group: "run" \| "platform"`）⇒ ⇒ **分组只有一个落点** ⇒ ⇒ 侧边栏**按它渲染** ⇒ ⇒ 不另设一张分组表 |
| D | 设计令牌**集中在 `front/style.css` 的 `:root`** ⇒ ⇒ 配色 / 字体 / 圆角**只有一处** ⇒ ⇒ 不在组件里散落字面量 |
| E | 顶栏运行条显示 **PC** 与**虚拟时间** ⇒ ⇒ **不显示指令退休计数**（F9 ⇒ ⇒ 无数据来源 ⇒ ⇒ **不编造**）⇒ ⇒ 原型那个「inst」是**示意数据** |
| F | 页头加载器**形态不动** ⇒ ⇒ STAGE-33 的 B-6 ~ B-11 **全部仍然成立**、**一字不改** ⇒ ⇒ 「加载固件…」按钮形态留给 v0.50 |
| G | 视图外框改成 `.vhead`（标题 + 提示）**加** `.card` 容器 ⇒ ⇒ **内容形态**留给 v0.50 ⇒ ⇒ 本批只换**外框** |
| H | 窄屏（`< 720px`）侧边栏变**抽屉**（汉堡按钮开合）⇒ ⇒ 720px 以下侧边栏**不占宽度** ⇒ ⇒ 主区不被遮挡 |
| I | 图标用**内联 SVG** ⇒ ⇒ 零依赖 ⇒ ⇒ **不用图标字体库**、**不用图片外链** |
| J | 契约层**零升版** ⇒ ⇒ `SCHEMA_VERSION` 仍 **8** / `SIM_STATE_SCHEMA_VERSION` 仍 **2** / `PLATFORM_SCHEMA_VERSION` 仍 **1** / `PLATFORM_RULES_VERSION` 仍 **3** ⇒ ⇒ 零新 DTO / 零新命令 / 零新事件 |
| K | 顶栏的运行条按钮**复用 app 层已有命令**（F8）⇒ ⇒ **不新增**命令处理分支 ⇒ ⇒ 与 v0.48 的 `handleLoadImageCommand` **同一套路**（抽出 → 两处共用） |

| 号 | 验收 |

## §6 判别力清单

| # | 判据 | 变红条件 |
| --- | --- | --- |
| 1 | A-1 / A-2（分组元数据） | 少一项 `group` 或分组计数错 |
| 2 | A-3（8 个导航项 + 图标） | 少一个项 / 少一个图标 |
| 3 | A-4（点导航项真切换） | `href` 写错 ⇒ ⇒ hash 不变 |
| 4 | A-5（`aria-current` 唯一） | 两个项同时带 `aria-current` |
| 5 | A-6（PC + 虚拟时间，无 inst） | 顶栏显示一个**没有数据源**的数 |
| 6 | A-7（顶栏按钮发对命令） | 单步发成 `continue` |
| 7 | A-8（令牌逐字 + 无旧令牌残留） | 颜色写错 / 旧名还在 |
| 8 | B-15（顶栏 PC == 寄存器视图 PC） | 两处**不是同一个状态源** |
| 9 | B-17（窄屏抽屉） | 侧边栏在 375px 仍占 196px |
| 10 | C-1（STAGE-33 的判据仍成立） | 改版把加载入口弄坏了 |
| 11 | A-6b（顶栏数字来自快照） | 顶栏 PC / 虚拟时间被**写死**成常量 |
| 12 | B-18b（令牌真进了浏览器） | `--accent` 的**计算值**不是规格里那个 |

⚠️ **B-12 的判别力来源**：它站在**默认落地页**上 ⇒ ⇒ 只在某个视图里才有侧边栏的实现**必然红**（这正是 STAGE-33 §5 记的那条教训的延续）。

⚠️ **「空转通过」也是假绿的一种**（§8 订正 6 实测到）：A-4 与 B-17 在**侧边栏整个没了**时**都**会**恒真**（前者 `for` 循环体一次都不执行、后者「右缘 = 0」自动成立）⇒ ⇒ **判据必须先钉住「被观测的对象存在」** ⇒ ⇒ 否则「测了等于没测」。

### 订正 1 · 顶栏的「运行」不做成「运行 / 暂停」切换

**规格原文**：§2 裁决 K 写的是「顶栏的运行条按钮**复用 app 层已有命令**（F8）⇒ ⇒ **不新增**命令处理分支 ⇒ ⇒ 与 v0.48 的 `handleLoadImageCommand` **同一套路**（抽出 → 两处共用）」；原型那张图上顶栏是**一个**「运行」按钮（点一下变「暂停」，运行中时按钮变成琥珀色 + 呼吸）。

**实测**：要实现「运行 / 暂停」切换，**必须知道「当前是否在运行」** ⇒ ⇒ 而那个量**当前没有任何状态源** ⇒ ⇒ 内核侧只有 `Tick` 事件（`sim.state.delta` / `tick`）⇒ ⇒ 要判断「在运行」就得**自己维护一个布尔量** ⇒ ⇒ ⇒ **那就是第二个真相源**（内核明明知道自己在跑，前端却要自己猜）⇒ ⇒ 与本仓「**一条约束一个落点**」「**不造第二个真相**」两条纪律**直接冲突**。

⇒ ⇒ 同时实测到：原型那个「运行中」的琥珀呼吸效果**在本批没法做**（同因）⇒ ⇒ 若硬做 ⇒ ⇒ 按钮的视觉状态会是**假的** ⇒ ⇒ 违反「界面不得说谎」。

**已改成**：顶栏给**三个独立按钮** —— **运行**（`continue`）/ **单步**（`step`）/ **复位**（`reset`）⇒ ⇒ 三个都**直接调 `handleCommand`** ⇒ ⇒ 与调试视图那份**共用同一条命令路径**（裁决 K 的**意图**不变）⇒ ⇒ 「是否在运行」的高亮**留给 v0.50 批**（那时基于**内核侧的真实状态**做，而不是自己猜）⇒ ⇒ ⇒ **通用判据**：**「把一个按钮做成两态」⇒ ⇒ 必须先确认「两态之间的那个判据」有真实状态源** ⇒ ⇒ 没有 ⇒ ⇒ 就做成**两个独立按钮** ⇒ ⇒ **别用一个自己维护的标志去模拟**。

### 订正 2 · 侧边栏图标不能用 `innerHTML` 造

**规格原文**：§2 裁决 I 写的是「图标用**内联 SVG** ⇒ ⇒ 零依赖 ⇒ ⇒ **不用图标字体库**、**不用图片外链**」；§7 的变更影响面里 `front/views/m01_workbench.js` 那一行写着「`VIEW_REGISTRY` 加 `group` + 侧边栏渲染」。

② 那条判据的注释里**自己**写了警告：「只匹配**赋值**（`x.innerHTML =`），不匹配散文——否则源码里一句『这里不用 innerHTML』的注释就会把门禁撞红（FRONTEND_Review.md R-17：过宽的静态断言 = 假红）」⇒ ⇒ ⇒ **实测正好踩进它警告的那个坑**：我为了说明「为什么不用 `innerHTML`」，在注释里**写出了那个形状**（`host.innerHTML = ""`）⇒ ⇒ **注释自己把门禁撞红了** ⇒ ⇒ ⇒ **判据要扫的是「代码形状」⇒ ⇒ 注释里也不能写出那个形状** ⇒ ⇒ ⇒ **通用判据**：**静态断言扫全文 ⇒ ⇒ 连注释都在射程内** ⇒ ⇒ 写注释时**别复述被禁的那个字面量**。

③ 顺带实测到：**SVG 元素在真浏览器里只能用 `createElementNS` 造**（`createElement("svg")` 出来的是 HTML 元素，**不渲染**）⇒ ⇒ 而 `front/tests/dom-stub.mjs` **不支持** `createElementNS` ⇒ ⇒ ⇒ **测试基础设施缺一个能力**。

**已改成**：① 侧边栏的图标改成 **`createElementNS` 逐个 DOM 调用**（形状是**常量**、不含用户数据）⇒ ⇒ **M-01 那条既有门禁一字不改仍然成立**；② `front/tests/dom-stub.mjs` **补上 `document.createElementNS`**（**新增能力**，不是放松判据）⇒ ⇒ 并在它的能力清单里**注明那个不保真的地方**（SVG 元素的 `tagName` 大小写）⇒ ⇒ 并**顺带把那条既有判据的适用范围说清楚**；③ 注释里**不再复述被禁的字面量**；④ ⇒ ⇒ **通用判据**：**「既有静态门禁」是改动的「护栏」⇒ ⇒ 不是「过一遍」而是「先查它盯的是什么」** ⇒ ⇒ 本批**零条既有门禁被放松**。

### 订正 4 · 面板标题**保留 `h2`** —— 换元素就换了判据口径

**规格原文**：§2 裁决 G 写的是「视图外框改成 `.vhead`（标题 + 提示）**加** `.card` 容器」⇒ ⇒ 原型那张图上，视图标题用的是 **`<h1>`**（`<div class="vhead"><h1>工作台概览</h1><span class="hint">…</span></div>`）⇒ ⇒ §7 的影响面里 `front/views/m01_workbench.js` 那一行写的是「`VIEW_REGISTRY` 加 `group` + 侧边栏渲染」⇒ ⇒ **没有提**面板标题这个元素。
