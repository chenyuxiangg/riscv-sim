1 功能概述

1.1 模块定位

M-21 为独立横切基础设施（NFR-07）：统一采集各层日志（trace/debug/info/warn/error），分级、会话关联、环形缓冲（溢出丢最旧）；只进不出，仅向系统管理员通道分发（控制台/导出/服务端收集），产品/嵌入式工作台不可见（§3.4 角色边界）。业务模块一律经 log() 上报，不得自行实现日志（4.7 唯一入口规则）。

与 M-22 HMS 职责分离：M-21 只记录（结构化日志、根因查询数据源），HMS 只监控分发（健康信号分级、降级动作）。日志条目为结构化格式（评审 P-22）：time_virt / time_host / sessionId / level / ctx / errCode / msg，双时间戳中虚拟时间对仿真语义、宿主时间对性能与时序定位（评审 P-21）。

1.3 MVP 范围与预留

MVP 实现范围：log(level, ctx, msg, errCode) 统一上报入口、五级过滤（运行时切换，仅管理员）、环形缓冲（按级别容量、溢出丢最旧）、双时间戳与会话关联、管理员通道 query/export（配合 M-23 归档）。

预留项：服务端日志收集（P1 服务端形态）；日志流对产品/嵌入式工作台可见（评审 L1，简化为 P1 引入）；指标面板（FR-20 趋势指标，评审 P-18，属 M-22 责任，M-21 仅提供日志数据源）。

2.1.1 复杂结构字段定义

logEntry 为唯一日志载体，七个字段逐项定义如下（字段名与语义来自源设计 4.6.2.2，评审 P-21/P-22）：

// logEntry: 结构化日志条目（唯一载体）
struct LogEntry {
  uint64_t time_virt;   // 虚拟时间戳（M-20 事件流 t_virt）：确定性、可重放，与仿真语义对齐
  uint64_t time_host;   // 宿主时间戳（M-21 内置 TimeSource）：性能与时序定位，单调递增
  uint32_t sessionId;   // 会话关联标签：跨会话隔离，多会话日志互不串扰
  uint8_t  level;       // 级别：TRACE/DEBUG/INFO/WARN/ERROR（见 2.2）
  char     ctx[24];     // 上下文：调用方约定的「模块-流程点」标识（如 ISS-TRAP、BUS-UNMAP）
  char     errCode[12]; // 错误码（可空）：3.4 完整场景码（如 E_ISS-03、E_BUS-01）；无错误时为空串
  char     msg[128];    // 消息文本（UTF-8，定长槽拷贝，评审 21-1）：log() 入口截断拷贝入槽，
                        //   调用方生命周期无关（栈上/临时缓冲传参不悬垂）；>128B 截断并置 truncated
  uint8_t  truncated;   // 截断标记（评审 21-1）：msg 溢出截断时置 1；错误码/上下文不因截断丢失
};

RingBuffer 按级别分带实现容量预算与溢出丢最旧策略（评审 P-13）；LevelFilter 为运行时可切换的过滤阈值（评审 P-22）：

// ringBuffer: 日志环形缓冲（按级别分带）
struct RingBuffer {
  uint32_t head;             // 写游标（单写者，内核单线程推进）
  uint32_t tail;             // 读游标（管理员查询/导出时快照推进）
  uint32_t capacity;         // 本级容量：trace 100000 / debug+info 10000 / warn+error 5000
  uint32_t overflowCount;    // 溢出次数（丢最旧计数，暴露给管理通道诊断）
  LogEntry* slots;           // 定长槽数组（会话隔离：每会话独立实例）
};
// levelFilter: 分级过滤（运行时切换，仅管理员通道）
enum Level { TRACE, DEBUG, INFO, WARN, ERROR };
//   过滤规则：仅记录 level >= levelFilter 的日志；切换由 setLevel() 执行并审计记录
// timeSource: M-21 内置宿主时间源（源 4.6.2.2 表77）
//   WASM 形态: performance.now()（单调时钟，不受系统时间跳变影响）
//   服务端形态: 宿主进程单调时钟（毫秒级）
//   全系统日志共享同一时间源，保证跨模块一致与单调递增

2.3 数据流说明

采集数据流：各层 log() → 附双时间戳 + 会话关联 → 级别过滤 → 结构化入缓冲（溢出丢最旧）→ 管理员通道 query/export → M-23 归档；M-22 根因查询引用日志数据源。

边界数据流：产品/嵌入式工作台不订阅日志流（L1 日志流边界）；导出为 CSV/JSON 分块（FR-10/14 配合 M-11/M-19）；级别切换仅管理员可执行并审计记录。

3 实现设计

3.1 统一采集入口 log()

所有业务模块（M-01~M-19）在各自处理流程/异常处理点调用 log(level, ctx, msg, errCode)（4.7 表86 调用约定）。实现要点：入口先按 levelFilter 过滤（不满足直接返回，避免格式化与缓冲写入开销）；errCode 可选，携带调用方完整场景码（如 E_ISS-03）；ctx 采用「模块-流程点」约定（※设计建议，源基线未规定格式）。msg 持有策略（评审 21-1）：定长槽拷贝（128B 截断 + truncated 截断标记）——调用方栈上/临时缓冲传参不悬垂，且 log() 期间不分配大块内存（槽位预分配于 RingBuffer 实例化时）。

// log: 统一上报入口（自动附双时间戳与会话关联）
void log(Level level, const char* ctx, const char* msg, const char* errCode) {
    if (level < levelFilter) return;            // 过滤：不满足当前阈值直接丢弃（O(1)）
    LogEntry* e = ring_reserve(&ring[band(level)]);
    e->time_virt  = event_stream_t_virt();      // M-20 事件流 t_virt（权威源 = M-12 虚拟时钟，评审 21-4）
    e->time_host  = timeSource.now();           // M-21 内置 TimeSource（宿主单调时钟）
    e->sessionId  = session_tag;                // M-04 会话创建时注入
    e->level      = level;
    snprintf(e->ctx, 24, "%s", ctx);            // 「模块-流程点」（如 ISS-TRAP）
    snprintf(e->errCode, 12, "%s", errCode ? errCode : "");
    // 定长槽拷贝（评审 21-1）：截断入槽 + truncated 标记；调用方生命周期无关，无悬垂
    size_t n = strlen(msg);
    if (n >= sizeof(e->msg)) { memcpy(e->msg, msg, 127); e->msg[127] = 0; e->truncated = 1; }
    else                     { memcpy(e->msg, msg, n + 1); e->truncated = 0; }
}
// ring_reserve: 环形写入（单写者）；容量满 → 丢最旧（head 覆盖 tail）并计数 overflowCount

3.2 双时间戳与会话关联

双时间戳语义（评审 P-21，源设计 4.6.2.1）：time_virt 取虚拟时钟基准——权威源为 M-12 虚拟时钟（评审 21-4），M-20 事件流仅承载时间戳（t_virt 由 M-12 推进派生），M-20/M-21 共享同一基准，保证确定性、可重放，与仿真语义对齐（trap 时序、访存事件序）；time_host 由 M-21 内置宿主时间源（TimeSource）提供——WASM 形态取 performance.now()（单调时钟，不受系统时间跳变影响）、服务端形态取宿主进程单调时钟（毫秒级），全系统日志共享同一时间源保证跨模块一致与单调递增。log() 入口自动合并为双时间戳，业务模块不感知时钟实现。sessionTag 由 M-04 会话创建时注入，跨会话隔离：不同会话的日志进入各自独立 RingBuffer 实例，查询/导出按 sessionId 过滤。

3.3 环形缓冲实现

按级别分带（评审 P-13/21-7）：带间独立容量预算；WASM 压缩形态默认容量与 1.5MiB 压缩预算显式对账——logEntry 字段字节 = time_virt(8)+time_host(8)+sessionId(4)+level(1)+ctx(24)+errCode(12)+msg(128)+truncated(1) = 186B，对齐 192B 定长槽；192B × 7×10³ 条 = 1,344,000B ≈ 1.34MB ≈ 1.28MiB/会话，占 1.5MiB 预算约 85%（预留管理结构余量）：trace 4×10³、debug/info 10³、warn/error 5×10² 条；服务端/导出形态可扩至 10⁵/10⁴/5×10³（不受 WASM 预算约束，setCapacity 管理员通道调整）。写入侧为单写者（内核单线程推进），O(1) 无锁；读侧（管理员 query/export）取快照拷贝当前窗口，不移动任何游标、不改变缓冲状态（评审 21-2：读不推进 tail、不改变后续可见性）。溢出策略：丢最旧 + overflowCount 计数（评审 21-3：仅递增暴露诊断字段；WARN 上报路径 = M-22 HMS report(WARN, "log overflow")，限频 ≥1s 一次，上报本身不调用 log()、不写入日志缓冲，杜绝自激；HMS 不可用时仅保留计数），不抛错、不阻塞（源设计 4.6.2.5）。

// ring_reserve: 环形槽位获取（单写者，O(1)）
LogEntry* ring_reserve(RingBuffer* rb) {
    if (count(rb) == rb->capacity) {            // 已满
        rb->tail = next(rb->tail);               // 丢最旧：tail 前移覆盖最旧槽（仅写侧溢出覆盖时移动）
        rb->overflowCount++;                     // 溢出计数（评审 21-3：仅字段递增，不上报写入）
    }
    LogEntry* slot = &rb->slots[rb->head];
    rb->head = next(rb->head);
    return slot;
}
// ring_snapshot: 读侧快照（评审 21-2）——拷贝当前窗口 [tail, head)，不移动 tail/head、
//   不改变缓冲状态；query/export 基于快照遍历，读不改变后续可见性
// 说明：log() 期间不做格式化、不做 I/O、不分配大块内存（msg 定长槽拷贝，评审 21-1），
// 保证不阻塞仿真主循环；查询/导出在管理员通道侧独立执行，与业务写入解耦。

3.4 管理员通道与级别切换

query(filter)：按级别/时间/会话过滤检索，仅供管理员通道（控制台/导出/服务端收集）；export()：分块导出 CSV/JSON（配合 M-23 归档，4.7 表86）；setLevel(level)：运行时级别切换，仅管理员可执行并审计记录（评审 P-22）；产品/嵌入式工作台不订阅日志流（L1 边界，2.4 表6 角色边界）。前端日志通道（评审 21-5）：内核侧日志（WASM 内 logBuffer）与前端侧 UI 操作日志分开——前端（M-01~M-03）不直接写入内核缓冲，其 UI 操作日志仅本地 console（调试通道）；管理员需要的前端日志经会话消息通道（postMessage）转发，消息格式 = {type:"log", level, ctx, msg}，内核侧校验 type === "log" 后转入 log() 统一入库（非 log 类型消息忽略），保证单缓冲单入口。管理员鉴权（评审 21-6）：权限判定位置 = 三层——① 前端路由隐藏入口（仅 UX，可被绕过）；② 内核接口鉴权（query/export/setLevel 在 WASM 侧校验管理员令牌，防绕过前端，MVP 基线以此为准）；③ 会话角色（角色来源 = M-04 会话创建时从用户登录态派生注入 sessionTag，令牌随会话上下文下发）。令牌校验失败 → 拒绝执行 + 审计记录（时间/操作者/操作/结果），非管理员越权同样留痕。

与 M-22 HMS 职责边界：M-21 只记录（结构化日志数据源），HMS 只监控分发（健康信号、降级动作、脱敏提示）；M-22 可引用 M-21 做根因查询，但不得改写日志缓冲。

ring_reserve(rb)环形槽位获取（内部）单写者 O(1)；容量满 → 丢最旧（tail 前移覆盖）+ overflowCount 递增（评审 21-3 仅计数不上报）
ring_snapshot(rb)读侧快照（内部）评审 21-2：拷贝当前窗口、不移动 tail/head、不改变缓冲状态；供 query/export 使用，与写入解耦、不阻塞业务

5 处理流程

5.1 日志采集与分发流程

单条日志闭环如下（对应图 1）：

（2）附戳与会话：自动附 time_virt（M-20 事件流 t_virt）+ time_host（M-21 内置 TimeSource）+ sessionId（M-04 注入）。

（4）入缓冲：按级别分带环形缓冲写入；容量满 → 丢最旧 + overflowCount，不阻塞业务。

（6）角色边界：产品/嵌入式工作台不订阅日志流（L1 边界）；M-22 根因查询只读引用。

6 异常处理

6.1 内部异常与处置

M-21 为记录方，自身不新增错误码族；logEntry.errCode 字段承载调用方完整场景码（如 E_ISS-03、E_BUS-01）。内部异常处置如下（源设计 4.6.2.5）：

内部异常处置来源
缓冲溢出丢最旧 + overflowCount 计数（评审 21-3：仅暴露字段；WARN 上报走 M-22 HMS、限频 ≥1s、上报不调用 log() 不写缓冲，杜绝自激）；不阻塞业务4.6.2.5、评审 P-13
导出失败WARN 日志 + 重试4.6.2.5
级别切换越权拒绝执行 + 审计记录（仅管理员可切换）4.6.2.5、评审 P-22

6.2 边界与降级

（1）日志写入不可用：尽力而为，不阻塞仿真主循环（※设计决策，源基线未规定；log() 内部失败静默降级）。

（2）级别过滤：低于阈值的日志直接丢弃，不产生副作用；切换即时生效。

（3）QEMU 后端能力降级：trace/快照随 M-17 能力位降级，但日志为全模块基础能力，不随能力位降级（4.7 能力降级规则）。

（4）多会话隔离：查询/导出按 sessionId 过滤，跨会话不串扰；每会话独立缓冲实例。

（5）审计：setLevel 每次切换记录审计日志（时间/操作者/目标级别），切换失败同样留痕。

7.2 可维护性手段

（1）结构化 logEntry：七个固定字段（评审 P-21/P-22），可机器检索、可断言（测试按字段比对）；

（2）query(filter) 过滤检索：按级别/时间/会话定位问题，替代人工翻日志；

（3）诊断暴露：overflowCount、当前 levelFilter 阈值对管理员可见，运行态可调（setLevel）；

（4）CI 门禁：核心模块单测覆盖率 ≥70%（估算基线，源设计 7.3 表92）；日志模块用例纳入确定性夹具（同输入同序列断言日志一致）；

（5）与 M-22 职责分离：M-21 只记录、HMS 只监控，日志数据源可被 HMS 根因查询引用。

（6）契约层可替换性（源 2.5 对齐）：本模块对外的 driving 端口收敛到 9.1.1 端口契约表，替代实现遵守同端口契约并通过契约测试即可接入；业务模块只依赖契约不依赖实现。
