## §1 裁决

### 裁决 A · 差量合成剥成**纯函数**（宿主内部）

- 宿主新增一个**内部**纯函数：`compose_memory_map(base: &PlatformDescription, ops: &[MemoryMapOp]) -> Result<PlatformDescription, PlatformError>`。
- ⚠️ **纯** = 只读 `base` + 只写返回值 ⇒ **不碰宿主任何状态**（图 / 用户的板 / 修订号 / 总线）。
- ⚠️ **不**进契约层 ⇒ 契约层的**公开表面一字未改** ⇒ 前端镜像**不需要**升版。
- ⚠️ **合成期间不碰任何状态**这条**既有语义一字不改**（v0.31 的裁决 J）⇒ 纯函数化**不得**改变失败时的可观测行为。

### 裁决 B · 等价性的**判据** = 生效图**逐字段相同**

- 口径：「**同一组改动** ⇒ 整份路径与差量路径 ⇒ **生效图逐字段相同**」。
- ⚠️ 判据用**键序无关**的规范形式 ⇒ **字段顺序不进判据**（顺序是**线上形状**的事，不是**图的内容**的事）。
- ⚠️ 比的是**最终量**（**应用之后**的生效图），不是差量路径里的**中间量**（合成结果）⇒ ⇒ 因为「应用」那一步**还会**跑一遍 `validate()`。

### 裁决 C · 等价性在**两层**各钉一次

| 层 | 怎么钉 | 为什么是这一层 |
| --- | --- | --- |
| **宿主层**（Rust，快，进默认门禁） | 两个宿主，**同一基座** ⇒ 一个走 `SetMemoryMap(target)`、一个走 `PatchMemoryMap(ops)` ⇒ 比两边的**生效图** | 差量的 **ops 在这里是手写的** ⇒ ⇒ 它验的是「**合成逻辑**对不对」 |
| **真机层**（真前端 + 真内核） | 真前端**自己**算差量 ⇒ 真内核合成 ⇒ 再整份提交一次 ⇒ 比两个**生效图** | 差量的 **ops 由真前端的算法算** ⇒ ⇒ 它验的是「**前端的差量算法 + 内核的合成**合起来对不对」⇒ ⇒ **不复制**前端的差量算法（那会是**第二份真相**） |

- ⚠️ **两层都要** ⇒ 只有宿主层 ⇒ 前端算错差量没人发现；只有真机层 ⇒ 不进默认门禁（真机门禁按需跑）。

### 裁决 D · 非法操作：两条路径**都**拒

- 差量里含**非法**操作（改成与邻段重叠 ⇒ `E_PLT_06`；删一段**不存在**的 ⇒ `E_PLT_14`）⇒ ⇒ **整份路径**（提交同样那张非法图）也必须被拒（`E_PLT_06` / `E_PLT_07` 等）⇒ ⇒ 且**什么都不动**。
- ⚠️ 两条路径**拒的码不一定相同**（整份路径没有「段不存在」这个概念）⇒ ⇒ 判据是「**都拒** + **都什么都不动**」，**不是**「码相同」。

### 裁决 E · 差量为**空** ⇒ 合成结果 == 基座

- 空差量 ⇒ 合成结果**逐字段等于**基座（既有的 B-10 语义）⇒ ⇒ 等价性上它对应「整份提交一份**与基座相同**的图」⇒ ⇒ 两边结果相同 ✓。

### 裁决 F · 前端乱序护栏：**更旧**的事件**不覆盖**较新那份

- `wireMemoryMap` 收到 `memory.map` 事件时：
  - `revision` **严格更旧**（`<` 手上的那个）⇒ ⇒ **不覆盖**已有的 `description` / `pending` / `loaded` / `revision` ⇒ ⇒ 状态**留在较新**那份 ⇒ ⇒ 差量**算在较新的那张图上**。
  - `revision` **相同或更新** ⇒ ⇒ **照收**（⚠️ 卸载后的重订推送就是**同号** ⇒ 必须照收 ⇒ 见裁决 G）。
- ⚠️ **丢弃要可观测**：前端**记一个计数器**（被丢弃的旧事件数）⇒ ⇒ 「不静默」靠这个计数器 ⇒ ⇒ 判定不靠文案、靠**数**。

### 裁决 G · 护栏的边界：**同号**事件照收

- `UnloadProject` 清订阅 ⇒ 前端重订 ⇒ 内核**立即**推一次当前图 ⇒ 那次推送的 `revision` 与手上那份**相同**（卸载**不改图** ⇒ 裁决 A 的修订号不 +1）⇒ ⇒ 护栏**必须放行**同号事件 ⇒ ⇒ 否则卸载后前端会**停在旧状态**。
- ⇒ ⇒ 判据必须是「**严格更旧**才挡」，不是「不等就挡」。

### 裁决 H · 护栏**不**改变提交路径的其它行为

- 基底被判为「旧」时 ⇒ 提交路径**照常**发命令（不静默吞、不改载荷形状）⇒ ⇒ 内核的 `expected_revision` 检查**照常兜底**（⇒ 并发丢更新**看得见**这条承诺**不动**）。
- ⚠️ 护栏只是让「基底本身」保持较新 ⇒ ⇒ 提交时带的 `expected_revision` 是**较新**那个 ⇒ ⇒ 内核**接受** ⇒ ⇒ 这正是 D-146 的判别式（乱序之后提交 ⇒ 内核接受）。

### 裁决 I · 门禁：**注册表即聚合源**

- 门禁的每一段跑完 ⇒ **登记**自己（名字 + 断言数组）⇒ ⇒ 判定聚合**只**从注册表取 ⇒ ⇒ 「新加一段忘了并进聚合」这件事**结构上不可能**（裁决 H 的思路：让 bug **写不出来**，而不是靠 review 抓）。
- ⚠️ 注册表是**进程内的一个数组** ⇒ ⇒ 顺序即登记顺序 ⇒ ⇒ 报告也按登记顺序打印。

### 裁决 J · 门禁：**期望段名表**是常量 ⇒ 不等就红

- 门禁持有一张**常量**的「期望段名」表（与实际段一一对应）⇒ ⇒ 跑完断言：**注册表里的段名集合 == 期望表** ⇒ 不等 ⇒ **红** ⇒ ⇒ 兜住「跑过了但没登记」与「登记了但不在期望表里」两种漏。
- ⚠️ 期望表**故意写死** ⇒ ⇒ 加段时**必须**同时改它 ⇒ ⇒ 漏了就红 ⇒ ⇒ 这是**故意的摩擦**。

### 裁决 K · 门禁探测**统一**走一个 helper

- 门禁新增一个 `awaitEval(cdp, expression)` ⇒ ⇒ 所有**取回值**的探测**必须**经过它 ⇒ ⇒ 「用 `Promise` 却忘了 `await`」在**语法层面**不可能（helper 内部 `awaitPromise: true`）⇒ ⇒ 同步探针也走它（形态统一 ⇒ **零**心智负担）。

### 裁决 L · ⚠️ **零**契约变更 ⇒ **两个版本都不升**

- `SCHEMA_VERSION` **仍是 7**；`PLATFORM_SCHEMA_VERSION` **仍是 1**。
- ⇒ ⇒ **零**新 DTO / **零**新命令 / **零**新事件 / **零**新场景码 / **零**字段形状改动 ⇒ ⇒ 前端镜像**一个字都不用改**（除了前端自己的护栏逻辑）。
- ⇒ ⇒ ⚠️ **不制造 D-143 的存量问题**（描述格式没变 ⇒ 库存量照旧合法）。

### 裁决 M · v0.31 的既有语义**一字不改**

- 差量的**合成顺序**（按 `base` 定位 · 命中替换未命中追加 · 删除定位不到就报错）· 修订号检查**排在 `validate()` 之前** · 卸载的**六步** · 「改图不自动重载运行中的 guest」那条护栏 ⇒ ⇒ **全部不动**。
- ⇒ ⇒ 本批只**加**判别力与**一道**结构性护栏（注册表），**不**改任何既有行为。

### 裁决 N · 规格号与顺延

- 本批规格 = **STAGE-17** ⇒ ⇒ **I2C 那批**（原写 STAGE-17）**顺延为 STAGE-18** ⇒ ⇒ 台账里那一处编号要跟着改。

## §3 内核宿主（v0.32 · 差量等价性）

### 3.1 `compose_memory_map` 的形状

```text
compose_memory_map(base: &PlatformDescription, ops: &[MemoryMapOp])
    -> Result<PlatformDescription, PlatformError>
```

| 步 | 做什么 | 失败时 |
| --- | --- | --- |
| ① | 复制 `base` 到工作副本 | — |
| ② | 逐条施加 `ops`：`UpsertRegion`（按 `spec.base()` 定位：命中替换 / 未命中追加）· `RemoveRegion`（定位不到 ⇒ **`E_PLT_14`**，**不静默忽略**）· `SetBudget`（两个预算字段一起改） | 返回 `Err` ⇒ **宿主状态一个字都不动** |
| ③ | 返回工作副本 | — |

⚠️ **纯函数不跑 `validate()`** ⇒ ⇒ 校验仍留在调用点（`on_patch_memory_map` 的第 ③ 步）⇒ ⇒ **既有语义一字不改**（裁决 M）⇒ ⇒ 纯函数可以被单独调用来测「合成逻辑」。

### 3.2 两条路径的**唯一**差别

```text
整份路径：target = 调用方给定的 description
差量路径：target = compose_memory_map(&self.platform, &ops)
应用路径：两边**共用**（记用户的板 → 未装载就换图重建 → 修订号 +1 → 回事件）
```

⇒ ⇒ **等价性 = 「合成的 == 给定的」** ⇒ ⇒ 判据落在**生效图**上（裁决 B）。

### 3.3 等价性用例的形状（宿主层）

```text
① 造**两个**宿主（同一条基座：同一张 user_board）
② 宿主 A：SetMemoryMap(target)         ← target = 基座 + 三种改动
③ 宿主 B：PatchMemoryMap(ops)          ← ops = 手写的、表达同一组改动的差量
④ 断言：A 的生效图 与 B 的生效图 **逐字段相同**
⑤ 断言：两边的生效图 与 target **逐字段相同**
```

⚠️ **ops 手写** ⇒ ⇒ 它验的是**合成逻辑** ⇒ ⇒ 「前端算出来的 ops 对不对」由真机层（裁决 C）验 ⇒ ⇒ **不复制**前端的差量算法。

## §4 前端与工具层

### 4.1 前端乱序护栏（**D-146** · 裁决 F）

| 情况 | 行为 |
| --- | --- |
| 事件 `revision` **严格更旧** | **不覆盖**已有状态 ⇒ 状态留在较新那份 ⇒ **丢弃计数 +1** |
| 事件 `revision` **相同** | **照收**（⚠️ 卸载后的重订推送是同号 ⇒ 必须放行 ⇒ 裁决 G） |
| 事件 `revision` **更新** | **照收** ⇒ 状态推进 |

⚠️ **唯一落点** = `wireMemoryMap` 的事件处理器 ⇒ ⇒ 视图层 / 服务层**不复制**这条判据。
⚠️ **丢弃计数**挂在**同一个** wiring 上 ⇒ ⇒ 可被测试观察 ⇒ ⇒ 「不静默」。

### 4.2 真机端到端等价性（**D-145 · 真机层**）

在浏览器真机门禁的**差量段**里追加：

```text
① 真前端把「当前生效的图」载入编辑器 ⇒ 改一段 ⇒ 提交 ⇒ ⇒ 走**差量**路径
② 记下生效图 E1
③ 把**同一张板**（含那处改动）**整份**提交一次 ⇒ ⇒ 走**整份**路径
④ 记下生效图 E2
⑤ 断言：E1 与 E2 **逐字段相同**
⑥ 断言：E1 与「改动前的图」**不相同**（⇒ 差量**真的**生效了，不是两边都没变）
```

⚠️ 第 ⑥ 条是**必要的对照** ⇒ ⇒ 否则「两条路都没生效」也会让第 ⑤ 条**假绿**。

### 4.3 门禁注册表（**D-147**）

```text
① 每段跑完 ⇒ registerSection(段名, 断言数组)
② 判定聚合 = 注册表里**所有**段的断言 ⇒ ⇒ 不再有手写的展开串
③ 期望段名 = 一张**常量**表 ⇒ 跑完断言「注册表的段名集合 == 期望表」⇒ 不等就红
④ 所有取回值的探测 ⇒ 统一走 awaitEval(cdp, expr) ⇒ 内部 awaitPromise: true
```

⚠️ ③ 的期望表**故意写死** ⇒ ⇒ 加段时**必须**改它 ⇒ ⇒ 这是**故意的摩擦**（裁决 J）。
⚠️ ② 让「忘了并进」**写不出来**（裁决 I）⇒ ⇒ ③ 兜住「忘了登记」。

### 4.4 冻结的 DOM 钩子（**本批不新增**）

- 本批**不新增**任何 DOM 钩子 ⇒ ⇒ v0.31 冻结的那批（`data-action="unload-project"` / `data-mmap-revision` / `data-mmap-field` / `data-mmap-budget-note` / `data-mmap-effective` / `data-mmap-loaded` …）**一个不动**。
- ⚠️ 真机层的新断言**只读**既有钩子 ⇒ ⇒ 不引入新的钩子名 ⇒ ⇒ 门禁脚本**不需要**与前端同步改。

### B 组 · 内核宿主（差量等价性）

| # | 验收 |
| --- | --- |
| **B-1** | `compose_memory_map` 是**纯函数**：同样的 `base` + 同样的 `ops` ⇒ 两次调用**逐字段相同**的结果；且**不碰**宿主状态（调用前后图 / 用户的板 / 修订号三者不变）。 |
| **B-2** | 差量路径**仍然**是「合成 → 整体校验 → 一次性应用」⇒ ⇒ v0.31 批的既有 B 组语义**一字未改**（⚠️ **两批的 B 组编号不是同一套** ⇒ 这里指的是 v0.31 批那套）。 |
| **B-3** | **等价性**：同一组改动（改一段 + 删一段 + 改预算）⇒ 整份路径与差量路径 ⇒ **生效图逐字段相同**。 |
| **B-4** | 等价性覆盖**三种改动**（改一段 / 删一段 / 改预算）⇒ ⇒ 三种**分别**验 ⇒ 不是只验一种。 |
| **B-5** | 差量里含**非法**操作 ⇒ 差量路径**拒**（`E_PLT_06` / `E_PLT_14`）⇒ 整份路径**也拒** ⇒ ⇒ **两边都什么都不动**（⚠️ 判据是「都拒 + 都不动」，**不是**「码相同」）⇒ ⇒ 裁决 D 的口径。 |
| **B-6** | 差量为**空** ⇒ 合成结果**逐字段等于**基座 ⇒ ⇒ 与「整份提交同一张图」**等价**（⇒ ⇒ 裁决 E）。 |
| **B-7** | `compose` 失败 ⇒ 宿主的图 / 用户的板 / 修订号**三者都不动**（既有语义**未改**）。 |

### C 组 · 前端（乱序到达）

| # | 验收 |
| --- | --- |
| **C-1** | 收到**严格更旧**的 `memory.map` 事件 ⇒ **不覆盖**已有状态（较新那份**留着**）⇒ ⇒ 丢弃计数 **+1**。 |
| **C-2** | 收到**相同**修订号的事件 ⇒ **照收**（⚠️ 卸载后的重订推送是**同号** ⇒ 必须放行）。 |
| **C-3** | 收到**更新**的事件 ⇒ **照收** ⇒ 状态推进（修订号与描述都变成新的）。 |
| **C-4** | 护栏**不**改提交路径：基底旧了就**照常提交**（载荷形状不变）⇒ ⇒ 内核的 `expected_revision` **照常兜底**。 |
| **C-5** | **乱序之后提交** ⇒ 内核**接受**（⇒ 差量确实算在**较新**的那份上 ⇒ 这就是 D-146 的判别式）。 |
| **C-6** | 护栏**不**改「已被内核接受」这个**推导量** ⇒ ⇒ 落库门槛**照旧可用**。 |

### T 组 · 工具层（门禁注册表 + 真机等价性）

| # | 验收 |
| --- | --- |
| **T-1** | 每段跑完**登记**自己 ⇒ 判定聚合**只**从注册表取 ⇒ ⇒ **不存在**手写的展开串。 |
| **T-2** | 跑完断言「注册表的段名集合 == 期望段名表」⇒ **不等就红** ⇒ ⇒ 兜住「跑过了但没登记」。 |
| **T-3** | 所有取回值的探测**统一**走 `awaitEval`（内部 `awaitPromise: true`）⇒ ⇒ 「忘了 await」**写不出来**。 |
| **T-4** | 真机层：差量路径与整份路径 ⇒ **生效图逐字段相同**；⚠️ 且**与改动前不相同**（⇒ 差量**真的**生效了 ⇒ 不是两边都没变）。 |
| **T-5** | 真机层：把内核的**合成逻辑**改错（变异）⇒ ⇒ T-4 **必须红** ⇒ ⇒ 证明它**真的**在验那条路。 |

## §6 破坏性变更

| 面 | 结论 |
| --- | --- |
| 契约（信封 / 描述 / 快照 / 传输帧） | **零变更** ⇒ **零破坏性** |
| 宿主行为 | **零变更**（纯函数化是**等价重构** ⇒ 既有 24 条 B 组用例**一条不改**仍绿 ⇒ ⇒ 那就是**证明**） |
| 前端行为 | **一处新增**：乱序事件**不再覆盖**较新状态 ⇒ ⚠️ 这在**旧前端**里是「后到的事件会覆盖先到的」⇒ ⇒ 行为**变了**（但那个行为本来就是**缺陷**）⇒ ⇒ 不影响任何线上格式 |
| 工具层 | 门禁脚本内部重构 ⇒ 不影响产品 |

## §7 闭环与新登记

### 7.1 本批闭环

| 欠账 | 闭环口径 |
| --- | --- |
| **D-145** | 宿主把差量合成剥成**纯函数** ⇒ 等价性变成**一条断言**（B-1 ~ B-7）；真机层再端到端验一次（T-4 / T-5）⇒ ⇒ **两层**都钉住 ⇒ ⇒ 「两条路径产出的图必须一致」这条**从口头承诺变成可执行断言**。 |
| **D-146** | 前端**用上**事件里已有的 `revision` ⇒ **更旧**的事件不覆盖较新那份（C-1 ~ C-3）；乱序之后提交**被内核接受**（C-5）⇒ ⇒ 差量**不再可能算在旧图上**。 |
| **D-147** | 门禁的**注册表即聚合源**（I）+ **期望段名表**（J）+ **统一探测 helper**（K）⇒ ⇒ 「新段的断言接不进判定」这一类缺口**结构上不可能**再发生。 |

### 7.2 本批**新登记**

| 欠账 | 一句话 |
| --- | --- |
| **D-148** | **等价性只覆盖了「手写的 ops」** —— 宿主层的等价性用例里差量是**手写**的 ⇒ ⇒ 它验的是**合成逻辑**；「前端算出来的 ops」那半边只有**真机层**覆盖 ⇒ ⇒ 而真机门禁**不进默认门禁**（按需跑）⇒ ⇒ 默认门禁里**没有**「前端差量算法 + 内核合成」合起来的等价性覆盖 ⇒ ⇒ **登记**（下一批若要把真机层的东西下沉到默认门禁，从这条开始）。 |
