## §1 目标与边界

### §1.1 本批要达成的

1. **八个视图的内部内容形态**：按原型改成卡片式（`.cards` / `.card` / `.kpi` / `.chip` / `.banner` / `.legend`），**判据取法一字不动**。
2. **产品树可折叠**（折叠状态住视图状态，不是 DOM 私藏）。
3. **板级内存图的地址比例条**（按**真地址区间**算比例）。
4. **终端 TX / RX 计数**（两个**不同源**，文案分别标注）。
5. **断点 UI**：反汇编表里能**真点**「加断点 / 断点 ●」· 断点列表 · 命中提示。

### §1.2 事实表（实测 · F1~F14）

| 号 | 事实 |
| --- | --- |
| F1 | 八个视图的正文是**平铺**的裸块（`front/views/m02_viewcomponents.js` 里是**模板字符串**，不是 DOM 调用）⇒ ⇒ 「内容形态」= **结构与呈现**的改造 ⇒ ⇒ M-01 那条「不拼 HTML 字符串」的门禁**只管 M-01**（`front/views/m01_workbench.js`）⇒ ⇒ **本批在 M-02 里用模板字符串不违反它** |
| F2 | **稳定钩子清单**（判据的取法）：`[data-view-body="<id>"]` · `data-embedded-pc` / `data-embedded-time` / `data-embedded-entry` / `data-embedded-link` · `.pc` / `.timeVirt` / `code.pc` / `.reg-grid > div` · `.channel-list > li` · `tr.disasm-row` / `[data-disasm-addr]` · `[data-region-base]` · `data-mmap-*` · `[data-terminal-out]` · `[data-action]` · `[data-trace-*]` ⇒ ⇒ 真机门禁 **104** 条与前端用例 **527** 条**都靠它们** ⇒ ⇒ **本批一字不动**（裁决 A） |
| F3 | 契约层的 GPR **没有 ABI 名**（`SimState::gpr` 是 `[u32; 32]`）⇒ ⇒ 原型那个「ABI 名」**没有数据源** ⇒ ⇒ **平台不编造**（裁决 E） |
| F4 | 内核的 console 事件是 `Console { bytes }`（**guest → 终端**）⇒ ⇒ **TX 计数有数据源** |
| F5 | 往 guest 写的命令是 `WriteConsole { bytes }`（**终端 → guest**）⇒ ⇒ **RX 计数由前端自己累计** ⇒ ⇒ 与 TX **不是同一个源** ⇒ ⇒ 文案必须**分别标注**（裁决 G） |
| F6 | 断点命令**契约层早就有**：`SetBreakpoint(Breakpoint)` / `ClearBreakpoint { id }`（`crates/contract/src/protocol.rs`）⇒ ⇒ **零新命令 / 零新 DTO / 零新事件** |
| F7 | 断点 DTO 是 `{ id: u32, addr: u32, source_hint: Option<String>, enabled: bool }` ⇒ ⇒ **`id` 由前端分配**（脚本口 `window.riscv_kernel.setBreakpoint(addr, id)` 也是前端给 id） |
| F8 | M-08 的 `set` 有**三条拒绝规则**：地址未按 **2** 对齐 / **该地址已存在** / **该 id 已绑到别的地址** ⇒ ⇒ 「**一址一断点**」是**内核语义** ⇒ ⇒ 前端**必须**知道哪些地址已有断点 ⇒ ⇒ **前端列表是必需的，不是装饰** |
| F9 | 内核**没有**「列出断点」的事件：`DebugMeta`（`model.rs`）是**死 DTO**（全仓无使用）⇒ ⇒ 前端列表**只能是 UI 回显** ⇒ ⇒ 必须**如实标注**它不是内核的镜像（裁决 O） |
| F10 | 断点命中由 `Halted { reason: HaltReason::Breakpoint, pc }` 报告 ⇒ ⇒ 前端**不自己判断**「是不是命中断点」（裁决 M） |
| F11 | 真机门禁**已有一整段断点测试**（`osz` 段的 E-7）⇒ ⇒ 它走**脚本口** `window.riscv_kernel.setBreakpoint()` ⇒ ⇒ 页面版只要发**同一个命令** ⇒ ⇒ **内核行为一字不变** ⇒ ⇒ **判别力路径现成** |
| F12 | demo 固件有**专用断点靶点** `DEMO_FIRMWARE_BREAKPOINT_ADDR = 0x20`（`front/dev/demo-firmware.js`）⇒ ⇒ 真机端到端断点测试**不需要**仓外 osz ELF |
| F13 | demo 固件在 boot 时**装上但没跑**（真机门禁 `kernelExec` 断言「单步后 PC = 0x00000004」⇒ ⇒ 跑之前 PC = 0）⇒ ⇒ 断点测试从 PC = 0 起 ⇒ ⇒ 「继续」必在 0x20 停 |
| F14 | 产品树当前是**扁平**渲染（`renderTree(node)` 递归）⇒ ⇒ 可折叠要**新增**折叠状态；源码的**文件列表**在 v0.22 批**已做**（`front/views/components/source-view.js` + `matchSourceFile`）⇒ ⇒ 本批**只调形态** |

### §1.3 本批**不做**

- ⛔ **波形图**（echarts / Canvas）⇒ ⇒ **v0.51 批**（本批只把波形视图的**通道列表**改成卡片形态）。
- ⛔ **寄存器 ABI 名** ⇒ ⇒ 契约层**没有**那个字段（F3）⇒ ⇒ **不编造**（裁决 E）⇒ ⇒ 登记为已知边界。
- ⛔ **源码行断点** ⇒ ⇒ 需要「行 → 地址」映射，而 M-11 的行表**只覆盖带 DWARF 的程序** ⇒ ⇒ 本批的断点**只从反汇编行走**（裁决 H）⇒ ⇒ 登记为已知边界。
- ⛔ **观察点（watchpoint）UI** ⇒ ⇒ 契约层有 `SetWatchpoint`，但本批只做**断点**（裁决 I）。
- ⛔ **断点持久化**（跨会话 / 跨工程）⇒ ⇒ 内核的断点集随工程失效 ⇒ ⇒ 前端列表也随会话清（与反汇编同一条规矩）。
- ⛔ **升级任何版本号** ⇒ ⇒ **契约层零升版**（裁决 N）：`SCHEMA_VERSION` 仍 **8** / `SIM_STATE_SCHEMA_VERSION` 仍 **2** / `PLATFORM_SCHEMA_VERSION` 仍 **1** / `PLATFORM_RULES_VERSION` 仍 **3**。
- ⛔ **改路由 / 改视图数量**（仍是 hash 路由、仍是 8 个视图）。

## §2 裁决

| 号 | 裁决 |
| --- | --- |
| A | **稳定钩子一字不动** —— 八个视图的 `[data-view-body]`、各视图内部那些 `data-*` 属性与关键 class（F2）**全部保留** ⇒ ⇒ 内容形态**只改结构与呈现** ⇒ ⇒ 真机门禁 **104** 条与前端用例 **527** 条**零改动** ⇒ ⇒ ⇒ **通用判据**：**改 DOM 结构前 ⇒ ⇒ 先查判据怎么取那个元素 ⇒ ⇒ 判据的意图与元素标签无关 ⇒ ⇒ 那就别动它**（STAGE-34 §8 订正 4 的延续） |
| B | **复用 v0.49 的卡片类**（`.cards` / `.card` / `.kpi` / `.chip` / `.banner` / `.empty` / `.legend`）⇒ ⇒ **不新造第二套类名** ⇒ ⇒ 设计令牌**仍只有 `:root` 一个落点** |
| C | **产品树可折叠** —— 折叠状态住**视图状态** `product.collapsed`（一个地址集合）⇒ ⇒ **不是 DOM 私藏** ⇒ ⇒ 切走再切回来**还在** ⇒ ⇒ ⛔ **不用 `hidden` class 私藏** |
| D | **内存图地址比例条** —— 每段宽度按**该段地址区间 / 整图跨度**算 ⇒ ⇒ 那是**真数据**的投影 ⇒ ⇒ ⛔ **不用固定百分比** |
| E | **不做 ABI 名** —— 契约层 `gpr` 是 `[u32; 32]`（F3）⇒ ⇒ 原型的「ABI 名」**没有数据源** ⇒ ⇒ ⇒ **通用判据**：**界面文案是能力声明 ⇒ ⇒ 声明的必须是现在真有的**（STAGE-34 §8 订正 3 的延续） |
| F | **寄存器变化高亮** —— 与**上一次读回的 GPR 快照**比 ⇒ ⇒ 落点 = **视图状态 `regmem.prevGpr`** ⇒ ⇒ 由 app 层在 `read-regs` **之前**存 ⇒ ⇒ **视图层只读**（分层不破）⇒ ⇒ 快照**只存一份** |
| G | **TX / RX 计数** —— TX = 内核 `Console` 事件累计字节（F4）· RX = 前端 `WriteConsole` 发出字节累计（F5）⇒ ⇒ **两个不同源** ⇒ ⇒ 界面上**分别标注**（「TX guest→终端」/「RX 终端→guest」）⇒ ⇒ **不是同一个源** |
| H | **源码行断点不做** —— 需要「行 → 地址」映射，而 M-11 的行表只覆盖带 DWARF 的程序 ⇒ ⇒ 断点**只从反汇编行走**（那里地址**现成**）⇒ ⇒ 登记为已知边界 |
| I | **观察点 UI 不做** —— 本批只做断点 ⇒ ⇒ `SetWatchpoint` 仍只有脚本口 |
| J | **断点 id = 断点地址** —— `id` 由前端分配（F7）⇒ ⇒ 令 `id = addr` ⇒ ⇒ 「**一址一断点**」这条**内核语义**（F8）在 id 上就成立 ⇒ ⇒ ⇒ 前端**不需要第二个计数器状态** ⇒ ⇒ **状态只有一份** ⇒ ⇒ `ClearBreakpoint { id }` 传的也是**地址** |
| K | **断点列表唯一落点 = 视图状态 `debug.breakpoints`**（元素是**地址**数组）⇒ ⇒ 视图层**只读 + 发命令**（不碰服务层）⇒ ⇒ app 层写 ⇒ ⇒ **一个落点** |
| L | **「停下」状态归到视图状态 `debug.halt`** —— 现在 `window.riscv_kernel.lastHalt()` 读的是 `exposeScriptCommands` 的**闭包变量** ⇒ ⇒ 若视图也要「停下原因」⇒ ⇒ 再订阅一次 `halted` 就是**两份状态** ⇒ ⇒ ⇒ **改成：app 层一处订阅写入视图状态 `debug.halt`，脚本口读同一份** ⇒ ⇒ **一个落点** |
| M | **命中提示以内核为准** —— 「命中断点」这句话**只在** `Halted.reason === "Breakpoint"` 时出现 ⇒ ⇒ 前端**不自己判断**「跑没跑到那个地址」 |
| N | **契约层零升版** —— 复用既有 `SetBreakpoint` / `ClearBreakpoint` / `Halted` ⇒ ⇒ **零新 DTO / 零新命令 / 零新事件** ⇒ ⇒ 前端镜像**不用改版本号** |
| O | **前端断点列表是「UI 回显」，不是内核镜像** —— 内核**没有**「列出断点」的事件（F9）⇒ ⇒ 界面上**如实标注**「本会话由界面设置的断点」⇒ ⇒ 与脚本口设的断点**互不可见** ⇒ ⇒ 这是**已知边界** ⇒ ⇒ ⇒ **通用判据**：**UI 手里那份列表 ⇒ ⇒ 必须说清它是「我请求过的」还是「它现在的」** |

## §8 施工期订正

### 订正 1 · `:root` 之外仍有 12 处裸 `rgba(...)`（已知边界）

- **规格原文**：§2 裁决 B「复用 v0.49 的卡片类 ⇒ ⇒ 设计令牌**仍只有 `:root` 一个落点**」。
- **实测**：`front/style.css` 在 v0.49 批落点之前就有 **12 处裸 `rgba(...)`**（`.banner`、`.map-table th`、`.reg-grid > div` 等）⇒ ⇒ v0.49 批那条「颜色字面量只在 `:root`」的判据**只查 `#rrggbb`** ⇒ ⇒ **抓不到 `rgba(...)`** ⇒ ⇒ 这 12 处一直躺在那儿。本批新增的 6 个 alpha 令牌（`--amber-wash` / `--amber-edge` / `--accent-wash` / `--accent-edge` / `--green-wash` / `--red-wash`）**全部**用 `color-mix(in srgb, var(--X) N%, transparent)` ⇒ ⇒ 本批**新增**的代码零 `rgba`、零 hex 散落；但**既有的 12 处本批不动**。
- **已改成**：登记为**已知边界**（§4），并在 `front/style.css` 的令牌注释里**逐字**写明「既有的 12 处裸 `rgba(...)` 本批不动」；清它是**另一批**的活（那条要把 v0.49 批的判据从「只查 hex」扩到「也查 rgba」）。

### 订正 2 · 验收表补 A-16（裁决 F 原本**没有**验收编号）

- **规格原文**：§2 裁决 F「寄存器变化高亮 —— 与**上一次读回的 GPR 快照**比 ⇒ ⇒ 落点 = 视图状态 `regmem.prevGpr`」；§3.1 的 A 组只到 **A-15**。
- **实测**：施工时发现**裁决 F 没有任何一条验收编号管它** ⇒ ⇒ 实现完了也**没人验** ⇒ ⇒ 那是一条「**看着像有覆盖、实际上零覆盖**」的空气（比没有判据更坏）。
- **已改成**：§3.1 补 **A-16**（快照落点 = `regmem.prevGpr` · app 层在 `read-regs` **之前**存 · 视图层**只读** · 变了的格子带 `.up` / `.down` · **没变的不加类**）；§6 判别力清单补**第 12 条**；§10 第 6 项与 `tools/stage35_check.py` 的 `EXPECT_ACCEPT` 同步改成 `A-1 ~ A-16`。

### 订正 3 · B-19 的「点了没报错」口径

- **规格原文**：§3.2 的 B-19「真点到调试视图反汇编表里的「加断点」按钮 ⇒ ⇒ **点了没报错**」。
- **实测**：错误区**故意保留**内核上一次的报告（`wireDebug` 的 `error` 订阅只写不清，理由是「那是内核的最后一次报告」⇒ ⇒ 不清）⇒ ⇒ 真机门禁跑到这一段时，错误区里**留着** `loadImage` 段 B-5 故意喂坏 ELF 得到的 `E_LDR-01：truncated ELF header: 41 < 52` ⇒ ⇒ 判「错误区是空的」会**恒红**。
- **已改成**：B-19 的判据改成「**点了之后错误区与点之前逐字相同**」⇒ ⇒ 点了没产生**新的**错误（**不是**「历史上没有过错误」）。

### 订正 4 · A-11 的「段表」指的是**编辑器里那张**

- **规格原文**：§3.1 的 A-11「内存图比例条的**分段数 == 段表行数**（且每段宽度按**真地址区间**算）」。
- **实测**：仓里有**两张**段表 —— ① 产品视图那张（`[data-region-base]` 行的 M-14 **当前生效**的映射表）· ② 板级内存图**编辑器**里那张（`[data-mmap-row]` 行的**草稿**表）。比例条落在**编辑器**那张（草稿是「用户正在配的那块板」，产品视图那张是内核**当前生效**的图）⇒ ⇒ 「段表」指的是 ②。
- **已改成**：A-11 的措辞补成「**编辑器里那张段表**（`[data-mmap-row]` 行）」⇒ ⇒ 免得后人拿产品视图那张来比（那**分不清**，因为两者的段数可能一样）。

### 订正 5 · A-13 的 ABI 名清单是**完整的 32 个**

- **规格原文**：§3.1 的 A-13「**ABI 名零出现**（界面里没有 `sp` / `ra` / `gp` **之类** ABI 别名 ⇒ ⇒ 裁决 E）」。
- **实测**：「之类」没有可执行的边界 ⇒ ⇒ 只查 `sp` / `ra` / `gp` 三个是**半截**判据 ⇒ ⇒ 剩下 29 个别名（`s0`-`s11` / `a0`-`a7` / `t0`-`t2` / `tp` / `gp` / `zero`）照样能编出来而不被抓住。
- **已改成**：A-13 的措辞改成「**完整的 32 个** ABI 别名」；实现按那张**完整的表**逐个查（`\b<name>\b` ⇒ ⇒ 十六进制值里的 `a0` 之类**不会**误判，因为 `\b` 要求非单词字符边界）。

### 订正 6 · §9 的 T3 期望红集**写错了**：红的是 **B-25**（不是 B-21）

- **规格原文**：§9 的 T3「把断点的 `id` 改成**自增序号**（不再等于地址）」⇒ ⇒ 期望变红「A-8 · A-9 · **B-21**」。
- **实测**：红的是 **A-8 · A-9 · B-25** ⇒ ⇒ **B-21 仍然绿**。原因：**内核按**地址命中（M-17 的 `breakpoint_at(state.pc)`），**与 id 无关** ⇒ ⇒ 「id ≠ 地址」**不妨碍**内核在那个地址停下 ⇒ ⇒ B-21（「内核在那个地址停下」）**照样成立**。
  ⇒ ⇒ **真正的后果在撤掉那一侧**：撤掉时 `ClearBreakpoint { id }` 发的是**另一个 id** ⇒ ⇒ M-08 的 `clear` 对**不存在的 id** 是**幂等**的（返回 `Ok(None)`，**不报错**）⇒ ⇒ **断点根本没被撤掉** ⇒ ⇒ 撤掉后再「继续」，**内核还在那个地址停** ⇒ ⇒ **B-25 变红**。
- **已改成**：§9 的 T3 期望红集改成「A-8 · A-9 · **B-25**」⇒ ⇒ ⇒ **通用判据**：**「界面上那个 id 等于什么」是一条**前端状态**的不变量，不是内核行为的不变量** ⇒ ⇒ 它的判别力落在「**撤掉之后内核还停不停**」（B-25）**不是**「内核停不停」（B-21）⇒ ⇒ ⇒ **写「期望变红」时要问：这条变异改变的是「界面显示」还是「内核行为」？** ⇒ ⇒ 两者的判据**不在同一组**。

### 订正 7 · §9 的「期望变红」列应读作「**至少**这些」

- **规格原文**：§9 的表头「期望变红」。
- **实测**：**T1 / T2 / T5 三条**的实测红集是期望的**超集** ⇒ ⇒ 例如 T1（删掉断点列内容）不只让 A-6 / B-19 / B-20 红，还让 **A-8 / A-9** 也红（那个按钮**根本不存在** ⇒ ⇒ 点它 ⇒ ⇒ 命令发不出去）⇒ ⇒ 还让 **B-21 / B-22 / B-23** 也红（内核**收不到**断点 ⇒ ⇒ 压根不会停 ⇒ ⇒ 也不会有「命中断点」那句提示）。
- **已改成**：§9 的表头改成「期望变红（**至少**这些）」，并新增「**实测红集**」一列 ⇒ ⇒ ⇒ **通用判据**：**「超集」是正常的**（一条变异常常连带打掉别的判据）⇒ ⇒ **「红集里出现没预料到的那一条」时必须逐条解释**（本批解释了 T1 与 T2 两处）⇒ ⇒ **不解释就写进 §9** 是在**藏**信息。
