## §2 判定口径（**逐字冻结**）

### §2.1 三档（用户 2026-11-01 拍板：**中档**）

| 情形 | 判定 | 后果 |
| --- | --- | --- |
| 镜像要的每个区间都**完全落在**当前板的**某个 RAM / ROM 分区**里 | **认得** | 正常装、正常跑 |
| 镜像要的区间**完全不落在**当前板的任何分区里（一个字节都不在） | **不认得** | ⛔ **拒** ⇒ ⇒ 报 **`E_PLT_17_BOARD_MISMATCH`**（「未知系统」）⇒ ⇒ **不建图、不写总线** |
| 镜像要的区间**部分落在**（有交集但不完整） | **中档** | **不拒** ⇒ ⇒ 仍然装、仍然跑 ⇒ ⇒ 撞到的那部分由**总线**报**未映射访问**（**既有**的错误码）⇒ ⇒ 本批**不新增**「未知系统」的那一档 |

⚠️ **为什么「中档」落在「部分落在 ⇒ 不拒」**（用户拍的是「中档」，而**新机制里没有「固件没声明」那个态** ⇒ ⇒ 三档**自然映射**成下面这个形态）：

| 档 | 部分落不在时 | 完全落不在时 |
| --- | --- | --- |
| **严** | **拒** | **拒** |
| **中（默认）** | **不拒**（让总线自己去报） | **拒** |
| **松** | 不拒 | 不拒 |

⇒ ⇒ ⇒ **中档**是**唯一**既能让「未知系统」**真的出现**、又**不破坏**存量链路的档 ⇒ ⇒ 默认取它。

### §2.2 判定函数（**纯函数** · 一处落点）

```
compatibility(mirror_ranges, board_regions) →
  { recognized: bool, partial: bool, missing: bool }
```

- `mirror_ranges`：镜像要落的区间（`(lo, hi)` 列表，**半开**）；
- `board_regions`：当前板的分区（`(lo, hi)` 列表，**半开**）；
- **只看 RAM / ROM**（F-5 ⇒ 外设窗口长度**不在描述里** ⇒ ⇒ 本批**不**算外设覆盖 ⇒ ⇒ 如实登记这条边界）。

⚠️ **「完全落在」与「有交集」是两个不同的判据** ⇒ ⇒ **不能**用同一个布尔 ⇒ ⇒ ⇒ 必须分开算 ⇒ ⇒ 否则「部分落不在」会被误判成「完全不落不在」⇒ ⇒ ⇒ 那是**把中档做成严档** ⇒ ⇒ ⇒ 用户拍的档就**没了**。

| 1 | **门禁的 `--serve-port` 不同步 URL** | 连撞三个端口都报「HTTP 服务没能在 10s 内就绪」⇒ ⇒ 而**服务其实起得好好的**（手工起同一个端口 `curl` 是 200） | `parseArgs` 只把 `--serve-port` 写进 `opts.servePort` ⇒ ⇒ **没改** `opts.url` ⇒ ⇒ 服务起在 A 端口、探测却打 **B 端口**（默认 8080）⇒ ⇒ ⇒ **「换端口避开冲突」这个诊断手段直接失灵**（而那正是撞端口时的标准做法）⇒ ⇒ **修法**：钉了 `--serve-port` ⇒ ⇒ URL 的端口**跟着换**（除非 `--url` 也钉了）⇒ ⇒ **通用判据：任何「一个参数决定两处」的地方 ⇒ ⇒ 只改一处 ⇒ ⇒ 另一处**默默指着旧值** ⇒ ⇒ 症状是「我明明指定了 X」⇒ ⇒ ⇒ **一个参数 ⇒ ⇒ 一个落点** |
