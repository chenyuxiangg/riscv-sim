## §1 事实（**逐条读源码**，不是推断）

1. **路线 α 已拍板**（STAGE-44 分岔点 0）：「现阶段**一块板一个 MCU** 就够」⇒ ⇒ 产品树 = 当前生效板的**派生视图**（前端算）⇒ ⇒ **本批的 MCU = 板描述的顶层属性**（不是内存图里的器件）⇒ ⇒ 路线 β（产品树进内核）仍排队第 60 批（**若选 β**）。
2. **描述形状**（`crates/contract/src/platform.rs:225` `PlatformDescription`）：顶层已有 `bridge` / `roles` / `pins` 三个**可选**段（各带 `#[serde(default, skip_serializing_if = "Option::is_none")]` ⇒ ⇒ 缺省**不带键**）⇒ ⇒ **MCU 段沿用同一加法模式**。
3. **固件装载只认 ELF32**（`crates/kernel/src/m06_elf/elf.rs`）：`ELFCLASS` 必须 1（32 位）；`e_machine` 必须 `EM_RISCV=0xF3`；`e_type` 必须 `ET_EXEC=2` ⇒ ⇒ **固件侧的 ISA 事实只有四个**：**class**（32/64）、**e_machine**（已查）、**e_flags**（MVP 里 `let _ = (e_flags, e_ehsize)` **未用**）、**e_entry**。
4. **固件实测**（`tests/golden/_out/*.elf` 共 80 个，逐一读头）：**全部** `class=1`（ELF32）、`machine=243`、`entry=0x8000_0000`、`flags=0x0`——**除一个**：`local-compressed_trap.elf` `flags=0x1`（`EF_RISCV_RVC`=1<<0 **置位**）⇒ ⇒ **只有这一个固件带 RVC 位**。
5. **RISC-V ELF 的 e_flags 只编码三件事**：`EF_RISCV_RVC`（bit0，压缩指令）、`EF_RISCV_RVE`（bit5，嵌入式）、float ABI（bits 8-11）⇒ ⇒ **m / a / f / d 等扩展在 ELF 头里查不到**（要 .riscv.attributes 段或指令解码，MVP 都不做）⇒ ⇒ **「按 ISA 校验固件」能查的只有 class 与 RVC 位**。
6. **内置描述不跟版本走**：`crates/kernel/src/kernel_host/platforms/qemu-virt.json` 是 `schema_version: 1`（v0.73/v0.74 两次升版都没动它 ⇒ ⇒ 内置靠**缺省优先**逐字不变）⇒ ⇒ **本批内置描述补 `mcu` 键、`schema_version` 仍保持 1**（老形状 + 新可选键，与 roles/pins/bridge 同款惯例）。
7. **版本现状**（`crates/contract/src/platform.rs:86-103`）：`PLATFORM_SCHEMA_VERSION = 3` · `SUPPORTED_PLATFORM_SCHEMA_VERSIONS = [1, 2, 3]` ⇒ ⇒ 本批 **3 → 4**、`SUPPORTED = [1, 2, 3, 4]`；**信封 `SCHEMA_VERSION` 11 不动** · **会话快照 `SIM_STATE_SCHEMA_VERSION` 2 不动**。
8. **场景码现状**（`crates/contract/src/error.rs`）：`E_PLT` 最高 **19**（`E_PLT_19_PINS_INVALID`）；`E_PLT_17_BOARD_MISMATCH` = 「未知系统」（**地址**层面：镜像要的区间不在板上）⇒ ⇒ **ISA 不匹配是另一层语义**（固件**架构**与板声明不符）⇒ ⇒ **一码一义：新码 `E_PLT_20_FW_ISA_MISMATCH`**。
9. **固件装载门禁的位置**（`crates/kernel/src/kernel_host/mod.rs:2639` `on_load_project`）：`backend.reset()` 在**函数开头** ⇒ ⇒ 「未知系统」判不过时 `E_PLT_17` 已把现场复原 ⇒ ⇒ **ISA 校验放同一处**（同款「判不过 ⇒ 报码 + 复原」）。
10. **前端板编辑器**（`front/views/components/memory-map.js`）：`roles` / `pins` 已有 `normalize*` 深复制往返（有 ⇒ 草稿有 ⇒ 提交回去还在；无 ⇒ **不带键**）⇒ ⇒ **MCU 段沿用同一模式**；前端**不判** roles/pins/bridge 的合法性（原样透传，合法性只由内核判）⇒ ⇒ **MCU 同样透传**。

## §2 口径（**逐字冻结** · 草稿版）

### §2.1 形状（描述顶层新加**可选**段）

```jsonc
{
  "schema_version": 4,            // 3 → 4（本批升版；1~3 仍受支持）
  // ...既有字段不变...
  "mcu": {                        // 可选；缺省不带键 ⇒ 无 MCU 声明
    "isa": "rv32ima",            // 必填（若给 mcu）· 词法见 §2.2
    "vendor": "qemu",            // 可选 · 自由文本
    "model": "virt",             // 可选 · 自由文本
    "vector_table": {            // 可选 · 见 §2.3
      "base": 0x80000000,
      "entries": 16
    }
  }
}
```

契约层新类型：`McuSpec { isa: String, vendor: Option<String>, model: Option<String>, vector_table: Option<VectorTableSpec> }` · `VectorTableSpec { base: u32, entries: u32 }`（**表项 4 字节固定**，RISC-V 直接模式的 mtvec 语义；不做可配宽度 —— 见 §6）。

### §2.2 ISA 词法（**一个落点**）

- `isa` 必须形如：`rv` + `32`|`64` + **扩展字母串**（字符集 `{i, e, m, a, f, d, c}`，**去重 + 规范序** `i e m a f d c`）⇒ ⇒ **归一化后比较**（`"RV32IMA"` ⇒ 归一 `"rv32ima"`）。
- **非法 ⇒ 契约校验就拒**（新增 **V-23**；⚠️ V-22 编号已被「缺 `base` 由装配期分配」占用 ⇒ MCU 校验用 V-23；码：**裁决 E**：isa 词法非法 = 新码 `E_PLT_21_MCU_INVALID`（`mcu` 段自身形状非法 —— 与「固件不匹配」是**两个对象**，一码一义纪律照旧）。
- **内核侧不抄词法**：解析 isa 用契约层**同一个函数**（`mcu_isa_info(&str) -> Option<McuIsaInfo>`，返回 rv32/rv64 + 是否含 c/e）⇒ ⇒ 一次查表，两处都用（与事件词表同款「一个落点」）。

### §2.3 向量表语义（**2026-11-03 用户拍板：声明 + 展示就行**）

- **本批 = 声明 + 展示**（MCU 身份数据：复位/中断向量表基址与表项数）⇒ ⇒ **不做**「镜像必须覆盖向量表区域」校验（那是又一层门禁，见 §6）⇒ ⇒ **用户已确认**。
- 语义钉死：`base` = 向量表首地址（RISC-V 惯例 = 复位入口）；`entries` = 表项数（× 4 字节 = 表长）。**前端显示、契约往返、内核接受但不据此行为**（如实登记：本批唯一行为 = ISA 校验）。真实 RISC-V MCU 的向量表 = 异常/中断入口表（表首复位向量 + 各 handler 入口）；模拟器里 `mtvec` 由 guest 自写 ⇒ 板声明的向量表是「数据手册信息」，非运行时行为。

### §2.6 顺手整改（2026-11-03 用户当场拍板 · 与 MCU 展示同在一个编辑面）

1. **板级视图 = 用户自己配置** ⇒ ⇒ 加载固件后**编辑面不自动实例化**生效板描述（`currentDraft` 的「草稿 → 生效板描述 → 默认草稿」那条链的**中间项作废**：生效板描述**只读展示**、不填充草稿）⇒ ⇒ 显示「当前生效板：QEMU virt（自动选择）· 只读」+ 引导「板级视图由你配置」。
2. **内置板 = 模版** ⇒ ⇒ 板编辑器提供「**从内置模版开始**」（qemu-virt 等内置板列为模版，用户点选后把该板描述导入草稿作为**起点**，自己改）⇒ ⇒ **不是系统默认选**。
3. **基址以 16 进制显示**（如 `0x02000000`）⇒ ⇒ 产品树/内存映射的 base 输入框与展示统一 hex。
4. **布局整改**：字段行 CSS grid 对齐（label 定宽、value 定宽）· 删除按钮降级为危险色幽灵按钮移到卡片角落 · 器件 id 与类型徽标去重（不再 `CLINT (CLINT)`）· 器件卡片分组清晰。
5. ⚠️ **内核自动选板保留为运行兜底**（固件要跑必须落在一块板上：未知系统门禁 E_PLT-17 依赖生效板）⇒ ⇒ 前端**只读标注**「自动选择（仅用于运行）」+ 引导用户自己配置 ⇒ ⇒ **编辑面不再被自动填充**（用户核心诉求）。

> ⚠️ 边界：若将来用户要求「加载固件时无板一律拒（连兜底也不要）」，那是另一批（影响存量 golden/真机链路），本批**不做** —— 本批只改**前端编辑面语义** + 模版入口。

### §2.4 内核 ISA 校验（**唯一行为** · 三个判据）

| 判据 | 板声明 | 固件事实 | 判定 |
| --- | --- | --- | --- |
| **① class**（双向严格） | `rv32…` | ELFCLASS=1（32） | 匹配 ✓ |
| | `rv64…` | ELFCLASS=1（32） | **拒** `E_PLT-20`（固件是 32 位，板声明 64） |
| **② c 位**（**单方向**严格） | isa **不含** `c` | e_flags & `EF_RISCV_RVC`（0x1）≠ 0 | **拒** `E_PLT-20`（固件用了板不支持的压缩指令） |
| | isa **含** `c` | 带或不带 RVC 位 | 都 ✓（`c` = 「允许压缩」，非「必须压缩」） |
| **③ m/a/f/d/e** | 声明里有 | ELF 头查不到 | **不校验**（如实登记：MVP 拿不到该事实） |
| **缺省**（无 `mcu` 段） | —— | 任意 | **不校验**（存量逐字不变 · 缺省优先迁移） |

⚠️ **为什么不双向严格**（c 位）：现有 80 个固件里 79 个不带 RVC、1 个（compressed_trap）带 ⇒ ⇒ 若「声明含 c ⇒ 必须带 RVC」，则内置板声明 `rv32ima`（无 c）会把 compressed_trap 拒掉 —— 那是**该有的行为**（板不支持压缩）✓；但若内置声明 `rv32imac`，则「含 c ⇒ 要求带 RVC」会把**其余 79 个**全拒 —— **存量固件全灭** ⇒ ⇒ ⇒ **c 位只能单方向**：**板声明不含 c ⇒ 压缩固件拒**（判别力在这一侧）**；板声明含 c ⇒ 不要求**（`c` 是能力不是义务）。

### §2.5 内置描述

- `qemu-virt.json` 补 `"mcu": { "isa": "rv32imac", "vendor": "qemu", "model": "virt", "vector_table": { "base": 0x80000000, "entries": 16 } }` ⇒ ⇒ **schema_version 仍 1**（内置惯例）⇒ ⇒ 校验对内置生效：**class 双向严格**（rv32 + ELF32 ⇒ 全过）· **c 单方向**（含 c ⇒ 不要求 ⇒ compressed_trap 也过）⇒ ⇒ **存量 80 固件 + 内核/真机测试固件零影响** ✓（实现时逐一核对）。
- ⚠️ `vector_table.base = 0x80000000` 与内置 RAM base=0 不一致 —— **声明不校验**（§2.3），仅作为 MCU 身份数据展示；如需一致可改 RAM（**本批不做**）。

## §4 判别力清单（**落地前先钉住**）

### §4.1 契约与跨层（A 组）

- **A-1** `mcu` 线上形状逐字钉住（`McuSpec` / `VectorTableSpec` 的 serde 字段名与 `skip_serializing_if`；缺省**不带键**）。
- **A-2** 往返：描述带 `mcu` ⇒ 契约解析 ⇒ 再序列化 ⇒ **逐字相同**；描述无 `mcu` ⇒ 序列化**没有** `mcu` 键。
- **A-3** isa 词法：`"rv32ima"` ✓ · `"RV32IMAC"`（归一）✓ · `"rv64x"`（非法扩展）✗ · `"rv32"`（无扩展字母）✗ · `"arm"` ✗ ⇒ 都拒 `E_PLT-21`。

### §4.2 内核（K 组）

- **K-1** 匹配装：`mcu.isa="rv32ima"` 的板 + ELF32 固件 ⇒ **装得上**（端到端跑）· 对照：无 `mcu` 的板 + 同固件 ⇒ 也装（缺省逐字不变）。
- **K-2** class 不匹配：声明 `rv64ima` + ELF32 固件 ⇒ **拒** `E_PLT-20`（判据 family+scenario，不看 message）⇒ 装板回**同一个码**。
- **K-3** c 位单方向：声明 `rv32i`（无 c）+ **RVC 固件**（`local-compressed_trap.elf`）⇒ **拒** `E_PLT-20`；对照：声明 `rv32imac` + 同固件 ⇒ **装得上**。
- **K-4** 缺省优先：无 `mcu` 段 ⇒ 压缩固件也装（不校验）⇒ 存量零风险。
- **K-5** 内置 qemu-virt（`rv32imac`）⇒ 存量 80 个 golden 固件 + 内核测试固件**全部照装**（实现时跑全量验证）。

### §4.3 前端（N 组）

- **N-1** `normalizeMcu` 往返：描述带 `mcu` ⇒ 草稿带 ⇒ 提交回去还在；无 ⇒ **不带键**（不塞空对象）。
- **N-2** 前端**零处**判 isa 合法性 / 固件匹配（原样透传 ⇒ 合法性只由内核 V-23 + 装载门禁判）。
- **N-3** 编辑器 **MCU 区**真的**显示**（isa/vendor/model/向量表 base+entries）——**只展示，不编辑**（用户拍板）。
- **N-4** （顺手整改）加载固件后**编辑面不自动实例化**生效板描述：草稿为空时显示「当前生效板（自动选择）· 只读」+ 引导；提供「从内置模版开始」（qemu-virt 模版导入草稿后用户自配）。
- **N-5** （顺手整改）基址输入框与展示统一 **16 进制**（`0x…`）；器件卡字段 grid 对齐 · 删除按钮降级 · id 徽标去重。

### §4.4 真机门禁（B 组 · **B-161 ~ B-165**）

- **B-161** 真机收下带 `mcu` 的板（isa `rv32ima` + 固件 ELF32）⇒ 照常装 + 跑。

- **B-163** 必要对照：无 `mcu` 的板 + 同固件 ⇒ **照常装**（缺省零风险）。

- **B-165** 编辑器显示 **MCU 区**（isa/vendor/model/向量表）⇒ 界面上看得到。
- **B-166** （顺手整改）加载固件后编辑面**不自动实例化**：草稿为空 + 生效板=内置 ⇒ 界面显示「当前生效板 · 自动选择 · 只读」提示、**不见**器件实例；点「从内置模版开始」⇒ 器件进入草稿（可编辑）。
