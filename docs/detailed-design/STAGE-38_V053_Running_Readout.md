## §1 为什么要做这一批

### §1.1 用户看到的现象

用户在 v0.52 批交付「连续运行」之后提出：

> 运行时寄存器/内存/PC 不应该显示，一直显示会导致界面闪动，只有当运行暂停（被断点停住、用户手动点暂停等）才能显示最新值。如果用户在运行时查看内存，需要报弹窗告警，弹窗需要能渐隐消失。

⇒ ⇒ 三件事：**① 运行中隐藏活值** · **② 运行中读内存 = 拒绝 + 告警** · **③ 告警是居中模态、5 秒后渐隐**。

⚠️ **用户拍定的形态**（三件，**逐字**）：

1. 活值显示成**固定符号 `-`**（**不是**占位文案、**不是**冻结旧值、**不是**隐藏整块）；
2. 「读内存」在运行中**拒绝执行**并弹窗，文案里要说「**请先暂停再读**」；
3. 弹窗**居中模态**、**5 秒后渐隐消失**、可以点「**知道了**」关闭。

### §1.2 实测事实（每条都对着仓库里**当前的**代码 / 内核源码量过）

| 编号 | 事实 |
| --- | --- |
| F1 | `Continue` **一定**产出一条 `Halted`（内核侧 `crates/kernel/src/kernel_host/mod.rs`：`steps.is_none()` ⇒ 必有 `HaltReason::EndOfExecution`）⇒ ⇒ 「在途 `Continue` 计数」可以被 `Halted` **精确**抵消 |
| F2 | `StepN` **通常不产** `Halted`（同处：`steps.is_some()` ⇒ `reason` 为 `None`，除非命中断点 / 陷阱）⇒ ⇒ 在途计数**只数 `Continue`**（否则要两条退休路径 ⇒ ⇒ 两个真相） |
| F3 | 界面的「暂停」**不发** `Pause` 命令（v0.52 裁决 E · F6 实测）⇒ ⇒ 暂停**不**产生 `Halted` ⇒ ⇒ 在途计数**不受**暂停影响 |
| F4 | `Halted` 是**唯一**的「一次执行结束」报告 ⇒ ⇒ 在途计数的**退休点只有一处** |
| F5 | 调试视图 / 寄存器视图 / 顶栏三处活值**都**来自 M-10 的**同一份**快照（`sim.gpr` / `sim.pc` / `timeVirt`）⇒ ⇒ **一处**隐藏口径就够 |
| F6 | 顶栏 PC / 虚拟时间由 `syncTopbarStats` 写（订阅 M-10 的快照）⇒ ⇒ M-10 的渲染节流是 **200 ms**（`RENDER_THROTTLE_MS`）⇒ ⇒ 活值每秒跳 **5** 次 ⇒ ⇒ 那就是**闪动**的来源 |
| F7 | 连续模式每续发一轮都 `publishViewState("debug")` ⇒ ⇒ 调试视图**整块** `body.innerHTML` 重建（**无节流**）⇒ ⇒ 连续跑时主线程被占满 |
| F8 | 运行中隐藏活值之后，调试视图的**渲染结果逐字相同**（活值那几格都是 `-`，其余字段这一趟没动）⇒ ⇒ 「同内容不重建」这条护栏**结构上**消掉每轮的 DOM 重建 |
| F9 | `window.riscv_kernel.continueRun()` 走的是**另一个窗口**（**不是**连续模式）⇒ ⇒ 「运行中」**不能**只看 `debug.run.mode` |
| F10 | 脚本口那个窗口**也**会产出 `Halted`（同 F1）⇒ ⇒ 在途计数**盖得住**它 |
| F11 | 仓里**没有** toast 设施（只有 `setNote()` 页脚一行、`.banner`、`.trace-notice`）⇒ ⇒ 告警弹窗是**新建**的 |
| F12 | 弹窗骨架必须**在视图正文之外** ⇒ ⇒ 否则调试视图每次 `body.innerHTML` 重建都会把它**销毁** |
| F13 | 「读内存 @0x100」在调试视图与 regmem 视图**各有一个**同名按钮（两处都发 `action: "read-mem"`）⇒ ⇒ **一条**拒绝路径就够 |
| F14 | 脚本口 `readMemory` 是**脚本**的路（`window.riscv_kernel.readMemory`）⇒ ⇒ 本批**不**弹窗（用户拍定） |
| F15 | 顶栏的 `data-topbar-time-ps` 是真机门禁**测量虚拟时间增长**的通道（B-34 / B-35 / B-37 / B-39 都读它）⇒ ⇒ 运行中**必须保留真实值** ⇒ ⇒ 隐藏的是**显示**，**不是**测量通道 |
| F16 | `front/tests/dom-stub.mjs` 支持 `classList` / `dataset` / `getAttribute` / `setAttribute` / `textContent` ⇒ ⇒ 弹窗的状态用**属性**表达 ⇒ ⇒ Node 侧可测 |

## §2 裁决

| 裁决 | 内容 |
| --- | --- |
| A | 「运行中」= `mode === "running"`（连续模式）**或** `busy > 0`（在途 `Continue` 计数）⇒ ⇒ 连续模式与脚本口那个窗口（F9 / F10）**都**盖得住 ⇒ ⇒ **一个判据、两个来源** |
| B | 在途计数**只数 `Continue`**（F2）⇒ ⇒ 退休点**只有一处**（`Halted`，F4）⇒ ⇒ 不写第二个真相 |
| C | 「暂停」**只**停续发，**不动**在途计数 ⇒ ⇒ `stopRunState` **保留** `busy` ⇒ ⇒ 正在跑的那**一个**窗口还在跑 ⇒ ⇒ 那段时间**仍然**算「运行中」⇒ ⇒ 活值**不**提前恢复 |
| D | 活值的隐藏口径**只有一个**（`liveValue(running, text)`）⇒ ⇒ 调试视图 / 寄存器视图 / 顶栏**三处**用**同一个词** ⇒ ⇒ 不是三份实现 |
| E | 隐藏的是**显示**，**不是**测量通道（F15）⇒ ⇒ 顶栏 `data-topbar-time-ps` 运行中**仍**给真实值 |
| F | 「读内存」在运行中**拒绝执行** + **弹窗** ⇒ ⇒ **不发** `ReadMemory` 命令 ⇒ ⇒ 不是「读了但不给看」 |
| G | 拒绝只发生在**界面**那两个按钮上；脚本口 `readMemory` **不弹窗**（F14 · 用户拍定） |
| H | 弹窗 = **居中模态** + **5 秒后渐隐** + 「知道了」**立即关闭** ⇒ ⇒ 三种关闭路径 |
| I | 弹窗状态用**属性** `data-alert-state`（`open` / `fading` / 空）表达 ⇒ ⇒ 不依赖 `style` / `hidden` 属性 ⇒ ⇒ Node 侧可测（F16） |
| J | 弹窗骨架住在 `front/index.html` 的**顶层**（视图正文之外）⇒ ⇒ 视图重渲染**不会**销毁它（F12） |
| K | 「同内容不重建」：渲染结果与上一次**逐字相同** ⇒ ⇒ **不**写 `body.innerHTML` ⇒ ⇒ 连续跑时 DOM **不**被重建 ⇒ ⇒ 主线程不再被占满（F7 / F8）⇒ ⇒ 闪动**结构上**消失 |
| L | `afterRender` 钩子**照旧**调用 ⇒ ⇒ 波形图那一张图**不受**去重影响 |
| M | 视图层读「运行中」只从**视图状态 `debug.run`**（app 层写）⇒ ⇒ 调试视图与寄存器视图**读同一份**⇒ ⇒ 不是第二个真相 |
| N | 契约层**零升版**、零新 DTO / 命令 / 事件；内核与宿主**零改动** ⇒ ⇒ 本批全是前端行为 |
| O | 单步**不**计入在途计数（F2）⇒ ⇒ 单步期间显示活值（那是用户**主动**的一步，显示的正是这一步之后的**新**值）⇒ ⇒ 不是「冻结旧值」 |

## §4 已知边界

1. **单步期间显示活值**（裁决 O）—— 单步是用户主动的一步，显示的正是这一步之后的**新**值 ⇒ ⇒ 不是「冻结旧值」；但严格说那一条指令执行期间内核**确实**在跑。
2. **脚本口 `readMemory` 在运行中仍然能读**（裁决 G · F14）—— 用户拍定；脚本口是**脚本**的路，弹窗对它没有意义。
3. **顶栏的原始 ps 属性在运行中仍是真实值**（裁决 E · F15）—— 它是**测量通道**，不是显示；界面显示的那一份**才是** `-`。
4. **内存单元表的地址列在运行中仍然显示** —— 地址是「**读了哪些单元**」的清单（读回一次就不再变），值那一列才是活值 ⇒ ⇒ 值列显示 `-`。
5. **「读寄存器」在运行中仍然能执行**（用户拍定的形态只覆盖读内存）—— 但运行中界面上的寄存器格**仍然**显示 `-` ⇒ ⇒ 读得到、看不见。
6. **本批的弹窗是全局的**（住在 `index.html` 顶层）⇒ ⇒ 任何视图下触发都看得见；**不**随视图切换消失。
