1 功能概述

1.1 模块定位

M-04 会话管理器（4.2.1）：管理会话生命周期（创建/运行/暂停/销毁）、并发隔离（每会话独立种子/事件序列/缓冲）、确定性状态持有（种子、事件序列、虚拟时间，表6 确定性约束），下发能力面白名单（按 role），并承担检查点触发策略（每 10s 虚拟时间或关键事件落盘；RPO ≤2s 宿主时间口径、快照保留 ≥5）。服务端形态执行会话配额（内存默认 256MB、会话数准入 ≥10，超限拒绝新会话并告警，R11）。会话建立时记录版本/环境 bundle（产品版本、内核版本、浏览器/UA、协议版本、构建哈希），随现场包与诊断包导出，支撑事后定位（评审 P-22）。恢复语义按后端分级（04-1，与 M-17 v1.2 对齐）：L3/self_iss → 最近检查点 + 稀疏输入事件序列重放（M-20 restore）；QEMU（L1）→ M-17 重启会话 + 输入事件重放（无 M-20 快照数据源），M-04 会话状态（sessionCtx/envBundle）随之重建。

1.3 MVP 范围与预留

MVP 实现范围：createSession(cfg)（配额校验 → 握手装配 → 输出 sessionId）；destroySession(id)（状态机校验 → 清理 M-23 句柄 → 确认）；checkpoint(reason)（按 checkpointPolicy 触发：10s 虚拟时间或关键事件 → M-20 记录 + M-23 原子写）；recordEvent(ev)（时间戳化输入事件 UART 写/按键/GPIO 注入 → 确定性事件流 → M-20）；capabilityList(role)（按 role 返回能力面白名单，QEMU L1 降级）；会话状态机（CREATING/RUNNING/PAUSED/DESTROYING/DESTROYED）+ 配额准入（内存 256MB/会话数 ≥10）。
预留项（P1 演进承接，不属现实现）：服务端实例资源配额完整预算（256 MiB×≥10 会话 → 实例基线内存 ≥3 GiB、CPU ≥2 vCPU、快照落盘 IOPS 按 RPO ≤2s 口径，评审 P-14）；现场包/诊断包自动导出（envBundle 已内建，导出流程 P-22 后续承接）；多会话调度与优先级策略。

2 数据描述

2.1 核心数据结构（源文档表29）

数据结构类型定义与用途
sessionCtxstruct会话上下文：sessionId、role、种子、事件序列号、虚拟时间、能力位
envBundlestruct版本/环境 bundle：产品版本、内核版本、浏览器/UA、协议版本、构建哈希（会话建立时记录，P-22）

2.1.1 复杂结构字段定义

sessionCtx 为每会话独立上下文（确定性状态持有：种子/事件序列/虚拟时间）；envBundle 在会话建立时一次性记录（不可变快照，随现场包/诊断包导出）；checkpointPolicy 定义检查点触发规则（10s 虚拟时间或关键事件清单）。字段定义如下：

// SessionState: 会话状态机（创建/运行/暂停/销毁/恢复；非法状态 → E_CTX-01）
// 04-9：新增 RESTORING（恢复专用态：M-22 触发恢复后、恢复完成前会话驻留；恢复失败重试 ≤3 → 终止会话 + 上报）
enum SessionState { CREATING, RUNNING, PAUSED, DESTROYING, DESTROYED, RESTORING };
// sessionCtx: 会话上下文（每会话独立，确定性状态持有，表29）
struct sessionCtx {
  uint64_t  sessionId;      // 会话标识（createSession 输出）
  Role      role;           // 角色（未知 role 装配 → E_CTX-01；枚举见下）
  uint64_t  seed;           // 确定性种子（同种子 → 同结果，表6）
  uint64_t  eventSeq;       // 输入事件序列号（recordEvent 单调递增）
  uint64_t  timeVirt;       // 虚拟时间副本（04-2：权威源=M-12 虚拟时钟，会话侧只读副本，随推进事件更新，不双维护）
  capBits   caps;           // 能力位（协商结果，QEMU L1 子集）
  SessionState state;       // 状态机当前态
};
// Role 枚举（04-6，与 capabilityWhitelist role 集合对应）：admin（管理员，全量能力面）/ guest（访客，基础能力面）/ anonymous（匿名，只读观测）
enum Role { admin, guest, anonymous };
// SessionCfg: 创建会话输入配置（04-6 展开）
struct SessionCfg {
  uint64_t  seed;           // 确定性种子（表6）
  uint64_t  clockHz;        // 虚拟时钟频率（M-12 时钟源）
  uint64_t  quantumNs;      // 仿真时间量子（M-12，默认 1µs 可配置）
  Role      role;           // 会话角色（装配校验：未知 role → E_CTX-01）
  uint32_t  ramMB;          // 内存区间预算（memUsed 求和项，04-7）
  uint32_t  bufMB;          // 缓冲/事件流预算（memUsed 求和项，04-7）
};
// InputEvent: 输入事件结构（04-6 展开；UART 写/按键/GPIO 注入，M-20 事件流接口）
struct InputEvent {
  uint8_t  kind;            // 0=UART 写（data/len）/ 1=按键（keyCode/down）/ 2=GPIO 注入（pin/level）
  uint64_t tVirt;           // 时间戳化（虚拟时间，recordEvent 赋值）
  uint64_t seq;             // 事件序列号（recordEvent 单调递增）
  json     payload;         // 载荷（按 kind 的具体字段：UART data/按键 keyCode/GPIO pin+level）
};
// CheckpointReason: 检查点触发原因枚举（04-6 展开）
enum CheckpointReason { TIME_INTERVAL, KEY_EVENT_BREAKPOINT, KEY_EVENT_PAUSE, CMD_CHECKPOINT };
// envBundle: 版本/环境 bundle（会话建立时记录，P-22；随现场包/诊断包导出）
struct envBundle {
  string  productVer;       // 产品版本
  string  kernelVer;        // 内核版本
  string  browserUA;        // 浏览器/UA
  uint8_t protoVer;         // 协议版本（与 M-05 negotiate 对齐）
  string  buildHash;        // 构建哈希
};
// quota: 服务端形态会话配额（P-14）；超限 → E_CTX-04 拒绝新会话并告警（R11）
struct quota { uint32_t memMB = 256; uint32_t maxSessions = 10; };
// checkpointPolicy: 检查点触发策略（每 10s 虚拟时间或关键事件；RPO ≤2s 宿主时间；快照保留 ≥5）
// 04-3 触发钩子：M-12 每量子/事件边界回调 m04OnTimeAdvance(tVirt) → 本策略判定；04-5 RPO 度量=宿主时间戳采样相邻检查点间隔
struct checkpointPolicy {
  uint64_t intervalVirtNs = 10e9;   // 触发间隔（10s 虚拟时间）
  Set<EventKind> keyEvents;         // 关键事件清单（断点命中/暂停/checkpoint 命令）
  uint32_t keep = 5;                // 快照保留份数（≥5，评审 R1）
};
// capabilityWhitelist: 按 role 下发的命令能力面白名单
struct capabilityWhitelist { Map<Role, Set<cmd>> allow; };  // capabilityList(role) 查询；QEMU 仅 L1 子集
// sessionTable: 会话表（并发隔离：每会话独立种子/事件序列/缓冲，会话间无共享可变状态）
struct sessionTable { Map<sessionId, sessionCtx> sessions; quota q; };

2.3 数据流说明

会话建立流：createSession(cfg) → 配额校验（超限 E_CTX-04 拒绝）→ 状态机 CREATING → M-07 建连 + M-05 negotiate（协议版本 + 能力位）→ 装配 sessionCtx + envBundle → RUNNING → 输出 sessionId。
运行期流：命令路由（M-05 dispatchCommand，能力面校验）→ 输入事件记录（recordEvent 时间戳化入确定性事件流，M-20）→ 检查点触发（M-12 每步回调判定：10s 虚拟时间或关键事件 → M-20 记录 + M-23 原子写，04-3）。
虚拟时间流（04-2）：M-12 虚拟时钟推进 → 每量子/事件边界回调 m04OnTimeAdvance(tVirt) → 更新 s.timeVirt（会话侧只读副本，不双维护）→ 触发 checkpointPolicy 判定。
恢复流（04-1 分级，与 M-17 v1.2 对齐）：L3/self_iss——崩溃/失控处置后（M-22 触发）→ 会话入 RESTORING → 最近检查点 + 稀疏输入事件序列重放（M-20 restore）→ 就绪后回 RUNNING（评审 R1）；QEMU（L1）——M-17 重启会话 + 输入事件重放（无 M-20 快照数据源）→ M-04 重建 sessionCtx/envBundle 回 RUNNING。

3 实现设计

3.1 createSession(cfg) 创建会话

createSession(cfg)：配额校验（会话数/内存，超限 E_CTX-04 拒绝新会话并告警 R11）→ 状态机 CREATING → 调 M-07 建连、M-05 协商（协议版本 + 能力位）→ 装配 sessionCtx + envBundle → RUNNING → 输出 sessionId。memUsed 口径（04-7）：创建时按配置预算求和（会话固定开销 + cfg.ramMB + cfg.bufMB），运行期按 sessionCtx 实际占用上限复核。伪代码如下：

// createSession: 创建会话并完成握手（4.2.1.3 表30）
sessionId createSession(SessionCfg cfg) {
  if (sessionTable.count() >= quota.maxSessions)   // 配额校验：会话数超限
    return E_CTX-04;                               // 拒绝新会话 + 告警（R11）
  if (memUsed(cfg) > quota.memMB) return E_CTX-04; // 配额校验：内存超限（默认 256MB，P-14）
  // memUsed 口径（04-7）：创建时 = 会话固定开销 + cfg.ramMB + cfg.bufMB（配置预算求和）；
  //   运行期 = 按 sessionCtx 实际占用上限复核（超限 → 强制降级/终止，6.2(1)）
  if (!validRole(cfg.role)) return E_CTX-01;       // 未知 role 装配 → 非法状态
  Session s = newCtx(sessionTable.nextId());       // 状态机 CREATING
  s.state = CREATING; s.seed = cfg.seed;
  m07Connect(s);                                   // M-07 建连（传输握手）
  NegoteResult r = m05Negotiate(cfg.protoVer, cfg.caps); // M-05 协议/能力协商（QEMU L1 降级）
  s.caps = r.result;                               // 能力位（降级明确）
  s.envBundle = captureEnvBundle();                // 版本/环境 bundle（P-22，不可变）
  s.timeVirt = 0; s.eventSeq = 0;
  s.state = RUNNING;                               // 装配完成 → 运行
  return s.sessionId;
}

3.2 destroySession(id) 销毁会话

destroySession(id)：会话不存在 → E_CTX-11（04-4）；状态机校验（已销毁/销毁中 → E_CTX-11）→ DESTROYING → 停止事件记录 → 清理 M-23 相关句柄（快照/日志归档）→ DESTROYED → 确认；销毁失败 → 回执携带状态（DESTROYING 保留重试）+ M-22 WARN 上报，异步重试路径不回 E_CTX-01（04-4）。伪代码如下：

// destroySession: 销毁会话并释放资源（4.2.1.3 表30）
Result destroySession(sessionId id) {
  Session s = sessionTable[id];
  if (!s) return E_CTX-11;                          // 04-4：会话不存在（新码，一场景一码）
  if (s.state == DESTROYING || s.state == DESTROYED) return E_CTX-11; // 已销毁/销毁中
  s.state = DESTROYING;
  stopEventRecording(s);                           // 停止 recordEvent 入流
  if (!m23ReleaseHandles(s)) {                     // 清理 M-23 快照/日志句柄
    m22Report(HMS_WARN, "session_destroy_fail", s.id); // 04-4：销毁失败 → 保留句柄并重试（4.2.1.5）
    return {status: DESTROYING, retry: true};     // 回执携带状态（DESTROYING 保留重试），不回 E_CTX-01
  }
  s.state = DESTROYED; sessionTable.erase(id);     // 释放会话资源
  return {status: DESTROYED, ok: true};
}

3.3 checkpoint(reason) 触发快照检查点

checkpoint(reason)：按 checkpointPolicy 触发——每 10s 虚拟时间或关键事件（断点命中/暂停/checkpoint 命令）→ 调 M-20 记录 + M-23 原子写 → 输出检查点确认；快照保留 ≥5（评审 R1）；非安全检查点（中断中的写）由 M-20 丢弃中间态并回退最近检查点。触发钩子（04-3）：M-12 每量子/事件边界回调 m04OnTimeAdvance(tVirt) 完成判定与调用。伪代码如下：

// checkpoint: 触发快照检查点（4.2.1.3 表30；策略 = 10s 虚拟时间或关键事件）
CheckpointAck checkpoint(CheckpointReason reason) {
  if (!policy.shouldTrigger(reason, s.timeVirt))    // checkpointPolicy 判定：10s 虚拟时间或关键事件清单
    return {skip, s.timeVirt};                      // 未到触发点（跳过）
  m20Record(s.sessionId, s.timeVirt);               // M-20 记录：证据流 + 稀疏输入事件序列
  m23AtomicWrite(snapshot, s.timeVirt);             // M-23 原子写落盘（宿主时间戳随写记录）
  m23TrimKeep(policy.keep);                         // 快照保留 ≥5（评审 R1，丢弃最旧）
  return {ack, s.timeVirt, hostTsn: m23LastTsn()};  // 检查点确认（携带宿主时间戳，RPO 采样用，04-5）
}
// 触发点：① 距上次检查点 ≥10s 虚拟时间；② 关键事件（断点命中/暂停/checkpoint 命令）
// 触发钩子（04-3）：M-12 每步回调 m04OnTimeAdvance(tVirt) → shouldTrigger 判定 → 满足即调用本函数
// 非安全检查点（中断中的写）：M-20 丢弃中间态 → 回退最近检查点（评审 C）
// RPO 度量（04-5）：监控/恢复侧按相邻检查点宿主时间戳间隔采样（≤2s 达标），不做虚拟↔宿主换算

3.4 recordEvent(ev) 记录输入事件

recordEvent(ev)：接收时间戳化输入事件（UART 写/按键/GPIO 注入，M-20 事件流接口）→ 附加会话上下文（sessionId + 单调 eventSeq + 当前虚拟时间）→ 入确定性事件流（按（虚拟时间, 插入序）稳定排序，表6）→ 调 M-20 记录。伪代码如下：

// recordEvent: 记录输入事件到确定性事件流（4.2.1.3 表30）
void recordEvent(InputEvent ev) {
  ev.sessionId = s.sessionId;                       // 会话归属（并发隔离）
  ev.seq = s.eventSeq++;                            // 事件序列号（单调递增，确定性排序）
  ev.tVirt = s.timeVirt;                            // 时间戳化（虚拟时间，不依赖宿主时钟）
  m20RecordInput(ev);                               // M-20：入 eventStream（按 虚拟时间,插入序 稳定排序）
  // 输入事件 = UART 写 / 按键 / GPIO 注入；不得绕过直接修改仿真状态（M-20 接口契约）
}

3.5 capabilityList(role) 返回能力面白名单

capabilityList(role)：按 role 查询 capabilityWhitelist 返回命令能力面白名单；ExecutionBackend 能力分级（L1/L2/L3）——自研 ISS 全量 L3，QEMU 仅 L1 子集（2.4 表6），协商降级由 M-05 negotiate 完成。伪代码如下：

// capabilityList: 返回能力面白名单（4.2.1.3 表30）
Set<cmd> capabilityList(Role role) {
  Set<cmd> allow = whitelist.allow[role];           // 按 role 下发能力面（capabilityWhitelist）

}
// 能力分级：L1 基础调试；L2 = L1 + 指令钩子；L3 = L2 + snapshot/restore + 事件流检查点
// 自研 ISS 全量 L3；QEMU 声明 L1 子集；前端按能力位协商降级（2.4 表6）

6.1 错误码与处置（E_CTX 族主属方）

M-04 为 E_CTX 错误码族主属方之一（源文档 3.4 表16），会话路径错误码统一收敛于此（一场景一码）：

6.2 边界与降级

（1）配额超限：会话数 ≥10 或内存超 256MB → E_CTX-04 拒绝新会话并告警（R11）；memUsed 口径（04-7）＝创建时配置预算求和（会话固定开销 + cfg.ramMB + cfg.bufMB），运行期按 sessionCtx 实际占用上限复核（超限 → 强制降级/终止 + M-22 上报）；服务端实例基线预算（P-14：256 MiB×≥10 会话 → 实例内存 ≥3 GiB、CPU ≥2 vCPU）为 P1 立项细化项。

（2）状态机非法：非法迁移/未知 role 装配 → E_CTX-01 + HMS 致命级上报（4.2.1.5）。

（3）销毁失败：M-23 句柄清理失败 → 回执携带状态（DESTROYING 保留重试）+ M-22 WARN 上报（04-4，不回 E_CTX-01）；重试成功才进 DESTROYED。

（4）检查点失败：落盘失败 → 跳过本检查点，下个触发点（10s 虚拟时间或关键事件）重试；非安全检查点（中断中的写）由 M-20 丢弃中间态、回退最近检查点（评审 C）。

（5）能力面降级：QEMU 后端仅 L1 子集 → capabilityList 输出 L1 白名单，协商降级由 M-05 negotiate 完成（E_CTX-03 语义联动）；前端按能力位降级提示。

（6）并发隔离：每会话独立种子/事件序列/缓冲，会话间无共享可变状态；隔离缺陷按确定性破坏处理（重放结果不一致 → 定位会话级污染）。

（7）恢复期间状态（04-9）：M-22 触发恢复后、恢复完成前会话驻留 RESTORING（恢复专用态）；恢复失败 → 重试 ≤3 次 → 终止会话 + HMS 上报（QEMU L1 同理：重启失败重试 ≤3 → 终止）。

（8）RPO 度量（04-5）：以宿主时间戳直接采样相邻检查点间隔（checkpoint 落盘记录宿主时间，监控/恢复侧比对 ≤2s 达标），不做虚拟↔宿主换算。

会话创建成功 → log(INFO, "SESS", "session create", "E_OK")（含 sessionId/role/种子/能力位）；配额超限 → log(WARN, "SESS", "quota exceed", "E_CTX-04")；状态机非法 → log(ERROR, "SESS", "state invalid", "E_CTX-01")（HMS 致命级联动）；会话不存在 → log(WARN, "SESS", "session not found", "E_CTX-11")；销毁失败 → log(WARN, "SESS", "destroy fail", "DESTROYING-retry")（保留重试，04-4）；检查点落盘 → log(INFO, "SESS", "checkpoint", "E_OK")（含虚拟时间/宿主时间戳/保留份数）；恢复流程 → log(INFO, "SESS", "restore", "E_OK")（含后端分级路径 L3/QEMU 与恢复结果）。会话关联字段（sessionId）随 M-21 双时间戳统一记录，产品/嵌入式工作台不可见（角色边界），仅管理员通道可查。
