1 重写缘由：v0.1 的四处硬伤

v0.1 的问题不是措辞，是结构。四处都撞了既有代码里已经写死的不变量或语义，逐条订正如下；v0.2 全部按订正后的口径展开。

2 输入方式 3 种落库，运行时语义 2 种

三类输入方式作为一等字段落库（kind 三值），但运行时只兑现两种语义：地址命中 / 谓词命中。符号断点落库后仍标 Symbol，便于列表筛选、快照还原与排障定位；它的命中路径与地址断点逐字相同。

3 表结构：一个权威 + 两个派生索引

既有 BreakpointTable 的权威是 by_addr——因为条目必须有地址。谓词条目没有地址，所以必须把权威换到 by_id：地址映射降级为索引，谓词条目另有一个 id 集合索引。业务状态仍只有一份。

表 3 · 结构字段与职责

字段角色职责
by_id: BTreeMap<u32, Entry>权威唯一业务状态。条目、enabled、命中计数、已解析 AST、降级标记全在这里
by_addr: BTreeMap<u32, u32>派生索引地址 → id，只收 Address / Symbol 条目；Condition 条目不入此索引。地址重复校验走这里
pred_ids: BTreeSet<u32>派生索引谓词类条目的 id 集合，供每指令遍历；由 by_id 唯一定定，不存额外信息
1Entry 存于 by_id —— 唯一业务状态（启停 / 计数 / AST / 降级）
2地址类条目同时在 by_addr 占一个地址槽（addr → id）
3谓词类条目同时在 pred_ids 占一个 id（无地址槽）
4写入路径必须同步三处；读取路径只用其中一处，不交叉推断
5任意时刻：by_addr 与 pred_ids 都必须能由 by_id 完整重算 ⇒ 不一致即内部损坏，按不存在处理，不 panic

「派生索引」的纪律：任何写路径（set / clear / set_enabled）结束后，三处必须一致；一致性可用一次只读断言验证（任一 id 在 pred_ids 中 ⇔ by_id 里该条 kind=Condition）。不一致时按「不存在」处理，不 panic（沿用现有 WASM 纪律：panic = Worker 崩）。

4 求值模型：条目级单一时刻

一条谓词描述的是某一时刻的状态，必须整体在一处求值。含不含内存读决定这个时刻落在哪里，但绝不把一条谓词拆到两个时刻。

表 5 · 两个求值时刻

时刻适用条目求值内容停止点
取指前 · 地址匹配Address / Symbol 条目，无附加条件不涉及表达式停在该条指令之前
取指前 · 地址+条件Address / Symbol 条目带附加条件地址命中后整条求值；含内存读也当场读总线——该地址命中频率极低，成本可忽略同上
取指前 · 谓词Condition 条目的谓词无内存读（常量 / 寄存器 / pc / 符号地址）整条谓词，用当前 gpr + pc 快照停在该条指令之前，与地址断点同心智模型
store 边界 · 谓词Condition 条目的谓词含内存读（变量值 / […]）整条谓词，用该时刻的 gpr + 该时刻的内存写已生效、指令已提交；PC 已推进到下一条
1注册：解析 AST，标记 contains_memory_read
2contains_memory_read = 假 ⇒ 每指令取指前整条求值
3contains_memory_read = 真 ⇒ 只在 store 成功写后整条求值
4store 边界：先用 gpr 算出各内存操作数的地址（不算总线访问）
5地址区间与本次写区间相交才读总线；不相交 ⇒ 谓词值不可能变 ⇒ 跳过
6相交 ⇒ 读总线取新值，整条谓词求值一次；为真即停
7命中回执带 trigger_addr（触发那次写所属指令的地址），因为 PC 已推进

表 6 · store 边界的三个精确口径

口径说明
写后判新值总线写已生效、指令已提交后才求值 ⇒ 读到的是新值，不是旧值
区间过滤是等价优化，不是近似store 指令不改 GPR（RV32 的 S 型指令没有 rd）⇒ ⇒ 若本次写区间与谓词引用的地址区间不相交，谓词读到的每个值都不变 ⇒ 跳过与求值结果必然相同。过滤用的地址由 gpr 现算（只读寄存器，不过总线）⇒ 连「先算地址再判」都不产生内存访问
引用 pc 的条目不做区间过滤提交后 pc 已推进，pc 本身就变了；此时区间过滤不再等价 ⇒ 这类条目按每条 store 都求值（保守）
要明写的语义代价含内存读的条目只在 store 边界求值，意味着它寄存器子式的变化不会单独触发。例如 a0 == 5 && [g] == 1 里 a0 变成 5 但没有任何 store 发生，这一轮不会停。这是「只监控 store 类指令」口径的直接后果，属于已接受的取舍，不是缺陷；要覆盖纯寄存器变化就得每条指令读总线，成本不可接受。

5 注册期：静态错必拒、动态错标降级

注册期做一次试求值，但只用来验证这条表达式在当前上下文求不求得出来，绝不据此判定命中。求值结果只记成基线供界面展示，不产生任何停止事件。

表 7 · 两类错误的分流

类别例子处置理由
静态错文法错 / 未知寄存器 / 未定义符号 / 寄存器取地址 &a0 / 空表达式拒绝注册，E_DBG-02，表不变这类错误不会因为运行推进而变好，早拒最省事

基线记录试求值得到的数值 / 是否已满足只存展示字段，不进命中路径避免「什么都没变就停」
为什么不判命中观察式的语义是「状态变化导致命中」。注册时若已满足就停，等于在没有任何变化时停住，且触发时机变得不可预测。基线只用来让界面显示「当前已满足 / 当前不满足」，帮助用户判断配置对不对。
