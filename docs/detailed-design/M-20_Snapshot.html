1 功能概述

1.1 模块定位

M-20 快照与确定性事件流记录（4.6.1）：横切基础设施，承载确定性（FR-12）与快照恢复（FR-19）——持续记录证据流（量子边界对齐、稀疏输入事件序列：UART 写、按键、GPIO 注入统一时间戳化入事件流）；执行检查点触发策略（每 10s 虚拟时间或关键事件）；恢复 = 最近检查点 + 稀疏输入事件序列重放执行（评审 R1，与全量证据流分离）；非安全检查点（中断中的写）丢弃中间态、回退最近检查点（评审 C）。定义现场包导出（评审 P-19）：崩溃/用户上报时导出「固件镜像 + 会话配置 + 最近检查点 + 稀疏输入序列 + 日志尾部 + 版本/环境信息」，确定性使其天然可复现，供管理员事后分析（不被后续检查点回退覆盖）。预留录制/回放格式与断言引擎（FR-17，P1，评审 P-02）。

MVP 实现范围：eventStream（稀疏输入事件序列）、checkpointList（≥5 保留）、replayCursor（重放游标）、crashKit（现场包，P-19）；recordInput/checkpoint/restore/replayInputs/exportCrashKit 五函数闭环（表75）。

2.1.1 复杂结构字段定义

事件流条目为时间戳化输入事件（确定性基线 FR-12）；检查点条目记录虚拟/宿主双时间戳与基线序列号（对账/恢复锚点）；现场包结构承载评审 P-19 六要素。字段定义如下：

// InputEvent: 稀疏输入事件（统一时间戳化，确定性基线 FR-12；P-16 夹具格式同源 {t_virt, seq, kind, payload}）
struct InputEvent {
  uint64_t tVirt;               // 虚拟时间戳（M-12 虚拟时钟，确定性、可重放）
  uint32_t seq;                 // 全局单调序列号（对账/重放游标锚点）
  uint8_t  kind;                // UART_WRITE / KEY / GPIO_INJECT（表75 recordInput 输入）
  Payload  payload;             // 载荷（UART 字节 / 键值 / GPIO 电平向量，见下方 union）
};
// Payload union: 按 kind 选其一（对齐 M-04 recordEvent 载荷，20-10）
union Payload {
  uint8_t  uartByte;            // kind=UART_WRITE：单字节
  uint32_t keyCode;             // kind=KEY：键值
  uint32_t gpioVector;          // kind=GPIO_INJECT：GPIO 电平向量（位图）
};
// kind -> payload 对应（20-10）：UART_WRITE→uartByte；KEY→keyCode；GPIO_INJECT→gpioVector
// Checkpoint: 检查点条目（checkpointList 元素，保留 ≥5，RPO ≤2s 宿主时间口径）
struct Checkpoint {
  uint32_t id;                  // 检查点 id（单调）
  uint64_t tVirt;               // 触发时虚拟时间
  uint64_t tHost;               // 触发时宿主时间（RPO 采样口径）
  uint32_t baseSeq;             // 基线序列号（后续输入事件起点）
  uint32_t version;             // schemaVersion（对齐 M-23 迁移链）
};
// Snapshot: 快照载荷（20-1 / 23-1 双侧对齐：恢复链核心，检查点实质 = 全仿真状态体）
//   入参形态 = 完整 Snapshot 单对象（M-20 组装 → M-23 m23SaveSnapshot(snap)/m23LoadSnapshot(cp) 同契约）
struct Snapshot {
  Checkpoint cpMeta;            // 检查点元数据（id/tVirt/tHost/baseSeq/version）
  EngineSnapshotDto  m12Engine; // M-12/M-17 段（队列 + 平台状态 + 插入序 + 虚拟时间 + 指令预算）
  M13State  m13State;           // M-13 段：内存页（RAM 内容）——寄存器不重复存，见裁决 B
  M14Map    m14Map;             // M-14 总线/内存映射状态
  M15Periph m15Periph;          // M-15 外设模型状态（UART/GPIO/定时器等）
  M16Intc  m16Intc;             // M-16 已拉起的 IRQ 行
};
// 采集路径（20-1）：checkpoint 时由各模块的状态导出接口收集（契约锚点，M-20/M-23 双侧核对）
//   M-14 export_map / export_pages → M-15 export_state → M-16 export_state
//   → M-17 snapshot_full（引擎段）
//   ⚠️ M-13 **没有**状态导出接口：它是纯解释器，CPU 架构状态由 m12Engine.state 承载
// 恢复路径（20-1）：loadSnapshot 后**先校验后应用**，按固定顺序回灌（v1.4 注记）
//   M-14 load_map → M-14 load_pages → M-15 load_state → M-16 load_state
//   → M-17 restore_full（引擎段）
// v1.2（2026-10-20 收口轮新增）—— 与契约层快照 DTO 的关系：
//   契约层 riscv_sim_contract::snapshot::EngineSnapshotDto 只覆盖本结构的
//   **M-12/M-17 段**（调度器待处理事件队列 + 平台状态 + 插入序计数器 +
//   虚拟时间 + 每量子指令预算），**不含** cpMeta / m14Map / m15Periph
//   （也不含 m13State / m16Intc；见 v1.4）。
//   它由 M-17 的 snapshot_full/restore_full 提供，可确定性还原**引擎**
//   （评审 20-1 的 Snapshot 仍需由 M-20 组装完整载荷）。
//   落盘格式契约归属：本结构（模块契约，M-20/M-23 双侧冻结）优先于契约层 DTO。
//
// v1.3（2026-10-20 协调者裁决）—— LLD 内部矛盾的裁定：
//   LLD **总纲**表12 / §2 持久化数据格式 / §4.6.4.1 / 表84 / 表85 曾把快照载荷
//   写成「SimState + DebugMeta」，与本节（评审 20-1 / 23-1）定义的完整单对象
//   **不一致**。裁定：**以本节为准**——快照载荷 = Snapshot{cpMeta, m12Engine,
//   m13State, m14Map, m15Periph, m16Intc}（六段全齐，v1.4 起）；DebugMeta 是
//   **项目级独立存储**（评审 23-8，键 "pdebug:"+ projectId，不随快照回滚），
//   不属快照载荷。
//   总纲侧已同步订正；契约层 EngineSnapshotDto 定位为**本结构中 M-12/M-17 段**
//   的承载类型，由 M-20 组装进本结构后落盘。

// v1.4（2026-10-21 会话级载荷批 · STAGE-3）—— 本节 §2.1.1 的三处裁决：
//   裁决 A —— 结构清单此前**漏列**了 M-12/M-17 段：而本文档自己的**正文**早就要求
//     「契约层 riscv_sim_contract::snapshot::EngineSnapshotDto 覆盖本结构的

//   裁决 B —— m13State 此前写「寄存器/内存视图」，而 CPU 寄存器**已经在**

//     → ③ M-15 load_state（外设内部状态）→ ④ M-16 load_state（已拉起的 IRQ 行）
//     → ⑤ M-17 restore_full（引擎段：队列 / 寄存器 / 虚拟时间）。
//     页写不进不存在的区域；外设状态写不进未绑定的实例；引擎段最后还原
//     ——它会**覆盖** gpr / pc / 虚拟时间。
// CrashKit: 现场包（评审 P-19：崩溃/用户上报导出，不被后续检查点回退覆盖）
struct CrashKit {
  Firmware fw;                  // 固件镜像
  Config cfg;                   // 会话配置
  Checkpoint cp;                // 最近检查点
  InputSeq inputs;              // 稀疏输入序列
  LogTail logs;                 // 日志尾部（M-21）
  VersionBundle env;            // 版本/环境 bundle（产品/内核/浏览器/协议/构建哈希）

3 实现设计

3.1 recordInput(ev) 输入事件记录（时间戳化）

recordInput(ev)：输入外部输入事件（M-04 recordEvent 调用方），统一时间戳化（tVirt 取 M-12 虚拟时钟、seq 全局单调）后追加事件流（确定性基线 FR-12）；事件流仅记录稀疏输入事件，与全量证据流分离（R1）。伪代码如下：

// recordInput: 输入事件记录（表75；输入：外部输入事件；输出：事件流追加）
void recordInput(InputEvent ev) {
  ev.tVirt = m12CurTimeVirt();                  // 时间戳化（M-12 虚拟时钟，确定性 FR-12）
  ev.seq   = ++globalSeq;                       // 全局单调序列号（重放游标锚点，P-16 同源）
  eventStream.append(ev);                       // 稀疏输入事件序列（R1：与全量证据流分离）
  if (eventStream.size > STREAM_CAP) {          // 环形上限（估算基线 10⁴ 条）
    dropInputsBelowWatermark();                 // 20-2：仅丢弃早于最低保留检查点 baseSeq 的输入
    m21Log(WARN, "M20", "event_drop", 1);       // 事件流写失败降级（4.6.1.5）
  }
}
// 环形水位保证（20-2）：STREAM_CAP ≥ 最大回退深度所需输入数（最低保留水位 = checkpointList 最早条目 baseSeq），
//   保证回退到倒数第 5 个检查点（≈2 触发间隔）时其 baseSeq 之前的输入仍完整可重放

3.2 checkpoint(reason) 检查点触发

checkpoint(reason)：检查点触发（M-04 策略调用方：每 10s 虚拟时间或关键事件）；安全检查点（运行边界）→ 采集快照载荷（20-1：六段——引擎段 + M-13 内存页 + M-14 映射 + M-15 外设 + M-16 已拉起的 IRQ 行）→ M-23 原子写 + M-04 确认；落盘失败 → 跳过 + 下次触发点重试 + WARN、内存态保留（20-12）；非安全检查点（中断中的写，UNSAFE 判定链 20-4）→ 丢弃中间态、回退最近检查点（评审 C）。RPO ≤2s 宿主时间口径采样（tHost），虚拟↔宿主换算基线 + 宿主时间漂移补偿辅助检查点（20-5）。伪代码如下：

// checkpoint: 检查点触发（表75；调用 M-23 原子写 + M-04 确认；输出：检查点确认）
CheckpointAck checkpoint(reason) {
  if (reason == UNSAFE) {                       // 非安全检查点（中断中的写，评审 C）
    dropPendingMidState();                      // 丢弃中间态
    return ROLLBACK_TO_LAST;                    // 回退最近检查点
  }
  cp = { id: ++cpId, tVirt: m12CurTimeVirt(), tHost: nowHostMs(),   // RPO 采样（tHost）
         baseSeq: globalSeq, version: schemaVersion };
  snap = collectSnapshot(cp);                   // 20-1：采集载荷（六段：引擎段 + M-13 内存页 + M-14 映射 + M-15 外设 + M-16 IRQ 行）
  checkpointList.append(cp);
  while (checkpointList.size > KEEP_N) {        // 保留 ≥5（表74）
    checkpointList.shift();
  }
  r = m23SaveSnapshot(snap);                    // M-23 原子写（临时+替换，schemaVersion 迁移）
  if (!r.ok) {                                  // 20-12：落盘失败 → 跳过 + 下次触发点重试，内存态保留
    m21Log(WARN, "M20", "checkpoint_write_fail", cp.id);
    return { ok: false, retryNextTrigger: true, cpId: cp.id };
  }
  m04ConfirmCheckpoint(cp);                     // M-04 确认
  return { ok: true, cpId: cp.id };
}
// 触发策略由 M-04 承担（每 10s 虚拟时间或关键事件，M-04 4.1.2 checkpoint 调用方）；M-08 断点关键事件经 M-04 触发
// UNSAFE 判定链（20-4）：M-13/M-14 中断处理期间 MMIO/内存写 → 上报 isrWrite 标志 → M-04/M-20 决策点判定 UNSAFE
// RPO 漂移补偿（20-5）：虚拟 10s ≪ 宿主 2s 时自然达标；慢速仿真（宿主时间漂移）→ 宿主时间辅助检查点（tHostDelta ≥2s → checkpoint(RPO_COMP)）

3.3 restore() 崩溃恢复

restore()：崩溃恢复（M-22 触发调用方，4.6.1.4）——读取最近检查点（M-23 loadSnapshot 返回 Snapshot 状态体，20-1）+ 按载荷回灌 M-14/M-15/M-16 状态与 M-12/M-17 引擎段（顺序见 2.1.1 v1.4 注记，**先校验后应用**）+ 输入序列重放（replayInputs(fromSeq) 显式传回退检查点 baseSeq，20-3），输出恢复完成状态；恢复失败回退更早检查点（最多 ≥5）；后端分级（M-04 04-1）：L3/self_iss → 本函数（检查点+重放）；QEMU L1 → M-17 重启 + 事件重放（不走 M-20 快照，按能力位协商降级）。伪代码如下：

// restore: 崩溃恢复（表75；读取最近检查点（M-23）+ 输入序列重放；输出：恢复完成状态）
RestoreStatus restore() {
  if (m17CapBits().allows("snapshot") == false) {   // QEMU L1：能力位降级（M-17）
    return m17RestartAndReplay();                   // 重启 + 事件重放（M-04 04-1 分级）
  }
  for (idx = 0; idx < KEEP_N; idx++) {              // 回退更早检查点（最多 ≥5，4.6.1.5）
    cp = checkpointList[checkpointList.size - 1 - idx];
    snap = m23LoadSnapshot(cp);                     // M-23 loadSnapshot（原子读，返回 Snapshot 状态体）
    if (snap.ok) {
      m14LoadMap(snap.m14Map);                      // 20-1：回灌 M-14 总线/内存映射（先重建区域拓扑）
      m14LoadPages(snap.m13State);                  // 20-1：回灌 RAM 内容（须在 load_map 之后）
      m15LoadState(snap.m15Periph);                 // 20-1：回灌 M-15 外设状态
      m16LoadState(snap.m16Intc);                   // 20-1：回灌已拉起的 IRQ 行
      m17RestoreFull(snap.m12Engine);               // 20-1：回灌引擎段（队列/寄存器/虚拟时间，最后）
      replayInputs(snap.baseSeq);                   // 20-3：显式传重放起点（回退检查点 baseSeq）
      return { ok: true, cpId: cp.id };
    }
  }
  m22Report(RECOVERY_FAILED);                       // M-22 恢复失败上报（4.6.1.5）
  return { ok: false, reason: E_RECOVERY };
}
// 恢复完成后回 M-04 会话状态（M-04 04-1：会话状态 sessionCtx/envBundle 随之重建）

3.4 replayInputs() 输入序列重放

replayInputs(fromSeq)：从指定起点序列号（回退检查点 baseSeq，20-3）重放稀疏输入事件序列；按 (tVirt, seq) 稳定排序后逐条调用 M-12 scheduleEvent 注入（与 M-12 稳定排序同语义，20-7）；重放游标推进；输出重放完成。伪代码如下：

// replayInputs: 稀疏输入事件序列重放（表75；输入：事件流；调用 M-12 scheduleEvent；输出：重放完成）
ReplayResult replayInputs(uint64_t fromSeq) {         // 20-3：显式传重放起点（回退检查点 baseSeq）
  events = eventStream.slice(fromSeq, last);          // 起点之后的输入事件
  stableSort(events);                                 // 20-7：按 (tVirt, seq) 稳定排序（M-12 同语义）
  for (ev in events) {
    m12ScheduleEvent(ev);                             // M-12 事件注入（确定性调度）
    replayCursor = ev.seq;
  }
  return { ok: true, replayed: replayCursor - fromSeq };
}
// 重放不依赖全量波形/trace 证据流（评审 R1：仅稀疏输入序列即可确定性复现）
// 调度一致性论证（20-7）：原始执行中 M-12 亦按 (tVirt, 插入序) 稳定排序；重放按同键排序后注入，
//   与原始执行调度序一致 → 恢复结果与原始一致（7.1 恢复一致用例）

3.5 exportCrashKit() 现场包导出

exportCrashKit()：崩溃/用户上报触发，导出六要素现场包（固件 + 配置 + 最近检查点 + 稀疏输入序列 + 日志尾部 + 版本/环境 bundle，P-19）为归档对象（M-23）；导出失败重试一次并告警（4.6.1.5）。伪代码如下：

// exportCrashKit: 现场包导出（表75；评审 P-19；输出：归档对象）
CrashKit exportCrashKit() {
  kit = {
    fw:   currentFirmware(),
    cfg:  sessionConfig(),                          // M-04 会话配置
    cp:   checkpointList.last,                      // 最近检查点
    inputs: eventStream.slice(cp.baseSeq, last),    // 稀疏输入序列
    logs:  m21LogTail(512),                         // 日志尾部（M-21）
    env:   versionBundle() };                       // 版本/环境 bundle（评审 P-22）
  for (retry = 0; retry < 2; retry++) {             // 失败重试一次并告警（4.6.1.5）
    r = m23Archive(kit);                           // M-23 归档（20-8：归档区独立于检查点保留策略，
                                                   //   不被后续检查点回退覆盖；契约锚点待 M-23 落地双侧核对）
    if (r.ok) return kit;
    m21Log(WARN, "M20", "crashkit_export_fail", retry);
  }
  m22Report(CRASHKIT_FAILED);
  return null;
}

6.2 边界与降级

（1）恢复失败：回退更早检查点（最多 ≥5 个），恢复不依赖全量波形/trace 证据流（评审 R1）。
（2）事件流写失败：降级丢弃 + warn，不影响仿真主路径（4.6.1.5）。
（3）现场包导出失败：重试一次 + 告警；仍失败 → M-22 上报（P-19）。
（4）非安全检查点（中断中的写）：UNSAFE 判定链 = M-13/M-14 中断处理期间 MMIO/内存写上报 isrWrite → M-04/M-20 决策点（20-4）；判定后丢弃中间态、回退最近检查点（评审 C）。
（5）后端分级：QEMU L1 → M-17 重启 + 事件重放（不走 M-20 快照，按能力位协商降级，M-04 04-1）；L3/self_iss → 检查点 + 重放。
（6）检查点保留：checkpointList 保留 ≥5；回退最差 ≈2 个触发间隔内（RPO ≤2s 宿主时间口径，表74）。
（7）事件流环形水位（20-2）：环形 ≤10⁴ 条（估算基线），溢出仅丢弃早于最低保留检查点 baseSeq 的输入（STREAM_CAP ≥ 最大回退深度所需输入数），保证回退到倒数第 5 个检查点时重放无缺口；仅稀疏输入事件，非全量。
（8）RPO 漂移补偿（20-5）：虚拟 10s ≪ 宿主 2s 时自然达标；慢速仿真宿主时间漂移 → 宿主时间辅助检查点（tHostDelta ≥2s → checkpoint(RPO_COMP)），RPO 上界不随仿真速率漂移。
（9）移动端：375px 可读（NFR-05），面板单列 + 横向滚动；同源 HTTP 部署直接可开。

9.1.1 端口契约（driving/driven，源文档表76 对齐）

按源文档 2.5 平台共享契约层、本模块对外交互收敛为语言无关的端口契约（驱动端口 = 本模块提供的服务，被驱动端口 = 本模块依赖的服务）；任何替代实现遵守同端口契约并通过契约测试（7.1）即可接入：

端口 / 服务方向契约（输入 -> 输出；错误码/约束）
recordInput(ev)提供（driving）输入：外部输入事件；输出：事件流追加（时间戳化 tVirt + 全局单调 seq，FR-12）
checkpoint(reason)提供（driving）调用 M-23 原子写 + M-04 确认；输出：检查点确认；保留 ≥5、RPO ≤2s；非安全检查点回退（评审 C）
restore()提供（driving）读取最近检查点（M-23）+ 输入序列重放；输出：恢复完成状态；失败回退更早检查点（最多 ≥5）；QEMU 走 M-17（04-1）
replayInputs()提供（driving）输入：事件流；调用 M-12 scheduleEvent；输出：重放完成（游标推进，R1 分离证据流）
exportCrashKit()提供（driving）固件 + 配置 + 检查点 + 输入序列 + 日志尾部 + 版本信息；输出：归档对象（评审 P-19；失败重试一次）

M-12依赖（driven）事件注入：scheduleEvent 确定性调度 + 虚拟时钟
M-13依赖（driven）快照载荷采集/回灌：寄存器/内存状态序列化（20-1；契约锚点待与 M-13 v1.4 双侧核对）
M-14依赖（driven）快照载荷采集/回灌：总线/内存映射状态序列化（20-1；契约锚点待与 M-14 v1.4 双侧核对）
M-15依赖（driven）快照载荷采集/回灌：外设状态序列化（20-1；契约锚点待与 M-15 v1.3 双侧核对）
M-17依赖（driven）快照接口：能力位协商（QEMU 下快照不可用 → 降级重启+重放）

9.2 日志对接（M-21）

事件流写失败 -> log(WARN, "M20", "event_drop", n)（4.6.1.5）；检查点落盘 -> log(DEBUG, "M20", "checkpoint", cpId)；非安全检查点回退 -> log(WARN, "M20", "unsafe_rollback", cpId)（评审 C）；现场包导出失败 -> log(WARN, "M20", "crashkit_export_fail", retry)（P-19）；恢复失败 -> log(ERROR, "M20", "recover_fail", idx)。日志条目含虚拟+宿主双时间戳与会话关联（P-22）；现场包内含日志尾部（M-21，512 条）。
