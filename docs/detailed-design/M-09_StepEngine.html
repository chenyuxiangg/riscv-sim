1 功能概述

1.1 模块定位

M-09 单步引擎（4.3.2）：实现指令级单步 step() 与源码级单步 stepSource()（按 DWARF 行映射边界推进，FR-08）。单步在安全检查点注入，保证不打断执行中的访存、不产生半指令状态（4.3.2.1）。stepOver()（跳过函数调用）为扩展能力，经 M-08 临时断点实现（4.3.2.3 表42）。

单步是「暂停态 → 执行 1 条/1 行 → 再暂停」的确定性推进：只接受暂停态命令（非暂停态 → E_CTX-02 拒绝），执行粒度由 M-17 抽象保证（指令驱动 step / 行边界 stepSource），单步结果经 M-05 上报 paused（可靠投递），前端刷新视图（4.3.2.4）。断点命中时 M-09 与 M-08 协作：onHit 调 M-09 暂停冻结（SimState 对齐量子边界，5.2 图3），单步/暂停状态一致。

1.3 MVP 范围与预留

MVP 实现范围：step()（指令级单步）、stepSource()（源码级单步，按 M-11 行映射边界推进，缺失降级 step + 提示）、stepOver()（跳过函数调用，M-08 临时断点）、安全检查点注入（safePointInject，对齐量子边界）、暂停态约束（E_CTX-02）、paused 上报（M-05 可靠投递）、单步异常日志（M-21）。

预留项（P1/P2 演进承接，不展开实现）：行映射深化（P1，依赖 M-11 DWARF .debug_line 行表与栈帧，行边界精确定位）；条件单步（P1，跳过 N 条/按条件暂停）；单步与指令 trace 联动（P1，配合 M-18）；反向单步（P2，配合 M-20 检查点重放）。

2 数据描述

2.1 核心数据结构

数据结构类型定义与用途

2.1.1 复杂结构字段定义

stepMode 定义单步模式；LineMapRef 是 M-11 行映射的引用句柄；StepState 记录一次单步推进的上下文；SafePoint 是注入到 M-12 量子边界的安全检查点。字段定义如下：

// StepMode: 单步模式（4.3.2.2 表41）
enum StepMode {
  INSTRUCTION = 0,  // 指令级单步：执行 1 条指令后暂停（step()）
  SOURCE      = 1,  // 源码级单步：按 DWARF 行映射边界推进（stepSource()）
};
// LineMapRef: M-11 行映射引用（源码级单步依赖；句柄由 M-11 行表提供）
struct LineMapRef {
  uint32_t handle;      // M-11 行映射句柄（地址→源码行双向索引）
  uint8_t  valid;       // 行映射有效性（0=缺失 → stepSource 降级 step + 提示）
};
// StepState: 单步推进状态（一次单步命令的上下文）
struct StepState {
  StepMode  mode;       // 本次单步模式（INSTRUCTION / SOURCE）
  uint32_t  targetLine; // 源码级单步目标行（SOURCE 模式；行映射边界）
  uint8_t   degraded;   // 降级标记（SOURCE 缺行映射 → 降级 INSTRUCTION，置 1）
  SafePoint safePoint;  // 安全检查点（safePointInject 写入；对齐 M-12 量子边界，评审 09-3）
  PauseInfo lastPause;  // 上次暂停信息（原因/PC/虚拟时间，来源 M-17，评审 09-8）
};
// SafePoint: 安全检查点（注入 M-12 量子边界）
struct SafePoint {
  uint64_t  quantumSeq; // 对齐的量子序号（M-12 量子化混合调度）
  uint8_t   inMemOp;    // 访存进行中标记（inMemOp=1 时禁止注入，保证不打断访存）
  uint8_t   injected;   // 已注入标记（1=已注入，等待单步执行）
};
// PauseInfo: 暂停信息（契约来自 M-17；评审 09-8 展开字段）
struct PauseInfo {
  PauseReason reason;   // 暂停原因：STEP_DONE=0 / BP_HIT=1 / ABORT=2（M-17 契约）
  uint32_t    pc;       // 暂停点 PC（指令边界，无半指令状态）
  uint64_t    time_virt;// 虚拟时间（M-12 权威时钟；日志/前端显示用）
};

2.2 单步模式语义

模式语义执行通道备注
instruction（指令级）执行 1 条指令后暂停（源 4.3.2.1）M-17 step()（指令驱动）不因事件插入跳过/多步（对齐 M-17 17-1/17-10）
source（源码级）按 DWARF 行映射边界推进至下一行M-09 循环 step + M-11 行表判跨行（评审 09-2 方案①）跨行后仅上报一次 paused；缺失 → 降级 step + 提示（E_CTX-10）

2.3 数据流说明

命令流：前端（M-01~M-03）→ M-05 会话 → M-09 step/stepSource/stepOver → 状态校验（暂停态，否则 E_CTX-02）→ 安全检查点注入 → M-17 执行通道。

执行流：M-17 step() 执行 1 条指令（指令驱动）→ 返回 PauseInfo（原因/PC/虚拟时间）→ M-09 记录 StepState.lastPause；stepSource 由 M-09 循环 step + M-11 行表判跨行（评审 09-2 方案①）。

上报流：单步完成 → M-05 publish(paused)（可靠投递，ack/重试）→ 前端刷新视图（寄存器/内存/反汇编/源码高亮联动，M-02/M-08~M-11 暂停态读写）。单步异常 → M-21 日志（单步异常日志，4.3.2.6 表43）。

3 实现设计

3.1 step 指令级单步

step()：暂停态接收命令（非暂停态 → E_CTX-02 拒绝）→ 安全检查点注入（safePointInject：对齐 M-12 量子边界，inMemOp=1 时等待访存完成，保证不打断执行中访存、不产生半指令状态）→ 调 M-17 step() 执行 1 条指令 → 暂停 → 记录 StepState → M-05 publish(paused)。伪代码如下：

// step: 指令级单步（4.3.2.3 表42；执行 1 条指令后暂停）
PauseInfo step(err_t* err) {
    if (!isPaused()) { *err = E_CTX-02; return (PauseInfo){0}; }  // 非暂停态调用拒绝
    safePointInject(INSTRUCTION);                 // 安全检查点注入（对齐量子边界）
    PauseInfo p = m17_step();                     // M-17 指令驱动：恰执行 1 条后暂停
    stepState.lastPause = p; stepState.mode = INSTRUCTION;
    publish("paused", &p);                        // M-05 可靠投递（ack/重试）
    log(INFO, "DBG-STEP", "step done", "E_OK");
    return p;                                     // 输出：暂停状态
}
// safePointInject: 安全检查点注入（4.3.2.1；保证不打断访存、无半指令状态）
void safePointInject(StepMode m) {
    stepState.mode = m; stepState.targetLine = currentLine();
    // 在 M-12 量子边界注入；若访存进行中（inMemOp=1）则推迟至该访存完成：
    // 保证「执行中的访存不被打断」「指令边界原子（无半指令状态）」
    m12_injectSafePoint(&stepState.safePoint);
}

3.2 stepSource 源码级单步

stepSource()：行边界是调试层概念，归 M-09 实现（评审 09-2 方案①）——执行后端只提供指令驱动 step()，M-09 循环 step 并以 M-11 行表判跨行；中间暂停不上报，跨行后仅 publish 一次（评审 09-8）。行映射缺失（lineMapRef.valid=0）自动降级为 step 并提示（WARN 日志 + 前端提示，E_CTX-10）。伪代码如下：

// stepSource: 源码级单步（4.3.2.3 表42；行边界归 M-09，评审 09-2/09-8）
PauseInfo stepSource(err_t* err) {
    if (!isPaused()) { *err = E_CTX-02; return (PauseInfo){0}; }  // 非暂停态调用拒绝
    if (!lineMapRef.valid) {                      // 行映射缺失 → 降级 step + 提示（E_CTX-10，评审 09-9）
        stepState.degraded = 1;
        log(WARN, "DBG-STEP", "line map missing, degrade to step", "E_CTX-10");
        return step(err);                         // 自动降级为指令级单步
    }
    safePointInject(SOURCE);
    uint32_t targetLine = m11_queryLine(lineMapRef, pc()); // 当前行；目标 = 下一行
    PauseInfo p;
    do {
        p = m17_step();                           // 指令驱动：恰执行 1 条后暂停
        // 中间暂停不上报（评审 09-8：仅在跨行后 publish 一次）
    } while (m11_queryLine(lineMapRef, p.pc) == targetLine); // M-11 行表判跨行
    stepState.lastPause = p; stepState.mode = SOURCE;
    publish("paused", &p);                        // 跨行后一次可靠投递
    log(INFO, "DBG-STEP", "stepSource done", "E_OK");
    return p;                                     // 输出：暂停状态
}

3.3 stepOver 跳过函数调用（扩展）

stepOver()：当前指令为函数调用（isCall 判定见 6.2 与下方注释，评审 09-4）时，在返回地址注入临时断点（M-08 setBreakpoint，sourceType=TEMP）后 resume 持续执行，直至命中返回地址断点（断点驱动停止，评审 09-1）；命中自动移除为主（M-08 08-3），removeBp 仅作 runUntil 因异常/其他断点终止时的兜底清理（评审 09-6）；注入失败前置检查返回 E_CTX-07（评审 09-5）；被调函数内用户断点先命中时暂停于用户断点、临时断点保留（评审 09-7）。非调用指令降级为 step。伪代码如下：

// stepOver: 跳过函数调用（4.3.2.3 表42 扩展；经 M-08 临时断点）
PauseInfo stepOver(err_t* err) {
    if (!isPaused()) { *err = E_CTX-02; return (PauseInfo){0}; }
    if (!isCall(currentPc())) return step(err);   // 非调用指令 → 降级 step
    // isCall 判定（评审 09-4）：经 M-17 readMem 取指解析当前指令——
    //   JAL rd = x1(ra)：调用；JAL rd = x0：纯跳转，非调用
    //   JALR rd = x1(ra)：调用；JALR rd = x0：纯跳转（含 c.jalr 展开后同判）
    uint32_t retAddr = currentPc() + instLen(currentPc()); // 返回地址
    err_t e; BpId bp = m08_setBreakpoint(retAddr, NULL, &e); // 临时断点（sourceType=TEMP）
    if (e != E_OK) { *err = e; return (PauseInfo){0}; }   // 注入失败前置检查（评审 09-5，E_CTX-07）
    PauseInfo p = m17_resumeUntilBp(bp);          // 持续执行直至命中返回地址断点（断点驱动停止，评审 09-1）
    if (p.reason == BP_HIT && p.pc == retAddr) {
        m08_removeBp(bp);                         // 返回地址命中：自动移除为主（对齐 M-08 08-3）
    } else {
        // 被调函数内用户断点/异常先终止：暂停于用户断点、临时断点保留待 resume 后命中即移除
        // （评审 09-7，对齐 GDB 语义）；removeBp 仅作无命中的兜底清理（评审 09-6）
        m08_removeBpIfStale(bp);                  // M-08 幂等兜底：已移除则无操作（对齐 M-08 N8）
    }
    publish("paused", &p); log(INFO, "DBG-STEP", "stepOver done", "E_OK");
    return p;                                     // 输出：暂停状态（返回地址/用户断点/异常点）
}

5 处理流程

5.1 单步处理流程（源 4.3.2.4 对齐）

单步为「暂停态 → 执行 1 条/1 行 → 再暂停」的确定性推进：暂停态接收单步命令 → 安全检查点注入 → 执行 1 条/1 行 → 暂停 → 上报 paused（可靠投递）→ 前端刷新视图。非暂停态调用与行映射缺失两条异常分支见 6 章。

1接收单步命令
暂停态校验（非暂停态 → E_CTX-02 拒绝）
↓
2安全检查点注入
对齐 M-12 量子边界；访存完成；无半指令状态（4.3.2.1）
↓
3执行 1 条 / 1 行
M-17 step（指令驱动）/ stepSource（行边界推进）
↓
4暂停
记录 StepState.lastPause（原因/PC/虚拟时间）
↓
5上报 paused
M-05 可靠投递（ack/重试）；前端缺口 reconcile 对账
↓
6前端刷新视图
寄存器/内存/反汇编/源码高亮联动（M-02/M-08~M-11）
↓
7等待下一次单步命令
暂停态保持；用户显式 resume / 继续 step

6 异常处理

6.1 错误码与处置

本模块错误码归属 E_CTX 族（3.4 表16，一场景一码）：

错误码场景处置

6.2 边界与降级

（1）非暂停态调用：运行/复位/故障态下 step 类命令一律 E_CTX-02 拒绝，不排队不缓存（确定性语义，2.4 表6）。

（2）行映射缺失：stepSource 降级为 step（指令级），降级提示可见；不阻断调试。

（3）QEMU 后端（L1 子集）：step 精确（RSP 's'）；stepSource 归 M-09 循环 step + 行表判跨行——QEMU 侧行映射缺失时同样降级 step（M-17 17-2 语义对齐）。

（4）半指令防护：安全检查点注入保证单步在指令边界原子推进——访存进行中（inMemOp=1）推迟注入；无中断插入导致半指令状态（4.3.2.1）。

（5）stepOver 无调用：当前指令非函数调用 → 降级为 step（语义等价，无副作用）。

（6）isCall 判定规则（评审 09-4）：经 M-17 readMem 取指解析当前指令 opcode/rd——JAL/JALR 的 rd == x1(ra) 视为调用；rd == x0 为纯跳转（非调用）；压缩 c.jalr 展开后按 rd 同判；来源 = M-17 readMem 取指，判定结果用于 stepOver 的「调用 / 降级 step」边界。

（7）stepOver 中被调函数内用户断点先命中（评审 09-7）：暂停于用户断点（paused 上报用户断点原因）；返回地址临时断点保留不清理；用户 resume 后再次命中返回地址即自动移除（对齐 GDB 语义）。

（8）stepOver 因异常终止：临时断点经 M-08 幂等兜底清理（remove_bp 对无效 id 幂等，评审 09-6 / 对齐 M-08 N8）；不残留。

（9）暂停态保持：单步完成后保持暂停（不自动 resume），避免命中风暴/自激（对齐 M-08 命中风暴防护）。

7.2 可维护性手段

（1）模式单一数据源：StepState 单一上下文，step/stepSource/stepOver 共享状态校验与上报路径，无隐式状态。

（2）执行与上报解耦：safePointInject + M-17 执行 + publish(paused) 三段独立，可分别单测（注入点/执行粒度/上报可靠性）。

（3）行映射引用隔离：M-09 只持 lineMapRef 句柄（M-11 提供），不解析 DWARF——行映射实现替换不影响本模块。

（4）抽象隔离：一切执行经 M-17 抽象（step/readMem/resumeUntilBp），行边界归 M-09（经 M-11 行表），M-09 无内核感知，双内核替换不影响本模块。

（5）CI 门禁：核心模块单测覆盖率 ≥70%（估算基线，源文档 7.3 表92）；单步用例纳入确定性夹具（同种子同输入序列断言暂停点一致）。

（6）契约层可替换性（源 2.5 对齐）：本模块对外的 driving 端口收敛到 9.1.1 端口契约表，替代实现（替代单步引擎）遵守同端口契约并通过契约测试即可接入。
