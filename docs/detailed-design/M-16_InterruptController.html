1 功能概述

1.1 模块定位

M-16 中断控制器实现简化 PLIC/CLINT（4.4.5.1）：外设 irqRequest → 挂起队列 → 量子边界采样 → 按优先级仲裁 → 触发 ISS 陷入（mtvec）；定时器用 mtime/mtimecmp 语义或行为级等价。承接 FR-06（异常/中断、向量表配置，与 M-12/M-13 协作）；M-16 在确定性适用范围（2.4 表6：同一种子 + 同一时间戳化输入事件序列 → 结果唯一）。

中断交付语义：仲裁结果在量子边界交付，经 M-13 trap 写入 mepc/mcause 并跳转 mtvec（4.4.2.4）；处理完成后由软件/外设 irqClear 清除。中断风暴按优先级 + 使能掩码抑制，未使能中断保持挂起不丢（4.4.5.5）。

1.3 MVP 范围与预留

MVP 实现范围：中断挂起队列（pendingQueue）、优先级表（priorityTable）、使能掩码（enabledMask，对应 mstatus/mie）、request/clear/arbitrate/deliver 四函数、量子边界采样（由 M-12 pollIRQ 驱动）、定时器中断行为级等价（mtime/mtimecmp 语义）、中断脉冲探针（probe → M-18）。

预留项（本模块仅保留演进承接说明，不展开实现）：完整 PLIC 上下文保存/恢复与嵌套中断（P1）；软件中断（SWI）与外部中断细分（P1）；多级优先级组与阈值（P1）；S 模式中断支持（随特权模式演进，P2）。

2 数据描述

2.1 核心数据结构

数据结构类型定义与用途
pendingQueuequeue中断挂起队列（按 line 挂起，未使能不丢）
priorityTableMap<line, prio>优先级表（仲裁依据）
enabledMaskbitmask中断使能掩码（对应 mstatus/mie）
intcStatestruct控制器内部状态：activeIrq、mtime/mtimecmp（行为级等价）等

2.1.1 复杂结构字段定义

PendingIrq 是挂起队列中的中断条目；IntcState 为控制器整体状态，字段定义如下：

// PendingIrq: 挂起队列条目（arbitrate 仲裁依据）
struct PendingIrq {
  uint16_t line;            // 中断线编号（rx-ready/tx-empty/timer-compare 等）
  uint8_t  prio;            // 优先级（priorityTable[line]，数值越大越优先）
  uint64_t requestTime;     // 请求时的虚拟时间（确定性排序，插入序锚点）
  uint8_t  triggerType;     // 触发模式（评审 16-2）：0=电平 / 1=边沿
  uint8_t  sourceType;      // 请求源类型（UART/GPIO/Timer/扩展）
  void*    source;          // 请求源实例（M-15 PeripheralInstance）
  uint8_t  state;           // 0=pending / 1=active（已交付未清除）
};
// IntcState: 中断控制器整体状态
struct IntcState {
  queue          pendingQueue;  // 挂起队列（按 requestTime + 插入序稳定排序）
  Map<uint16_t,uint8_t> priorityTable; // line → prio（仲裁依据）
  uint32_t       enabledMask;   // 使能掩码（对应 mie，量子边界从 M-13 拉取刷新，评审 16-5）
  uint8_t        activeIrq;     // 当前已交付未清除的中断线（0xFF=无；单级中断语义）
  uint64_t       mtime;         // 定时器计数（行为级等价，随虚拟时间推进，评审 16-3）
  uint64_t       mtimecmp;      // 比较值：mtime >= mtimecmp 触发定时器中断（电平语义）
  uint64_t       lastPoll;      // 上次定时器轮询时刻（mtime 步进基准，评审 16-3）
  PendingIntr    pendingDelivery; // 交接结构（评审 16-4）：M-13 iss_take_intr 拉取
};

2.2 中断线与优先级

中断线请求源（M-15）默认优先级使能对应
rx-readyUART 接收就绪高mie.MEIE（机器外部中断位）
tx-emptyUART 发送缓冲空中mie.MEIE
timer-compareTimer 比较到期 / mtimecmp最高（定时器）mie.MTIE（机器定时器中断位）

优先级语义：timer-compare 使用机器定时器中断语义（mie.MTIE），rx-ready/tx-empty 走外部中断语义（mie.MEIE，评审 N4：统一为标准位名，与 M-13 一致）；仲裁结果为「挂起且使能」集合内最高优先级的中断线（同优先级按 requestTime + 插入序稳定排序，确定性）。触发模式（评审 16-2）：timer-compare = 电平（CLINT：mtime≥mtimecmp 持续有效，改写 mtimecmp 前不撤）；rx-ready/tx-empty = 边沿（M-15 事件触发，单次请求）。

2.3 数据流说明

上行：M-15 request(line) 入挂起队列 → M-12 量子边界 pollIRQ → arbitrate（「挂起且使能」内优先级仲裁）→ deliver(irq) 登记交接结构 → M-13 iss_take_intr 拉取执行陷入（写 mepc/mcause，跳 mtvec）→ 处理完成后 irqClear。观测：中断脉冲经 probe 上报 M-18 → M-19 波形；记录：中断事件经 log 上报 M-21。

3 实现设计

3.1 请求与挂起（request / clear）

外设请求中断线：request(line) 在挂起队列登记（含优先级/请求时间/源实例），未使能中断保持挂起不丢；软件处理后 irqClear 清除，activeIrq 复位。伪代码如下：

// request: 外设请求中断线（M-15 irqRequest 调用，评审 16-2：同线去重）
void intc_request(IntcState* s, uint16_t line, void* src) {
    if (s->pendingQueue.has(line)) return;   // 同线去重：已挂起即满足，不堆积
    PendingIrq irq = { line, s->priorityTable[line], virt_clock_now(), trigger_type(line), 0, src, 0 };
    s->pendingQueue.push(irq);                 // 按（requestTime, 插入序）稳定排序
    ProbeRegistry::sample_irq_pulse(now_ps, irq_line);  // M-18 中断脉冲探针（评审 N2：直接对接
}                                                  //   M-18 探针通道（ch 键控，不经信号名匹配），
                                                   //   不经 M-15 periph_probe，无 NULL 实例）
                                                   //   now_ps = 虚拟时间戳（本模块 virt_clock_now()），
                                                   //   irq_line = 中断线号（本模块 line）
// 触发模式（评审 16-2）：timer-compare = 电平（CLINT：mtime≥mtimecmp 持续有效，
//   改写 mtimecmp 前不撤，与真实语义一致）；rx-ready/tx-empty = 边沿（M-15 事件触发，单次请求）
uint8_t trigger_type(uint16_t line) {
    return (line == LINE_TIMER) ? LEVEL_TRIGGER : EDGE_TRIGGER;
}
// clear: 清除中断线（软件 irqClear 调用）
void intc_clear(IntcState* s, uint16_t line) {
    s->pendingQueue.remove(line);              // 移除挂起；activeIrq 复位
    if (s->activeIrq == line) s->activeIrq = 0xFF;
}

3.2 量子边界采样与仲裁（arbitrate）

仲裁在量子边界由 M-12 pollIRQ 驱动（4.4.1.1、4.4.5.4）——量子边界是抢占点（调度器可在此让出并采样），不是停止条件：引擎不会因为到达量子边界而停下（台账 D-74，承 D-57 的新口径）：先在量子边界从 M-13 拉取 mie 刷新 enabledMask（评审 16-5，避免用过期的使能掩码）；随后扫描挂起队列，在「挂起且使能」集合内按「优先级 → requestTime + 插入序」选最高——未使能的高优先级不阻塞已使能的低优先级（评审 16-1，与真实 PLIC「只在挂起且使能集合内仲裁」一致）；已交付未清除（activeIrq≠0xFF）时返回无中断（评审 16-6，单级中断语义）。

// refreshEnableMask: 量子边界从 M-13 拉取 mie 同步使能掩码（评审 16-5）
void intc_refreshEnableMask(IntcState* s) { s->enabledMask = iss_get_mie(); }
// arbitrate: 量子边界仲裁（M-12 pollIRQ 调用）
int intc_arbitrate(IntcState* s) {
    intc_refreshEnableMask(s);                 // 量子边界同步 mie（评审 16-5）
    if (s->activeIrq != 0xFF) return NO_IRQ;   // 单级中断：已有活动中断未清除 → 不覆盖（评审 16-6）
    // 扫描挂起队列：在「挂起且使能」集合内选优先级最高（评审 16-1，未使能高优先级不阻塞）
    PendingIrq best = {0}; bool found = false;
    for (irq : s->pendingQueue) {
        if (!(s->enabledMask & (1u << irq.line))) continue;   // 未使能：跳过但保持挂起
        if (!found || irq.prio > best.prio ||
            (irq.prio == best.prio && irq.requestTime < best.requestTime)) { best = irq; found = true; }
    }
    if (!found) return NO_IRQ;
    s->activeIrq = best.line;
    return best.line;
}
// 定时器中断（行为级等价，评审 16-3）：mtime 随虚拟时间步进（M-12 每量子调用）
void intc_timer_poll(IntcState* s, uint64_t now) {
    s->mtime += (now - s->lastPoll);           // mtime 推进：时间差步进（由 M-12 量子推进驱动）
    s->lastPoll = now;
    if (s->mtime >= s->mtimecmp) intc_request(s, LINE_TIMER, NULL); // 电平语义 + 同线去重（评审 16-2）
}

3.3 交付与陷入（deliver）

deliver(irq) 登记交接结构，由 M-13 主动拉取（评审 16-4，与 M-13 契约 iss_pending_intr/iss_take_intr 对齐，替代原「M-16 主动调 iss_trap」）：仲裁命中后，M-16 把 line/cause 写入 pendingDelivery，M-13 在取指边界经 iss_pending_intr 检查、iss_take_intr 取走并执行陷入（写 mepc/mcause、跳 mtvec，4.4.2.4）。两层使能判定（评审 16-10）：交付前须同时满足 per-line enabledMask 命中 AND mstatus.MIE 全局使能，未满足则保持挂起待下次采样。mcause 中断原因编码依赖 IRQ_BASE 常量（评审 16-7）。

#define IRQ_BASE 0x80000000UL   // RV32 中断位（mcause[31]）；cause = IRQ_BASE | line（评审 16-7）
// deliver: 登记交接结构，供 M-13 拉取（评审 16-4，对齐 M-13 契约）
void intc_deliver(IntcState* s, int line) {
    s->pendingDelivery.line  = line;
    s->pendingDelivery.cause = IRQ_BASE | line;  // mcause 中断原因编码（最高位置 1）
    log(INFO, "INTC", "deliver irq", "");       // M-21 中断交付日志
}
// M-13 侧契约（评审 16-4，替代 iss_trap 主动调用）：
//   bool iss_pending_intr(void);            // true = 有待交付中断（pendingDelivery 有效）
//   void iss_take_intr(PendingIntr* out);   // 取走交接结构；M-13 写 mepc/mcause 并跳 mtvec
// 两层使能组合判定（评审 16-10）：per-line enabledMask（arbitrate 已筛）AND mstatus.MIE 全局，
//   M-13 在执行陷入前检查全局 MIE，未使能则保持挂起待下次采样。

3.4 定时器中断（mtime/mtimecmp）

MVP 采用行为级等价：mtime 随虚拟时间推进（由 M-12 量子推进驱动 intc_timer_poll 步进，评审 16-3），mtime >= mtimecmp 时按机器定时器中断语义挂起（mie.MTIE，电平触发；线号 3）。固件经 M-14 MMIO 访问 mtime / mtimecmp 的通路推迟到 P1（台账 D-82 · 冻结规格 STAGE-4 §1.2 裁决 E）——本批不做评审 16-8 描述的「本模块向 M-14 mapRegion 登记 CLINT 地址区间、读写映射到 mtime/mtimecmp」这条固件侧通路。推迟的三条理由：① 落它要同时动 M-14 的区域类型（新增 RegionType::Clint + 一条派发路径）与契约层的区域 kind（SessionSnapshotDto::validate() 按 "ram" / "rom" / "peripheral" 分类做检查）——会把本批从「落地一个模块」拉成「改会话载荷的形状」，而契约层刚升 v2 不到一批；② 固件侧今天没有消费者（demo 固件不写 mtimecmp）⇒ 该通路今天没有活影响；③ 定时器中断的语义本批照样闭环——mtime 随虚拟时间推进、mtimecmp 由宿主 API 设置（set_timer_compare）、mtime >= mtimecmp 时按电平语义挂起 line 3 → 仲裁 → 交付 → 陷入的整条链可端到端验证，缺的只是「固件自己写 mtimecmp」这一步。职责边界（评审 N3）：定时中断权威源 = 本模块 mtime/mtimecmp（标准 CLINT，固件标准路径 0x02004000 区域）；M-15 Timer 外设的 timer-compare 中断线 MVP 不启用（避免双权威源计数不一致），Timer 外设仅作平台周期计数（count 可被固件读）；后续若启用 Timer 外设中断，其 CMP 经 M-14 透传 mtimecmp（同一权威源），作为 P1 变更项管理。

5 处理流程

5.1 中断处理流程

中断处理闭环如下（对应图 1，源设计 4.4.5.4）：

（1）请求：M-15 外设 irqRequest(line) 入挂起队列（含优先级/请求时间/源实例）。

（2）采样：M-12 量子边界 pollIRQ 调 arbitrate，按「优先级 → requestTime + 插入序」取最高且命中使能掩码的中断；未使能中断保持挂起。

（3）交付：deliver(irq) 登记 pendingDelivery，M-13 经 iss_take_intr 拉取并执行陷入——写 mepc/mcause，跳转 mtvec（评审 16-4，4.4.2.4）。

（4）清除：处理完成后软件 irqClear(line)，activeIrq 复位，恢复执行。

（5）观测与记录：请求时 probe 中断脉冲 → M-18 → M-19；交付经 log → M-21。

1外设请求中断线：M-15 irqRequest(line)（UART rx-ready / tx-empty / Timer 比较）
↓
2挂起队列 pendingQueue：按（requestTime, 插入序）稳定排序；未使能不丢
↓
3量子边界采样 + 仲裁：M-12 pollIRQ 节奏 → arbitrate（优先级 + 使能掩码 mstatus/mie）
↓
4交付陷入：deliver(irq) 登记交接 → M-13 iss_take_intr 拉取（写 mepc/mcause，跳 mtvec）
↓

↓
6记录：log(INFO, "INTC", "deliver irq") → M-21（仅管理员通道）
回环：处理完成 → 软件 irqClear(line) → 清除挂起 → 恢复执行；未使能中断继续挂起（确定性）

6.2 边界与降级

（1）交付时机边界：仲裁在量子边界采样（量子边界是抢占点、不是停止条件——引擎不会因为到达量子边界而停下），中断交付最多延迟一个量子（1µs 虚拟时间，估算基线）。

（2）确定性边界：仲裁排序不依赖宿主时钟；请求时间取虚拟时钟，违反 → 确定性断言失败（2.4 表6、源文档 7.3 表92）。

（3）使能切换：固件修改 mie（经 CSR）后，未使能中断保持挂起；enabledMask 在量子边界从 M-13 拉取刷新（评审 16-5），生效以下次采样为准（不丢不抢）。两层使能组合判定（评审 16-10）：per-line enabledMask AND mstatus.MIE 全局，M-13 陷入前检查全局层。

（4）性能边界：量子边界采样开销计入每量子固定开销预算 ≤10% 单量子执行时间（估算基线，评审 P-11）；脉冲探针采样可整体关闭（性能开关）。

9.4 会话状态导出 / 载入接口（本轮落点 · 台账 D-36）

M-16 产出 / 消费会话载荷的段 5（已拉起的 IRQ 行）——台账 D-36 点名「已拉起的 IRQ 行不在快照里」。M-16 的 InterruptController 有真实状态：raise / lower 是生产者接口，且内核宿主已持有它并真的委派（HostSinks::raise → 控制器）——通道本身是通的。⚠️ 段 5 的形状在本批按冻结规格扩展（STAGE-4 §2.3）：从「只有 raised（已拉起的 IRQ 行）」扩到 { raised, pending, priorities, enabled_mask, active_irq, mtime_ps, mtimecmp_ps }——新增字段全部 #[serde(default)]，旧载荷（stub 时代捕获的「一个中断都没有」的会话）仍能反序列化，且默认值正是那个时代的真实状态（不只是「能读」，是「读出来是对的」）⇒ 会话载荷 schema_version 保持 1。⚠️ active_irq 的默认必须是 NO_ACTIVE_IRQ = 0xFFFF（不能是 0——否则旧载荷会「有一个 active 的 line 0」而不通过载荷校验）。⚠️ 虚拟时间字段（mtime_ps / mtimecmp_ps）走十进制字符串（契约 v2 §2.2），不得用 u64 JSON 数字（2⁵³ ps ≈ 2.5 小时即可越界）。⚠️ 宿主的 raise_irq() / lower_irq() 是测试辅助入口，不构成生产路径，不要把它当成「段 5 已有生产者」。

接口方向契约（输入 → 输出；错误码/约束）
InterruptController::export_state()提供（driving）输出：段 5（raised = 当前拉起的 IRQ 行，升序、去重；本批按 STAGE-4 §2.3 扩展为 { raised, pending, priorities, enabled_mask, active_irq, mtime_ps, mtimecmp_ps }）——段 5 的生产者
InterruptController::load_state(state)提供（driving）输入：段 5；替换语义（整体替换，不是合并）：快照前拉起、载荷里没有的 IRQ 行会被清掉；回灌已拉起的 IRQ 行（恢复后的仲裁起点与快照时一致）

⚠️ 本批的落点（冻结规格 STAGE-4 §2.3 / §3）：M-16 的 CSR 管道随本批接线（mip / mie / mcause / mepc / mtval，且 mtval 落在契约层的通用 CSR 文件 SimState.csrs 里，不新增 SimState 专用字段 ⇒ 契约层不升 schema_version）——段 5 的生产者随之成立（外设 request(line) → 挂起 → 量子边界采样 → 仲裁 → 交付）。⚠️ 恢复顺序（不可换）：① M-14 load_map（映射）→ ② M-14 load_pages（内存页）→ ③ M-15 load_state（外设状态）→ ④ M-16 load_state（IRQ 行）→ ⑤ M-17 restore_full（引擎段）。⚠️ 校验先于应用：载荷必须先整体校验通过，再按上述顺序逐段回灌——半个应用完的快照比被拒绝的快照更糟。
