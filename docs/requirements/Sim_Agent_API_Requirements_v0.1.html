01

现状与为什么要提这个需求

kernel 能力不缺，缺的是「外部进程怎么调它」。

1.1 三条事实证据

位置现状后果
crates/server/src/main.rs文档写着「将托管 kernel、暴露 WebSocket 127.0.0.1:9876、POST /api/project」，实现只有 eprintln! placeholder没有任何进程级入口
front/services/m07_transport.jsserver-mode 分支存在，但「未配置 WebSocket URL」即降级为 E_TRX-03，注释明确 P1 仅骨架前端也只能跑 Worker 形态
crates/kernel/src/wasm_api.rs会话住在 thread_local! + RefCell，一个 wasm 实例 = 一个会话要并发 / 隔离，只能在进程层起多个实例

1.2 现在的唯一可用路径，以及它为什么不够

当前 Agent 侧实际可行的做法是：在 Node 里 import front/assets/pkg/riscv_sim_kernel.js，把 ELF 字节塞进 LoadProject，再用 StepN 轮询 console。这条路能跑通（已实测：150 万条指令进 shell，与 Spike 逐字节一致），但它是把「前端构建产物」当成「对外接口」在用：

七个硬约束，全都不是 API 该有的样子：
  • 耦合构建产物路径：front/assets/pkg/ 是 tools/build-wasm.sh 的输出，改名/换布局/未构建就全断。
  • 没有进程边界：guest 死循环 = 宿主进程卡死，杀不掉、也没法限时。
  • 没有预算与超时的服务端语义：客户端自己切 StepN 分片算「预算」，每个客户端各写一套。
  • wasm 单会话：一次并发调试两枚 ELF，就得自己起 N 个实例、自己管生命周期。
  • 非 JS 客户端不可用：Python / Rust / shell 侧无法接入。
  • 错误只在内核事件流里：E_PLT-22 这类码没有 HTTP 状态/退出码的落点，脚本判错得自己扫 JSON。
  • 无版本协商：schema_version 只能靠 import 后现算，缓存里放了一份旧 wasm 就会静默错配。
连带问题（同一批要一起解决）：tools/boot-osz.sh 的候选侧现在跑不通 —— 因为 v0.76（STAGE-52 · B1）取消了「无板自动选档」，而 osz-boot 仍是「直接 LoadProject」，于是 --print-memory 一上来就撞 E_PLT-22，脚本在参数校验阶段退出。
本需求把它当作验收对象之一：headless 判定不该由两个 CLI 各写一套，应当由同一个 API 提供。
02

需求总览

P0 = 没有它，Agent/CI 无法以工程化方式使用；P1 = 调试完整体验；P2 = 观测面。own 标记的条目是「需受理方拍板实现形态」。

R-01进程级入口与版本协商P0
  • 可执行 riscv-sim-server，参数含 --bind（默认 127.0.0.1）、--port（默认 9876）、--board（默认板模板 id）、--session-ttl。
  • GET /api/version → { kernel, schema_version, contract_version }；GET /healthz → 就绪状态。
  • 启动即打印实际绑定的地址与版本（便于脚本马上开始发请求，不必重试盲猜）。
验收：冷启动 < 2 s；curl /api/version 的 schema_version 必须等于 protocol_schema_version()。
R-02会话生命周期与隔离P0
  • POST /api/sessions → { session_id }；GET /api/sessions 列出（含板、镜像、状态）；DELETE /api/sessions/{id} 回收。
  • 每个会话一份独立内核状态（等价一个 wasm 实例语义）：会话之间零共享，一侧跑飞不影响另一侧。
  • 会话内命令串行化（同一时刻只有一个 run/step 在推进）；并发请求返回明确的忙状态而不是交错执行。
  • 空闲 TTL 与显式回收都要释放线程/内存；DELETE 后再次访问返回 404 + E_SESS-01。
验收：两个会话并行跑同一条 prefix，控制台字节各归各；删一侧后另一侧继续可跑。
R-03板级配置（保持「无板不装载」纪律）P0
  • 板来源三种：内置模板 id（POST …/board {"template":"qemu-virt"}）、完整 PlatformDescription（{"description":{…}}）、服务启动参数默认板。
  • 不得回退到 v0.76 之前的自动选档：没配板就装载，必须原样返回 E_PLT-22，并保留现有中文引导文案。
  • 配板返回 revision；装载时若镜像地址落在板外，返回 E_PLT-17，detail 里保留「第一个落不在的区间」。
  • 模板清单/模板详情各给一个只读端点（GET /api/board/templates、GET /api/board/templates/{id}），不要让客户端抄一份地址表。
验收：不配板直接装 ELF → 409 + E_PLT-22；osz.elf + qemu-virt → 装载成功且 entry 0x80000000。
R-04镜像装载P0
  • 支持 ELF 与原始 BIN 两种（kind 可省略则按扩展名推断，与前端 image-loader 同口径；.hex/.ihex 继续明确拒绝）。
  • 两种投递方式：服务端路径（{"path":"…/osz.elf"}，受 --allow-image-root 约束）与请求体字节（application/octet-stream，避免 200 KB 级 JSON 数字数组）。
  • 返回装载摘要：entry、segments（各自 base/size）、总字节数、以及 ELF 的 ISA（供与板 mcu.isa 做门禁）。
  • 装载本身不运行；装载失败时机器状态不变（与内核既有次序纪律一致）。
验收：osz.elf 走向上传：返回 entry 0x80000000、段数与 readelf -l 一致；坏 ELF 返回 422 + 既有 E_PLT/E_PROTO 码。
R-05运行与停止：预算、前缀、超时、断点四个停因P0
  • POST …/run 一次请求描述「跑到什么时候停」，服务端自己分段推进，客户端不必切 StepN：{steps?:N, prefix?:"OSZ$ ", timeout_ms?, until?:breakpoint|halt}。
  • 同步返回：{ stop_reason, executed, pc, t_ps, console:{from,to} }；stop_reason ∈ {budget, prefix, breakpoint, halt, timeout, paused}。
  • 同时提供 POST …/step {n}（精确 n 条，调试语义）与 POST …/pause、POST …/reset；异步模式（async:true）可选，P1。
  • 停点与 console 的一致性：响应返回时，停点之前的 console 字节必须已经可读（先 flush console，再返回停因）。
验收：run {prefix:"OSZ$ ", timeout_ms:30000} → stop_reason=prefix、executed 在一个与实现无关的区间内可复现、pc 可从后续 state 读回。
R-06console 字节流：增量、单调、原样P0
  • GET …/console?offset=N&limit=M → 原始字节（application/octet-stream），响应头带 X-Console-Total 与本次 offset。
  • 只追加不改写：offset 单调，已发出的字节永远不变；ANSI 转义、\r、半截 UTF-8 一律不加工（Spike 对拍依赖这一点）。
  • 保留上限可配（--max-console），溢出时明确报「已截断 + 丢弃区间」，不静默丢。
  • P1 同时提供 WS 推送（sim.console 主题原样转发），拉取与推送共用同一份 offset，不能两个真相。
验收：osz 到 shell 的 console 31 字节，与 Spike stdout cmp 逐字节相同；翻页两次拼接后与一次性读取一致。
R-07状态、内存、符号：读得到、看得懂P0
  • GET …/state → {pc, registers[0..32], t_ps}；寄存器读要区分「x0 恒 0」与「PC 不属于 GPR」这一基本事实（上一轮我就踩过：把 values[0] 当 PC）。
  • GET …/memory?addr=&len= → 原始字节 + 可选 format=u32|asc 视图；越界/未映射返回明确码。
  • GET …/symbols?name=|prefix= → 精确命中与候选列表（复用 ResolveSymbol），供「按符号打断点」「按符号读内存」用。
  • GET …/disasm?addr=&count= → 反汇编窗口，允许短于 count（未映射即止，与内核一致）。
验收：装载后 state.pc = ELF entry；在 shell 停住时按 main/shell 之类符号能解析出地址。
R-08断点与观察点P0
  • POST …/breakpoints {addr|symbol}、DELETE …/breakpoints/{id}、GET …/breakpoints；支持启停开关。
  • 命中即在 run 的返回里体现（stop_reason=breakpoint + 命中的断点 id 与地址），P1 另有 Hit 事件。
  • 观察点（watchpoint）按内核既有能力暴露，语义与 SetWatchpoint 一致。
验收：在 main 首条指令下断点 → run 停在断点地址、executed 与步进到同址的条数一致。
R-09错误契约：码 + detail 原样透出P0
  • 统一错误体 { code:"E_PLT-22", detail:"…", status:409 }；code 必须是契约层既有码，不新造同义词。
  • HTTP 状态映射固定：用法/载荷 → 400；会话/资源不存在 → 404；状态冲突（无板、忙、修订号不符） → 409；内核拒绝（门禁不过、镜像畸形） → 422；超时 → 504；内部 → 500 且必须带 detail。
  • 禁止「500 无 detail」与「成功但 body 里藏错」；装载失败不得返回 200。
验收：表里 12 个码各有一条用例，断言 status 与 code 均正确。
R-10确定性：同输入同输出P0
  • 预算以指令条数计，不以墙钟计；墙钟只作为熔断，不参与结果。
  • 同一 ELF + 同一板 + 同一预算 ⇒ console 字节流、stop_reason、pc 完全一致（两次运行可直接 cmp）。
  • 不引入「随机初始寄存器 / 依赖真实时间」的行为；t_ps 只由指令推进产生。
验收：同参数连跑 3 次，console 与 pc 三次一致。
R-11超时与熔断：跑飞必须杀得掉P0
  • 每请求可带 timeout_ms；服务端到点必须让 guest 停下并返回 504 + stop_reason=timeout，且会话仍可用（可再 reset）。
  • 会话级预算上限 + 服务级并发上限；超限给出 429 与剩余额度，不排队到无限。
  • 进程退出/被 kill 时不得留下孤儿线程与半初始化会话。
验收：跑到「死循环」的镜像，timeout_ms=3000 秒回 timeout；随后同会话 reset 后仍能正常装载运行。
R-12CI / 脚本友好P0
  • 零浏览器依赖、离线可用（不下载 npm/wasm；二进制自带 wasm 或原生内核）。
  • 便捷端点 POST /api/boot：{path, prefix, steps, timeout_ms} → 一次调用完成「配板 → 装载 → 跑到前缀 → 返回 console 字节（或写文件）」，等价 osz-boot 的判定口径；退出码概念用 stop_reason 表达。
  • POST /api/boot 的 stdout/返回体只放 console 字节，统计信息走 meta 字段 —— 这样与 Spike 的 cmp 不用再写 sed。
  • tools/boot-osz.sh 与 osz-boot 改为调用该端点（顺带修掉现在的 E_PLT-22 断链），仓内只保留一份判定口径。
验收：一条 curl 完成 osz 判定；--out 产物与 Spike 逐字节相同。
R-13事件流（WebSocket，复用 M-07 帧）P1
  • GET /api/sessions/{id}/events 升级为 WS，帧格式直接复用 front/lib/frame.js 的 {type, seq, sessionId, role, reqId, payload}，内核事件不做二次包装。
  • Subscribe/Unsubscribe 在会话上生效（sim.console / sim.state.delta / debug.trace / sim.waveform …）。
  • 背压：客户端跟不上时可丢帧，但必须显式报「丢了多少、从哪个 seq 起」，不允许静默断流。
验收：前端 m07_transport 的 server-mode 分支指到该端点即可工作（不再只在 Worker 模式可用）。
R-14快照 / 复位 / trace（闭环调试）P1
  • POST …/snapshot 与 POST …/restore（复用 Snapshot/Restore）：先存一份「坏现场」，再反复回放。
  • POST …/reset：回到当前工程的装载起点（与前端「复位 = 重新装载当前工程」同口径）。
  • POST …/trace {enabled} + GET …/trace?offset=：分页取轨迹，供 Agent 事后分析。
验收：快照 → 跑 1 万条 → restore → 再跑同一万条，两次 console 与 PC 一致。
R-15安全边界P0
  • 默认只绑 127.0.0.1；绑定非回环地址必须显式 --allow-remote 并配 token（P2 再做鉴权，但开关先留好）。
  • 镜像路径读取受 --allow-image-root 约束，默认只允许仓库根与显式传入的目录；拒绝 .. 穿越。
  • API 不提供任意文件写入；console 落盘只在显式 --out 时发生。
验收：{"path":"/etc/passwd"} → 403 + E_IO-xx；默认 curl 从非本机 IP 连不上。

04

关键语义（容易实现跑偏的地方）

4.1 console 是字节，不是字符串

幂等要求很硬：ANSI 序列、\r、半截 UTF-8 必须原样保留，否则与 Spike 的逐字节对拍立刻失效。取回接口的 offset 单调、只追加；「转发时顺便美化」一律禁止。

4.2 停因先于判定，console 先于返回

「跑到 prefix 就停」这条判定必须由服务端做（客户端逐段 StepN 会把预算口径打散）。返回停因之前，把已产生的 console 落进会话缓冲；否则客户端会遇到「说有 31 字节，取回只有 24 字节」这类时序 bug。

4.3 板不自动选，但可以给默认值

v0.76 的「无板不装载」是纪律，不要在 API 层用「贴心兜底」把它绕过去。可行的折中是：--board qemu-virt 作为显式默认在会话创建时配好，等价于客户端自己调一次 PUT board，语义仍可追溯。

4.4 单会话串行，跨会话并行

AC-07对死循环镜像 run {timeout_ms:3000}约 3 s 返回 timeout，随后同会话 reset 仍可用
AC-08两会话并行跑同一镜像各得 31 字节；删 A 后 B 仍可 run
AC-09console 分两页取（limit=16 再取余下）拼接结果与一次取全一致，X-Console-Total 恒为 31
AC-10同参数 run 连跑 3 次console、stop_reason、最终 pc 三次一致
07

非目标（明确不做）

不做理由
替代浏览器工作台前端仍是主要交互面；API 是给 Agent/CI 的第二个入口，两者共用内核与契约
在 API 层改内核语义（自动选板、自动改地址、自动重试装载）会把 v0.76 的门禁纪律绕空，故障现场被抹掉
支持 IHEX与产品入口保持一致（明确拒绝，不静默降级）
多板并行于同一会话一个会话一个生效板；要多板就多会话
远程鉴权体系（P2 再说）本批只留开关，不引入账号体系
