## §0 目标（用户原话，不改写）

> 「产品树的定位是给用户**创建自己的产品**用的，用户要能**自定义开发板**（增加 mcu、增加外设、引脚连接与管理等），创建之后需要给定义的开发板**映射内存**，**经过这两个步骤**加载的固件才能运行，**否则系统应该提示未知系统**。」

⇒ ⇒ 拆成**四段链路**（下面 §1 用它当判据）+ **两个用户拍板的口径**（**中间层在内核侧** · **状态关联逐实例**，v0.66 批已按此落地）。

## §1 现状：四段链路，哪几段是通的

| # | 链路 | 状态 | 落地在哪 |
| --- | --- | --- | --- |
| L1 | **读**：前端 → 中间层 → 内核（问「内核支持什么」「每个实例绑到哪儿了」） | ✅ **通** | v0.66 批：`device.types` / `device.instances` 两条只读通道 + M-15 器件类型注册表 + 宿主逐实例状态 |
| L2 | **写 · 改板**：前端 → 内核（改内存段 / 外设窗口 / 参数） | ⚠️ **有，但不走树** | v0.29 起的**板级内存图编辑器** → `SetMemoryMap` / `PatchMemoryMap` ⇒ ⇒ **产品树仍是只读**（`onCommand` 里只有 `toggle-tree`） |
| L3 | **写 · 连线**：前端 → 内核（定义器件之间的连接） | ❌ **没有** | 前端对 `wiring` **只做透传**（「从界面提交的板永远没有 `wiring`」是已登记的已知边界）⇒ ⇒ 界面上**定义不了**任何连接 |
| L4 | **绑定**：固件 ↔ 板（固件声明它属于哪块板 ⇒ 不匹配就「未知系统」） | ❌ **没有** | 契约层 `Project` 只有 `id`/`name`/`tree`/`images`/`version` ⇒ ⇒ **不带板引用** ⇒ ⇒ **「未知系统」连判定对象都没有** |

⚠️ **还有一个更底层的缺口**：**产品树这个概念本身仍是 `Project.tree`** —— **前端造、内核不造** ⇒ ⇒ 树与板**还不是同源** ⇒ ⇒ 这就是 L2 走不通的根（树改不了，因为树不是板）。

## §2 分岔点 0：产品树是「派生视图」还是「内核持有的数据」？

⚠️ **这一条决定后面五批的形态 ⇒ ⇒ 必须在第 52 批开工前拍**。

| | **路线 α**（本计划默认） | **路线 β** |
| --- | --- | --- |
| 产品树是什么 | **当前生效的板**的**派生视图**（前端算 ⇒ ⇒ 树与板**永远同源**） | **内核持有的数据**（契约层 `ProductTree` 扩成「板 / 段 / 器件」的完整层级 ⇒ ⇒ 内核也持有一份） |
| 能表达什么 | **一块板**的构成（段 + 器件 + 参数） | **产品 → 主板 → 元器件**的**多层结构**（多板 / 多芯片） |
| 代价 | 小 ⇒ ⇒ 纯前端、契约零升版 | 大 ⇒ ⇒ 契约升版 + 内核持有 + 校验 ⇒ ⇒ 与 D / F 耦合 |
| 什么时候不够 | 用户目标里出现「**增加 MCU**」且 **MCU 与其它芯片并存**（那是**层级**，不是单板） | —— |

⇒ ⇒ **判据给用户看**：如果一块自定义板上**只有一个 MCU** ⇒ ⇒ α 够用；如果板上**要挂多个芯片 / 多个板** ⇒ ⇒ 那是 β 的形态。

⇒ ⇒ ⚠️ **但有一条无悔的路**：**第 52 批（A + H）无论走哪条都要做** ⇒ ⇒ 树**能改板**这件事、类型清单**只有一处**这件事，α 与 β **都要** ⇒ ⇒ **先做它不亏**。

## §4 破坏性批次的两条统一口径

### §4.1 一次升版、一次迁移

⇒ ⇒ **第 55 批把 `B2` + `G` + `D1` 合成一批**（三个都要动描述格式）⇒ ⇒ **只迁一次存量板档案** ⇒ ⇒ 而不是分三次各迁一次。
⇒ ⇒ **迁移规则**：**缺省优先** —— 老描述缺新字段 ⇒ ⇒ 内核补缺省（而不是拒）⇒ ⇒ 老板**仍能装**；⇒ ⇒ 只有**语义真的变了**的字段才要求显式迁移。

### §4.2 「未知系统」的严格程度（三档，**要用户拍**）

| 档 | 固件**没有** `board_id` 时 | 后果 |
| --- | --- | --- |
| **严** | **拒**（报「未知系统」） | 老工程 / 仓外 ELF **全部要补声明** ⇒ ⇒ 真机门禁的 osz 链路**要跟着改** |
| **中**（推荐） | **警告 + 按当前生效的板跑** | 用户看得见「这块固件没声明板」，但流程不被打断 ⇒ ⇒ 严格档可**逐用户开启** |
| **松** | 静默按自动选档跑 | 「未知系统」**永远不会出现** ⇒ ⇒ 这一档等于**不做 C** |

⚠️ **推荐中档** ⇒ ⇒ 因为它既给出了提示，又**不破坏**现有的真机链路 ⇒ ⇒ 且把「严」做成**用户可选的严格模式** ⇒ ⇒ 而不是一刀切。

## §5 每批都要带的验收与判别力

| 项 | 要求 |
| --- | --- |
| **真机端到端** | 每批**至少一条**走**真 WASM 内核**的端到端断言（不是 mock、不是脚本口） |
| **变异自检** | 每批 ≥ **3 条**真变异 + **1 条对照**；⇒ ⇒ **红集互不重叠**、⇒ ⇒ **期望红集跟实测走**（不跟「应该红」走） |
| **跨层门禁** | 每批**两侧同源**的量（类型清单、偏移表、参数区间）**必须有跨层断言** ⇒ ⇒ 漂移当场红 |
| **判据纪律** | 钉**外部可观测**（不钉实现细节）· **先钉「对象存在」**（否则「空转通过」）· **空态分得开**（「没收到」vs「收到但零条」）· **每条判据配一条专打它的变异** |
