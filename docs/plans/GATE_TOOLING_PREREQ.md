## §2 阻塞前置（R-1 ~ R-4）

> 四条做完才动产品代码。每条必须带可复算的判据，判据不合格视为未落地。

### R-1 门禁支持分段重跑

- **现状**：`node tools/browser-verify.mjs` 只能整轮跑，无跳段能力，单轮约 7 分钟。
- **改法**：新增两个开关
  - `--only <section-id>`：只跑指定段（段 id 沿用现有段注册表的稳定名，不新造命名）。
  - `--from <step-id>`：从指定步骤续跑。**诚实约束**：真机门禁是「顺序装载 + 状态累积」的，续跑必须重建前置状态；因此每段需**显式声明前置依赖**（需要哪块夹具板、哪段固件、是否要重新装载）。声明不出来就退化为 `--only`，不允许靠"跳过等待"伪造续跑。
- **判据（三条同时满足）**
  1. `--only <段>` 的断言数与全量跑该段的断言数**一致**，结论一致；
  2. 该段耗时 ≤ **90 秒**（对照 7 分钟）；
  3. 未被选中的段在报告里显式标 `SKIP`，**不得静默消失**（防止"跳过的段被误读为通过"）。
- **收益**：定位期单轮 7 分钟 → 30~60 秒，同类事故的定位成本降约 90%。
- **落点**：`tools/browser-verify.mjs`。

### R-2 断言失败即 dump 证据

- **现状**：失败只输出 `✗ 标题 — 补充说明`；本次 `matched=false` 把"读到空串"和"功能没触发"完全混同了。
- **改法**：断言辅助函数在失败时附带结构化 `evidence`：
  - 采集到的**原始值**（`JSON.stringify` + 长度 + 前 200 字符原文，空串要能一眼看出是 `""`）；
  - 当轮订阅主题表；
  - PC / 关键寄存器快照；
  - DOM 快照文件路径（截图或 `outerHTML` 落 `/tmp`）。
- **判据**：用 `--inject-fail`（或临时构造一个必失败断言）跑一次，日志里必须出现 `evidence=` 字段且含被测值原文；只输出标题、无 evidence 判不合格。
- **收益**：把"产品没做"和"工具读不到"在**第一轮**就分开——本次可省 r48~r55 共 8 轮。
- **落点**：`tools/browser-verify.mjs` 的断言封装。

### R-3 采集通道 health check

- **现状**：采集器失效时的表现与产品缺陷完全相同（都是"断言红"），导致把工具故障记成内核缺陷（本次代价：8 个 diag 测试 + 3 个前端探针 + 3 轮假红）。
- **改法**：
  - 每段开始前跑一个**已知必现**的 needle（如装载成功后的 banner / 固定回显），不通即 **abort 该段**；
  - 报工具侧错误码 `E_HARNESS_CHANNEL`，与产品断言 ✗ **分开计数、分开退出码**。
- **判据**：
  1. 故意把 health-check needle 改错 ⇒ 报告出现 `harness: channel unavailable`，且**不出现任何产品断言 ✗**；
  2. 该场景退出码 ≠ 产品失败退出码；
  3. 通道正常时，health check 自身耗时 ≤ 5 秒。
- **收益**：防误判。这是本批最大的隐性成本来源。
- **落点**：`tools/browser-verify.mjs`。

### R-4 wasm mtime 检查前置

- **现状**：wasm 比 Rust 源码旧时，脚本会跑到浏览器装载阶段才报错退出（r50 白跑一整轮）。
- **改法**：main 第一段做 mtime 检查——过期则**自动调用** `tools/build-wasm.sh`（推荐，省一轮人工），构建失败才退出并明示原因。
- **判据**：`touch` 任一 `crates/**/*.rs` 后直接跑门禁，必须在 **5 秒内**给出明确结论（自动重建或秒退），**不得进入浏览器装载阶段**。
- **收益**：消除整轮白跑。
- **落点**：`tools/browser-verify.mjs` 入口。

## §3 顺手整改（R-5 ~ R-7）

> 随批完成，不阻塞开工。

### R-5 `--trace` 取代改生产代码

- **现状**：诊断靠临时改 `front/app.js` / 测试文件加探针，事后要清理 + 核验归零 + 再跑一轮确认（r57 整轮成本）。
- **改法**：门禁自带 `--trace`，只通过 CDP 侧取数；诊断入口由脚本开关控制，**默认不存在**。
- **判据**：`--trace` 全程 `git status` 干净（不修改仓库任何文件），追踪输出落 `/tmp`。

### R-6 clippy 前移

- **现状**：`large_enum_variant` 到收口才被 clippy 发现，直接触发一轮全量真机（r58）。
- **改法**：Rust 改动落盘即跑增量 `cargo clippy -p <crate>`；或在 AGENTS 纪律里写成硬性一条。
- **判据**：收口期首次运行 `cargo clippy --workspace --all-targets -- -D warnings` 即 **0 错**（不得靠收口期才发现）。

### R-7 门禁分段计时

- **现状**：日志没有任何耗时字段，复盘只能靠文件 mtime 反推（本次复盘即如此）。
- **改法**：每段开始/结束打 `[timing] section=<id> ms=<n>`，结束打印 top 5 段。
- **判据**：一轮全量日志中 `[timing]` 行数 ≥ 段数，top5 可读且合计与总耗时误差 ≤ 5%。

## §5 边界（不做什么）

1. **不重写门禁架构、不引入新测试框架**——只在现有 `tools/browser-verify.mjs` 上加能力。
2. **不降低任何现有断言强度**——只增加"跳段/证据/自检/计时"能力，不改判据本身；37 段注册表语义不变。
3. **不用 `--only` 替代全量绿**——每批收口的最终判据**仍然是全量 0 ✗**，分段重跑只用于定位期。
4. **不引入并行跑多轮**——真机门禁依赖单浏览器 + 单 HTTP server 的独占状态，并行会引入新的假象。

## §5.1 R-8 · 按影响面选测（v0.92）

**动机**：全量门禁 4~15 分钟、前端 758 条、内核数百条 ⇒ ⇒ 改一行注释也跑一遍全量
⇒ ⇒ 「改完立刻验」在成本上不成立 ⇒ ⇒ 红点攒到收口才暴露。选测把这一步压到可负担。

**两条硬规矩**

1. **不准漏**：选测只许**缩小**必跑集合。映射不出来 / 扇出太大 / 是共享底座
   ⇒ ⇒ **一律收敛到全量**。计划工具失败、输出不可解析 ⇒ ⇒ 也全量。
2. **前端用例集合是算出来的**：按 `front/tests/*.test.mjs` 的**静态 import 闭包**
   （含 `importFront("lib/x.js")` 这类动态字符串写法、以及「正文里点名该路径」的
   源码文本断言）推导 ⇒ ⇒ 改哪个模块就只跑依赖它的用例，不靠手写清单。

**映射表的写法**：只有「改动面确实很窄」的路径才进窄表（目前 4 条：`docs/**`、
`trace-export.js`、`trace-switch.js`、`run-loop.js`、`waveform-data.js`）；其余
一律走兜底（全量）。**收益是少跑，成本是漏跑** ⇒ ⇒ 宁可少写几条。

**用法**

```bash
node tools/impact.mjs --base origin/main          # 看计划（人类可读）
node tools/impact.mjs --base origin/main --json    # 给脚本
node tools/impact.mjs --paths front/lib/x.js       # 演练：模拟一组改动
node tools/browser-verify.mjs --impact [--impact-base HEAD]
tools/check-front.sh --impact
node tools/impact.mjs --selftest                   # 映射规则 8 条不变量
```

**边界**：`--impact` 只用于**定位期**。收口判据仍是「全量 0 ✗」（§2.5 第 3 条）。
计划输出会让被跳过的段在报告里显式标 `SKIP（--impact ⇒ 本段不在影响面内）`
—— 跳过永远是**可见**的，不会静默消失。
