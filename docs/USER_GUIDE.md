# RISC-V 仿真/调试平台 · 用户指南

> **读者**：想用这个平台跑固件、看波形、对拍 RTOS 的人。
> **本文档**讲**怎么用**；架构与设计在 [`docs/architecture/RISC-V_Architecture_Design.html`](./architecture/RISC-V_Architecture_Design.html)，
> 欠账与已知缺口在 [`docs/reviews/REVIEWS.md`](./reviews/REVIEWS.md)。
>
> ⚠️ **本文档里的每个数字都从当前树实测**（`tools/count_scale.py` + 门禁输出）⇒ ⇒ **不写死历史值**。

---

## 1. 这个平台是什么

一个 **RV32IMC（+ S/U 特权级 · PMP · Zicntr）** 的指令集仿真与调试平台：

- **仿真内核**（Rust，自研，BSD/MIT）——事件驱动引擎 + ISS + 总线/内存图 + 外设模型（UART / CLINT / PLIC / GPIO）+ 断点/单步 + DWARF 行号 + 探针/波形 + 快照；
- **浏览器工作台**（原生 ES modules，**零构建 · 零安装**）——七个视图 + 一个板级内存图编辑器；⚠️ **不是「零依赖」**（**波形图**走 CDN 的 `echarts` ⇒ ⇒ 不可达时**优雅降级**）；
- **两种运行形态**——浏览器内 WASM（默认）/ 服务端 P1（仅占位）；
- **正确性对拍**——与 **Spike** 逐条比判决（riscv-tests 语料）或逐字节比 UART 字节流（真实 RTOS）。

⚠️ **一句话边界**：这是**仿真器**，不是 QEMU 的替代品，也没有 QEMU 的系统仿真广度——它面向**固件级验证**（跑你自己的裸机/RTOS 镜像、看它的寄存器与波形、与参考侧对齐）。

## 2. 五分钟跑起来

### 2.1 装依赖

```bash
# Rust + WASM 目标 + wasm-pack
rustup target add wasm32-unknown-unknown
cargo install wasm-pack

# 前端门禁需要 Node ≥ 22（零依赖，只用 node:test）
node --version
```

可选（**不进默认门禁**，按需运行）：**Spike**（参考侧）、**RISC-V 交叉工具链**（编固件）、**Chrome**（真机复验）。

### 2.2 编译 + 构建 WASM 内核

```bash
cargo build                 # native
tools/build-wasm.sh         # 浏览器内核（调试版）；--release 出发布版
```

产物落在 `front/assets/pkg/`（wasm-pack `--target web` ⇒ **原生 ES module + 具名导出**，零构建前端可直接 `import`）。
⚠️ 这一步**不能跳**——不构建 WASM，浏览器里就没有内核（页面会起来，但全是空态）。

### 2.3 起前端

```bash
python3 -m http.server 8080 --directory front
# 浏览器打开 http://localhost:8080
```

> ⚠️ **必须走 HTTP(S)**：前端用 **Worker + ES module**，两者都要求同源 ⇒ `file://` 直开被浏览器拦（页面顶栏会明写「请通过 HTTP 打开」）。

### 2.4 确认内核真的连上了

打开页面后看两处：

| 位置 | 正常长什么样 | 不正常说明什么 |
| --- | --- | --- |
| 顶栏右侧状态 | `kernel 已连接 — wasm worker` | `工作台已就绪 — kernel transport 未连接（…）` ⇒ **WASM 没构建**或 Worker 起不来 |
| 页脚右侧 | `WASM 内核已就绪（Nop 往返成功）` | `内核未就绪：…` ⇒ 内核侧报错（把整句抄下来） |

⚠️ **页脚这句话比状态栏更准**：它是一次真实的 `Nop` 往返的结果。
⚠️ 状态栏可能显示「已连接」但页脚说「**探针流不可用**」⇒⇒ 那**不是**内核没就绪（是波形那条流订阅不上，寄存器与反汇编仍可用）。

## 3. 界面导览

**左侧是分组导航**（v0.49 起）：两个分组——「**运行与调试**」（嵌入式 / 调试 / 寄存器·内存 / 波形 / 终端）与「**平台**」（产品 / 板级内存图 / 源码）⇒ ⇒ 共 **8** 个视图 ⇒ ⇒ 当前视图那项会**高亮**（点它就切路由，URL 里的 `#/xxx` 照旧可用）⇒ ⇒ **窄屏（< 720px）时侧边栏变抽屉**，点左上角**汉堡按钮**拉开。

**顶栏右侧是全局运行条**：**PC** 与**虚拟时间**（跟「寄存器 / 内存」那一屏**同一个数据源**）＋ **运行** / **单步** / **暂停** / **复位** 四个按钮 ＋ 一个**运行状态位** ⇒ ⇒ 四个按钮走的是**调试视图那条命令路径**（不是另写的一套）⇒ ⇒ 任何视图下都能单步 ⇒ ⇒ **「运行」= 连续运行**（点一次就一直跑，见 §3.8）。

⚠️ **v0.49 批**换**骨架与视觉** ⇒ ⇒ **v0.50 批**换**视图内部的内容形态**并给**断点**补上**页面入口** ⇒ ⇒ **v0.51 批**把**波形**换成**真图**。

### 3.1 产品（`#/product`）

- **产品树**：当前装载的工程结构（板 → 芯片 → 外设）⇒ ⇒ **可折叠**（点节点左侧的三角收起 / 展开）⇒ ⇒ 折叠状态**记住**（切走视图再切回来还在）。
- **内存映射 (M-14)** 表：**当前生效**的板级内存图（来自内核 `memory.map` 事件，不是假数据）。没有数据时如实显示空态。
- 按钮「**编辑板级内存图**」⇒ 跳到编辑器；「**重新 seed demo 状态**」是 dev-only。
- **当前固件**（v0.58 批起）：这一块**只显示状态**，**不再有装载入口** ⇒ ⇒ 装载入口**只有页头那一个**（用户定案「**只应该有一个入口**」）。
  - 显示「**已选择**〈文件名〉（N 字节）」/「**已装载**〈文件名〉（N 字节）」/「**装载失败**：〈内核原话〉」⇒ ⇒ 你能看见当前装的是哪个固件、上次装载成没成；
  - ⚠️ **装完就停**：平台**不会**替你自动跑 ⇒ ⇒ 想跑自己去调试视图点「**继续**」；
  - ⚠️ **装载失败会把内核的原话显示出来**（含错误码，如 `E_LDR-01`），**面板与页脚两处**都写 ⇒ ⇒ 不吞。
  - ⚠️ **要装载请回页头**（品牌名右边）的「**加载固件**」⇒ ⇒ 那个入口**任何视图都在**，**不必**切标签页。

### 3.2 嵌入式（`#/embedded`）

落地工作台的概览页：**内核连接状态**、**当前 PC**、**虚拟时间**，以及四个子视图入口按钮（调试 / 寄存器·内存 / 波形 / 源码）。

### 3.3 调试（`#/debug`）

平台的主操作面。工具条：

| 按钮 | 做什么 | 看完什么 |
| --- | --- | --- |
| **单步** / **单步 ×10** | 推进 1 / 10 条指令 | 「寄存器 / 内存」面板里 `x0..x31` 与 PC 变化 |
| **继续** | **一直跑**下去（连续运行），直到命中断点 / 观察点 / 陷阱 | 页脚给出停下原因；顶栏状态位显示「**连续运行中**」 |
| **暂停** | **停止续发**（不再跑下一个窗口） | 顶栏状态位回到「**已停止**」；正在跑的那一个窗口会跑完才停 |
| **复位** | 重新装载当前工程 | PC 回到复位向量 |
| **读寄存器** | 拉一次全量寄存器 | 32 个通用寄存器刷新 |
| **读内存** | 读**地址输入框**里那个地址起的一 / 二 / 四个字（**v0.54 批起**；此前地址**写死**成 `0x100`） | 「内存单元」表出现一行 |
| **反汇编** | 请求**当前 PC** 起 16 条的反汇编 | 表格出现：地址 / 机器码 / 助记符 / 宽度 / 源码 |
| **导出执行轨迹 (CSV)** | 导出执行轨迹 | 面板出现进度行 + 内容块 + **下载**按钮 |
| **导出波形 (VCD)** | 导出波形 | 同上（文件名 `trace-waveform.vcd`） |
| **继续导出** | 还有剩余条目时出现 | 进度行从 `next_offset` 继续 |
| **开启 / 关闭 trace 记录** | 控制访存轨迹记录 | 开启后有「仿真会明显降速」的提示 |

⚠️ **助记符是 ISA 助记符**：压缩指令保留 `c.` 前缀，**不做伪指令别名改写**。

**断点（v0.50 批起）**：反汇编表**多一列**「断点」⇒ ⇒ 每行有个按钮，点了就在**那个地址**下断点（文案在「**加断点**」与「**断点 ●**」之间变）⇒ ⇒ 再点一次或用列表里的「撤掉」就移除 ⇒ ⇒ **断点列表卡**列出本会话由界面请求过的断点，每条都能撤 ⇒ ⇒ **命中断点**提示**只**在内核报告停下原因是断点时出现（页面上写明命中的地址）⇒ ⇒ ⚠️ **v0.54 批起**，断点**也可以直接在地址输入框里填**（不必先反汇编到那儿）⇒ ⇒ 见 **§3.10**。

⚠️ **断点列表是「界面回显」，不是内核断点集的镜像** ⇒ ⇒ 界面**如实标注**这一点 ⇒ ⇒ 用脚本口（`window.riscv_kernel.*`）设的断点**在这个列表里看不到**、界面设的断点脚本口也列不出来 ⇒ ⇒ 两条路**各管各的**。
⚠️ **导出窗口不是完整历史**：源环溢出过 ⇒ 面板会明确标「⚠️ 导出窗口**不是完整历史**」。
⚠️ **下载按钮**出现后点它，文件名由「源 + 格式」派生（`trace-execution.csv` / `trace-waveform.vcd`），不是写死的。

### 3.4 寄存器 / 内存（`#/regmem`）

通用寄存器 `x0..x31`、PC、虚拟时间，以及「读内存」读回的内存单元表（**v0.54 批起**读**任意地址**，见 **§3.10**）。

⚠️ **变化高亮（v0.50 批起）**：寄存器格子会标出**与上一次读回相比变了**的那些（变了的是一种颜色，没变的不加标记）⇒ ⇒ 它比的是**上一次读回的快照**，不是「上一次你看见的样子」⇒ ⇒ 第一次读回时全部不算变化。

### 3.5 波形（`#/waveform`）

探针通道列表：通道名 + **边沿数** + 最新值。空态说明「尚无探针信号」——固件得真的驱动外设引脚才会有（内建的 demo 固件会写 `GPIO0.OUT`）。

**波形真图（v0.51 批起）** —— 这一屏现在**有图**了：

- **怎么用**：切到「**波形**」视图 ⇒ ⇒ **跑起来**（顶栏的「运行」或调试视图的「继续」）⇒ ⇒ 图上出现每个通道的**阶梯线**（横轴是**虚拟时间**、连续刻度，不是等距的分类轴 ⇒ ⇒ 边沿的真实间隔不会被画成一样宽）。
- **图例里的两个数不是一个数**：图例写成 `通道名（显示条数/总数）` ⇒ ⇒ **左边那个 = 图上画出来的条数**（每通道**最多 512 条**、只留**最近**的）、**右边那个 = 边沿总数**（**一直累加**、**不受**那个上限影响）⇒ ⇒ 跑久了这两个数**必然不同** ⇒ ⇒ ⚠️ 别把「图上只有 512 条」当成「内核只记了 512 条」。
- **缩放平移**：图下方有一条缩放条，图内可直接拖拽，**滚轮**也能缩放 ⇒ ⇒ 放大到某一段时间看细节。
- ⚠️ **图是空的时候先看两件事**：① 固件**真的驱动引脚了吗**（通道列表也是空的 ⇒ ⇒ 就是还没有边沿）；② **波形库可达吗**（离线 / CDN 不通 ⇒ ⇒ 这一屏显示「**波形库不可用**」⇒ ⇒ **通道列表仍在**、**跑 / 断点 / 寄存器 / 反汇编照常**）。

### 3.6 终端（`#/terminal`）

串口终端。输入框里的文本按 **UTF-8 编码**成字节，发给 guest 的 **UART0**（契约 v5 的 `WriteConsole`）。

- 「**发送**」按钮，或在输入框里**按 Enter**；
- ⚠️ **回显来自 guest**，平台不做本地回显；也**不**模拟终端控制序列（不追加换行、不处理 Ctrl-C / 退格 / 历史）；
- ⚠️ 只送**原始字节**——送字符串会被内核按 `E_PROTO-08` 拒掉。
- **收发字节数（v0.50 批起）**：终端上方显示 **TX**（guest 发出来的字节）与 **RX**（你发出去的字节）⇒ ⇒ **两个方向分别标注**、不是同一个数（TX 来自内核的 console 事件、RX 是前端发出的累计）⇒ ⇒ **RX 数的是「发出去了」，不是「内核确认收到了」**。
- ⚠️ **行结束符（v0.55 批起）**：「发送」时会在你输入的字节**后面追加一个行结束符** ⇒ ⇒ **四档可选**（**CR** = 0x0D / **LF** = 0x0A / **CRLF** = 0x0D 0x0A / **不加**），**默认 CR** ⇒ ⇒ **为什么默认 CR**：真实串口终端按回车发的就是它，而 osz 这类**只认 CR** 的 shell 只有拿到 CR 才会**执行**那一行 ⇒ ⇒ 只送原文 ⇒ ⇒ 命令永远停在缓冲区里 ⇒ ⇒ **界面看上去「guest 没反应」** ⇒ ⇒ ⚠️ **选「不加」就回到 v0.5x 批之前的行为**（只送原始字节）⇒ ⇒ 换固件时按固件的约定挑档（**平台不猜**）。
- ⚠️ **屏幕显示（v0.56 批起）**：终端**默认按「真实终端」那样显示** ⇒ ⇒ guest 的 shell 每敲一个键就用 `ESC[2K` + `CR` **重画整行** ⇒ ⇒ 后一次重画**覆盖**前一次 ⇒ ⇒ **屏幕上是一行**（例如 `OSZ$ cyx`）⇒ ⇒ **不是**把每一次重画堆成一行（那样会看到「提示符 + 半截命令」好几行）；⚠️ **字节流一个字都没丢**（内核里仍然是那串原始字节 ⇒ ⇒ 与 Spike 的逐字节对拍**照旧**）⇒ ⇒ 点「**原始字节**」按钮可切回**未经解释**的字节流（那一档会看到 `[2K` 这类字面量 —— 那是**故意**的）；⚠️ **本批不做**：颜色（SGR 被吞掉 ⇒ ⇒ 屏幕是单色）· 光标块 · 回滚缓冲。

### 3.7 源码（`#/source`）

- **装载目录 / 装载文件**：用浏览器原生文件选择器把源码读进**前端**（**不进内核**，刷新即失）。
- **解析当前 PC 的源码行**：问内核「这个地址对应哪一行」（DWARF 行表）。
- ⚠️ **三种「没有答案」分得很清楚**：没问过 / 镜像没有 DWARF 行表（要 `-g` 重编译）/ 地址不在行表内。
- ⚠️ 匹配到**多个**候选文件时，界面**列出候选让你选**，不静默挑第一个。
- **两栏形态（v0.50 批起）**：左边是**文件列表**、右边是**代码区**（窄屏自动改成上下两段）⇒ ⇒ 当前 PC 所在行会标出来。

### 3.8 顶栏全局运行条（全局 · v0.49 起）

- **PC**：8 位十六进制 ⇒ ⇒ 与「寄存器 / 内存」那一屏**逐字相同**（**同一个状态源**，不是第二份数据）。
- **虚拟时间**：皮秒 / 纳秒 / 微秒 / 毫秒**自适应**显示 ⇒ ⇒ 同时在元素上挂一份**原始皮秒**供脚本读。
- ⛔ **没有「指令退休计数」** ⇒ ⇒ 契约层的 `SimState` **没有**那个字段 ⇒ ⇒ **没有数据源 ⇒ ⇒ 不编造**。
- **运行 / 单步 / 暂停 / 复位** 四个**独立**按钮 ⇒ ⇒ 四个按钮都**直接调 `handleCommand`** ⇒ ⇒ 与调试视图**共用同一条命令路径**。
- **「运行」= 连续运行**（v0.52 批起）⇒ ⇒ 点一次**就一直跑**下去 ⇒ ⇒ 一直跑到**命中断点 / 观察点 / 陷阱**为止 ⇒ ⇒ 调试视图的「**继续**」也是同一条路径 ⇒ ⇒ 两处**一个意思**。
  - ⚠️ **为什么不是「点一次走一段」**：内核一次 `Continue` 只跑 **10 000 条指令**（= **10 µs** 虚拟时间）就**主动让出控制权** ⇒ ⇒ 「连续」是**前端在收到「让出控制权」之后接着发下一条** ⇒ ⇒ **不是**内核的新语义 ⇒ ⇒ 契约层 / 内核**一个字都没改**。
- **「单步」= 执行一条指令**（实测 +1 ns）⇒ ⇒ 「单步 ×10」= 十条 ⇒ ⇒ **单步会退出连续运行**（否则下一轮「继续」会立刻把它盖掉）⇒ ⇒ 连续运行中想单步，**先单步再点运行**。
- **「暂停」= 停止续发** ⇒ ⇒ ⚠️ **不是**「立刻冻结」：正在跑的那一个窗口（10 µs 虚拟时间）会跑完才停 ⇒ ⇒ 用户感知不到。
  - ⚠️ **界面的「暂停」不会给内核发「暂停」命令** ⇒ ⇒ 因为那会让内核**留下**一个待处理的暂停 ⇒ ⇒ **下一次「运行」会被白吃一整轮**（实测过）⇒ ⇒ 所以界面的暂停**只停前端这边的续发**。
  - ⇒ ⇒ **内核那条「暂停」命令在界面上没有入口了**（脚本口与契约测试仍覆盖它）。
- ⚠️ **运行时寄存器 / 内存 / PC 显示 `-`**（v0.53 批起）⇒ ⇒ **正在跑的时候**
  **一律显示 `-`** ⇒ ⇒ 界面**不闪** ⇒ ⇒ **只有暂停之后**（命中断点 / 观察点 / 陷阱 /
  手动点「暂停」）**才显示最新值** ⇒ ⇒ ⇒ **隐藏的是显示、不是测量通道**
  （顶栏那条**原始皮秒**属性运行中**仍是真值** ⇒ ⇒ 脚本照样能读）。
- ⚠️ **运行中点「读内存」会被拒**：**不发出那条命令** + 弹一个**居中告警**
  （**5 秒后自己渐隐**；点「知道了」**立刻**关掉）⇒ ⇒ **拒绝的是执行、不是显示**
  ⇒ ⇒ 内存表里**不会**多出那一行。
  - ⚠️ **脚本口的 `readMemory` 不弹窗**（只挡界面那两个按钮）。
- ⇒ ⇒ **「暂停」只停续发** ⇒ ⇒ 正在跑的那一个窗口还在跑时**仍**算「运行中」
  ⇒ ⇒ 所以「暂停后那一瞬间仍显示 `-`」是**符合语义**的，不是 bug。
- **运行状态位** ⇒ ⇒ 连续运行时显示「**连续运行中 · 已跑 N 轮**」⇒ ⇒ 停下后显示「**已停止**」⇒ ⇒ **看得见**自己是不是在跑。
- **「复位」= 重新装载当前工程** ⇒ ⇒ **顺带退出连续运行**（⇒ ⇒ 轮数也一起归零 ⇒ ⇒ 新工程不该继承上一个工程的数）。

### 3.9 断点 UI（v0.50 批起）

页面上终于有**断点按钮**了（此前**只有脚本口** `window.riscv_kernel.*`）。

| 落点 | 长什么样 | 做什么 |
| --- | --- | --- |
| **反汇编表** | 每行末尾一列「断点」，一个按钮 | 点一下 = 在**该行那个地址**下断点；再点一下 = 撤掉 |
| **调试视图 · 断点列表卡** | 逐条列出地址，每条一个「撤掉」 | 移除本会话由界面请求过的断点 |
| **调试视图 · 命中提示** | 「命中断点 @ 0x…」 | **只**在内核报告停下原因是断点时出现 |

怎么用：

1. 切到**调试**视图 ⇒ ⇒ 点「**反汇编**」拿到当前 PC 起的 16 条；
2. 在想停的那一行点「**加断点**」⇒ ⇒ 按钮变成「**断点 ●**」，断点列表里出现该地址；
3. 点「**继续**」⇒ ⇒ 内核在**那个地址**停住（⇒ ⇒ 停下原因 = 断点）⇒ ⇒ 页面显示「命中断点 @ 0x…」（⇒ ⇒ 内核**在取指之前**就命中 ⇒ ⇒ 那条指令**没有执行**）；
4. 不想要了 ⇒ ⇒ 在列表里「撤掉」⇒ ⇒ 列表清空 ⇒ ⇒ 再点「继续」就**不会**在那个地址停。

⚠️ **三条边界**（**说在前面**，免得你以为它比它能做的多）：

- **只认地址** ⇒ ⇒ 断点**从反汇编下**（源码行断点**没做** ⇒ ⇒ 需要「行 → 地址」的映射）；
- **列表是「界面回显」** ⇒ ⇒ 内核**没有**「列出断点」的事件 ⇒ ⇒ 界面只能显示**本会话由界面请求过的**那些 ⇒ ⇒ 脚本口设的断点**看不到**、界面设的脚本口**列不出** ⇒ ⇒ **两条路各管各的**；
- **地址对齐与合法性由内核判** ⇒ ⇒ 界面**不自己校验** ⇒ ⇒ 内核拒了就把它的原话显示出来。

### 3.10 任意地址断点 + 任意地址读内存（v0.54 批起）

此前「加断点」**只能从反汇编行点** ⇒ ⇒ 想在一个**离当前 PC 很远**的地址下断点 ⇒ ⇒
**做不到**（反汇编窗口是从当前 PC 起的）；「读内存」的地址则**写死**成 `0x100` ⇒ ⇒ 想读别的
地址 ⇒ ⇒ **没有入口**。⇒ ⇒ v0.54 批给这两件事各补了一个**地址输入框**。

| 落点 | 长什么样 | 做什么 |
| --- | --- | --- |
| **调试视图 · 断点卡** | 一个地址输入框 + 一个「加断点」按钮 | 填**任意十六进制地址**（可带 `0x`）⇒ ⇒ 直接下断点 ⇒ ⇒ **不必**先反汇编到那儿 |
| **调试视图 · 寄存器/内存卡** | 一个地址输入框 + 一个宽度选择 + 一个「读内存」按钮 | 读**任意地址** ⇒ ⇒ 宽度可选 **Byte / Half / Word**（一次最多 **4 字节**） |
| **寄存器/内存视图 · 工具栏** | 同一组控件（与上面**共用**一份） | 同上 ⇒ ⇒ 两处**一个真相**（填的地址**共享**） |

怎么用：

1. 切到**调试**视图 ⇒ ⇒ 在「**断点**」卡里填一个地址（十六进制，例如 `0x400`）⇒ ⇒ 点「**加断点**」
   ⇒ ⇒ 断点列表里出现**那个地址** ⇒ ⇒ 点「**继续**」内核就在**那儿**停；
2. 想看某处内存 ⇒ ⇒ 在「寄存器 / 内存」卡里填地址、选宽度 ⇒ ⇒ 点「**读内存**」
   ⇒ ⇒ 内存单元表里**出现那一行**（地址 = 你填的那个、值 = 内核内存里的真值）。

⚠️ **四条边界**：

- **地址是十六进制** ⇒ ⇒ `100` 读作 `0x100`（与界面其它地方显示地址的口径一致）⇒ ⇒
  最多 **8 位**（`0xFFFFFFFF`）；
- **地址框默认为空** ⇒ ⇒ 第一次点「读内存」**要先填地址** ⇒ ⇒ 填错会**就地**给一句提示
  （不会「点了没反应」）；
- **一次最多读 4 字节** ⇒ ⇒ 「**一次看一段内存**」**还没有**（⇒ ⇒ 属下一批的契约升版）；
- **对齐与合法性由内核判** ⇒ ⇒ 界面**不预校验** ⇒ ⇒ 奇数地址**照样发过去** ⇒ ⇒ 由内核回错误。

### 3.11 按符号断点 + 条件断点 + 整段转储（v0.57 批起）

此前「加断点」**只能填数值地址** ⇒ ⇒ 想断到 `main` 这样的**函数名**上 ⇒ ⇒ 得自己
去查地址（而多数镜像里根本查不到符号名）⇒ ⇒ **做不到**；「读内存」一次**最多 4 字节**
⇒ ⇒ 想看**一段**内存 ⇒ ⇒ 也做不到。⇒ ⇒ v0.57 批补了这三件事。

| 落点 | 长什么样 | 做什么 |
| --- | --- | --- |
| **调试视图 · 断点卡** | 一个**符号名**输入框 + 一个「查找」按钮 + 一个**候选列表** | 按**名字**查符号 ⇒ ⇒ 候选里**点一下**就在那个符号的地址上下了断点 |
| **调试视图 · 断点卡** | 一个**条件**输入框（可选） | 断点**命中地址还不够** ⇒ ⇒ 还要**条件成立**才停（例：`x1 == 5`） |
| **寄存器/内存视图** | 一个地址框 + 一个字节数框 + 一个「转储」按钮 | 一次看**一段**内存 ⇒ ⇒ 渲染成 `偏移 / 十六进制 / ASCII` 三列 |

怎么用：

1. **按符号下断点** ⇒ ⇒ 在「**断点**」卡的符号框里填名字（`main`，或只填前缀
   `mai`）⇒ ⇒ 点「**查找**」⇒ ⇒ 候选列表里出现**候选符号**（每个都写着「名字 @ 地址」）
   ⇒ ⇒ **点其中一个** ⇒ ⇒ 断点列表里出现**那个地址**，那一行还**写着符号名**；
2. **带条件** ⇒ ⇒ 在条件框里写一个表达式（例：`a0 != 0`）⇒ ⇒ 再下断点 ⇒ ⇒ 断点
   **到这个地址时**，条件**不成立**就**继续跑**，**成立**才停；
3. **看一段内存** ⇒ ⇒ 在「寄存器 / 内存」视图里填地址与字节数 ⇒ ⇒ 点「**转储**」
   ⇒ ⇒ 出现一张 `偏移 / 十六进制 / ASCII` 的表（每行 16 字节）。

⚠️ **条件表达式怎么写**（v1 的全部语法）：

- **操作数**：`pc` · `x0`~`x31` · ABI 别名（`zero` `ra` `sp` `gp` `tp` `t0`~`t6` `s0` `s1` `fp` `a0`~`a7` `s2`~`s11`）· 十进制 / `0x` 十六进制字面量；
- **比较运算符**：`==` `!=` `<` `<=` `>` `>=`（**无符号**比较）；
- **逻辑运算符**：逻辑与（`&&`）· 逻辑或（两根竖线）· 取反（`!`）⇒ ⇒ 优先级从低到高是
  「逻辑或 → 逻辑与 → 比较 → 取反 → 括号」；
- **例子**：`x1 == 5` · `a0 != 0` · `pc >= 0x80001000` · `x1 == 5 && x2 != 0` · `!(x1 == 0)` · `s0 == sp`。

⚠️ **八条边界**：

- **符号来自镜像的 `.symtab`** ⇒ ⇒ **被 strip 过的固件查不到任何符号** ⇒ ⇒ 界面会
  明确说「这个镜像没有符号表」（不是「查不到这个符号」）⇒ ⇒ 两件事**分得开**；
- **条件表达式 v1 只支持寄存器与 PC** ⇒ ⇒ **不能**读内存（`mem[...]` 写不了）⇒ ⇒
  也不能做算术（`x1 + x2` 写不了）⇒ ⇒ 想看内存的值 ⇒ ⇒ 用**整段转储**；
- **条件是「命中地址时」求值的** ⇒ ⇒ 看到的寄存器值 = **那条指令执行前**的值；
- **条件写错 ⇒ 内核拒**（`E_DBG-02`）⇒ ⇒ 界面显示**内核原文** ⇒ ⇒ 断点**不会**被悄悄
  加上（地址非法也是同一条纪律：拒了就是拒了，断点表不变）；
- **一次最多转储 4096 字节** ⇒ ⇒ 超了 ⇒ ⇒ 内核拒（`E_DBG-03`）⇒ ⇒ 原文上屏；
- **转储读的是「调试视角」** ⇒ ⇒ **不**计入总线统计、**不**触发探针、**不**匹配观察点
  ⇒ ⇒ 调试器的窥视**不污染** guest 自己的可观测性；
- **候选最多 16 条** ⇒ ⇒ 前缀命中太多时只给**前 16 条**（按名字排序）；
- **界面上的断点列表仍不是内核断点集的镜像** ⇒ ⇒ 它列的是「**本会话由界面请求过**的
  断点」⇒ ⇒ 用脚本口设的断点在这里**看不到**（这条边界从 v0.50 批起**原样保留**）。

## 4. 换一块板（板级内存图编辑器）

这是平台目前最有特色的能力：**在界面上定制板子的 RAM 段与 MMIO 窗口**，不用改宿主代码。

### 4.1 编辑

| 字段 | 说明 |
| --- | --- |
| **板 id** | 板的主键；**已保存的板只读**（改 id 就是另一块板 ⇒ 用「另存为板」） |
| **板名** | 显示名 |
| **优先级 priority** | 多板共存时的排序意图 |
| **每段的声明大小上限** `region_budget_bytes` | 任一 RAM/ROM 段的**声明** size 不得超过它（超出 ⇒ 内核报 `E_PLT-07`） |
| **RAM / ROM 段** | 逐段填 `base` + `size` |
| **外设窗口** | 填 `base` + 器件类型 + 器件参数 |

器件类型与参数：

| 器件 | 参数 |
| --- | --- |
| `gpio` | 无 |
| `uart16550` | `irq_line` · `baud_rate`（**不设上界**——架构没有） |
| `clint` | `freq_hz` · `harts` |
| `plic` | `sources` · `contexts` |

⚠️ 参数的**合法区间由内核校验**（越界 ⇒ `E_PLT-12`）⇒ ⇒ 界面**不写第二份区间表**，只在内核的消息里给出。

### 4.2 提交

点「**提交板级内存图（整份替换 / 差量）**」：

- 元数据（id / name / priority / auto_selectable）改了 ⇒ **整份替换**；否则 ⇒ **差量**（只发改动的那几段）；
- 什么都没改 ⇒ **不发命令**（页脚说「板级内存图没有改动 —— 不用提交」）；
- **校验失败** ⇒ 面板上出现带**场景码**的错误块（如 `E_PLT-06` 地址重叠 / `E_PLT-07` 超预算）⇒ ⇒ **前端不自己判合法性**，只如实显示内核的裁决；
- **并发丢更新看得见**：提交带着期望修订号，图被别人改过 ⇒ `E_PLT-13`（界面会提示「图已被改，请刷新后再提交」）。

### 4.3 生效时机

| 情形 | 效果 |
| --- | --- |
| 还没装载镜像 | **立即生效**（改完总线直接重建） |
| **已装载**镜像 | **待生效**（面板顶部出现「待生效 —— 重新装载工程后应用」）⇒ 改板只换总线、不动正在跑的固件 |
| 点「**卸载工程**」 | 清运行态（**镜像与用户的板留着**）⇒ 此后改板**立即生效** |

⚠️ 「待生效」是**推导量**（用户配的板 ≠ 当前生效的图），不是独立的标志位。

### 4.4 板档案

「保存当前板 / 另存为板 / 选用 / 删除」四个动作**一律不发契约命令**——只动**本机浏览器**的板档案。

- ⚠️ **落库门槛 = 只有被内核接受过的描述才允许落库** ⇒ 草稿没提交过 ⇒ 「保存 / 另存为」是**禁用**的（面板上明说「当前草稿尚未被内核接受」）；
- ⚠️ **保存 ≠ 生效**：板要生效仍需「提交板级内存图」；
- ⚠️ **另存为必须给新的板 id**（id 撞了会被明确拒绝，不静默覆盖）；
- ⚠️ **选中项不跨刷新保留**（档案条目只有 id 与描述两个字段）；
- ⚠️ 浏览器没有可用持久化存储 ⇒ 面板明说「板档案只存在于本会话 —— 刷新即失」，**不静默假装成功**；
- 选用**旧规则版本**的板 ⇒ **明确提示**（不静默迁移）；内核接受后档案条目**升级**到当前规则版本。

## 5. 命令行用法

平台有两个 headless runner，都在 `crates/kernel/src/bin/`。

### 5.1 `riscv-golden` —— 跑一个 ELF 出判决

```bash
cargo run --bin riscv-golden -- <path/to.elf>
```

输出**两行**：

```
GOLDEN-STATS retired=<n> traps=<n> tohost=0x<addr>
VERDICT <PASS|FAIL <n>|NOVERDICT|ERROR>
```

最后一行永远是 `VERDICT` 行；**进程退出码与判决一致**（`0` = PASS / `1` = FAIL / `2` = NOVERDICT / `3` = ERROR）。

### 5.2 `osz-boot` —— 跑真实 RTOS，抓 UART 字节流

```bash
cargo run --bin osz-boot -- <path/to.elf> [--out <path>] [--prefix <text>] \
                            [--budget <n>] [--timeout-ms <n>] [--max-console <n>]
```

- **stdout** = console 的**原始字节**（可直接 `cmp`）；**stderr** = 判决行；
- `--prefix` 让它「看到这段文字就停」（真实 RTOS 是死循环，没有墙钟兜底会永远跑下去）。

### 5.3 与 Spike 对拍

```bash
tools/fetch-golden-deps.sh          # 拉 riscv-tests + 交叉工具链到**仓库外**
tools/golden-run.sh --self-check    # 变异金丝雀自检
tools/golden-run.sh --keep-going    # 全量语料 —— 77 例
tools/golden-run.sh --check-mem     # 额外打印两侧 RAM 窗口并断言逐字相同
```

判决口径：**两侧的判决必须一致**（`FAIL` 还要一致到**测试号**）。

```bash
tools/boot-osz.sh --elf <path/to/osz.elf>   # 真实 RTOS 与 Spike 逐字节比 UART
```

判决口径：**两侧 UART TX 字节流逐字节相同** ⇒ 打印 `VERDICT MATCH / MISMATCH / NO-VERDICT`。

⚠️ 这两个脚本**不进默认门禁**（需要仓外的镜像与本机的 Spike）。
⚠️ osz 的产物**在仓外**（默认读 `$OSZ_ELF`，其次 `/tmp/osz-artifacts/osz.elf`）。

### 5.4 在浏览器里加载自己的固件

#### 路 A：界面上点一下（**推荐**，v0.47 批起有 · **v0.48 批起入口在页头** · **v0.58 批起只剩这一个入口**）

1. 打开页面 ⇒ ⇒ **页头**（品牌名**右边**）就有「**固件镜像**」的文件选择器和
   「**加载固件**」按钮 ⇒ ⇒ **任何视图都在**，**不用**切标签页；
2. 选一个文件（`.elf` / `.out` 按 ELF 解析，其余按原始字节）⇒ ⇒ 页头那条短状态
   显示「已选择〈文件名〉（N 字节）」；
3. 点「**加载固件**」⇒ ⇒ 短状态变成「已装载〈文件名〉」；
4. 回调试视图点「**继续**」开始跑。

⚠️ **装载入口只有一个**（v0.58 批起）⇒ ⇒ **页头**那个 ⇒ ⇒ 界面上**不会再有第二个**
「加载」按钮（产品视图里那块**只显示当前固件的状态**）⇒ ⇒ 不会出现「在**一处**装完、
到**另一处**再点 ⇒ ⇒ 报『没有待加载的文件』」那种坑。

⚠️ **连点两次不会报错**（v0.58 批起）⇒ ⇒ 装成功之后再点一次「加载固件」⇒ ⇒ 状态**仍然是**
「已装载」⇒ ⇒ 页脚会提示「已装载〈文件名〉 —— 无需重复加载」⇒ ⇒ **不会**报「装载失败」。
⇒ ⇒ 而**装载失败**之后再点一次 ⇒ ⇒ 会**重试同一份文件**（页脚仍显示内核原话）⇒ ⇒
**要换文件必须重新选一遍**。

⚠️ **不需要**任何 HTTP 服务、**不需要** CORS、**不需要**起后端 ⇒ ⇒ 文件在**浏览器里**读成字节再交给内核（内核**不联网**）。
⚠️ **装完就停** ⇒ ⇒ 第 4 步的「继续」是**你的**动作。
⚠️ `.hex`（Intel HEX）**按原始字节**处理 ⇒ ⇒ 契约层只有 `Elf` / `RawHex` 两种镜像类型，**表达不了** IHEX 语义。

#### 路 B：脚本驱动（自动化 / 真机门禁用）

页面暴露了一个脚本口（`window.riscv_image`）：

```js
// 装载（按 URL 取字节 ⇒ ⇒ 内核不联网，字节是前端 fetch 来的）
await window.riscv_image.loadFromUrl("http://127.0.0.1:8081/osz.elf");

// 反复发 Continue，直到 console 里出现某段字面量
await window.riscv_image.runUntilConsole("OSZ$ ", { timeoutMs: 60000 });
```

⚠️ **路 B 与路 A 共用同一条装载路径**（`loadProjectIntoKernel`）⇒ ⇒ 重订流、清残留这些语义**只有一处**。
⚠️ **文件在仓外 / 另一个端口**时，浏览器要能 `fetch` 到它 ⇒ ⇒ 那台服务**必须带 CORS 头**（前端的 HTTP 服务只服务 `front/`，不带跨域头）⇒ ⇒ 例如：

```bash
# 一个带 CORS 头的临时服务（仓外镜像用）
python3 - <<'PY'
import http.server, functools
class H(http.server.SimpleHTTPRequestHandler):
    def end_headers(self):
        self.send_header("Access-Control-Allow-Origin", "*")
        super().end_headers()
http.server.HTTPServer(("127.0.0.1", 8081),
    functools.partial(H, directory="/tmp/osz-artifacts")).serve_forever()
PY
```

⚠️ **界面上那个文件选择器**（路 A）**不需要**这一步 ⇒ ⇒ 日常用路 A 就够。

## 6. 常见问题

| 症状 | 多半是 | 怎么办 |
| --- | --- | --- |
| 页面全白 / 顶栏写「请通过 HTTP 打开」 | 用 `file://` 打开了 | `python3 -m http.server 8080 --directory front` |
| 顶栏「kernel transport 未连接」 | 没构建 WASM | `tools/build-wasm.sh` |
| 页脚「内核未就绪：…」 | 内核侧真报错 | 把整句抄下来查（码是 `E_*` 家族） |
| 波形视图一直空 | 固件没驱动外设引脚 | 确认固件真的写了 GPIO/UART |
| 终端没输出 | 固件没往 UART0 写，或没订阅 console 流 | 看页脚是否说「console 流不可用」 |
| 板级内存图提交报 `E_PLT-06` | 两段地址重叠 | 改 `base` |
| 板级内存图提交报 `E_PLT-07` | 某段声明 size 超预算 | 调 `region_budget_bytes` 或调小该段 |
| 板级内存图提交报 `E_PLT-12` | 器件参数越界 | 按器件模型的寄存器布局改参数 |
| 板级内存图提交报 `E_PLT-13` | 图被别人改过（并发丢更新） | 刷新后重新提交 |
| 「保存当前板」按钮是灰的 | 草稿还没被内核接受过 | 先「提交板级内存图」，校验通过才能存 |
| 板档案刷新就没了 | 浏览器没有可用持久化存储 | 面板会明说「只存在于本会话」 |

⚠️ **场景码速查**（契约层是唯一定义处；`tools/error_code_check.py` 会守着「一个码一个含义」）：

| 族 | 含义 |
| --- | --- |
| `E_CTX-*` | 上下文 / 通道（如超时、管理通道未开） |
| `E_PROTO-*` | 协议层（版本不符、CRC 不符、消息非法） |
| `E_PLT-*` | 平台 / 内存图（见上表） |
| `E_HMS-*` | 健康管理（降级失败、致命终止） |
| `E_TRX-*` | 传输层（通道未就绪 / 挂 / WASM 宿主侧失败） |
| `E_STORE-*` | 持久化（板档案 / 归档） |
| `E_DBG-*` / `E_ENG-*` | 调试面 / 引擎 |

## 8. 已知限制（如实说）

| 限制 | 说明 |
| --- | --- |
| **服务端形态是占位** | `crates/server/src/main.rs` 只有 20 行；HTTP / WebSocket 宿主是 P1 的活 |
| **板档案只在浏览器里** | 服务端持久化（SQLite）还没做 ⇒ 跨进程持久化要等它 |
| **源码树只在前端** | 源码**不进内核**、**刷新即失** |
| **管理通道实际不可达** | 准入已收口成「角色」，但**令牌 → role** 那一段还没做 ⇒ 宿主侧设角色没有认证门槛 |
| **降级只落地两档** | `Terminate` 与 `TraceDown` 有实现；`SnapshotRestore` / `Pause` / `Disconnect` 还够不着（要跨进程 ⇒ 得升契约版本） |
| **写内存仍然只有脚本接口** | **断点**在 v0.50 批已有页面入口（反汇编行上的按钮 + 调试视图的断点列表）⇒ ⇒ 但**写内存**还是只有脚本接口（`window.riscv_kernel.*`） |
| **`time` 与参考侧不再可比** | 计数器那批把 `time` 接上了 CLINT ⇒ 有意为之的明示取舍 |
| **`.hex` 不按 Intel HEX 解析** | 契约层的镜像类型只有 `Elf` / `RawHex` 两种 ⇒ ⇒ `.hex` 按**原始字节**走；IHEX 语义在契约层**表达不了** |
| **波形图走一个外部依赖** | 波形真图用 **echarts 5.5.1**（jsdelivr 的 ESM 产物 ⇒ ⇒ 浏览器**原生**动态 `import()`）⇒ ⇒ ⚠️ **不是「零依赖」**、但「**零构建**」与「**零安装**」**仍然成立** ⇒ ⇒ **离线 / CDN 不可达时优雅降级**（显示「波形库不可用」而不是白屏）⇒ ⇒ ⚠️ **刻意不 vendor 进仓**（vendor ⇒ ⇒ 「离线不可用」这个缺口就不存在 ⇒ ⇒ 降级路径会变成**装饰**）⇒ ⇒ ⚠️ **订正一条此前登记错的说法**：此前写的是「**破 ADR-6 / NFR-05 的零依赖**」⇒ ⇒ 实测 **NFR-05 讲的是「零安装」不是「零依赖」** ⇒ ⇒ ⛔ **需求文档一个字未改** ⇒ ⇒ 真正改的**只有 ADR-6 §9.6 与架构 §11.2** |
| **v0.55 批的六条已知边界** | **释放不是「立刻」**（发生在宿主同步点 ⇒ ⇒ 一个指令预算窗口 = **10 µs** 虚拟时间）· **guest 不解除源 ⇒ 会被反复交付**（平台**如实复现**标准行为 ⇒ ⇒ 不替 guest 掩盖它自己的 bug）· **单级嵌套**（LLD 明写 **P1**）· **前端行结束符是「一行」的约定**（输入框是**单行**的）· **osz 的 shell 只认 CR**（选 LF 时它**不会**执行命令 ⇒ ⇒ 那是**固件的属性**，平台不猜）· ⚠️ **平台没有参考侧那个 per-source `claimed` 位**（⇒ ⇒ 「服务中」只能在平台级记**一个**） |
| **v0.54 批的五条已知边界** | **「任意地址」是数值地址** ⇒ ⇒ **不能按符号名**（契约层**没有**「列出符号」的事件 ⇒ ⇒ 属升版批次）· **一次读最多 4 字节**（`Byte` / `Half` / `Word` 三档）⇒ ⇒ **没有整段转储** ⇒ ⇒ 「一次看一段内存」属升版批次 · **断点地址必须 2 字节对齐**（M-08 的规则）⇒ ⇒ 前端**不预校验** ⇒ ⇒ 奇数地址**由内核拒**（前端**照发**）· **界面回显的断点列表不是内核断点集的镜像**（内核**没有**「列出断点」的事件 ⇒ ⇒ 脚本口设的断点在界面上**看不到** —— v0.50 批就登记过，本批**原样保留**）· **写内存仍只有脚本口**（契约有 `WriteMemory`，界面**没有**入口） |
| **v0.56 批的六条已知边界** | **屏幕没有回滚缓冲**（屏幕是一条**线性**缓冲 ⇒ ⇒ 行数会一直涨）· **不实现 SGR 颜色**（颜色序列被**吞掉** ⇒ ⇒ 屏幕是**单色**）· **LF 按 ONLCR 建模**（真实串口上 host 端 tty 默认开它 ⇒ ⇒ 与「严格 LF」的终端**不一样**）· **光标不画**（屏幕上没有闪烁的光标块）· **「原始字节」档会显示 `[2K` 这类字面量**（**故意**的 —— 那一档就是看原文）· **屏幕仿真是前端侧的**（⇒ ⇒ 与内核、与 Spike 对拍**无关** ⇒ ⇒ 对拍结论不变） |
| **v0.57 批的八条已知边界** | **条件表达式 v1 只支持寄存器与 PC**（**不能**读内存 · **不能**做算术）· **符号只认 ELF 的 `.symtab`**（`.debug_info` **不在**内核的调试节区白名单里 ⇒ ⇒ **被 strip 的固件查不到任何符号** ⇒ ⇒ 界面会说清「这个镜像没有符号表」）· **候选最多 16 条**（前缀命中更多时只给前 16 条）· **转储最多 4096 字节**且**没有**文件导出 · **条件断点没有命中计数**（不能「命中 N 次后停」）· **条件表达式的错误码住在 `E_DBG` 族**（与模块设计文档 §6.1 那句「本模块错误码归属 `E_CTX` 族」**并存但不一致** ⇒ ⇒ **有意偏差**，如实登记）· **条件表达式在真机上只能由内核判**（前端**不解析** ⇒ ⇒ 写错了是**内核原文**上屏）· **界面回显的断点列表仍不是内核断点集的镜像**（既有边界**原样保留**） |
| **v0.59 批的五条已知边界** | **「复位」= 重新装载当前工程**（⇒ ⇒ 你的固件**留在内核里** ⇒ ⇒ 复位后接着跑**还是它**；⚠️ **不是**「换回内置 demo」）· **复位会顺带应用「待生效的板」**（复位与「重新装载工程」是**同一条路** ⇒ ⇒ STAGE-16 的「待生效板」在复位时一起生效）· **复位清空上一个会话的健康信号流**（⇒ ⇒ 「上一个会话为什么死的」**取证靠 M-21 的日志环** —— 那**不**清）· **「已装载」那一格仍不许「不重新选文件」地重装**（⇒ ⇒ 要重装同一个固件必须**重新选一次** ⇒ ⇒ 本批让「重选同一个文件」**能**触发了，但**仍要点一次「加载固件」**）· **读文件期间点「加载固件」不会装上**（⇒ ⇒ 读镜像字节是**异步**的 ⇒ ⇒ 那一瞬间状态条显示「**正在读取固件…**」⇒ ⇒ 这一下**不会被当成本次装载**⇒ ⇒ **等状态条变成「已选「…」（N 字节）」再点一次** ⇒ ⇒ ⛔ 界面**不会**骗你说「已装载」） |
| **v0.58 批的三条已知边界** | **装载失败后 pending 保留** ⇒ ⇒ 点「加载固件」会**重试同一份文件** ⇒ ⇒ **要换文件必须重新选**（界面**不**单独提示这一点）· **「已装载」那一格只改页脚提示**（面板与页头状态条**都仍是「已装载」** ⇒ ⇒ 用户**看得到**「无需重复加载」那句话）· **产品视图里没有装载入口**（那一块**只显示当前固件的状态** ⇒ ⇒ 要装载得回**页头**） |
| **v0.53 批的四条已知边界** | **「运行中」的判据 = 模式是 running 或在途 `Continue` 计数 > 0**（⇒ ⇒ 在途计数**只数 `Continue`** ⇒ ⇒ **单步期间显示活值**）· **运行中隐藏的是显示、不是测量通道**（顶栏原始皮秒属性**仍给真值**）· **拒绝的是执行、不是显示**（运行中点「读内存」**不发命令** + 弹窗；⚠️ **脚本口 `readMemory` 不弹窗**）· **「暂停」只停续发**（在途窗口还在跑时**仍**算运行中 ⇒ ⇒ 「暂停后那一瞬间仍显示 `-`」是**符合语义**的） |
| **v0.51 批的三条已知边界** | **离线 / CDN 不可达时没有真图**（界面显示「**波形库不可用**」而**通道列表仍在** ⇒ ⇒ 核心调试闭环不受影响）· **图上只显示每通道最近 512 条边沿**（而通道列表里的「N edges」是**边沿总数** ⇒ ⇒ **两个数不是同一个数** ⇒ ⇒ 图例里分开标注 `通道名（显示条数/总数）`）· **波形导出动作只在调试视图**（FR-10 要求的落点在**波形视图** ⇒ ⇒ **本批如实登记、不做**） |
| **v0.50 批的三条已知边界** | **寄存器 ABI 名**（契约层**没有**别名字段 ⇒ ⇒ 界面**不编造**）· **源码行断点不做**（断点**只能从反汇编下**）· **断点列表是「界面回显」不是内核镜像**（⇒ ⇒ 与脚本口设的断点**互不可见**）；另有一条既有边界 = `front/style.css` 里 **12 处裸 `rgba(...)`**（v0.49 批落点之前的遗留） |
