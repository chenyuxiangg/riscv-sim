# Golden corpus manifest — the authoritative list of riscv-tests cases that
# the platform compares against Spike.
#
# Format:  <suite>  <test>  <march>  <status>  [env]  [reason]
#
#   suite   riscv-tests suite directory under isa/
#           The `local` suite is the exception: it is **this
#           repository's own** self-contained cases, read from
#           `tests/golden/local/<test>.S` (the harness falls back to
#           that directory when the upstream tree has no such file).
#           It exists for behaviours upstream riscv-tests has no case
#           for — e.g. an unmapped access trapping (STAGE-7
#           adjudication H / ledger D-99).
#   test    test case name (isa/<suite>/<test>.S)
#   march   -march= value used to assemble the case
#   status  active  — the case must agree with Spike; a mismatch fails the run
#           pending — the case needs an ISA extension M-13 does not implement
#                     yet.  For a pending case the harness tolerates **only**
#                     "the candidate cannot execute it" (ERROR / NOVERDICT).
#                     Any other disagreement is a real defect and fails the
#                     run.  A pending case that starts agreeing is reported
#                     as NOW-PASSING and **fails the run** — flip it to
#                     `active` and the flag stops being stale.
#   env     the environment variant to build the case with:
#             (empty) / -   the default (CSR-free) environment
#             csr           the CSR-capable environment (env/csr/)
#             smode         the supervisor-capable environment (env/smode/)
#           The variant's include path is searched **first**, so its
#           `riscv_test.h` wins over the default one (STAGE-6 adjudication F).
#           ⚠️ `smode` is the `csr` variant **plus** a *direct* `tohost`
#           verdict and a **strict** M-level trap vector (STAGE-22
#           adjudication M) ⇒ ⇒ it is the only environment in which a
#           supervisor-level case can tell "the `sret` landed in U mode"
#           from "the `sret` landed in S mode" ⇒ ⇒ the `csr` variant's
#           trap vector reports the three ECALL causes as PASS ⇒ ⇒ under
#           it, a wrong `sret` landing is a **false green on both sides**.
#   reason  REQUIRED for `pending`: why it is out of scope + the ledger
#           entry that tracks it.  The harness validates that every
#           pending row carries one.
#
# Scope rules (see tests/golden/env/riscv_test.h for the full rationale):
#   * the **default** environment is CSR-free, so `rv32mi` / `rv32si` are
#     OUT with it — they need trap delivery and `mret`;
#   * the **csr** environment (env/csr/) provides the trap vector, the
#     `mtvec` programming and the `mret` epilogue, so the machine-level
#     corpus becomes comparable;
#   * the **smode** environment (env/smode/) is the same room **plus** a
#     *direct* `tohost` verdict and a **strict** M-level trap vector, so
#     the supervisor-level corpus becomes comparable **and** meaningful
#     (STAGE-22 adjudication M / §8 correction 2);
#   * `zifencei` is enabled everywhere so that `fence_i` assembles;
#   * `rv32um` needs the M extension, `rv32uc` the C extension — both
#     landed in v0.16 (ledger D-43 closed), so the corpus is now **all
#     `active`**.  The `pending` mechanism stays in place for the next
#     extension gap.
#
# The machine-level cases that are **still** out of scope are listed in
# `tests/golden/README.md` (§ "Cases that are not in the corpus") together
# with the divergence each one produces.  They are deliberately **not** rows
# here: the harness's `pending` rule tolerates only "the candidate cannot
# execute it", and three of them do execute — they merely diverge, because
# the platform has no S mode, no PMP, and no Zicntr (ledger D-94).  Listing
# them would force the rule to be loosened into a hole; leaving them in the
# README keeps the manifest's rows all-or-nothing.
#
# Runtime ISA for the reference side is
# `rv32imc_zicsr_zicclsm_zifencei_zicntr`:
#   * Zicclsm is what makes Spike *perform* misaligned accesses instead of
#     trapping on them, which is what our ISS's default MisalignedPolicy::Allow
#     does;
#   * Zicntr is load-bearing: the Zicntr *shadow* counters (`cycle` / `instret`
#     / `cycleh` / `instreth`) are **standard** CSRs and Spike gates them by
#     extension ⇒ ⇒ without it, reading `cycle` traps on the reference side
#     and `rv32mi/zicntr` cannot be compared at all;
#   * Zicsr is named explicitly rather than relied on as implied by `rv32imc`
#     (measured: the `csrr` / `csrw` instructions run fine either way).
# See tests/golden/README.md for the full note.

# The `local` suite — this repository's own self-contained cases
# (tests/golden/local/).  They cover behaviour upstream riscv-tests has
# no case for: an **unmapped access** must trap (load ⇒ mcause 5,
# store ⇒ mcause 7, mtval = the faulting address) instead of aborting
# the run — ledger D-99, STAGE-7 adjudication G / H — and a **PMP
# denial** must trap on an address that **is** mapped — ledger D-94,
# STAGE-21 adjudication L — and a **locked TOR PMP entry freezes the
# previous entry's `pmpaddr`** — ledger D-152.
#
# ⚠️ The判据 is the **guest's own check** of mcause / mtval / mepc: the
# guest writes PASS only when all three are exactly right, so "both
# sides stopped erroring" is **not** what these rows prove.
local unmapped_store rv32i_zicsr_zifencei active csr
local unmapped_load rv32i_zicsr_zifencei active csr
#
# `unmapped_fetch` — an **instruction fetch** from an unmapped address
# must trap with `mcause = 1` (instruction access fault), `mtval` = the
# faulting fetch address and `mepc` = the same address (the instruction
# that could not be fetched).  It is the third sibling of the two rows
# above: RISC-V numbers the three access faults differently (instruction
# `1`, load `5`, store `7`), so one case per number is what makes the
# split observable — a platform that used one number for all three would
# agree with the reference side on **one** case and diverge on the other
# two.  Ledger D-103, STAGE-10 adjudication F.
#
# ⚠️ The guest checks all three values itself, and the reference side
# agrees on all three (measured through the corpus' own tohost pipeline:
# the three-check variant is PASS, the reverse control with a wrong
# `mepc` expectation is FAIL 3 ⇒ the check has discriminating power).
local unmapped_fetch rv32i_zicsr_zifencei active csr
#
# `compressed_trap` — a **compressed** store to an unmapped address must
# trap, and the trap context must carry the **exact** faulting PC.
# The faulting store is placed at a 2-mod-4 address on purpose: the
# reference side was measured writing `mepc = 0x8000014a` (bit 1
# preserved), so a write-side mask on `mepc` would show up here as a
# one-bit disagreement. Upstream riscv-tests never traps from a
# 2-byte-aligned instruction, so nothing else in the corpus covers it.
#
# The guest checks all three context values itself (mcause == 7,
# mtval == the faulting address, mepc == the faulting instruction) and
# only reports PASS when all three are exactly right.
local compressed_trap rv32ic_zicsr_zifencei active csr
#
# `pmp_deny` — **PMP must deny a store to an address that IS mapped**.
# With `mstatus.MPRV = 1` (M-mode loads/stores are subject to PMP only
# while MPRV is set), PMP entry 0 (NAPOT, 4 KiB at `0x80040000`, **no**
# permissions) matches the access ⇒ ⇒ the store is denied ⇒ ⇒ the
# guest's trap handler must see `mcause == 7` (store access fault),
# `mtval == 0x80040000` and `mepc` == the address of that `sw`.
# Upstream riscv-tests has **no** case for this: `rv32mi/pmpaddr` only
# writes a `pmpaddr` register and reads it back, it never performs an
# access that PMP could refuse ⇒ ⇒ a platform that *stores* the PMP
# registers but ignores them on the access path would still agree with
# it ⇒ ⇒ the corpus needs a case of its own (STAGE-21 adjudication L).
#
# ⚠️ The denied address `0x80040000` is **inside the RAM window both
# sides map** (`0x8000_0000` + 4 MiB) ⇒ ⇒ the store can fail **only**
# because of PMP, not because the address is unmapped ⇒ ⇒ that is what
# separates this row from `unmapped_store` (which faults on
# `0x90000000`, unmapped on both sides) ⇒ ⇒ a PMP denial and an
# unmapped access share the same cause numbers, so the **address**,
# not the cause, is what tells them apart.
#
# ⚠️ Entry 1 (NAPOT, 1 MiB at `0x8000_0000`, `R`+`W`+`X`) is the
# **control group**: the guest stores to `0x80002000` — inside entry 1,
# outside entry 0 — and reads the value back, and both must succeed
# ⇒ ⇒ without it, an implementation that denies *every* access would
# be green too.
#
# ⚠️ **Packing pitfall**: RV32's `pmpcfg` register holds **four** 8-bit
# entries (byte 0 = entry 0, byte 1 = entry 1) ⇒ ⇒ entry 1 has to be
# packed into **byte 1 of `pmpcfg0`** ⇒ ⇒ the whole register is
# `pmpcfg0 = 0x1f18` (entry 0 = `0x18`, entry 1 = `0x1f`).  Writing
# `pmpcfg1` instead configures entries **4..7** ⇒ ⇒ entry 1 would
# silently never exist ⇒ ⇒ the control group would then fail for the
# wrong reason.
#
# ⚠️ The criterion is the **guest's own check** of mcause / mtval / mepc:
# the guest writes PASS only when all three are exactly right, so "both
# sides stopped erroring" is **not** what this row proves.  Without PMP
# the store simply succeeds ⇒ ⇒ the guest falls through to `fail` ⇒ ⇒
# the row reports FAIL 3 ⇒ ⇒ it has discriminating power.
#
# With this row the corpus grows from **68** to **69** cases.
local pmp_deny rv32i_zicsr_zifencei active csr

# ---------------------------------------------------------------------------
# The supervisor-level corpus (STAGE-22 · v0.38 · S mode)
# ---------------------------------------------------------------------------
#
# `rv32si/sbreak`, `rv32si/scall` and `rv32si/csr` are upstream's
# supervisor-level cases.  They are built with the **`smode`** environment
# (`env/smode/`), which is the `csr` environment plus two behavioural
# changes (STAGE-22 adjudication M / §8 correction 2):
#
#   * the verdict is written **straight to `tohost`** instead of travelling
#     through `ecall` -> trap -> `tohost` — the *encoding* is byte for byte
#     the same (PASS = 1, FAIL n = `(n<<1)|1`), so the harness's comparison
#     is unchanged;
#   * the M-level trap vector is **strict**: it no longer reports the three
#     ECALL causes (8 / 9 / 11) as PASS.
#
# ⚠️ **Why the second change is load-bearing**: under the `csr` environment,
# `rv32si/scall` is a **false green** — if the `sret` wrongly lands in S
# mode, the `scall`'s cause is 9, which the `csr` trap vector reports as
# PASS ⇒ ⇒ **both sides report PASS** ⇒ ⇒ the row proves nothing.  Under
# `smode` the same situation is a **failure** ⇒ ⇒ the row really pins where
# `sret` lands.
#
# ⚠️ The `march` column does **not** grow a new value: the toolchain
# rejects `-march=..._s` (F22), and `sbreak` / `scall` / `sret` /
# `csrr sstatus` all assemble under `rv32i_zicsr_zifencei` ⇒ ⇒ the column
# keeps its existing vocabulary.
#
# The reference side passes all three (measured; see
# `tests/golden/README.md`).
rv32si sbreak rv32i_zicsr_zifencei active smode
rv32si scall rv32i_zicsr_zifencei active smode
rv32si csr rv32i_zicsr_zifencei active smode

# `smode_csr` — the **self-contained** supervisor-level case (STAGE-22
# adjudication N).  Upstream's three cases above cannot observe **why** an
# S-mode trap went where it went, and none of them touches the S-mode CSR
# set; this one does:
#
#   * the S-mode CSRs (`sscratch` / `stvec` / `sepc` / `scause` / `stval` /
#     `sstatus`), each with its WARL rule — including the two `sstatus`
#     judgements that the **untruncated** measurement pins: the guest write
#     mask is `0x000C_6122` (⇒ ⇒ **S mode can write `sstatus.SPP`**) and the
#     read view is `0x800D_E162` (⇒ ⇒ **`SD` is visible**);
#   * the **per-level accessibility** rule — reading or writing an M-mode
#     CSR in S mode is an **illegal instruction** (cause 2), and so is
#     touching an unimplemented CSR;
#   * the **delegation routing** — with `medeleg`'s bit 2 cleared, the very
#     same trap lands on **`mtvec`** instead of `stvec`;
#   * where **`sret` lands** (U mode ⇒ a U-mode `sstatus` read is an
#     illegal instruction).
#
# ⚠️ Every trap-shaped assertion checks a "a trap really happened" flag, so
# a platform that does **not** trap is caught ("no trap" can never be
# mistaken for "pass").
#
# ⚠️ The case **defines `stvec_handler`** on purpose: the environment only
# writes `medeleg` when the test defines one ⇒ ⇒ without it the delegation
# surface would be zero and the case would prove nothing.
local smode_csr rv32i_zicsr_zifencei active smode

# `mstatus_warl` — `mstatus.MPP` is WARL, and writing the **reserved** value
# 2 **legalises the field to 0** while the rest of the same write lands
# normally (measured on the reference side for every old value: 0, 1, 3).
# This row is the golden-side carrier of the `MPP` semantics: it is what
# tells "legalised to 0" from "kept the old value" (the old value is set to
# 3 first) and from "the whole write was discarded" (the low byte must
# still carry `SIE`).
#
# It runs under the **`csr`** environment: it is an M-mode case, and its
# verdict travels through the environment's `ecall` trap path — which is
# exactly what `pmp_deny.S` does too.
local mstatus_warl rv32i_zicsr_zifencei active csr
#
# `pmp_lock_tor` — a **locked** (`L` = 1) **TOR** PMP entry **freezes the
# previous entry's `pmpaddr`** (privileged spec §3.7.6: "if the locked
# entry's `A` field is set to TOR, the `pmpaddr` register of the preceding
# entry is also frozen") ⇒ ⇒ the write is silently dropped and the **old**
# value reads back.  The platform implements this per the spec, but it had
# **never been measured against the reference side** ⇒ ⇒ this row **is**
# that measurement: it is `active`, so the harness runs it on **both** sides
# and compares the two exit codes ⇒ ⇒ a disagreement is a **red row**, i.e.
# a finding about the reference side, not a defect of the case.  Ledger
# D-152.
#
# ⚠️ The case carries its **mandatory control** in the same register: entry
# 2 is a TOR entry that is **not** locked ⇒ ⇒ its predecessor's `pmpaddr`
# must still take a written value ⇒ ⇒ "the value was frozen" and "the write
# was ignored" are told apart ⇒ ⇒ without it, a platform that drops every
# `pmpaddr` write would be green too.
#
# ⚠️ It pins **three** lock semantics, each with its own verdict number:
#   1. the **frozen** scenario — entry 3 is a locked **TOR** entry ⇒ ⇒ the
#      **preceding** entry's `pmpaddr2` is frozen (FAIL 3);
#   2. the **locked entry's own** `pmpaddr3` is read-only — that is the
#      v0.37 batch's **F12 / F13** ("a **locked** entry … its registers stop
#      accepting writes"), measured then and pinned in the corpus now
#      (FAIL 7);
#   3. the **mandatory control** — an unlocked TOR entry's predecessor is
#      **not** frozen (FAIL 4).
# ⇒ ⇒ rules 1 and 2 are two **different** rules (the entry *before* a
# locked TOR entry vs. the locked entry *itself*) ⇒ ⇒ neither substitutes
# for the other ⇒ ⇒ both are asserted separately.
#
# ⚠️ Entry 0 stays the **permit-all** NAPOT entry ⇒ ⇒ the verdict store to
# `tohost` (`0x8000_1000`) can never be denied by the locked entry ⇒ ⇒ the
# row measures the **CSR write behaviour** only, not the access path (that
# is `local/pmp_deny`'s job).
local pmp_lock_tor rv32i_zicsr_zifencei active csr
#
# With these five rows the corpus grows from **69** to **74** cases, and
# with this one from **74** to **75**.

# ---------------------------------------------------------------------------
# The PMP per-piece corpus (STAGE-23 · v0.39 · PMP 逐片判定批)
# ---------------------------------------------------------------------------
#
# `local/pmp_straddle` pins the **two** boundary-crossing semantics of the
# PMP decision rule.  The platform used to decide a whole access with **one**
# "deciding entry" and to require that entry to cover **every** byte; the
# **reference side** (Spike) was **measured** (STAGE-23 §1.2) and it decides
# **piece by piece**, at the 4-byte PMP granularity:
#
#   * scenario A — a misaligned 4-byte **load** at `0x8003_FFFE` whose **tail**
#     lands in a **DENY** entry ⇒ the reference side **denies** it
#     (`mcause` = 5) ⇒ ⇒ "only the start address decides" is falsified;
#   * scenario B — a misaligned 4-byte **load** at `0x800F_FFFE` that
#     straddles **two ALLOW** entries ⇒ the reference side **allows** it and
#     the loaded value is the **mixed** one (`0xBBBB_AAAA`) ⇒ ⇒ "one entry
#     must cover the whole access" is falsified.
#
# ⚠️ **Both rows are needed** — F10 alone is also compatible with "only the
# start address decides", and F9 alone is also compatible with "the deciding
# entry must cover everything" ⇒ ⇒ only the **pair** separates the three
# readings (STAGE-23 F11) ⇒ ⇒ a single case cannot.
#
# ⚠️ The row asserts the **reference side's** behaviour (STAGE-23 §4.3
# 裁决 L) ⇒ ⇒ it was **RED on our side** until **v0.41** closed ledger
# **D-154** (the failing piece's start address is now reported) ⇒ ⇒ that
# red row **was** the discriminating-power evidence ⇒ ⇒ the assertion
# must **not** be softened.
#
# ⚠️ **v0.41 (D-154) added a second assertion**: the trap's `mtval` must be
# the **start of the failing piece** (`0x8004_0000`) ⇒ ⇒ **not** the access's
# effective address (`0x8003_FFFE`) ⇒ ⇒ both sides now agree on it.
#
# ⚠️ A third check — the **control group** — proves the case is alive: an
# **aligned** load and a **misaligned** load that stay **fully inside** the
# ALLOW region must both succeed and return the expected values (the
# reference side **executes** misaligned accesses — STAGE-23 F8 — and so do
# we, F15).
#
# ⚠️ `mstatus.MPRV` = 1 **and** `mstatus.MPP` = 0 are both needed: MPRV
# turns the M-mode bypass off and MPP = 0 (U-mode) is the privilege the data
# accesses then run at ⇒ ⇒ PMP really applies.  Every verdict path clears
# MPRV first, so the `tohost` store (`0x8000_1000`) can never be denied.
#
# ⚠️ The failure numbers tell **which** scenario broke:
#   1 = PASS · 3 = scenario A was **not** denied (platform too loose) ·
#   4 = the aligned control broke · 5 = a trap happened but `mcause` was not 5 ·
#   6 = `mcause` was 5 but `mepc` was not the faulting instruction ·
#   7 = scenario B was **denied** (platform too strict) ·
#   8 = scenario B was allowed but the value was not the mixed one ·
#   9 = the misaligned control broke ·
#   10 = the trap's `mtval` was **not** the failing piece's start (**v0.41**).
#
# With this row the corpus grows from **75** to **76** cases.
local pmp_straddle rv32i_zicsr_zifencei active csr

# ---------------------------------------------------------------------------
# The PMP privilege-scope corpus (v0.40 · D-153 · PMP 的「特权口径」)
# ---------------------------------------------------------------------------
#
# `local/pmp_privilege` pins the **five cells** of the rule "at which
# privilege level does an access run", because that is what decides whether
# PMP applies to it at all.  The privileged spec's rule (§3.7.6) is:
#
#   effective privilege = MPRV ? MPP : current privilege   (loads / stores)
#   fetch always uses the current privilege                 (MPRV is irrelevant)
#   effective privilege == M  =>  PMP is exempt            (unless the deciding
#                                                             entry is locked)
#
# The platform used to collapse that formula into "look at MPRV only" — and
# the fetch path was **unconditionally** exempt ⇒ ⇒ it is wrong in **three**
# directions (ledger **D-153** for the first two):
#
#   * **(a) too strict** — `MPRV` = 1 and `MPP` = 3 (M) ⇒ ⇒ the effective
#     privilege is M ⇒ ⇒ PMP must be **exempt** (allow) · the platform checked
#     it anyway (deny);
#   * **(b) too loose — ⚠️ the security direction** — **S mode** with
#     `MPRV` = 0 ⇒ ⇒ the effective privilege is S ⇒ ⇒ PMP **must** apply
#     (deny) · the platform **exempted** it (allow) ⇒ ⇒ S-mode code can
#     reach memory it must not reach;
#   * **(c) too loose — ⚠️ the security direction** — an **instruction fetch**
#     in **S mode** into an entry with **no `X`** ⇒ ⇒ the reference side
#     **denies** it (`mcause` = 1, instruction access fault) · the platform
#     **exempted every fetch** ⇒ ⇒ allowed.
#
# ⚠️ **The five cells.**  **One** program runs all five; the four data cells
# use the **same** address `T` = `0x8004_0000` (which sits in the DENY
# entry), and the fetch cell jumps to that same address:
#
#   A — M mode · `MPRV` = 0 · `MPP` = 0 ⇒ ⇒ effective privilege M ⇒ ⇒
#       **allow** (and the loaded value must be the pre-filled one)
#   B — M mode · `MPRV` = 1 · `MPP` = 0 (U) ⇒ ⇒ effective privilege U ⇒ ⇒
#       **deny** ⇒ ⇒ a trap with `mcause` = 5
#   C — M mode · `MPRV` = 1 · `MPP` = 3 (M) ⇒ ⇒ effective privilege M ⇒ ⇒
#       **allow** (and the loaded value must be the pre-filled one)
#   D — **S mode** · `MPRV` = 0 ⇒ ⇒ effective privilege S ⇒ ⇒ **deny** ⇒ ⇒
#       a trap with `mcause` = 5
#   E — **S mode** · an **instruction fetch** @ `T` ⇒ ⇒ the fetch uses the
#       **current** privilege ⇒ ⇒ PMP applies ⇒ ⇒ **deny** ⇒ ⇒ a trap with
#       `mcause` = 1 (instruction access fault) and `mepc` = the target address
#
# ⚠️ Cell A alone has **zero** discriminating power (the old and the new
# implementation agree on it) ⇒ ⇒ the discriminating power lives in cell C
# (catches (a)), cell D (catches (b)) and cell E (catches (c)) ⇒ ⇒ **all
# three** must be there.  ⚠️ And D / E are not substitutes for each other:
# they are **two different code paths** in the platform (the data path's
# `m_mode_bypass` and the fetch path's unconditional exemption) ⇒ ⇒ pinning
# one leaves the other hole open.
# ⚠️ And A / B are not redundant either: they differ **only** in `MPRV` ⇒ ⇒
# that pair pins what `MPRV` actually does (it swaps the effective privilege
# of a load / store for `MPP` — it is **not** "turn the check on").
#
# ⚠️ **One program for the five cells** ⇒ ⇒ a "half-fixed" implementation
# cannot look green ⇒ ⇒ the verdict is per-cell and independent.
#
# ⚠️ **Only the FIRST failing cell is reported** (the verdict is a single
# number) ⇒ ⇒ fixing one cell means re-running to see the next one ⇒ ⇒ the
# order is: the **control group** first (it proves the setup), then the two
# cells both implementations agree on (A / B — if they fail, the setup is
# broken and every later verdict is meaningless), then C (the only M-mode
# discriminating cell), then D and E last (they need the S-mode entry, which
# is therefore exercised exactly once and needs no "back to M mode" machinery).
#
# ⚠️ The **control group**: an access inside the ALLOW entry (and outside the
# DENY one) must deliver the pre-filled value — and it is run with PMP
# **actually in effect** (`MPRV` = 1, `MPP` = 0 ⇒ ⇒ the same window as cell B)
# ⇒ ⇒ without it, an implementation that denies *every* checked access would
# satisfy cells B, D and E.
#
# ⚠️ **The trap's causality**: `mcause` must be **5** (load access fault) for
# the data cells and **1** (instruction access fault) for the fetch cell, and
# `mepc` must be **the faulting instruction** (data) or **the target
# address** (fetch) ⇒ ⇒ a trap from somewhere else cannot pass as a denial.
#
# ⚠️ **Cell E's "not denied" is visible.**  The word pre-filled at the target
# (`0xfeedface`) is **not** a valid instruction ⇒ ⇒ if the fetch is allowed,
# that word is *executed* ⇒ ⇒ illegal instruction (`mcause` = 2) ⇒ ⇒ and
# cause 2 **is** delegated ⇒ ⇒ so that trap lands on the **S-level** handler
# ⇒ ⇒ the failure is reported from there ⇒ ⇒ it cannot be confused with
# "denied with the wrong cause".
#
# ⚠️ `mtval` is still **not** asserted here — but the **reason changed**:
# ledger **D-154** was closed in **v0.41** ⇒ ⇒ the platform now reports the
# **failing piece's start address**, exactly like the reference side ⇒ ⇒
# asserting it here **would be green** ⇒ ⇒ it is **not asserted because it
# would be a duplicate**, not because it cannot be asserted ⇒ ⇒ the
# cross-piece `mtval` assertion lives in `local/pmp_straddle` (it expects
# `0x8004_0000`).
#
# ⚠️ The failure numbers tell **which** cell broke:
#   1 = PASS · 3 = cell A was denied · 4 = cell A's value was wrong ·
#   5 = cell B was not denied · 6 = cell B's `mcause` was not 5 ·
#   7 = cell B's `mepc` was not the faulting instruction ·
#   8 = cell C was denied (the platform is too **strict**) ·
#   9 = cell C's value was wrong · 10 = cell D was not denied (the platform
#   is too **loose** — ⚠️ the security direction) · 11 = cell D's `mcause`
#   was not 5 · 12 = cell D's `mepc` was not the faulting instruction ·
#   13 = the control group broke · 14 = an unexpected trap ·
#   15 = the "we really are in S mode" proof did not happen ·
#   16 = cell E's fetch was **not** denied (the platform is too **loose** —
#   ⚠️ the security direction) · 17 = cell E's `mepc` was not the target
#   address.
#
# ⚠️ **The platform side is RED until D-153 is fixed** ⇒ ⇒ that red row **is**
# the discriminating-power evidence ⇒ ⇒ the assertion must **not** be softened
# to make our side green.
#
