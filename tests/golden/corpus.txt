# Golden corpus manifest — the authoritative list of riscv-tests cases that
# the platform compares against Spike.
#
# Format:  <suite>  <test>  <march>  <status>  [env]  [reason]
#
#   suite   riscv-tests suite directory under isa/
#           The `local` suite is the exception: it is **this
#           repository's own** self-contained cases, read from
#           `tests/golden/local/<test>.S` (the harness falls back to
#           that directory when the upstream tree has no such file).
#           It exists for behaviours upstream riscv-tests has no case
#           for — e.g. an unmapped access trapping (STAGE-7
#           adjudication H / ledger D-99).
#   test    test case name (isa/<suite>/<test>.S)
#   march   -march= value used to assemble the case
#   status  active  — the case must agree with Spike; a mismatch fails the run
#           pending — the case needs an ISA extension M-13 does not implement
#                     yet.  For a pending case the harness tolerates **only**
#                     "the candidate cannot execute it" (ERROR / NOVERDICT).
#                     Any other disagreement is a real defect and fails the
#                     run.  A pending case that starts agreeing is reported
#                     as NOW-PASSING and **fails the run** — flip it to
#                     `active` and the flag stops being stale.
#   env     the environment variant to build the case with:
#             (empty) / -   the default (CSR-free) environment
#             csr           the CSR-capable environment (env/csr/)
#           The variant's include path is searched **first**, so its
#           `riscv_test.h` wins over the default one (STAGE-6 adjudication F).
#   reason  REQUIRED for `pending`: why it is out of scope + the ledger
#           entry that tracks it.  The harness validates that every
#           pending row carries one.
#
# Scope rules (see tests/golden/env/riscv_test.h for the full rationale):
#   * the **default** environment is CSR-free, so `rv32mi` / `rv32si` are
#     OUT with it — they need trap delivery and `mret`;
#   * the **csr** environment (env/csr/) provides the trap vector, the
#     `mtvec` programming and the `mret` epilogue, so the machine-level
#     corpus becomes comparable;
#   * `zifencei` is enabled everywhere so that `fence_i` assembles;
#   * `rv32um` needs the M extension, `rv32uc` the C extension — both
#     landed in v0.16 (ledger D-43 closed), so the corpus is now **all
#     `active`**.  The `pending` mechanism stays in place for the next
#     extension gap.
#
# The machine-level cases that are **still** out of scope are listed in
# `tests/golden/README.md` (§ "Cases that are not in the corpus") together
# with the divergence each one produces.  They are deliberately **not** rows
# here: the harness's `pending` rule tolerates only "the candidate cannot
# execute it", and three of them do execute — they merely diverge, because
# the platform has no S mode, no PMP, and no Zicntr (ledger D-94).  Listing
# them would force the rule to be loosened into a hole; leaving them in the
# README keeps the manifest's rows all-or-nothing.
#
# Runtime ISA for the reference side is
# `rv32imc_zicsr_zicclsm_zifencei_zicntr`:
#   * Zicclsm is what makes Spike *perform* misaligned accesses instead of
#     trapping on them, which is what our ISS's default MisalignedPolicy::Allow
#     does;
#   * Zicntr is load-bearing: the Zicntr *shadow* counters (`cycle` / `instret`
#     / `cycleh` / `instreth`) are **standard** CSRs and Spike gates them by
#     extension ⇒ ⇒ without it, reading `cycle` traps on the reference side
#     and `rv32mi/zicntr` cannot be compared at all;
#   * Zicsr is named explicitly rather than relied on as implied by `rv32imc`
#     (measured: the `csrr` / `csrw` instructions run fine either way).
# See tests/golden/README.md for the full note.

# The `local` suite — this repository's own self-contained cases
# (tests/golden/local/).  They cover behaviour upstream riscv-tests has
# no case for: an **unmapped access** must trap (load ⇒ mcause 5,
# store ⇒ mcause 7, mtval = the faulting address) instead of aborting
# the run — ledger D-99, STAGE-7 adjudication G / H.
#
# ⚠️ The判据 is the **guest's own check** of mcause / mtval / mepc: the
# guest writes PASS only when all three are exactly right, so "both
# sides stopped erroring" is **not** what these rows prove.
local unmapped_store rv32i_zicsr_zifencei active csr
local unmapped_load rv32i_zicsr_zifencei active csr
#
# `unmapped_fetch` — an **instruction fetch** from an unmapped address
# must trap with `mcause = 1` (instruction access fault), `mtval` = the
# faulting fetch address and `mepc` = the same address (the instruction
# that could not be fetched).  It is the third sibling of the two rows
# above: RISC-V numbers the three access faults differently (instruction
# `1`, load `5`, store `7`), so one case per number is what makes the
# split observable — a platform that used one number for all three would
# agree with the reference side on **one** case and diverge on the other
# two.  Ledger D-103, STAGE-10 adjudication F.
#
# ⚠️ The guest checks all three values itself, and the reference side
# agrees on all three (measured through the corpus' own tohost pipeline:
# the three-check variant is PASS, the reverse control with a wrong
# `mepc` expectation is FAIL 3 ⇒ the check has discriminating power).
local unmapped_fetch rv32i_zicsr_zifencei active csr
#
# `compressed_trap` — a **compressed** store to an unmapped address must
# trap, and the trap context must carry the **exact** faulting PC.
# The faulting store is placed at a 2-mod-4 address on purpose: the
# reference side was measured writing `mepc = 0x8000014a` (bit 1
# preserved), so a write-side mask on `mepc` would show up here as a
# one-bit disagreement. Upstream riscv-tests never traps from a
# 2-byte-aligned instruction, so nothing else in the corpus covers it.
#
# The guest checks all three context values itself (mcause == 7,
# mtval == the faulting address, mepc == the faulting instruction) and
# only reports PASS when all three are exactly right.
local compressed_trap rv32ic_zicsr_zifencei active csr
