# Golden corpus manifest — the authoritative list of riscv-tests cases that
# the platform compares against Spike.
#
# Format:  <suite>  <test>  <march>  <status>  [env]  [reason]
#
#   suite   riscv-tests suite directory under isa/
#   test    test case name (isa/<suite>/<test>.S)
#   march   -march= value used to assemble the case
#   status  active  — the case must agree with Spike; a mismatch fails the run
#           pending — the case needs an ISA extension M-13 does not implement
#                     yet.  For a pending case the harness tolerates **only**
#                     "the candidate cannot execute it" (ERROR / NOVERDICT).
#                     Any other disagreement is a real defect and fails the
#                     run.  A pending case that starts agreeing is reported
#                     as NOW-PASSING and **fails the run** — flip it to
#                     `active` and the flag stops being stale.
#   env     the environment variant to build the case with:
#             (empty) / -   the default (CSR-free) environment
#             csr           the CSR-capable environment (env/csr/)
#           The variant's include path is searched **first**, so its
#           `riscv_test.h` wins over the default one (STAGE-6 adjudication F).
#   reason  REQUIRED for `pending`: why it is out of scope + the ledger
#           entry that tracks it.  The harness validates that every
#           pending row carries one.
#
# Scope rules (see tests/golden/env/riscv_test.h for the full rationale):
#   * the **default** environment is CSR-free, so `rv32mi` / `rv32si` are
#     OUT with it — they need trap delivery and `mret`;
#   * the **csr** environment (env/csr/) provides the trap vector, the
#     `mtvec` programming and the `mret` epilogue, so the machine-level
#     corpus becomes comparable;
#   * `zifencei` is enabled everywhere so that `fence_i` assembles;
#   * `rv32um` needs the M extension, `rv32uc` the C extension — both
#     landed in v0.16 (ledger D-43 closed), so the corpus is now **all
#     `active`**.  The `pending` mechanism stays in place for the next
#     extension gap.
#
# The machine-level cases that are **still** out of scope are listed in
# `tests/golden/README.md` (§ "Cases that are not in the corpus") together
# with the divergence each one produces.  They are deliberately **not** rows
# here: the harness's `pending` rule tolerates only "the candidate cannot
# execute it", and three of them do execute — they merely diverge, because
# the platform has no S mode, no PMP, and no Zicntr (ledger D-94).  Listing
# them would force the rule to be loosened into a hole; leaving them in the
# README keeps the manifest's rows all-or-nothing.
#
# Runtime ISA for the reference side is `rv32imc_zicclsm_zifencei`:
# Zicclsm is what makes Spike *perform* misaligned accesses instead of
# trapping on them, which is what our ISS's default MisalignedPolicy::Allow
# does.  See tests/golden/README.md for the full note.
